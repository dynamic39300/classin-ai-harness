# IM Copilot 测试环境真实业务闭环升级方案

> 2026-09-14 更新：用户已批准全力实施，并要求 PRD → Spec → Tickets。当前执行状态以[实施 Tickets](../04-specs/features/classin-test-integration/TICKETS.md)及[回归清单](../04-specs/features/classin-test-integration/REGRESSION.md)为准；下文现状与未启动描述保留为规划时基线。

## 1. 目标与本次研究边界

让老师在 V2 的 IM Copilot 中，围绕其 ClassIn 测试账号有权访问的班级、班级内课程、单元、课堂与学习任务进行沟通；教学建议由这些对象的当前状态产生，AI 使用可追溯的业务证据生成内容，老师确认后通过真实测试消息链路交付，最后用学生端与接口回读核验结果。

首个完整例子：测试环境确有一节即将开始的课 → Copilot 识别它和该课应参加的学生 → 生成正确的课前提醒 → 老师编辑确认 → 真实测试班级收到 → 三个测试学生在 ClassIn 中核验收到。群消息覆盖全群；如果该课只指定部分成员，必须核验定向提及或私聊能力，不能把群发送说成仅目标学生可见。

本次只读取代码、规格与既有接口研究，产出方案；未开发、未切换运行模式、未调用业务写接口、未重新验证线上/测试接口的当前可用性。接口证据详见 [研究证据清单](../01-research/CLASSIN-TEST-INTEGRATION-EVIDENCE-2026-09-14.md)。

“真实测试接口”与“自然发生的教学数据”分开记录：已有课题、题目、资源和部分作答为构造的测试内容；它们可以是真实持久化、经真实 API 返回的测试业务对象，但不能因此称为线上自然教学记录。后续真实上课、学生提交等行为才产生相应结果证据。

## 3. 推荐范围与事实所有权

第一批限定为当前老师测试账号、现有目标班级、班级内目标数学课程和三个已注册测试学生。沿真实接口逐层发现，不重新全量筛选机构或搬运生产数据库。完整单课程足以建立首条链路；跨班和同班多课程的隔离，先用契约反例，再用确有权限的少量测试对象核验。

建议保留两种隔离的运行配置：`demo` 与 `classin-test`（名称为提议，不是现有能力）。切换由配置完成，教师日常流程不增加技术选择器。测试模式必须同时隔离身份、目录、缓存、会话绑定、草稿和回执；不能在同一个群里混入原固定物理场景。请求失败应明确无法读取，不自动回退到假数据。

第一批前端范围为教师身份、班级/聊天入口、Copilot 教学动态与上下文、消息交付及相关对象跳转。课程、作业、学生端全站模拟页面不是一次性全部替换：已提供的导航必须到真实测试对象；未接通的编辑功能必须显式不可用，不能把真实对象带进 Mock 编辑页。学生收件与学习行为优先使用已安装的 ClassIn 测试客户端核验。

ClassIn 持续拥有业务事实；V2 只保存必要的带来源业务快照、对象引用、草稿与执行审计。允许有时效的缓存，不建立第二套权威课程库。保留 UI、自然语言对话、生成、编辑和确认的已审阅体验。[依据：架构基线](./ARCHITECTURE-BASELINE.md)、[D-120、D-131、D-142、D-147、D-151](../00-project/DECISION-LEDGER.md)。

## 4. 七个工作面

### 4.1 身份、环境与权限

- 将测试环境地址和教师凭据留在服务端受限配置中，浏览器、Prompt、普通日志与仓库不持有 secret。
- 分开核验教师签名、机构身份、报告专属 `classUserKey`、IM 身份和学生登录票据；教师 secret 不是所有业务的通用通行证。
- 服务端从认证会话确定教师和机构，并按每个对象验证权限。不能信任前端传入的 `actorRef` 或 `tenantRef`。
- 测试环境请求只进入明确允许的测试域；凭据失效、无权、跨环境对象分别报错。
- 本地试验可先限定一个老师账号的服务端会话；多用户 SSO 与生产部署另行定界，不妨碍本次测试闭环，但不能将本地单账号机制宣传为生产鉴权。

### 4.2 业务对象关系与字段合同

统一业务关系：`机构 → 教师可见班级 → 班级内 LMS 课程分类 → 单元 → 活动 → 各类业务详情`；成员关系独立保留班级成员、活动分配名单和实际参与结果。

物理字段必须按接口逐项核对：部分接口的 `courseId/course_id` 表示班级；LMS `categoryId/category_id` 表示班级内课程；`activityId`、`bizId`、课堂 `classId/clientClassId` 不能互换。数仓字段结论作为映射线索，不能直接推广到所有 API。[依据：关联复核](../01-research/CLASSIN-CLASSROOM-COURSE-RELATION-REVIEW-2026-09-14.md)。

建立带环境和机构范围的显式 ID 映射，展示名只用于阅读。每项记录原字段、业务含义、类型、来源接口、关联键、空值/状态枚举、分页规则、时间单位和时区。历史改期曾重建活动，禁止把旧造数脚本的 ID 当长期常量。

必须区分：

- 班级成员数、学生数、活动应参加人数、实际进入人数；
- 作业已发布、学生已分配、已查阅、已提交、待批阅、已批阅和打回；
- 测验未参加、进行中、已提交、客观题结果和主观题待评分；
- 未得分、未批阅、没有数据与 0 分；
- 排定结束、实际授课结束与报告已生成；
- 回放、独立录播、课堂报告、AI 授课分析和 AIC 报告。

### 4.3 API 接入与共享事实读取

建议在现有服务端增加 ClassIn 测试 Adapter，集中处理签名、超时、供应商业务错误码、分页、详情聚合、报告凭据交换和受控资源地址。浏览器仍消费项目 Interface。

`BusinessContextAdapter` 与 `TeachingDynamicsAdapter` 共享同一批经过权限过滤和标准化的业务事实，避免顶部写“3 人未交”而 AI 读到“2 人”。展示、生成和发送是不同时间的快照，使用版本与再次校验处理正常变化。

现有合同可复用，但还需表达环境、有效读取时间、源更新时间、数据窗口、是否取全、缺失原因、对象版本和可用性。`read-only-business-data` 本身不足以区分实时测试读取与 DW 冻结快照。

消息历史与同步合同目前甚至将 `truthLabel` 限定为 `SIMULATED`，也需显式扩展真实测试来源，不能用类型断言强行套入；权限同步 getter 能否承载远端异步状态也需在 INT-0 评估。[依据：消息生命周期合同](../../src/contracts/message/message-lifecycle.ts)。

首期优先按需读取：目录轻量加载，进入班级再取当前课程窗口，点到作业/测验才读相关学生明细。合并同一请求内重复调用、限制并发和分页，明确超时预算，避免为了问一句“下一节课是什么”读取整月所有附件与报告。资源内容需要时再读取，短期链接到期重新获取。

### 4.4 时间与教学动态

测试连接使用服务端真实时间与明确的 Asia/Shanghai 展示规则。单元用例可注入测试时钟，但不得把冻结时钟下的“马上开课”当真实联调验收。

规则模块依据事实计算：开课前的有效提醒窗口、已取消/改期、任务截止、待提交范围、报告生成状态及重复提醒冷却。窗口阈值写入 Spec 并可配置，先用少量规则形成闭环。

课前提醒的对象是本节应参加学生；课中“尚未进入”必须有足够及时且完整的出勤接口。已有课后出勤报告不能证明实时到课能力。若无法取得实时数据，课中只展示可确认的排课信息，不输出缺勤/全勤断言。首讲三人实到为 0 的历史证据尤其不能写成全员到齐。

### 4.5 Copilot 与 Harness 上下文

快捷事项保留自然语言请求，但课程、人数、时间和学生范围从业务对象获取；Prompt 只定义任务与表达方式，不内置“6 人未交”等事实。无候选或多个候选时，在对话里说明缺失或补问。

首条链路先由后端按当前聊天和目标对象捕获小而完整的 Context，复用现有 Runtime。随后为自由查询增加少量按业务意图命名、带教师范围的只读工具，例如查课表、读学习任务结果；通过同一事实读取 Module 实现，不把整个 Apifox 目录开放给模型。

当前 Harness guard 明确不放行业务工具；增加时必须同时更新工具合同、执行鉴权、超时和拒绝测试。模型只生成建议/草稿，正式发送由审批后的执行路径负责。

旧物理/DW 会话与新测试班级会话隔离，避免历史假事实污染回答。现有 Envelope 每个 `value` 截断为 240 字、最近消息最多 6 条，必须检查长题目、报告和计算口径的必要信息是否被截断；按问题抽取或分段读取，不盲目塞入全量资料。[依据：上下文封装](../../src/domain/workbuddy/runtime-context-envelope.ts)。

### 4.6 真实 IM 交付

这是独立的早期可行性门槛。必须找到测试环境中可合法调用、与实际教师和群身份一致的发送及回读链路，确认是 HTTP、原生 SDK/桥接还是两者组合。不能用 Agent Runtime 的 `messages` 接口代替 ClassIn 聊天发送。

建议让 Copilot 的 `ClassInMessageDraftAdapter` 与普通 IM 的 `MessageLifecyclePort` 汇入同一真实传输实现，保留各自生成审批与消息生命周期职责。避免 Copilot 继续通过 `appendMessage` 绕过交付链路。

服务端执行：确认草稿版本与审批 → 重读相关课程时间/取消状态/活动名单和发送权限 → 核对实际群及提及对象 → 发送 → 保存真实消息引用 → 回读。生成时的 `focusRefs` 和对象依赖要保留到执行阶段；当前非个性化发送前重捕获没有传递这些引用，接入时需修正，防止只复核群信息而漏掉本节课已改期。

幂等状态必须持久化并覆盖重启；现有 Mock 只在进程 Map 内按 action 去重，而每次 `proposeMessageSend()` 会生成新 ID。重试应复用同一逻辑请求。服务端是否支持幂等/查询需验证，若响应丢失且无法确认结果，显示“发送结果待核实”，不能盲目重发或承诺恰好一次。

“已接受”“已发送”“学生可见”“已读”分别需要相应证据。接口成功不自动表示三个学生已读。原生 ClassIn 测试客户端的实际收件是首期闭环验收的一部分。

若真实 IM 能力暂不可用，可以交付“真实数据生成草稿”或由老师在原生客户端手动发送，须明确为中间状态；这不满足“V2 真实 API 交付闭环”的最终目标。

### 4.7 稳定性、观测与可重复验收

每次操作贯穿请求引用、教师/环境范围、业务对象引用、Snapshot 版本、Runtime Session、草稿版本、审批、上游消息引用和回读结果。日志脱敏，不保存凭据或完整学生答卷到通用日志。

计时分段记录身份校验、业务取数、模型首响应/完成、发送和回读；错误区分供应商限流、连接超时、业务拒绝、模型失败与结果未知。用户此前遇到的“模型繁忙”不会因数据接入自动解决，应先建立性能基线，再决定缓存/并发/重试预算。

只读请求采用有上限的重试；写请求必须受幂等与结果核实约束。使用测试模式开关回退运行配置，保留已发生的真实消息和审计，不用“回退代码”暗示外部写入也被撤销。

## 5. 推荐里程碑与推进节奏

使用 `INT-0～INT-5`，避免与既有产品 M0/M2 重名。每个阶段交付可见成果、接口证据和未闭合项；按结果过关，不靠“调用了多少个接口”衡量进度。当前均未启动实现。

| 阶段 | 工作内容 | 可检查交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| INT-0 可行性与范围冻结 | 重测最小读取链路；确认教师/机构/班级/课程/学生与 IM 群映射；优先验证真实发送通道与出勤时效 | 带调用日期的能力矩阵、字段字典、目标对象表、真实 IM 接入结论；PRD/Feature Spec 和 Tickets 草案 | 读取路径与首条闭环所需发送方式明确；缺少 IM 接入时不承诺完整闭环排期 |
| INT-1 真实只读现场 | 服务端鉴权、目录和成员、课程/单元/活动读取、模式隔离、相关导航；模型外先核验数据 | V2 能显示与 ClassIn 一致的目标班级、课程和五类活动；权限/分页/失败测试 | 选定范围无漏页、错归属或 Mock 混入；名单与字段口径一致 |
| INT-2 真实课前提醒草稿 | 实时时钟、课前机会、同一对象的上下文、真实模型生成、编辑、发送前依赖校验设计 | 班级有即将开始的真实课时能出现提醒；课名/日期/对象正确，改期或取消后会更新 | 正常、无近期课、改期、多个候选、读取失败均按规则运行；尚不能标记真实交付完成 |
| INT-3 第一条真实交付闭环 | 对接真实消息 Adapter、教师审批、重验、幂等、消息回读；学生端收件 | 一节实际课前提醒由 V2 发送到正确测试群，三名测试学生核验可见；重复/失效测试证据 | 发件身份、群、内容、时间和消息引用相符；未确认不发送；不重复、不跨班 |
| INT-4 学习任务与结果扩展 | 作业催交 → 测验提醒/结果 → 有证据的课堂回顾；录播/资料可用性与完成记录按需接入；补受控只读查询工具 | 一名学生实际提交后，待交名单更新；测验主客观状态正确；报告完成后可用于总结 | 没有结果时不补造；对象级权限与分母正确；自由查询与快捷事项读取同源事实 |
| INT-5 连续使用与收口 | 连续真实使用覆盖课前、提交变化和课后；跨班/多课程隔离、超时/重启、缓存/历史污染、资源失效与回退演练 | 全量验收清单、缺口和性能报告、运行说明；逐项 Review | 核心验收全部有证据，剩余能力明确标为不支持/未验证；用户完成整体审阅 |

依赖顺序：`INT-0 → INT-1 → INT-2 → INT-3 → INT-4 → INT-5`。INT-0 内，LMS 读取与 IM 通道核验可并行；INT-1 后可并行准备生成与传输，但必须在同一课堂、同一群上合流验收。

建议每 1–3 个工作日形成一个小而可验证的工作包，遇到外部接口/权限依赖单列等待，不以等待天数算完成度。先完成 INT-0，再依据真实 IM 接入方式、当前接口成功率和测试数据缺口估算后续工期；本稿不把未知 SDK/权限交付时间假设为已解决。

用户审阅优先集中在三个节点：方案范围与闭环定义、INT-3 首条真实闭环、INT-5 整体验收。中间通过文档和证据检查，无需用户逐接口批准；实际向群发送仍经过产品中的教师确认。

## 6. 最小验证剧本

1. 重新读取当前测试课程，选一节仍未开始的课堂。若当前没有即将开始的课，在后续经授权的测试数据准备中安排专用短课，记录真实排课变更；不静默挪动现有教学记录、不在真实验收中伪造 now。
2. 核对该课堂实际分配给三个测试学生；读取班级群身份，并在原生客户端确认关系。
3. 开课前进入 V2，出现由真实时钟及课表产生的提醒。老师可直接说“帮我提醒这节课的同学”。
4. 草稿引用正确课题与绝对日期/时间，建议准备项区分教学建议与既有作业/资料事实；没有入课链接时不编造。
5. 审阅期间尝试一次改期/取消或成员变更，旧草稿发送应触发重新核对；恢复正确数据后再生成、确认。
6. 真实发送后，用消息回读和三个学生端核验同一条消息。双击或重试不得产生第二条；没有已读证据不显示全员已读。
7. 扩展到一份已有作业：让一个测试学生通过学生端真实提交，老师再问“谁还没交”；待交集合按任务分配名单和提交状态更新。此行为变更是数据闭环证据。

保留三层测试：固定 Adapter 验证规则和故障；真实测试 API 验证权限/关联/状态；真实模型与客户端验证端到端效果。固定时钟测试通过不能替代真实运行窗口测试。

每项状态填写：`未开始 / 通过 / 失败 / 不支持 / 待外部依赖`，另填证据时间、引用与反馈。“不支持”不计入完整通过。

| 编号 | 验收内容 | 核验方法 |
| --- | --- | --- |
| C01 | V2 测试模式使用正确教师和机构 | 服务端身份与 ClassIn 客户端一致，前端改 ID 无法越权 |

| C07 | 无课/缺数据/过期不伪造建议与闭环 | 不输出无依据的全勤、全部完成或 0 分 |

| C10 | 老师可以编辑、取消，未确认不发送 | 检查消息接口调用与原生群无新增记录 |
| C11 | 改期/提交/成员变化会影响发送复核 | 旧内容不会静默发出，保留修改或重新生成入口 |

| C15 | 测验反映真实答题与评分状态 | 未答、已交、主观待评、分数/正确率分母正确 |

| C18 | 跨班、同班多课程、跨环境会话隔离 | 不串对象、缓存、旧假场景或草稿；测试环境不发到生产 |
| C19 | 性能和失败可定位 | 取数/模型/发送分段耗时，错误不统一伪装“模型繁忙” |

## 8. 实施前文档与决策调整

当前 [项目简报](../00-project/PROJECT-BRIEF.md) 和 [AGENTS.md](../../AGENTS.md) 仍以模拟原型为基线。用户这次明确提出测试环境真实接入目标，但同时要求先规划；因此本稿仅提出新增受限测试接入路线，不将任何方案静默标为 LOCKED，也不沿用过去“继续造数”的授权在本轮执行写入。

方案审阅后，更新项目事实：允许授权测试账号的实时 API 接入；保留模拟配置用于可重置测试；生产 API 和生产数据写回仍在范围外。将测试接入身份、真值来源、读写能力范围和验收门槛记录到决策与 Feature Spec，再拆工程票据。模拟与真实通过 Adapter 切换、ClassIn 事实所有权、教师最终发送确认仍沿用已锁定原则。

建议工程改动集中在：应用依赖注入与身份配置、服务端测试 Adapter、业务字段合同与规则、Runtime Context/受控查询工具、真实消息传输与持久回执、教师相关入口和测试。具体文件 Write Set 在 INT-0 形成；本次 Write Set 仅此规划文档与研究证据文件。

## 9. 本次结论与未决项

可行性判断：已有代码具备可替换 Interface，已有课程与多类活动的测试接口历史成功证据，因此具备推进基础；完成真实闭环仍有明确工程工作，不能概括为“把 Mock URL 换一下”。

优先待核实：真实 IM 身份/群映射与发送回读；当前教师权限与接口可用性；实时出勤时效；学生结果数据覆盖；报告与媒体读取条件。三个测试账号和教师已有凭据应优先复用现有安全配置，只有具体重测证明过期或缺失时再请求补充。

下一步建议：审阅本方案后启动 INT-0，先交付一份“这些读取能用、这条 IM 通道能发、这些条件仍缺失”的实测结论，再进入真实只读现场开发。
