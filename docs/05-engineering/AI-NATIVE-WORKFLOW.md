# AI Native 工程协作规范

## 单一任务包

每个 Agent 或本地执行任务必须先写清：

```text
Objective: 要回答或实现的问题
Context: 最小必要文件和决策
Scope: 本次改变与明确不改变
Write Set: 允许写入的路径
Interface: 输入、输出和依赖
Acceptance: 可检查的完成条件
Verification: 命令、截图或文档证据
```

## 研究任务

研究只使用官方文档、源码、协议或一手 API。输出单一 Markdown 研究记录，区分 `FACT`、`JUDGMENT` 和 `UNKNOWN`，并保留来源链接。营销页面可以说明体验，不可证明未公开的内部架构。

## 编码任务

先锁定共享契约，再分配不重叠 Write Set。主 Agent 负责冲突、结果审查和最终验证。子任务的结果必须回到仓库中的 Spec、代码、测试或研究文档。

## 上下文与记忆

优先使用仓库文档和固定 Fixture，不把一次聊天自动升级为项目事实。教师偏好、学生事实、机构规则、任务历史和推断分开治理；高风险内容需要人工确认后才可成为持久数据。

## 失败处理

先复现和定位，再修改。相同假设连续失败两次时回到证据和 Interface 检查。无法验证的结果必须写明未验证范围，不伪造成功。
