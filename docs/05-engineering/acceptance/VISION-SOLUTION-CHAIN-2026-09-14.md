# 识图与解析图完整链路验收（2026-09-14）

问题复现：IM Sidecar 已把图片保存为 Harness 附件，但 BFF 同步等待 `session.prompt`，浏览器与服务端约 60 秒后均把仍在执行的模型回合误报为失败。迁移后的 `tokenhub/gemini-3.5-flash` 路由还在真实请求中返回 HTTP 429 容量限制，因此只有代码能力存在，页面链路并未稳定可用。

修复结果：消息 POST 在图片校验、模型选择和请求发起后返回 `running`，页面通过既有 1.5 秒轮询读取 Harness 持久事件；运行时互斥锁不再覆盖整个模型回合。图片会话使用已由同一凭据实测通过的 `company-gateway/gemini-2.5-pro`。解析图工具对相同结构化内容使用内容哈希 ID，模型重复工具调用不会产生多张重复图片。

真实纵向验收使用一张 1000×650 的“高二物理·动量守恒课堂练习第 5 题”PNG：带图 POST 约 1.28 秒返回 `running`；模型正确识别 2 kg 小车以 4 m/s 与静止 3 kg 小车粘连，给出 `1.6 m/s，向右`；调用 `create_solution_image` 并在约 39 秒结束为 `idle`。解析图接口返回 HTTP 200、`image/png`、1600×900，图片正文由结构化步骤确定性排版。

安全边界保持不变：API Key 仅留在未提交的服务端 `.env`；BFF Session JSON 只保存图片文件名和内容签名，图片字节由 Harness 附件存储；所有模拟业务数据继续标注为固定演示数据。解析图仍需老师核对，当前不代表真实 ClassIn 图片发布回执。
