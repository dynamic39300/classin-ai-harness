# 教师 WorkBuddy 全量能力覆盖矩阵

本矩阵是工程能力资产清单，和[核心业务闭环与能力优先矩阵](./CORE-BUSINESS-LOOP-PRIORITY-MATRIX.md)配套使用。前者回答“每项能力由哪些 Module、Interface、输入和输出支撑”，后者回答“这些能力如何组成全局业务闭环以及先做什么”。

能力分为三层：

- **单点能力**：一次调用完成生成、识别、转换、检索、解释或检查；通常是 AI Tool。
- **组合能力**：多个 Skill、Tool 和规则校验围绕一个业务对象形成草稿或判断；通常是 Copilot。
- **闭环能力**：跨业务对象完成目标、证据、产物、审批、写回和复查；只有满足运行、审批和跟踪条件时才是有限 Agent 候选。

除非标记为 `REAL`，当前均为 `SIMULATED`、`INTEGRATION-SIMULATED` 或 `FUTURE`，不表示真实 ClassIn 已提供全部接口。除 `EDU-01` 外，新增或细化的内部追踪 ID 都是本矩阵的工作编号，不是已锁定的项目决策。

## 读法与约束

- 四类输入必须分开拥有：产品逻辑决定教师流程，业务规则决定合法变化，Domain Knowledge 提供判断依据，业务数据/API 提供当前事实和执行回执。
- 每个组合或闭环能力至少应有 `ContextSnapshot`、可审阅的 `ArtifactDraft` 或判断草稿，以及可追溯的 `EvaluationEvent`。
- 每个业务写回都经过 `ProposedAction`、策略校验、教师 `Approval`、领域 Adapter 和 `ExecutionReceipt`；模型输出不能直接成为业务事实。
- 每个模拟、集成模拟和未来能力都必须展示真值标签；D1 只对“课程目标 → 课程对象”做结构高保真。
- 业务场景名称是产品语言，内部追踪 ID 是工程语言；两者必须同时保留但不能混用。
