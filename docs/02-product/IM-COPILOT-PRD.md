# IM Copilot——基于学情的个性化师生教学沟通

产品需求文档 · v0.1 · 2026-09-17 · 待产品审阅

审阅入口：[Notion PRD v0.1](https://app.notion.com/p/3dea5c3b026b811c8883f15f04ef83e9)；代码基线：`d33e776` / `im-copilot-milestone-2026-09-17`。Notion 新页与功能范围参考页并列放在“详细设计”目录下。

本 PRD 以当前阶段交付为基础独立起草，完整描述产品目标、入口、页面、IM 基础功能、AI 功能、关键规则与验收框架；每个 Feature 用一句话说明功能和核心设计点，作为后续逐项细化的产品主文档。

## 1. 产品定位与目标

**让老师在班级群或师生沟通现场，直接了解教学与学习情况，并把真实业务信息整理成准确、合适、可审阅的消息。**

老师通常需要在课程、课堂、作业、测验、学生记录与群聊之间反复查找，再组织提醒和反馈；本产品把这些上下文与 AI 能力带到 IM 内，减少查数、复制、核对和组织话术的操作。

产品目标：

1. 方便沟通：保留完整的 IM 消息主线，使查看、回复、查找资料和与 AI 协作能够在同一页面完成。
2. 理解业务：围绕当前班级、课程和学生取得相关真实数据，让回答有具体依据。
3. 主动引导：按课前、课中、课后、总结提供合适的建议，同时支持老师随时自由提问。
4. 教师控制：老师决定说什么、对谁说、什么时候发，AI 负责查询、整理和起草。
5. 持续改进：围绕问答匹配、相关性、准确性和可用性迭代，技术取数与字段校验由工程侧承担。

当前阶段已跑通“真实测试业务读取 → DeepSeek 生成 → 教师审阅/修改 → 当前 IM 呈现”的闭环；消息传输及个别业务能力的边界集中说明在第 11 节。

## 2. 用户、角色与使用场景

| 用户或角色 | 核心任务 | 可见性与控制 |
| --- | --- | --- |
| 任课教师 | 查看课程和学情、发提醒、回顾课堂、讲解题目、回复学生 | 使用右侧 AI 消息助手，审阅后决定是否发送 |
| 学生 | 阅读老师消息、回复和提交问题、使用获授权的班级 Agent | 看不到教师助手的私密对话、草稿和处理过程 |
| 班级管理教师 | 查看群资料与公告、管理班级沟通秩序及 Agent 使用范围 | 管理能力按角色授权提供 |

### 2.1 典型场景

- 老师进入班级群，先了解课程进度与下一节课安排，再发一条课前提醒。
- 老师在课中核对学生是否进入课堂，只对有确切未进入记录的学生发提醒。
- 老师课后同步本讲任务，核对作业/测验提交与批改状态，整理高频错题材料。
- 老师根据课堂转写、笔记与报告形成课堂回顾，或按明确周期整理个人/班级学习摘要。
- 老师引用学生在群里提出的问题，查看上下文、已有回复和关联题目，再组织回复。
- 老师或学生选择当前班级已授权的 Agent，在群内公开提问或进入自己的 Agent 私聊。

### 2.2 三种 AI 沟通关系

| 形态 | 谁发起 | AI 输出在哪里 | 核心区别 |
| --- | --- | --- | --- |
| 教师 AI 消息助手（IM Copilot） | 教师 | 教师私密侧栏；教师确认后进入目标聊天 | 服务老师的查数、分析与起草，公开发言权属于老师 |
| 群聊 @Agent | 获授权的教师或学生 | 当前班级群，使用 Agent 身份 | 群成员可以沿同一公开消息主线继续讨论 |
| Agent 单聊 | 获授权的教师或学生 | 当前用户与该 Agent 的独立会话 | 同一个 Agent 的不同用户私聊彼此隔离 |

## 3. 入口与页面结构

### 3.1 入口 Feature

| ID | Feature | 一句话功能与核心设计点 |
| --- | --- | --- |
| ENT-01 | 一级“消息”入口 | 从一级导航进入消息中心，按会话选择沟通对象，并在教师可用会话旁呈现 AI 消息助手。 |
| ENT-02 | 课程/班级详情“班级群聊”入口 | 从详情页直达对应班级群，自动带入当前班级与课程语境，保留返回原详情页的路径。 |
| ENT-03 | 两个入口体验一致 | 两个入口复用同一聊天与 Copilot 能力，同一会话的消息、AI 历史和草稿能够连续使用。 |
| ENT-04 | 沉浸式消息工作区 | 将消息列表、当前聊天与 AI 辅助区组织在同屏工作区，进入和退出时保留当前会话及编辑状态。 |
| ENT-05 | 单班级聚焦布局 | 从详情进入时只呈现当前班级聊天与助手，省去跨会话列表，突出当前教学现场。 |
| ENT-06 | 栏宽与紧凑窗口适配 | 宽屏允许调整聊天与助手的空间比例，紧凑窗口按可用宽度切换为覆盖面板，保持输入和关键动作可达。 |
| ENT-07 | 按角色显示入口 | 教师在可交互班群及受支持私聊中使用助手，学生、系统通知和官方公告不显示教师私密 Copilot。 |

### 3.2 页面区域

| 区域 | 主要内容 | 交互原则 |
| --- | --- | --- |
| 页面导航 | 消息/班级群聊定位、退出沉浸或返回班级 | 返回后保持业务来源 |
| 会话列表 | 四类分类、搜索、对象入口、未读提示 | 仅消息中心显示完整跨会话列表 |
| 聊天顶部 | 会话名称、公告、提醒、搜索、群文件、资料与管理 | 操作围绕当前会话，不增加常驻第四栏 |
| 聊天时间线 | 普通消息、引用、媒体、结构化内容与发送状态 | 消息正文是阅读主线 |
| 聊天输入区 | 输入、表情、图片、提及、引用和发送 | 与右侧 AI 输入明确区分 |
| 助手顶部 | AI 消息助手、建议摘要、四阶段导航和事项 | 说明能做什么，并引导当前可操作事项 |
| 助手对话区 | 三问引导、教师问题、运行状态、回答、草稿及历史 | 一条连续对话，过程按需展开 |
| 助手输入区 | 自由提问、图片、“可以问什么”、发送/停止 | 不依赖顶部推荐加载完成即可输入 |

## 5. IM Copilot 通用 AI 功能

### 5.1 发现与引导

| ID | Feature | 一句话功能与核心设计点 |
| --- | --- | --- |
| AI-01 | 教师私密助手 | 以“AI 消息助手”身份在当前聊天旁协助老师，生成过程和草稿只对当前教师可见。 |
| AI-02 | 四阶段建议导航 | 按课前、课中、课后、总结展示当前业务可支持的建议，数量来自实际可操作事项并允许手动切换。 |
| AI-03 | 顶部展开与收起 | 老师手动控制建议区展开状态，后台更新不强制展开、不抢焦点、不打断对话阅读。 |
| AI-04 | 推荐加载与更新 | 首次进入读取推荐，成功后按一小时更新节奏刷新，加载、慢请求、失败及重试均在顶部局部表达。 |
| AI-05 | 三个快捷问题 | 从已审阅的问题中提供三个可直接发起的问题，并依次入场，在推荐尚未可用时帮助老师开始沟通。 |
| AI-06 | 引导平滑交接 | 当前展开阶段的可操作建议呈现后让三问平缓退出，保护正在悬停或键盘操作的问题，不追加临时 toast 或按钮闪亮。 |
| AI-07 | “可以问什么” | 在输入区持续保留分类问题目录，供老师发现课程、考勤、作业、学生、课堂资料与群聊相关能力。 |
| AI-08 | 自由提问 | 支持直接输入班级、课程、作业等问题或写消息要求，无需等待顶部推荐完成。 |

三问展示补充规则：有历史但历史默认收起时仍可展示；老师主动展开历史或开始新一轮对话后退出；如果当前阶段没有可操作建议，三问可继续保留；三问本身不写入聊天历史。

### 5.2 理解、生成与连续对话

| ID | Feature | 一句话功能与核心设计点 |
| --- | --- | --- |
| AI-09 | 当前业务上下文 | 自动绑定当前会话允许访问的班级、课程与相关对象，遇到真实歧义再向老师补问。 |
| AI-10 | 按问题取数 | 根据问题调用适合的业务读取能力，仅把直接相关的真实数据作为回答依据。 |
| AI-11 | 消息引用给 AI | 将老师指定的群消息带入助手，连同必要的前后文和关联业务信息理解问题。 |
| AI-12 | 图片输入与理解 | 接受老师提供或授权引用的图片，区分原始图像、识别结果与模型分析，并在无法读取时明确提示。 |
| AI-13 | 连续追问与改写 | 保持当前聊天内的连续沟通语境，支持补充条件、调整表达和继续处理上一轮结果。 |
| AI-14 | 可感知的真实运行 | 用简洁状态反馈读取、生成、完成和失败，详细处理过程按需展开，不展示伪造进度或原始思维链。 |
| AI-15 | 停止与恢复 | 老师可以停止生成，连接或会话异常时保留已读内容并提供恢复，避免重复执行。 |
| AI-16 | 历史恢复与隔离 | 刷新或返回时恢复同一聊天的 AI 历史并默认收起，不同老师、班级与私聊的数据互不混用。 |
| AI-17 | 结构化回答 | 按信息类型选择段落、列表或表格，多对象比较与进度明细优先采用表格，表头和首列形成清晰层级。 |
| AI-18 | 事实与覆盖说明 | 对回答涉及的对象、时间范围、数据覆盖及缺失给出必要说明，不把未知值写成零或肯定结论。 |

### 5.3 草稿审阅与消息交付

| ID | Feature | 一句话功能与核心设计点 |
| --- | --- | --- |
| AI-19 | 查询与写消息意图区分 | 普通查询直接回答，明确写消息的要求才生成待发送草稿，建议型回答可进一步整理成消息。 |
| AI-20 | 可发送正文整理 | 生成适合目标对象阅读的消息正文，自动隔离对老师的寒暄、写法说明和内部处理信息。 |
| AI-21 | 草稿修改与取消 | 老师可修改正文和适用的接收对象，取消编辑回到原回答而不发送，修改后以当前版本为准。 |
| AI-22 | 目标与确认发送 | 在发送动作旁明确目标群或个人，老师确认后才交付，私密 AI 对话不会自动进入公开聊天。 |
| AI-23 | 发送前事实复核 | 核对草稿依赖的对象、名单与业务状态，真实变化时提示重新生成，单纯读取时间变化不误拦截。 |
| AI-24 | 发送结果与失败保留 | 发送成功后显示对应结果，失败保留草稿和恢复动作，模型完成不等于消息已发送。 |
| AI-25 | 同一内容跨区一致 | 审阅正文与发送后的聊天消息共用结构化呈现规则，表格、列表、强调和提及不因发送而变成乱码。 |

## 6. 四阶段教学沟通功能

以下十项是完整的推荐意图；它们会按当前事实出现，不要求每个时刻固定显示十条。

| ID | 阶段 | Feature | 一句话功能与核心设计点 |
| --- | --- | --- | --- |
| P01 | 课前 | 同步课程学习计划 | 汇总本班各课程的学习安排、当前进度与后续课堂，按课程分列后生成可发送的计划消息。 |
| P02 | 课前 | 下一课堂提醒 | 根据最近一节已发布且未取消的课堂，生成含课名、时间及有依据准备要求的课前提醒。 |
| P03 | 课中 | 提醒尚未进入课堂的学生 | 仅在取得当前课堂成员级实时证据后确定未进入学生并起草提醒，满勤时只说明无需催课。 |
| P04 | 课后 | 同步本讲学习任务 | 汇总与本课或单元明确关联的已发布作业、测验及资料，说明任务要求与截止时间。 |
| P05 | 课后 | 作业催交 | 按作业真实提交状态和截止时间定位未交学生，形成语气适当且可核对的提醒。 |
| P06 | 课后 | 测验催交 | 按测验自己的参与和提交规则定位待完成学生，避免把测验状态与作业状态混用。 |
| P07 | 课后 | 高频错题材料 | 根据可核验的逐题结果整理高频错题、涉及人数与解析材料，明确有效统计分母。 |
| P08 | 总结 | 本讲课堂回顾 | 结合实际可读的原始转写、教师笔记与 AI 分析提炼课堂内容，再生成适合分享的回顾。 |
| P09 | 总结 | 整班阶段学习总结 | 在明确课程、周期和学生覆盖范围内汇总整班已发生的学习情况，并把未来安排另列。 |
| P10 | 总结 | 个人阶段学习总结 | 围绕指定学生和周期整理到课、任务及其他可读学习证据，生成由老师审阅的个人沟通内容。 |

### 6.1 四阶段统一规则

- **真实空态**：没有对应业务事项时显示提示说明，不生成模拟任务、模拟学生或模拟成绩填充页面。
- **课中无课**：仅显示“当前没有正在上课的课堂”，不显示不可执行按钮或“仅供查看”徽标。
- **课中满勤**：有可靠成员级证据时可说明课堂、已上课时长及满勤状态，不生成催课消息。
- **课中未知**：处于排课时间但实时到课未确认时明确未知，课后考勤或总人数不能替代实时成员结果。
- **建议计数**：只统计实际可操作事项，空态、满勤提示和数据未知不计入建议数量。
- **建议去重**：同一意图与业务对象只出现一次，作业催交与测验催交分开处理。
- **总结范围**：只保留课堂回顾、整班总结、个人总结等沟通事项，不展示课程活动总数/完整性说明卡。
- **触发与更新**：生成或发送消息不会自行改变课堂、作业和学生事实，建议随真实业务变化更新。

## 7. 老师可主动询问的业务问题

主动问答与阶段推荐共用取数和生成能力，下面按 21 类已预验证问题定义回答范围；编号沿用问题目录，编号不连续不表示漏项，也不重复计作十项阶段推荐。

| 题号 | 代表问题 | 一句话回答要求 |
| --- | --- | --- |
| A1 | 我们班有哪些课程，分别学到哪了？ | 按课程说明单元数、已结束课堂、最近课堂和下一课堂，不合成混合进度百分比。 |
| A2 | 接下来上什么课，什么时候上？ | 给出下一课堂名称、日期、时间及可确认的学生人数，排除取消或未发布课堂。 |
| A3 | 我们班有多少学生？ | 按当前成员身份统计学生人数，区分教师、助教和其他成员类型。 |
| A4 | 这节课有哪些配套活动和资料？ | 根据明确的课程结构关联列出本课或单元的活动与资料，不按相似名称猜关系。 |
| B1 | 这节课到课怎么样？ | 按课堂阶段区分实时到课和课后考勤，说明能够确认的人数、状态和范围。 |
| B2 | 最近几节课谁迟到或缺席？ | 按实际覆盖课次列出学生与次数，缺少请假数据时说明限制，不评价学生态度。 |
| B3 | 这节录播大家学到哪了？ | 说明分配人数、未开始/学习中/已完成状态及个人进度和时长，适合比较时使用表格。 |
| C1 | 这份作业有什么要求，什么时候交？ | 准确说明作业要求、题目范围、截止时间及相关附件。 |
| C2 | 谁还没交，交上来的批完了吗？ | 分清未提交、待批阅和已批阅，按活动类型核对名单与汇总。 |
| C5 | 最近作业和测验哪些题错得多？ | 列出题目、可判定人数、错误人数和判定来源，避免把未批阅当作答错。 |
| D1 | 这位同学最近学习情况怎么样？ | 在指定学生和周期内陈述实际取得的学习事实，说明覆盖范围及无法判断的内容。 |
| D2 | 这位同学还有哪些任务没完成？ | 按课程区分当前未完成、逾期和未来任务，遵循各活动类型自己的完成规则。 |
| D5 | 根据这些学情信息写一段给家长的话。 | 将已有事实改写为合适的沟通草稿，不新增成长判断、家长关系或送达承诺。 |
| E1 | 这节课有哪些报告、回放和板书？ | 分别说明资源是否存在、可否读取及进入方式，不把目录存在等同于内容已读。 |
| E2 | 帮我整理这节课的课堂回顾。 | 从实际课堂内容提炼知识、方法和练习要点，区分转写、笔记与 AI 结论来源。 |
| E3 | 把这份学习资料的方法整理成三点。 | 基于实际可读正文提炼方法，文件不可读时提示补充而不凭文件名生成内容。 |
| E4 | 总结一下本周班级学习情况。 | 汇总当前周期内已发生的学习活动，明确课程、学生及活动覆盖，并另列未来安排。 |
| E5 | 把刚才的内容整理成一条消息。 | 沿用当前对话已经核实的内容生成消息，保留对象和时间，不新增业务事实。 |
| F1 | 总结一下最近几天群里聊了什么。 | 基于实际取得的原始消息归纳要点，注明条数、时间范围和分页覆盖限制。 |
| F2 | 帮我讲解群里提到的这道题。 | 从引用消息定位题目和版本，结合完整题面生成讲解，并区分标准解析与 AI 新解。 |
| F3 | 帮我回复这位同学的问题。 | 结合原问题、前后文及已有回复判断是否需要再答，必要时生成可编辑回复。 |

## 8. 班级 Agent 的群聊与单聊

这两类功能属于 IM AI 的整体产品范围，与教师私密 Copilot 使用不同的身份和可见性规则。

| ID | Feature | 一句话功能与核心设计点 |
| --- | --- | --- |
| AG-01 | 已授权 Agent 发现 | 只展示当前班级、角色和渠道可用的 Agent，并允许按名称或能力查找。 |
| AG-02 | 群聊 @Agent | 在群消息输入区选择一个目标 Agent 并提问，Agent 用自己的身份在当前群公开回复。 |
| AG-03 | Agent 选择与替换 | 发送前明确本次目标 Agent，允许替换或移除，避免同时触发多个不明确的执行对象。 |
| AG-04 | 师生 Agent 单聊 | 教师或学生进入自己与已授权 Agent 的独立聊天后可连续提问，无需每轮再次 @。 |
| AG-05 | 班级与角色上下文 | 同一 Agent 按班级绑定及教师/学生身份使用允许的内容，不跨用户共享私聊信息。 |
| AG-06 | 授权变化与失败恢复 | Agent 被停用、渠道不允许或请求失败时给出相应提示和可用恢复动作，不冒充回复成功。 |

教师配置哪些 Agent 加入班级以及是否向学生开放是目标产品的治理要求；当前已实现发现、选择、渠道和权限骨架，完整配置后台及真实模型/数据接入另行验收。

## 9. 核心用户流程与状态

### 9.1 看情况，再写消息

进入班级沟通现场 → 点击推荐或自由提问 → 系统读取相关信息 → AI 回答 → 老师要求整理为消息 → 审阅/修改 → 确认目标并发送 → 在聊天区查看结果。

### 9.2 直接处理阶段建议

选择课前/课中/课后/总结 → 点击某条业务建议 → 助手自动带入对象和要求 → 生成草稿 → 老师核对内容与对象 → 发送前复核事实 → 交付并显示结果。

### 9.3 回复学生问题

定位学生消息 → 引用给 AI → 核对问题、已有回复和相关业务 → 得到讲解或回复建议 → 老师补充/修改 → 确认后发到目标聊天。

### 9.4 状态要求

| 状态 | 老师看到什么 | 可进行的操作 |
| --- | --- | --- |
| 顶部加载中 | 局部加载效果和可用的提问入口 | 继续输入或点击快捷问题 |
| 读取成功但无任务 | 对应阶段的提示说明 | 切换阶段或自由提问 |
| 数据未知/部分可读 | 具体缺失范围及对回答的影响 | 补充对象、按可用范围继续或重试 |
| 需要澄清 | 与当前任务有关的最少必要问题 | 直接在同一对话补充 |
| 生成中 | 简洁运行状态与可展开过程 | 停止生成；避免重复提交 |
| 回答完成 | 正文及必要的依据/覆盖说明 | 继续追问、改写或整理为消息 |
| 草稿待审阅 | 消息正文、目标对象与发送操作 | 修改、取消编辑或确认发送 |
| 业务事实变化 | 指明需要核对的内容并保留草稿 | 核对最新信息后重新生成 |
| 权限拒绝/连接失败 | 可理解的失败原因 | 恢复连接、切换允许的对象或重试 |
| 发送失败 | 未发送成功的明确状态及原稿 | 使用正确恢复操作重试 |
| 已发送 | 与实际通道能力一致的结果 | 回到对应聊天查看并继续沟通 |

本期阶段建议定位为信息同步与沟通辅助，不新增学生必须确认、老师必须关闭任务或学生再练结果自动回流的流程。

## 10. AI 运行与真实业务数据要求

本节描述用户体验成立所依赖的能力，具体接口字段、路由实现和模型配置由技术规格维护。

| ID | 能力 | 一句话需求与核心设计点 |
| --- | --- | --- |
| RT-01 | DeepSeek Harness 运行 | 复用现有 DeepSeek Harness 执行理解、取数与生成，以真实运行事件驱动页面状态。 |
| RT-02 | 工具与业务 API 调用 | 将老师问题关联到受控工具和测试环境业务接口，确保调用对象与当前授权范围一致。 |
| RT-03 | 业务数据作为上下文 | 将真实返回的业务事实整理成模型可用上下文，保留来源、读取时间、对象和必要限制。 |
| RT-04 | 数据类型与统计口径 | 区分课程与课堂、作业与测验、未交与待批、零值与未知、已发生与未来安排。 |
| RT-05 | 会话与执行可靠性 | 支持连续运行、停止、断线和失效会话恢复，避免重复请求导致重复产物或消息。 |
| RT-06 | 教师审阅与执行分离 | 将 AI 生成、教师确认和消息交付作为不同状态，未获确认不执行外发。 |
| RT-07 | 问答质量评估 | 由老师评价答到点、相关性和好用程度，工程侧负责接口准确性、字段完整性与可追溯检查。 |
| RT-08 | 独立接口审阅台 | 在研发审阅页面查看问题、取数计划、实际接口、业务数据和模型回答，并记录质量评价及补充信息建议。 |

当前业务数据覆盖班级/课程/单元/活动、成员、作业测验及逐题结果、课后成员级考勤、录播参与、课堂转写/笔记/报告、可读学习资料，以及授权群聊样本。保留原始消息语义；本机凭据和私有样本不随仓库或 PRD 发布。

## 12. 验收框架

### 12.1 产品功能验收

| 维度 | 验收标准 |
| --- | --- |
| 入口一致 | 消息中心与班级详情可进入同一班级沟通现场，AI 历史与草稿连续、返回路径准确 |
| IM 基础沟通 | 分类、发送、引用、Reaction、搜索、资料、翻译等在所标明的交付范围内可操作 |
| 四阶段 | 十项推荐均有触发与空态规则，计数正确，未知不补造，课中无课只作提示 |
| 主动问答 | 21 类问题逐项检查对象、时间、口径、上下文及最终回答，条件能力显示其实际范围 |
| 问答质量 | 老师能直接判断是否答到点、是否相关和是否好用；关键业务事实须与当前验收样本一致 |
| 消息审阅 | 查询不被默认包装成待发送任务，正文可修改/取消，发送使用老师最终确认的版本 |
| 内容呈现 | AI 区与聊天区的表格、标题、列表和强调保持一致，紧凑窗口可阅读且关键动作不被遮挡 |
| 交付安全 | 零次未经教师确认的外发；一次确认只产生一次交付，失败不显示成功 |
| 身份与权限 | 学生看不到教师私密过程，不同班级、用户及 Agent 单聊之间不串数据 |
| 加载与恢复 | 推荐加载不阻塞提问，刷新不丢失历史，失败保留可恢复内容且无静默模拟回退 |
| 可访问性 | 键盘可完成核心操作，焦点不被后台更新抢走，减少动态效果设置下仍可正常使用 |

### 12.2 阶段验收与效果评价

当前真实问题验证记录为 15 项通过、6 项带覆盖条件通过；十类推荐为 7 项通过、2 项带条件通过、1 项实时考勤外部阻塞。这些数字只描述当前样本与能力边界，不能换算为任意自由问题的准确率。

工程门禁包含类型检查、Lint、单元/集成测试、Harness 契约、构建、浏览器及适用的无障碍验收；产品签收仍以老师实际问答体验与业务核对为依据。

后续评估建议观察首次有效提问、建议触发后完成率、草稿修改程度、老师采纳率、事实错误率和任务耗时；具体指标口径及目标值在下一轮审阅确定，本稿不填造运营结果。
