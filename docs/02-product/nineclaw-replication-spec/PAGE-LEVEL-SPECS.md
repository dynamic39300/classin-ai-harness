# NineClaw 页面级 PRD

## 1. 阅读方式

每个页面按“目的 → 区域 → 字段/操作 → 状态 → 跳转 → 证据缺口”描述。尺寸、字体、色值和精确间距在现有截图标定前不写死；可见结构、文案语义和行为必须保留。经产品审阅确认，本文中的 `UNKNOWN` 在后续实施中可以基于经验补充合理默认值和处理方式，补充项统一标记为 `DESIGN_COMPLETION`，不作为 NineClaw 一手事实。

## 2. G-P01 全局应用壳

### 用户目的

在任务、能力、内容、文件和系统配置之间切换，并持续访问历史任务、会员和积分。

### 区域与元素

| 区域 | 元素 | 行为 |
|---|---|---|
| 品牌区 | NineClaw 标识、侧栏收起按钮 | 收起后保留图标模式 |
| 主导航 | 新建任务、技能广场、工具广场、内容广场、定时任务 | 单选高亮，切换主内容 |
| 历史区 | 标题、展开/列表/搜索控制、任务条目、相对时间与“…”菜单 | 打开既有任务；条目菜单支持重命名、置顶、删除；搜索行为待补录 |
| 资产区 | 我的文件、文件数量 | 进入文件页，完整行为 `UNKNOWN` |
| 系统区 | 设置 | 进入设置壳 |
| 商业区 | 会员卡、积分卡 | 进入会员/积分页面或弹层 |
| 用户区 | 头像、姓名 | 用户菜单内容 `UNKNOWN` |

### 状态

展开、收起、当前一级模块、历史空/有数据、历史加载、账户已登录；历史条目右侧默认显示距离当前几小时等相对时间，操作位置显示“…”并打开重命名/置顶/删除浮层。【OWNER-C1】离线和未登录壳未完整观察。

## 3. T-P01 新建任务首页

### 用户目的

用一句自然语言或快捷任务开始工作，并指定文件、目录、Skill 或模型。

### 页面结构

- 顶部右侧：用户头像与名称；
- 中心推广横幅；
- mascot 与问候语“Hi，有什么需要我帮忙的吗”；
- 大型输入器；
- 快捷入口：智能教案、教学动画、课后练习、逐字稿。【UI-E1】

### 输入器字段与操作

| 元素 | 默认/显示 | 操作结果 |
|---|---|---|
| 工作目录 | `我的文件`或最近目录 | 打开 T-O01，切换本次任务落点 |
| 文本区 | 自然语言目标 | 多行输入；精确最大长度 `UNKNOWN` |
| 附件按钮 | 图标 | 选择文件/文件夹；类型和上限 `UNKNOWN` |
| Skill 按钮 | 图标；选择后显示 chip | 打开 T-O02；chip 的 X 移除本次选择 |
| 模型选择 | 当前/默认模型 | 打开 T-O03 |
| 发送 | 图标按钮 | 创建 Run；无有效输入时不可用 |

### T-O01 工作目录选择器

显示最近使用目录和“添加文件夹”；选择后关闭并更新输入器。取消、路径权限失败和不存在目录状态待补录。

### T-O02 Skill 选择器

- 搜索框“搜索技能”；
- 可见列表包含 Word 文档、网页设计、文件上传、PDF 文档、PPT 演示文稿、学科专家；
- 每项显示图标、名称、截断说明和“官方”标识；
- 底部入口进入技能广场；
- 选择后返回首页并显示 Skill chip。【UI-E1】

### T-O03 模型选择器

支持默认模型与模型选项，包含进入自定义模型设置的入口；具体供应商与排序随配置变化。【UI-E1】

### 快捷任务

快捷入口应注入任务意图并进入输入/补参链，而不是绕开统一任务。是预填后等待发送还是立即创建 Run，现有证据不足，登记 `UNKNOWN`。

## 4. T-P02/T-P03 历史与运行中任务

### 顶部

任务标题、`本地`标签、工作目录和更多菜单。标题生成/改名规则、更多菜单内容待关键帧确认。

### 会话时间线

按时间显示：用户消息、Agent 文本、思考过程、补参卡、计划、步骤更新、Skill/Tool/命令/文件事件、阶段总结、Artifact 卡和错误恢复。详细规则见 [Agent 任务执行交互规格](./TASK-EXECUTION-INTERACTION-SPEC.md)。

### 底部输入器

- 空闲时允许追加文字、附件和能力上下文；
- 运行时仍可中途追加约束；
- 运行时主控制显示红色停止按钮；
- 停止后保留已有事件并恢复发送能力；
- 同时发送与停止的竞态表现 `UNKNOWN`。

### 结构化补参卡 T-O04

卡片标题“需要您的确认”、说明、教材版本问题、选项、“其他”、跳过和提交；提交后出现“用户确认”结果并继续任务。多页进度、返回上一问、其他问题类型和必填校验保持 `UNKNOWN`。【UI-E1】

### 任务结束

显示完成总结、生成文件链接和可能的下一步建议。完成不等于业务系统写回；NineClaw 主要闭环是本地 Artifact。【UI-E1】

## 5. T-P04/T-P05 右侧产物与编辑

### 通用头部

文件名/标题、格式/状态、关闭按钮，以及随类型出现的查看、解析、编辑、AI 修改、保存动作。

### 视图状态

| 状态 | 主内容 | 主要操作 |
|---|---|---|
| preview_loading | 骨架/加载反馈 | 关闭 |
| preview_ready | 可阅读产物 | 编辑、AI 修改、保存/下载 |
| answer_hidden | 练习题正文 | 显示解析答案 |
| answer_visible | 题目 + 解析答案 | 隐藏答案 |
| edit_dirty | 可编辑内容、未保存标识 | 保存、取消、AI 修改 |
| ai_revising | 修改进度 | 取消能力待确认 |
| saving | 保存反馈 | 防止重复保存 |
| saved | 成功反馈与时间 | 继续编辑/关闭 |
| preview_failed | 安全错误信息 | 重试、外部打开 |
| save_failed | 草稿保留 | 重试、另存 |

### 编辑工具

录屏可见块级文本工具栏和编辑模式；具体格式项、快捷键、撤销/重做、选区与整文 AI 修改边界需图册逐项确认。任何未确认项不得在还原稿中假装与 Word/Notion 等编辑器等价。

## 6. S-P01/S-P02 技能广场与我的技能

### 页面目的

发现、安装、使用和管理 Agent 能力包。

### 结构

- 标签：`官方推荐 / 技能广场 / 我的技能`；
- 搜索；
- Skill 卡片网格；
- 添加技能主行动；
- 卡片包含图标、名称、说明、来源/官方标识、安装或已安装状态。【UI-E1】

### 卡片动作

| 状态 | 主动作 | 次动作 |
|---|---|---|
| 未安装 | 安装 | 查看详情 |
| 安装中 | 进度/禁用重复安装 | 取消能力 `UNKNOWN` |
| 已安装且启用 | 去使用/立即使用 | 详情、禁用、删除 |
| 已安装且禁用 | 启用 | 详情、删除 |
| 安装失败 | 重试 | 查看原因 |

### S-O01 Skill 详情

显示名称、来源、说明、适用场景、核心功能、示例/文档和安装/去使用。版本、权限、文件清单、签名、变更日志等治理字段没有在材料中被完整观察。

### S-O02 添加 Skill

上传入口画面列出文件夹、ZIP、Markdown 和 GitHub URL 等方式；另一入口为创建 Skill。选择创建后通过 Skill Creator 进入 `T-P01`，形成一条独立的“创建 Skill”任务流；创建链可在对话中生成 `SKILL.md` 等文件，并包含一次对结果满意度/调整幅度的确认，完成后出现在“我的技能”。【OWNER-C1】【UI-E1】删除/覆盖需要用户确认。

### 还原边界

23 个当前运行时 Skill 属于源码快照，技能广场可见卡片不等于当前全部安装项。列表必须分别表达“供给”“安装”“启用”和“本任务选择”，不能混成一个布尔值。【SRC-E4】【INF】

## 7. M-P01/M-P02 工具广场与我的工具

### 页面目的

发现和管理 MCP/外部工具，使主 Agent 在任务内访问外部能力。

### 结构与卡片

- 标签：工具广场、我的工具；
- Tool 卡片；
- 安装/已安装、启用开关；
- 自定义工具入口；
- 可见工具包括 NineClaw 工具、GitHub、GitLab、Context7、Fetch 等，低清晰度名称不强行记录。【UI-E1】

### M-O02 自定义 MCP

支持表单和 JSON 两种配置方式；可配置服务名、描述、接入类型、命令或 URL、参数、环境变量。保存前至少校验：名称、配置语法、接入方式必填项、环境变量结构。连接测试、权限说明、密钥掩码和导入覆盖策略待补录。

### 任务内表现

工具不是独立结果页，也不能从 Tool 详情/管理页直接发起任务。Agent 只能在已从其他入口创建的任务中按需调用 Tool，并显示工具名、参数、原始 JSON 响应和后续总结；失败后应能重试或换策略。【OWNER-C1】【UI-E1】

## 11. C-O01 发布作品四步向导

### 共同结构

- 模态标题“发布作品”、关闭按钮；
- 左侧四步：1 上传文件、2 完善信息、3 设置定价、4 提交审核；
- 当前步骤高亮；
- 上一步/下一步；
- 关闭时草稿保留/丢弃规则 `UNKNOWN`。

### Step 1 上传文件

| 字段 | 规则/文案 |
|---|---|
| 作品文件 | 选择课件/PPT/文档；任意格式；不超过 100MB |
| 封面 | JPG/PNG/WebP |
| 下一步 | 必要文件未就绪时禁用 |
| 提示 | 机器 + 人工审核，预计 1–24 小时 |

需覆盖上传中、上传失败、重试/重新选择、成功、预览生成中。【UI-E1】

### Step 2 完善信息

可见字段包括标题、作品介绍（`0/500`）、必填内容类型，以及学科、教材版本、年级、期次和章节。内容类型可见课件、教案、学案、作业、试卷、游戏、素材、示范课、备课综合；页面提示目录越准确，作品越容易出现在筛选和搜索结果中。标题/标签的精确上限、右侧下拉全集和字段依赖仍需补录。【UI-E1】

### Step 3 设置定价

- 积分字段；
- 免费开关；
- 0 表示免费；
- 付费为 1–999999 的整数积分；
- 非整数、负数、超限和免费切换时字段行为需验证。【UI-E1】

### Step 4 提交审核

展示作品摘要、定价和逐项完整性检查；截图可见“文件未上传”“标签信息不完整”为警告、“价格已设置（5 积分）”为通过，缺失时提交仍不可视为有效。底部说明提交后进入机审、预计 1–24 小时反馈、通过后自动展示到广场。真正提交成功回执、关闭与进入“我发布的”路径仍需关键帧确认。【UI-E1】

## 16. 页面级验收原则

- 每个主行动都必须有加载、不可用、成功和失败反馈；
- 页面返回后保留合理的筛选、滚动、草稿和任务上下文；
- 所有异步动作防止重复提交；
- 所有删除、覆盖、扣分、恢复和外部发送动作需要影响说明；
- 所有 `UNKNOWN` 在视觉稿中不得被静默当作已确认行为。
