# Flowin 使用情况调研总结

> 整理日期：2026 年 9 月 16 日。本文为调研讨论与方案总结，尚未形成完整的使用情况结论。

本次调研源于“班级里的共创使用率怎么样”这一业务问题，范围聚焦 **ClassIn 班级课程详情页中的“共创”共享文档功能**，不代表 Flowin 全产品的使用情况。

我们希望了解师生是否在使用共创、内容如何产生，以及这些内容是否被持续使用和共同编辑。先以最近一周试分析，确认数据和统计口径后，再扩展到最近一个月。

本文以五个业务问题和双线分析图为核心，同时保留统计口径、当前数据情况及下一步安排，作为后续详细报告的基础。

## 一、调研要回答的问题

1. 有多少班级、老师和学生在使用共创？
2. 新增共享文档有多少，分别来自直接新建和导入创建？
3. 以前创建的共享文档，还有多少在继续使用？
4. 使用主要停留在阅读，还是形成了多人、师生共同编辑？
5. 共创实际用于哪些教学任务，哪里存在使用障碍？

首轮观察时间为 **2026 年 9 月 9—15 日**，以 **9 月 8 日结束时的已有内容**作为期初基线。

## 二、整体分析路径

采用“两类文档分别往下看，最后汇总”的结构：一条线观察**本周新增文档有没有用起来**，另一条线观察**以前的文档有没有继续使用**。两条线使用相同的查看、编辑指标，再进一步观察多人和师生共同编辑。

```text
                    班级中的共享文档
                            │
             ┌──────────────┴──────────────┐
             │                             │
      本周新增的文档              本周之前已有的文档
             │                             │
       ┌─────┴─────┐                       │
       │           │                       │
    直接新建    导入创建                     │
       │           │                       │
       └─────┬─────┘                       │
             │                             │
    本周有没有被使用？          本周有没有继续被使用？
      查看／实际编辑                  查看／实际编辑
             │                             │
             └──────────────┬──────────────┘
                            │
                 有多少篇被多人编辑？
                            │
             其中多少篇由师生共同编辑？
                            │
               主要用于什么教学任务？
```

这张图希望逐层回答：内容来自哪里、有没有被使用、有没有形成共同创作，以及具体服务于什么教学任务。入口点击人数作为整体规模指标单独统计。

图中的箭头表示分析逐层深入。查看和编辑先分别统计；如果要计算“查看的人中有多少人随后编辑”，需要关联同一用户对同一文档的行为，不能直接用两个总人数相除。

## 三、关键统计口径

报告统一使用“班级共享文档”等业务名称，区分下面几件事：

| 统计内容 | 怎么理解 |
| --- | --- |
| 本周新增文档 | 本周在该班级直接新建或导入创建的共享文档 |
| 直接新建与导入创建 | 导入包括从 Flowin、从其他班级导入；只统计文档篇数，不统计导入操作次数 |
| 本周之前已有的文档 | 本周开始前已经存在于该班级的共享文档 |
| 活跃文档 | 本周被查看或实际编辑过的文档，同一篇只计一次；查看和编辑另行拆分展示 |
| 多人、师生共同编辑 | 同一篇文档在本周被至少两人编辑；其中有教师和学生分别编辑的，再计入师生共同编辑 |

新增文档和已有文档分别统计活跃篇数，汇总后观察两类内容对本周使用的贡献。参与人数需要跨两类去重，不能直接相加。

默认模板、系统初始化和空白文档需要识别，不能仅凭“有一条共创记录”就认定师生创作了内容。导出可作为后续内容复用的补充观察，不作为所有文档都必须经过的漏斗环节，也不默认减少原班级的文档数。

## 四、当前已查到什么，还缺什么

**目前通过 DW Hunter 已查到共创存储记录，但尚未取得完整的共创使用大数。现有结果不足以判断使用率高低。**

| 数据环节 | 当前情况 | 代表什么 |
| --- | --- | --- |
| 共创存储情况 | 已获取真实数据 | 能看到班级级存储记录及变化，但不能直接当作共享文档篇数或使用人数 |
| 新增与来源 | 已找到一张上游表，其业务数据读取被明确拒绝；来源含义仍待核实 | 存在一处确定的权限限制，但不能说所有创建数据都没有权限 |
| 入口点击 | 通用页面访问数据可查，尚未确认共创对应记录；部分查询未成功 | 暂时不能给出共创入口点击人数，也不能据此判断没有点击 |
| 文档查看、编辑 | 尚未准确定位所需记录 | 暂时不能计算查看、编辑人数，以及新增和已有文档的活跃篇数 |
| 师生协作与教学用途 | 尚未取得完整证据 | 需要角色与编辑记录；教学用途后续结合内容样本和访谈判断 |

首轮核验还发现，大量班级的共创存储大小完全一致，提示可能存在统一模板或初始化内容，但原因尚未确认。因此，存储记录只能作为核验线索，不能用来填充使用漏斗。

已确认的权限问题是：当前 `pd` 角色通过 `impala_warehouse` 读取 `eo_odsdb.ods_ms_eo_oslms_collection_lms_collection_f` 时，被数据库级权限拒绝。表结构可见，不代表业务数据可读；该表也尚未证明包含每篇文档的查看和编辑历史。

后续报告在各环节统一标注“已获取真实数据”“权限受限”“尚未定位或核实”“查询未成功”。**没有取到的数据不填零；尚未找到数据源，不等于数据库里没有。**

## 五、下一步先做一个宏观版本

先争取取得五个基础数字：**入口点击人数、文档创建人数、新增文档篇数、文档查看人数、查看后继续编辑的人数**。新增文档按直接新建和导入创建拆分；查看和编辑尽可能按新增文档、已有文档分别呈现。

推进顺序为：

1. 确认共创入口、创建成功、查看和编辑四类操作是否有记录，以及记录在哪里。
2. 优先使用现有权限可查询的数据；对实际被拒绝的数据，明确所需表或只读视图。
3. 用少量真实案例核对文档数量、创建来源和行为含义，再统计一周的去重人数和文档篇数。
4. 数据可靠后，扩展一个月趋势、师生参与及典型教学用途。

详细报告最终应能说明：**共创有没有被使用，使用主要由新增内容还是已有内容带动，师生是在阅读资料还是共同创作。** 哪些问题已有证据、哪些仍无法回答，都与结论一并呈现。
