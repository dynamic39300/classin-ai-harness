# ClassIn 教学活动下钻：类型、参数、师生操作与反馈

**教学活动需要同时看“老师布置了什么、分配给谁、学生怎样参与、产生了什么结果、老师怎样反馈”。** 仅有活动类型或最终分数，无法准确回答“谁没完成”“谁需要批改”“哪些题需要再讲”。

本篇在[教学数据地图](./CLASSIN-TEACHING-DATA-MAP-2026-09-15.md)之下进一步解释业务，不重复抄录全部字段。[活动字段字典](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md)负责逐字段查询；[作业、测验与答题卡规则分册](./CLASSIN-TEACHING-ACTIVITY-ASSESSMENT-RULES-2026-09-15.md)负责三类复杂评测活动的详细枚举与操作证据。

## 1. 范围、依据和阅读方式

本轮以 dw-hunter 在线知识库为依据，复读 LMS 总览及各活动字典；沿用同日已核验的原始表结构，不新增教师或学生业务行采集。这里分析的是 **ClassIn 业务数据可以表达的能力**，不是原项目已经接入的功能清单，也不是某个班级实际拥有的活动清单。

全文采用三种证据标记：

- **已知**：字段、枚举、关联或字典说明明确支持的业务含义；仍不代表每条记录都有值。
- **流程推演**：将上述事实组织成老师和学生的业务动作，便于理解；不宣称已经核验实际页面按钮、操作顺序、自动触发或所有客户端版本。
- **待核**：字段不足或说明存在差异，须补接口合同、内容样本或实际产品行为。

除特别标注外，下面“关键参数/可记录结果”属于已知；“老师/学生操作”属于流程推演。对于可选行为使用“按配置”“需要时”，不把每一种活动都强制套入教师批阅流程。

## 2. 用户提出的四个维度，以及需要补充的维度

| 维度 | 要弄清楚的问题 | 为什么影响老师提问 |
| --- | --- | --- |
| ① 活动类型 | 课堂、作业、测验，还是阅读/观看/语言练习？ | 决定参与和完成的含义 |
| ② 参数与业务属性 | 内容、时间、对象、评分、公开规则是什么？ | 决定“要做什么、还能不能做、谁能看到” |
| ③ 老师操作 | 创建、配置、发布、查看、批阅、反馈等哪些动作适用？ | 决定老师当前可以处理什么 |
| ④ 学生操作与反馈 | 查看、进入、作答、提交、查看批阅、订正等哪些动作适用？ | 决定学生下一步要做什么 |
| ⑤ 归属与参与范围 | 哪个班级、哪门课程、哪个单元、哪些分配对象？ | 不能把同班所有课程、全班当前成员混成一个分母 |
| ⑥ 时间及例外规则 | 何时开放/截止，是否允许补交、补卡、结束后查看？ | 截止、迟到、补交、补考不是同一个状态 |
| ⑦ 内容与资源 | 题面、标准答案、学生答案、反馈分别在哪里？ | 有文件 ID 不等于已经读懂正文；有分数不等于知道错因 |
| ⑧ 评价与完成口径 | 谁评分、按什么规则，提交/完成/通过如何区分？ | 避免把得分率叫正确率，把已批阅叫已掌握 |
| ⑨ 历史与版本 | 当前提交还是旧稿？谁在什么时候改过、批过？ | 支撑“改了几次、有没有看反馈、是否改对” |
| ⑩ 数据可用性 | 权限、删除、刷新时间、字段缺失怎样处理？ | 区分“没有发生”“数据未到”“当前无法查看” |

“课前 / 课中 / 课后 / 总结”是产品引导的教学阶段；本篇的 15 类是底层活动类型。二者是多对多关系：测验可以课前诊断、课中检查或课后巩固；总结则可以汇集多类活动。不能把活动类型固定等同于某一个顶部 Tab。

## 3. 每项活动共同拥有的业务骨架

```mermaid
flowchart LR
  A[活动：归属、对象、发布与时间] --> B[类型内容：要求、题目、资源和规则]
  A --> C[分配到的学生]
  C --> D[按类型参与：出勤、查看、观看、作答或打卡]
  B --> D
  D --> E[过程记录与当前结果]
  E --> F[按类型产生系统评价或教师反馈]
  F --> G[按规则查看反馈、订正或继续学习]
```

图表示业务理解路径，不表示全部活动都有评分、订正或相同状态机。

| 共性参数 | 关键字段 | 业务解释 |
| --- | --- | --- |
| 归属 | `school_uid / course_id / category_id / unit_id` | 此处 `course_id` 是班级，`category_id` 是班内课程；单元不自动等于一堂课 |
| 活动身份 | `lms_activity.id / biz_type / biz_id` | 活动 ID 与类型业务 ID 分开；必须带类型定位子表 |
| 名称与负责角色 | `name / teacher_uid / creator_uid` | 活动老师与创建人分别记录，不自动等于班主任或课节主讲 |
| 分配对象 | `is_all_student / student_total`、活动学生关系 | 全员/指定范围及应参与人数；还需核对实际分配、历史成员、删除状态 |
| 时间 | `start_time / end_time`、类型专属时间 | 活动时间、个人开始/提交时间、批阅时间分别记录 |
| 发布与进展 | `publish_flag / process_flag / is_deleted` | 发布 0 草稿、1 隐藏、2 发布；进展 0 未开始、1 进行中、2 结束；删除独立处理 |
| 评分规则 | `is_score / max_score / passing_score / system_method` | 是否计分、满分、及格分，人工/系统方式；类型专属规则仍需继续读取 |
| 评分呈现与权重 | `system_grade_rule_id / grade_display_id / score_weight_id` | 评分规则、显示方式和权重引用，不凭一个 ID 推断最终学情公式 |
| 内容附件 | 活动扩展、`lms_activity_file`、`lms_file` | 用 `role / uid / to_uid` 区分老师资料、学生提交及定向反馈；再取得正文或媒体 |

来源：[活动壳与关系字段 A1–A5](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md#a1)。通用学生状态字段的适用类型在字典版本中存在差异，不用一张通用状态表覆盖所有业务表。

## 5. 按活动下钻

### 5.1 在线课堂：一次同步教学，而非一份待提交任务

**关键参数与属性**：课节名称、开始/结束时间、主讲与助教、分配学生、课堂类型、在线/智慧教室模式、席位、录制/直播与开放配置。`class_status` 为 1 未开始、2 进行中、3 已结束、4 已取消；它与 LMS 活动进展编码不同。主讲/助教的机构教师 ID 需转换为用户身份。

**老师操作（推演）**：安排课节与参与师生 → 开展课堂教学 → 根据课堂能力组织互动 → 查看参与、点评及可用回放。具体课内工具、强制签到和报告生成触发点不由这些字段直接证明。

**学生操作（推演）**：进入课堂 → 参与教学和适用互动 → 离开课堂；若存在且允许，可在课后查看回放。出入记录用于重建参与过程，不能用一次进入证明全程在场。

**可记录结果**：应到名单、出入与停留、部分互动记录、点评和回放引用。应到人数、累计到过人数、此刻在线人数是三个口径；实时缺勤不能用延迟 DW 直接判断。

**可以支撑的问题**：“这节课谁没来、谁提前离开？”“老师给了什么反馈？”“有这节课的回放吗？”完整课堂问答、逐题正确率和知识点总结，需要额外题面、答题内容或报告正文。

来源：[课堂、报告、参与与消息字段分册](./CLASSIN-TEACHING-DATA-CLASSROOM-DICTIONARY-2026-09-15.md)。LMS 录播课与在线课堂回放是不同对象。

### 5.2 作业：要求—提交—批阅—按需订正

**关键参数与属性**：作业描述及图文音视频附件、分配对象、起止时间、允许结束后提交、下载权限、未来新成员是否加入、评分与标准答案公开时机。标准答案、学生提交内容和老师反馈是三个内容层。

- `is_revise`：1 不允许、2 允许结束后提交，**不是“允许订正”**。
- `open_answer`：分别表达无答案、不公开、立即、提交后、批阅后、结束后公开。
- `is_draft`、提交时间、学生状态、`is_reform`、`emend` 分别表达草稿、提交、打回、订正等事实。
- 老师评分、评语、反馈附件与批阅人/时间单独记录；`rd_ch_time` 可支持批阅后查看的判断。

**老师操作（推演）**：布置要求并设置规则 → 发布给学生 → 查看提交 → 批阅、评分和反馈 → 需要时打回重做 → 再查看学生更新。不能假定每项作业都计分、每次反馈都必须打回。

**学生操作（推演）**：阅读要求 → 完成内容并保存草稿或提交 → 查看老师反馈 → 按要求订正/重做并再次提交；超过截止后是否可交，由专属规则决定。

**可记录结果**：已交/未交/已批、补交、打回、订正、反馈查看及多次操作历史。日志必须以 `stu_homework_id` 串联，日志 `uid` 是操作人；只筛学生 UID 会漏掉教师批阅。

**可以支撑的问题**：“还有谁没交？”“哪些已经交了但我没批？”“谁看过批语却还没有订正？”最后一问必须联合反馈查看、打回/订正和版本时间，不能只看总分。

来源：[作业规则与枚举](./CLASSIN-TEACHING-ACTIVITY-ASSESSMENT-RULES-2026-09-15.md)、[字段 A6–A8](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md#a6)。

### 5.3 测验：试卷—考试窗口—作答—评阅

**关键参数与属性**：试卷与题源、题型/子题、满分、分配学生、开放窗口、个人答题限时、补考/迟到规则、试卷与解析公开规则、主观题批阅要求。`exam_time_limit` 单位是分钟，0 不限时。

**老师操作（推演）**：准备试卷和评分配置 → 设置对象/考试规则并发布 → 查看进行与提交情况 → 处理需要人工批阅的答案 → 查看结果和题目表现。不能由结束时间推断客户端必然自动交卷。

**学生操作（推演）**：在允许窗口进入测验 → 作答 → 提交 → 按公开规则查看结果/解析；补考需符合规则，`is_retake` 不能解释为无限次重考。

**可记录结果**：个人起止时间、是否交卷 `is_exam_end`、作答/待批/已批状态、逐题回答、系统/人工判题、主观题内容及阅卷人。提交和批阅是两件事；系统评分不代表老师已经逐题确认。

**可以支撑的问题**：“谁还没交卷？”“哪些主观题等着批？”“这次哪道题失分最多？”测验 JSON 的 `correctRate` 在字典中解释为**得分率**，不能直接输出为答题正确率；跨表分数单位需核对后再计算。

来源：[测验规则与枚举](./CLASSIN-TEACHING-ACTIVITY-ASSESSMENT-RULES-2026-09-15.md)、[字段 A9–A13](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md#a9)。试题来源及关联见字段字典后续试题表。

### 5.4 录播课：观看权限—播放过程—有效进度

**关键参数与属性**：视频及总时长、活动窗口、指定学生、是否允许倍速 `is_fast`、首次播放是否允许拖动 `is_drag`、结束后能否看 `is_end_look`、能否互看进度 `is_mutual_look`、播放次数限制 `play_max`、新增学生自动加入 `auto_add`。`is_caption` 在字典中是**防录屏跑马灯**，不是字幕开关；`play_max=0` 的含义未明确。

**老师操作（推演）**：准备视频/说明 → 配置观看规则和对象 → 发布 → 查看学生观看情况及未完成部分。这里未发现“每次观看后老师必须批改”的依据。

**学生操作（推演）**：打开视频 → 在允许的倍速、拖动和次数规则内观看 → 继续未看部分；结束后能否继续取决于配置。

**可记录结果**：首次查看、累计观看、每段视频的最后位置/最远位置、有效观看时长、观看片段、结束后观看片段、已完成视频集合 `video_end`。最远播放位置、累计时长和有效覆盖不能互相替代。

**可以支撑的问题**：“谁还没有开始看？”“这位学生停在哪段？”“哪些内容还没看完？”完播需遵循业务规则和 `video_end` 等证据；不能简单用累计时长除视频时长推断掌握程度。

来源：在线《105.5-原始数据-LMS活动-录播课.md》；[字段 A16–A18](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md#a16)。

### 5.5 学习资料：内容分发—查看

**关键参数与属性**：标题、说明、图片/视频/音频/文档内容、开放时间、分配学生、能否下载 `is_download`、新成员自动加入 `auto_add`。

**老师操作（推演）**：整理文字或附件 → 设置对象、时间、下载规则 → 发布 → 查看哪些学生打开过。

**学生操作（推演）**：打开资料 → 阅读或查看其中媒体 → 允许时下载。字段没有证明学生必须额外提交回执或教师必须批阅。

**可记录结果**：学生首次查看时间、查看次数。主表 `check_total` 表示已查看学生数量；学生表同名字段表示该学生查看次数，不能混算。`score_percent` 虽有“得分率”注释，其产生规则待核，不能据此声称理解正确率。

**可以支撑的问题**：“这份资料谁没打开过？”“老师发了哪些参考文件？”不能仅凭查看记录回答“谁已经完全理解”。

来源：在线《105.4-原始数据-LMS活动-学习资料.md》；[字段 A19–A20](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md#a19)。

### 5.6 讨论：活动类型已知，正文与互动规则尚缺

**已知参数与属性**：类型码 6，可通过活动壳知道归属、标题、对象、发布与时间。LMS 总览称其为内部活动，无独立业务表；不能据此断言没有讨论内容，仍需补扩展结构或服务接口。

**老师/学生操作（待核的业务推演）**：老师提出主题，学生围绕主题表达或回复，老师阅读并反馈。这只是一种合理的业务理解；当前证据不足以确认发帖、楼中楼、点赞、置顶、匿名、评分和审核等具体功能。

**潜在问题**：“讨论里大家最困惑什么？”必须取得主题正文、回复、作者、时间和必要的可见性信息后才能回答。目前不能把“活动存在”转化为“已掌握讨论内容”。

来源：在线《105-原始数据-LMS活动.md》；[活动覆盖与缺口](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md)。

### 5.7 答题卡：题号与计分结构—学生作答—逐题分析

**关键参数与属性**：标题、说明、时间、满分、答题限时 `time_limit`（秒，0 不限时）、补交开关、答案解析公开时机 `open_type`、学生互看作答/成绩时机 `check_type`。教室内答题卡可带 `class_id`；不能因此把所有答题卡都归入某一课节。

内容按题号、题型、答案、选项数、满分/半对分和展示顺序组织；与测验的完整试卷题库模型不同。只有答案键和选项统计时，不保证具有完整题干。

**老师操作（推演）**：准备题目对应的答题卡和评分规则 → 配置时间、公开规则并发布 → 查看提交 → 批阅需要人工判断的答案 → 查看选项/失分分布。

**学生操作（推演）**：按题目及题号作答 → 提交 → 在规则允许时查看成绩、答案或同学作答；不能由同名 `is_retake` 推断测验和答题卡有完全一致的补考机制。

**可记录结果**：未作答/作答中/待批/已批、系统或老师批阅、客观题/主观题答案、逐题正确/错误/部分正确、选项人数。

**可以支撑的问题**：“第 5 题谁选了 B？”“哪些题半对、主要扣在哪里？”解释错因还需真实题面和作答过程，选项人数本身不说明原因。

来源：在线《105.6-原始数据-LMS活动-答题卡.md》；[规则分册](./CLASSIN-TEACHING-ACTIVITY-ASSESSMENT-RULES-2026-09-15.md)及[字段 A21–A26](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md#a21)。

### 5.8 打卡：周期配置—按日提交—按日反馈

**关键参数与属性**：起止日期、星期频率 `frequency`、具体应打卡日期 `clock_dates`、应打卡天数 `clock_days`、提醒时点 `remind_time`、允许补卡 `is_allow_late`、补卡范围 `late_limit`、每日内容及评分反馈。`late_limit` 的 1–30 表示天数，0 不限；`remind_time` 是相对零点的秒数，不是实际消息已送达证据。

**老师操作（推演）**：定义打卡要求和日历 → 配置参与对象及补卡规则 → 发布 → 按日期查看提交 → 需要时批阅、点评、标优秀或要求改正。底层业务的类型枚举出现“小组作业”，但当前字典明确目前使用打卡类型，不能据此承诺完整小组作业功能。

**学生操作（推演）**：在规定日期完成并提交当日内容 → 查看对应反馈 → 按要求更新；漏交后能否补、补哪一天须检查补卡规则。

**可记录结果**：学生×活动×应打卡日的提交、补卡、订正/打回与批阅日志；汇总已打卡、补卡和连续天数。`continuous_days` 是**最长连续天数**，不是当前连续天数。

**可以支撑的问题**：“本周漏了哪几天？”“这次补卡补的是哪天？”统计截至今天应完成的日期，不把未来日期算作漏交；同一天重复提交不增加完成天数。设置 ID、业务作业 ID 和某天学生记录 ID 必须分别使用。

来源：在线《105.1-原始数据-LMS活动-打卡.md》；[字段 A27–A34](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md#a27)。

### 5.9 SCORM：课件学习—课件上报—完成/通过

**关键参数与属性**：课件文件及云盘引用、路径、基础信息与解析结构 `scorm_base_info / scorm_info`，活动归属和分配。`scorm_setting` 与 `scorm_result` 在字典中注明“暂空”，不能用字段名推导已经支持的设置或报告。

**老师操作（推演）**：准备 SCORM 学习包 → 组织为活动并分配 → 查看学习进展、成绩和可用报告。具体导入页面、包兼容性、重学次数和手动批阅入口需另核验。

**学生操作（推演）**：进入课件 → 完成其中的学习和交互 → 由课件/平台记录学习结果。具体交互由课件内容决定，不能承诺每个包都包含测验或逐题错因。

**可记录结果**：未参与/参与中/已完成/已批阅；学习时长、进度、`sco_comp_status` 完成标志、`sco_succ_status` 通过标志、成绩和报告 JSON。`learn_duration` 是时分秒字符串，`total_time` 是秒；进度/分数的具体换算须遵循合同。

**可以支撑的问题**：“谁完成了但没通过？”“这份课件学到哪了？”完成和通过分开；有“已批阅”状态不等于所有课件都要求老师手动批阅。

来源：在线《105.9-原始数据-LMS活动-SCORM.md》；[字段 A35–A38](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md#a35)。

### 5.10–5.15 语言活动：六种任务，共用内容与评阅结构

共用结构包含 `reading` 活动、`reading_question` 题目、学生整体结果与逐题结果。可记录有序题目、原文、标准音频、释义/音标、学生音频/作答扩展、AI 评分、教师评分、反馈与打回/订正。

| 类型 | 独有的教学内容关注点 | 老师操作（推演） | 学生操作（推演） | 可依据的反馈与边界 |
| --- | --- | --- | --- | --- |
| 10 英语跟读 | 单词/句子、标准音频、释义和适用音标 | 组织跟读材料，查看逐题评测，需要时给反馈 | 听/读材料，跟读并提交响应，按反馈再练 | 学生音频、AI/教师逐题评分；不能从音频 ID 直接得到识别文本 |
| 11 英语背诵 | 指定英语材料及题目顺序 | 指定背诵材料，查看提交和评阅结果，需要时要求重做 | 完成背诵并提交，查看反馈后调整 | 共用提交、评测、反馈字段；隐藏原文方式、背诵判定算法待核 |
| 12 英语听写 | 听写题目、标准音频及答案相关内容 | 组织听写任务，查看作答及评阅 | 按听写要求作答并提交，查看反馈 | 需读取 `answer_ext` 及具体合同；不能凭共用 `answer_audio` 字段断言一定是录音、键盘或手写提交 |
| 13 语文朗读 | 单字、词语、句段、诗词及标准音频 | 指定朗读内容，查看表现并反馈 | 朗读指定内容并提交，按反馈练习 | 可用逐题评测；不能将语文题型统称为英语单词/句子 |
| 14 语文背诵 | 指定句段或诗词 | 指定背诵内容，查看结果及反馈 | 背诵并提交，按要求重做 | 共用评阅/订正结构；不据此声称已支持逐字漏背定位 |
| 15 语文听写 | 字词等听写材料与音频 | 组织听写任务，查看学生作答与评阅 | 根据要求完成听写并提交 | 与英语听写一样，需要明确真实输入和答案解析格式 |

**关键参数**：`question_ids` 保留题序；英语题型 1 单词、2 句子，语文题型 1 单字、2 词语、3 句段、4 诗词；`audio` 是标准音频的文件引用，`answer_audio` 是学生逐题回答音频引用。`ai_review_rate / tea_review_rate` 分开，细分结果在各自扩展结构；有评分槽位不代表每个任务都已经有全部评分。

**状态与过程**：整体状态 0 未提交、1 已提交、2 已批阅、3 已打回；逐题状态是另一套 0 未答、1 已答、2 已批。补交、订正、打回、优秀与教师反馈单独记录。`last_submit_time / last_review_time` 在字典中说明仅类型 10 使用，其他类型为 0，不能把 0 直接解释为“从未提交”；其他类型需查看通用状态 JSON。

**可以支撑的问题**：“这次哪些词需要再练？”“AI 和老师对这道题的评阅有差异吗？”“哪些学生被打回后还没更新？”必须具备具体材料、该学生的答案和对应版本的评测，不能只用一个总评分生成精确发音诊断。

来源：在线《105.3-原始数据-LMS活动-英语语文学科活动.md》；[字段 A39–A42](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md#a39)。

## 6. “完成了没有”必须拆成多个问题

| 老师口中的“完成” | 实际需要判定什么 | 适用示例 |
| --- | --- | --- |
| 老师布置完了 | 活动已发布，范围、内容、时间配置有效 | 创建草稿不等于学生能看到 |
| 学生参与了 | 出勤、首次查看、播放或开始作答 | 已进课堂、已打开资料 |
| 学生交了 | 有有效提交，排除仅草稿和不适用对象 | 作业、测验、答题卡 |
| 学习过程完成 | 符合该类型的完成规则 | 录播有效覆盖、SCORM 完成、打卡截至当前应完成日期 |
| 评价完成 | 适用的系统/教师评阅已经完成 | 已交作业仍可能待批；AI 评分与教师审核不同 |
| 学生收到并看了反馈 | 有具体的反馈查看记录，且对应相应版本 | 作业批阅后查看；不能将所有类型普通查看时间都当批阅查看 |
| 学生改了 | 有订正或新提交，且在反馈之后 | 打回重做、订正；补交并不表示改错 |
| 学生改对/掌握了 | 对新答案再次评价或有明确达成标准 | 单凭“订正标志”或“提交成功”不能成立 |

因此，“全班都完成了”必须指明 **哪项活动、哪些学生、截至何时、采用哪种完成口径**。缺字段、接口延迟和真实未完成应区别表达。

这是一套后台业务理解维度，不要求在 Copilot 顶部增加状态管理界面。既有导航继续展示业务事实及建议；AI 生成/发送状态与教学活动状态保持独立。

## 7. 从细节反推老师可以问什么

| 问题方向 | 更贴近老师的问法 | 要读的最小证据链 |
| --- | --- | --- |
| 布置与安排 | 这门课这周要做哪些任务，各什么时候截止？ | 班内课程 → 活动 → 类型内容/时间/分配 |
| 参与跟进 | 这份作业谁没交，和没看资料的是同一批人吗？ | 两项活动各自有效对象 → 各自提交/查看 → 按学生交集 |
| 批阅工作 | 我还有哪些提交没批？先看哪份？ | 类型适用的待批状态 → 学生业务记录 → 提交时间/内容；优先级是建议，不是数据库事实 |
| 反馈闭环 | 谁看过我的批语，后来有没有改？ | 教师反馈版本 → 查看证据 → 后续提交/订正及再评阅 |
| 具体学习困难 | 第 5 题哪些同学错了，主要错在哪？ | 同一题面版本 → 标准答案 → 学生答案 → 逐题评阅；错因分析标为解释 |
| 学习过程 | 录播没看完，是没开始还是有些片段没看？ | 分配 → 逐视频观看 → 有效片段/完成规则 |
| 时间与资格 | 打卡漏的那两天还能补吗？ | 应打卡日历 → 按日提交 → 允许补卡及时间窗口 |
| 阶段学情 | 这位学生最近作业、测验、朗读有哪些进步？ | 各活动内容与时间 → 同口径结果 → 反馈/版本变化；难度和评分不可比时需说明 |
| 内容生成 | 根据这次作业错题，帮我写一条讲解发给学生 | 真实题面/答案/错误表现 → 可复查讲解草稿；按既定流程由老师确认发送 |

这里的“最小证据链”用于限定检索和回答范围，不意味着把全班全部内容无差别输入模型。上表是能力候选；真实接口是否有这些内容、当前老师是否有权限，还需逐链验证。

## 8. 后续最值得补证的细节

| 优先项 | 目前缺口 | 取得什么才算补齐 |
| --- | --- | --- |
| 作业提交—批阅—打回—订正版本 | 状态字段有，但联动、版本更新与旧稿保留规则未完整确认 | 同一学生作业的完整生命周期接口样本/合同，对齐当前表和日志 |
| 测验/答题卡逐题评分 | 题源、题号、分数尺度与公开对象存在差异 | 同一份题面、作答、评阅、分数和解析的脱敏对账样本 |
| 六类语言输入与评测 | 共用表不足以解释听写输入、背诵呈现和全部细分评分 | 每类一套题目、学生输入、AI 评测、教师反馈的合同或样本 |
| 录播完成与 SCORM 通过 | 时长、覆盖、进度和完成标志的规则不完全等价 | 完成判定规则及一次真实进度/结果对照 |
| 讨论完整链路 | 缺少正文、回复及可见性结构 | 活动扩展或讨论服务的正式对象定义 |
| 课堂与配套活动关系 | 同单元不能证明某作业由某课节布置 | 显式课节关联或可核验的内容关系；答题卡 `class_id` 只覆盖适用情况 |
| 数据能否用于当前提醒 | DW 有延迟，部分实时状态由业务服务拥有 | 各类接口刷新时间、实时状态及名单有效性合同 |

这些是深化业务认识所需的验证点，不阻碍现在形成完整的类型地图；但未补证部分不能包装成已经可用的自动操作或准确回答能力。
