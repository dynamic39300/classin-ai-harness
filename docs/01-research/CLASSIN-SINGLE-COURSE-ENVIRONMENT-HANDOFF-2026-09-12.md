# 测试环境接续检查

本轮可确认的目标数据为 14 个课堂和 1 项作业；全部详情与目录逐项比对通过。资料、录播和新增测试学员尚未写入成功。以下说明用于环境同事定位问题，尚未对外发送。

## 云盘目录

- 请求：测试网关 `POST /cloudspace/api/user/getFolderList`，表单签名。
- 定义依据：Apifox 云盘项目中的“个人云盘-某个文件夹下文件和文件夹信息”，接口编号 3500701。
- 参数：当前测试 UID、`folderId=0`、`cate=2`、`order=0`、`resourceFileType=3`、`language=cn`。
- 当前结果：服务返回“操作失败/未知错误”；此前旧云盘目录读取曾返回 HTTP 500 并表明数据库连接故障。
- 检查要求：确认该测试网关对应的云盘服务和数据库连接正常，并能通过当前测试账号返回根目录。当前不能确认账号资源为空。
- 恢复后：盘点课程所需的 3 项资料和 2 项录播对应的测试文件，逐项核对内容与可访问性，再绑定活动。可用文件必须有明确来源与测试环境内引用。

## 测试学员

- 读取：`POST /coreapi/student/getStudentList`，JSON，当前测试机构上下文、`perpage=20`、`page=1`；接口成功，返回机构学生数 0。
- 创建：`POST /coreapi/student/addStudent`，依据 Apifox 接口 3470023，使用测试姓名、保留域名邮箱、未分类和测试学号；表单与文档所列 JSON Schema 两种方式均返回参数错误，没有创建成功回执。
- 结论：不能由参数错误推断教师权限不足。需核对所需机构会话、字段校验（包括测试邮箱可用规则）、分类值和服务部署契约。
- 所需支持：可执行的测试机构学生创建请求示例或测试环境预置学员。凭证应配置在受控位置，不能写入此说明。还需要测试学员可登录，才能实际产生提交和观看记录。
- 范围：不更改验证开关、不冒用其他用户身份、不向真实手机号或邮箱注册账号。

## 接续完成条件

1. 测试教师云盘根目录可读，所需资料和视频可打开。
2. 一个明确测试身份能创建或被预置，且可由机构目录和班级成员接口回读。
3. 再扩充目标班级的测试学员，并按源课程配置写入资料和录播。
4. 通过实际测试操作产生行为，逐人明细与汇总一致。

当前不具备自动监控或后台重试任务；环境修复后，在本任务中继续执行上述步骤。
