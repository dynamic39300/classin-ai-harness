# 教学活动下钻——作业、测验与答题卡的参数及师生操作闭环

[返回教学数据地图](./CLASSIN-TEACHING-DATA-MAP-2026-09-15.md) · [完整活动字段字典](./CLASSIN-TEACHING-DATA-ACTIVITIES-DICTIONARY-2026-09-15.md)

全部 15 类活动的参数、师生操作及反馈对比见[教学活动业务下钻](./CLASSIN-TEACHING-ACTIVITY-BUSINESS-DEEP-DIVE-2026-09-15.md)。

作业、测验和答题卡都涉及“布置—作答—批阅—反馈”，但它们不是同一种活动换三个名字。作业侧重开放形式的提交及往返批阅；测验围绕试卷、题库、计时和逐题阅卷；答题卡侧重题号、答案、计分和选项分布，也可与教室内课节关联。

本篇重新完整读取在线 DW 知识库作业、考试测验、答题卡字典共 23 个分片，沿用本日上一轮已核验的表结构。不查询学生业务行，不修改业务数据，不以元数据证明当前产品界面如何操作。

证据分为三种：**已核验**指在线字典明确说明字段含义或枚举；**流程推演**指据这些字段整理的师生业务动作及条件分支，尚未逐项通过真实页面/API 操作验收；**待核实**指字典未交代、含义有差异或必须通过样本/产品合同确认。下文“老师操作、学生操作”的顺序均为流程推演，不代表强制步骤或已验证菜单名称。

## 1. 三类活动先分清

| 维度 | 作业 | 测验 | 答题卡 |
| --- | --- | --- | --- |
| 活动类型 | biz_type=2 | biz_type=3 | biz_type=7 |
| 教师布置的主要内容 | 标题、要求、文字及图片/音频/视频/文档附件、标准答案 | 一份试卷，试卷内题号、题源与新旧试题关系 | 卡片说明、题号、题型、标准答案、选项数、每题分数/半对分数 |
| 学生提交的主要内容 | 文字、各类附件、留言，可存在草稿 | 客观题作答 JSON；主观题另存 HTML 作答 | 客观题作答详情；主观题另存 HTML 作答 |
| 教师反馈的主要内容 | 批阅内容及附件、评语/语音评语、分数、打回/重做、优秀作业标志 | 逐题阅卷结果与得分、阅卷人、阅卷时间 | 逐题正确/错误/半对及得分、系统/老师批阅类型 |
| 特有过程 | 补交、打回重做、订正、多次提交/批阅日志、批阅后查看 | 开始答题、交卷、待批阅、补考、迟到考试策略 | 秒级答题限时、教室内课节关联、选项学生分布 |
| 不能混淆 | 有评分不表示有结构化逐题答案；作业题库 ID 字段被字典标为无效 | 交卷不等于已批阅；存在试题条目不等于学生已作答 | 答题卡答案/题号不一定带完整题面；选项频次不等于独立学生总数 |

共用的班级、课程、单元、对象分配、发布/隐藏、开始/结束和评分方案由活动层提供。下钻时先取得有权限的活动，再通过类型与业务 ID 进入本篇的专属数据；同一数值的业务 ID 跨类型不能混用。

## 2. 作业：不止“交了没有”，还包括内容与多轮反馈

### 2.1 关键参数与业务属性（已核验）

| 参数组 | 数据字段 | 业务解释与需要注意的规则 |
| --- | --- | --- |
| 作业要求 | homework_title、homework_desc；image/video/audio/docs | 要求可写题号、页码、提交形式，附件可能承载实际题面；仅附件地址不足以理解内容 |
| 时间窗口 | start_time、end_time、status | 作业专属 status：1进行中、2已结束、3已删除；发布状态另读活动层 |
| 对象范围 | num、auto_add；活动分配名单 | num 是此作业学生总数；auto_add：0不向后进班学生开放、1开放；不能直接用班级总人数当应交数 |
| 截止后的提交许可 | is_revise | **1不允许、2允许作业结束后提交**，不是“允许订正” |
| 作业公开策略 | is_open、open_type | is_open：1公开、2不公开；open_type：1结束后、2提交后、3批阅后。字典未完整解释公开对象/范围，不擅自改写为全班可见或互评 |
| 标准答案可见时机 | open_answer | 0无答案、1不公开、2立即公开、3提交后公开、4批阅后公开、5结束后公开；与作业公开策略分开 |
| 标准答案内容 | 作业主记录的 th_content、th_image/th_video/th_audio/th_docs | 是该作业的答案；同名 th_* 出现在学生记录时则是老师对学生的批阅内容 |
| 附件下载 | is_download | 1允许、2不允许；附件可看和可下载是不同规则 |
| 评分与显示 | score_type、score_value、grade_id；活动 grade_display_id | 字典说明现用 score_type 4不评分、5分数；旧百分/十分/等第和自定义显示经评分显示方案解释，不把 5 当百分制 |
| 总体进度 | cnum、rnum、is_done | 提交数、已批阅数；**is_done=0表示批阅完成，1表示未完成**；计数必须与同一时间的学生状态核对 |
| 学生作答当前态 | status、is_draft、is_startd、ref_time | status：0未提交、1已提交、2已批阅；草稿标志1是/0否；is_startd：1已开始、2未开始；ref_time 是最后提交时间 |
| 学生作品与老师反馈 | content、附件、stu_homework_desc；th_*、comment、comment_audio、score | 分开保留学生原作、留言、教师批阅附件和评语；避免把教师改写后的答案当学生原答 |
| 多轮作业 | is_revised、is_reform、reform、emend、readover、th_num | 分别表达补交、打回重做、重做、订正、批阅中与批阅次数，详见下表 |
| 看过与反馈到达 | ch_time、rd_ch_time、th_time、comment_time | 首次/一般查看、批阅后查看、批阅、评语时间各有意义；看过反馈不等于理解或改正 |
| 优秀与互动 | is_cream、admire、belittle | 优秀作业、赞数、踩数；不能作为学习掌握或品行评价 |
| 答对/答错与成绩 | correct、wrong、score_p | 仅有数量和得分率不证明每题题面、判分规则和学生解题过程均可获取 |

### 2.2 老师与学生的操作闭环（流程推演）

| 环节 | 老师可以做什么 | 学生需要做什么/可反馈什么 | 能核对的证据 |
| --- | --- | --- | --- |
| 准备和布置 | 编写要求、添加附件/标准答案，确定对象、截止、补交、评分与答案可见规则，发布给学生 | 在分配与可见规则满足后查看要求 | 活动发布与分配；作业正文、附件、规则 |
| 做题与提交 | 查看尚未提交情况，按需要提醒 | 形成文字/附件作品，留言；草稿和正式提交区分 | 学生内容、is_draft、status、ref_time |
| 首轮批阅 | 阅读学生作品，评分或不评分，写评语/语音反馈或添加批阅附件；必要时打回 | 等待批阅，随后查看反馈 | readover、status、score、th_*、comment、th_time、rd_ch_time |
| 打回与再提交 | 指出需要重做的部分，后续复核 | 按反馈重新完成并提交 | is_reform、reform、作品及日志；状态如何回退仍需真实操作合同 |
| 订正 | 查看订正结果，必要时追加反馈 | 订正原有错误 | emend 及前后内容/日志；一个标志不足以证明订正正确 |
| 截止后处理 | 区分未交、允许补交及已补交，不把截止一律解释为永久关闭 | 仅在规则允许时补交 | 主表 is_revise 与学生 is_revised；补交具体操作入口待核 |
| 回顾过程 | 查看这个学生提交、批阅和改动的时间线 | 查看此前提交及教师反馈的历史是否开放需核产品合同 | 学生作业主键关联操作日志；不是只读最后一条内容 |

作业的六个相近概念必须各自保留：

| 概念 | 字段和枚举（已核验） | 不代表什么 |
| --- | --- | --- |
| 允许补交 | 主表 is_revise：1否、2是 | 不代表已经发生补交，也不代表允许订正 |
| 已补交 | 学生 is_revised：1否、2是 | 不代表老师已批阅 |
| 被打回重做 | 学生 is_reform：0否、1是 | 不能仅据此断言学生尚未再次提交 |
| 重做状态 | 学生 reform：0否、1是 | 与 is_reform 的完整联动条件未给出 |
| 订正 | 学生 emend：0否、1是 | 不证明订正已复核、已全部正确 |
| 批阅中/批阅完成 | readover；status=2；主表 is_done | 当前记录、个人结果和全作业汇总是不同粒度 |

### 2.3 日志为何是关键的一层

学生作业记录保存当前内容与状态；操作日志保存同一份学生作业的多次内容、状态和评分记录。日志的 uid 是**操作者**：学生提交/修改时是学生，老师批阅时是老师。按某个学生的 uid 筛日志会漏掉老师的批阅，必须先用该学生的 stu_homework_id 串起日志，再解释操作人与时间。

日志行数不等于提交次数。要回答“重交几次、老师批了几次”，还要解读 info、状态变化和时间，并去掉同一动作的重复/技术性记录；目前字典未给 info 的完整事件枚举。不能只按行数统计，也不能把日志最后一行无条件当正式当前状态。

## 3. 测验：试卷、参加过程与逐题阅卷必须连起来

### 3.1 关键参数与业务属性（已核验）

| 参数组 | 数据字段 | 业务解释与边界 |
| --- | --- | --- |
| 试卷内容与版本 | exam_paper_id、exam_paper_version、exam_paper_info | 题序、大小题、topicId 和题源在试卷结构中；同名/同题号不代表同一版本 |
| 题型与题面 | exam_topic_type/type；题干、选项、答案、解析等 | 单选、多选、判断、填空、问答、综合题；新旧题库承载不同，按题源解析；综合题需要父子关系 |
| 开考时间 | arrange_time、start_time、end_time | 布置时间、开放开始和结束分开；不是一个“时间”字段 |
| 答题限时 | exam_time_limit | **单位分钟，0不限时**；不等于考试整体开放窗口 |
| 迟到/补考/后入班 | is_late_exam、is_retake、is_rjcs_exam | 都是0否/1是，分别允许迟到考试、补考、后入班学生参加，彼此独立 |
| 对象与人数 | exam_student、should_exam_sum | 指本次考试参考名单与应试人数；未参加者必须从这里及有效分配识别 |
| 解析与考试公开 | public_parsing、public_exam | 两个独立字段，均0未知、1不公开、4交卷后、5批阅后、7结束后；public_exam 的具体公开范围待核，不混同活动发布 |
| 填空判分 | blank_answer_diff | 答案不一致时0判错、1手动批阅；“文本不同”可能进入待人工判断 |
| 是否要手阅 | is_judge | 0历史数据、1需要、2不需要；不能把0解释成不需要 |
| 考试状态与可见 | status、is_display | status：10未开始、5进行中、15已结束；is_display：0显示、1隐藏；与活动层发布状态并列核对 |
| 汇总进度 | exam_end_sum、tobe_reviewed_sum | 已交卷人数、待批阅人数；不能将所有交卷者视为评分已完成 |
| 学生过程 | start_time、end_time、is_exam_end、status、is_retake | 个人开始/结束；交卷标志0否/1是；status：0未作答、3作答中、9待批阅、6已批阅；个人 is_retake 是已经补考的属性 |
| 作答与批阅内容 | answer_info、主观题 answer_info、marking_info | 客观题及全部阅卷信息在学生考试详情，主观题作品另取；逐题关联须包含题源、题 ID、大小题关系 |
| 成绩与反馈时间 | exam_score、result_info、marking_time、review_teacher_uid、read_at | result_info.correctRate 字典称**得分率**，不直接叫答题正确率；read_at 仅写首次查看，不能当批阅后查看 |

试卷 full_marks 明确按实际值扩大100倍存储；exam_score 与逐题 score 在本字典没有给出同等完整的换算约定。不能仅凭字段同为分数就全部除以100，需要样本与接口合同确认。

### 3.2 老师与学生的操作闭环（流程推演）

| 环节 | 老师可以做什么 | 学生需要做什么/可反馈什么 | 能核对的证据 |
| --- | --- | --- | --- |
| 组卷与布置 | 确定试卷版本、题目分值、参加对象、时间、限时和解析开放规则 | 在许可范围内查看和参加 | 试卷—发布记录—活动分配 |
| 开始与作答 | 查看未作答和作答中的人数；按规则处理迟到资格 | 开始答题，提交客观答案和主观作品，交卷 | 个人 status、is_exam_end、时间、answer_info |
| 评分 | 查看系统判分，处理需手工阅卷的题，记录逐题得分 | 等待评分结果 | marking_info、is_judge、待批数、阅卷人与时间 |
| 结果查看 | 按既定可见策略开放对应内容 | 依规则查看成绩/答案/解析 | public_parsing/public_exam；具体成绩可见合同仍需补齐 |
| 补考 | 在策略允许时处理补考 | 符合条件时参加补考 | 主表允许补考、个人补考标志；次数上限与历史保留待核 |
| 教学分析 | 对比题目、作答、判分，整理共性难点 | 可继续向老师问问题，但非本字典已证实的测验内对话功能 | 题目内容+学生答案+逐题评分；不能只看总分 |

这些字段尚不能证明“限时到了自动交卷”“所有客观题必然自动批完”“学生可随意反复重考”“补考取最高分”等行为。没有完整尝试次数/版本合同，也不能只按学生+考试汇总就保证保留全部补考过程。

## 4. 答题卡：题号级结果清楚，但题面完整性需单独核对

### 4.1 关键参数与业务属性（已核验）

| 参数组 | 数据字段 | 业务解释与边界 |
| --- | --- | --- |
| 标题与关联 | title、description、class_id | class_id 仅用于教室内答题卡的课节关联；不是所有卡都属于教室内 |
| 时间与限时 | start_time、end_time、time_limit | **限时单位秒，0不限时**，不能复用测验的分钟格式 |
| 内容与计分 | content、structure、total_score | 每题题号、题型、答案、选项个数、满分、半对分数、顺序；结构含题数和分值占比 |
| 相互查看策略 | check_type | 0不可互看、1提交后、2被批阅后、3结束后，明确控制学生互相查看作答和成绩 |
| 答案和解析公开 | open_type | 0不公开、1提交后、2被批阅后、3结束后；与互看策略分开 |
| 补交策略 | 主表 is_retake | 0否、1是，主表说明“允许补交”；学生同名字段说明“是否补考”。词义差异需与产品核对，不擅自统一为重复尝试 |
| 填空不同答案 | blank_answer_diff | 0判错、1需要手动批阅 |
| 学生状态 | status、start_time、end_time | 0未作答、1作答中、2待批阅、3已批阅；与测验状态数字不同 |
| 阅卷与成绩 | review_type、review_teacher_uid、review_time、score | review_type：0系统、1老师；记录批阅人与时间，不证明所有题采用同一阅卷方式 |
| 逐题判定 | review_detail | reviewDetail：1正确、2错误、3半对，同时有逐题 score/rate；总分不能替代这些判定 |
| 主观作品 | 主观题 answer_detail | HTML内容，可能包含图片/公式，需实际解析 |
| 选项分析 | question_id、option_order、student_uid_list、student_num、correct_score | 某题某选项的学生及人数；多选题同一学生可能计入多个选项，不能简单加总当作答人数 |

### 4.2 老师与学生的操作闭环（流程推演）

| 环节 | 老师可以做什么 | 学生需要做什么/可反馈什么 | 能核对的证据 |
| --- | --- | --- | --- |
| 准备 | 设置卡片题号、题型、答案、分值、限时、互看和解析规则 | 取得卡片及对应题面；题面是否另在课堂/资料需核 | 卡片配置和活动上下文 |
| 作答 | 查看学生是否开始和提交 | 按题号填写/选择，主观题提交内容 | 个人状态、客观作答与主观作答详情 |
| 批阅 | 查看系统结果，处理人工批阅项，确认得分 | 等待评分，并在规则允许时查看结果 | 系统/老师批阅类型、逐题正确/错误/半对 |
| 讲评 | 查看某题选项分布，结合题面解释典型错误 | 根据公开时机查看解析；同伴互看仅规则允许时 | 题号+题面+选项分析+逐题判定 |
| 补交 | 按允许补交规则处理未完成者 | 在许可范围内完成补交 | 主表与个人 is_retake；具体时机/尝试限制仍待核 |

答题卡不应被直接当成完整电子试卷。当前字典清楚给出了题号、正确答案、选项数量和计分结构，但没有证明每张卡都有完整题干、解析正文及题库知识点。可以先回答“哪些题错得多、选了哪些选项”；回答“为什么错、怎么讲解”需要再取得对应原题及学生作答。

## 5. 除用户提出的四个维度，还需要补充的五个维度

| 补充维度 | 为何影响实际教学 | 本轮可得到的证据与剩余缺口 |
| --- | --- | --- |
| 可见性与对象资格 | 老师已布置不等于每位学生现在能参加、看答案或看他人作品 | 对象分配、公开/互看/补交/后入班规则；仍需上层课程及权限合同 |
| 多条独立状态轴 | 活动结束、已交、已批、已查看、已订正分别回答不同问题 | 各表状态、时间与标志；不能压成一个“已完成” |
| 版本与往返过程 | 老师关心“改过什么、这次反馈后有没有调整” | 作业日志有支撑；测验/答题卡完整重试历史与事件协议待核 |
| 内容可读取性 | 标题、附件 ID 或答案统计不足以解释知识和错误 | 文字、JSON、HTML、媒体分开解析；题源/版本、公式、图像需还原 |
| 评价口径与反馈质量 | 已批阅、看过、得分高都不等于掌握 | 评分显示、满分、半对、逐题结果、教师反馈；统计必须说明分母和时间 |

可以采用“活动可见/进行状态 × 学生作答状态 × 评价状态 × 反馈查看/订正”的描述框架。这是给后续数据整理用的**建议模型**，不是要求老师操作一个复杂状态流程，也不应把这些数据库状态全部放进 Copilot 顶部导航。

## 6. 能反推哪些更贴近业务的老师问题

| 老师的问题 | 优先读什么 | 回答边界 |
| --- | --- | --- |
| 这份作业截止了，还能让没交的同学补交吗？ | 当前作业规则 is_revise、对象资格与可见性 | 说明当前规则；不能据此自行修改截止或替老师开放补交 |
| 哪些作业我已经批了，学生还没看反馈？ | 同一作业分配、status=2、rd_ch_time | 仅代表缺少批阅后查看证据，不评价学生态度 |
| 我打回的这份作业，学生改了哪里？ | 学生作业记录、按学生作业 ID 串起的日志、前后内容 | 需要读原作品和修订作品；只有标志则只报状态 |
| 为什么交卷了还没有成绩？ | 交卷/待批阅、逐题批阅、填空差异策略 | 先判断是否待人工批阅，不能编造系统故障原因 |
| 这次测验考了哪些内容，哪些题需要讲？ | 试卷版本、题源题面、学生答案、逐题结果 | 分清考查内容和真实薄弱点；未参加者不计作答错误 |
| 学生现在能看到答案或别人的作答吗？ | 该活动类型的可见策略+个人提交/批阅时间 | 作业/测验/答题卡不可套用同一枚举；未知公开范围要说明 |
| 答题卡第5题为什么这么多人选B？ | 第5题题面、B选项、选项人数与具体作答 | 统计能确认选B人数；错因是基于作品的分析，不冒充学生自述 |
| 这个同学是真的全部做对，还是只拿到了及格分？ | 逐题正确/错误/半对、得分、满分、显示方案 | 得分率不等于正确率，及格阈值另查；不能把 correctRate 字段名直译 |

这些是建立完整取数与解析后的候选能力，不是已上线功能。生成给学生的文字或解析，还需遵循答案可见时机与教师发送确认；教师内部看得到标准答案不意味着可以立即向全班公开。
