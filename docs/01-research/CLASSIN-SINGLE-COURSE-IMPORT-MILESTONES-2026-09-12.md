# 单课程测试数据导入里程碑

## 目标与边界

目标是在测试教师班级内建立一门来源一致、可由教师 API 读取的课程数据集，用于验证 TeachBuddy 对课程、课堂、活动和学情的理解。课程结构来自同一门真实中文数学课程；生产学生身份、答案、附件链接和凭证不进入测试环境或仓库。

此清单只记录测试环境导入进度和验收证据，不改变 TeachBuddy 当前“模拟 Adapter”产品边界。任何测试环境写入都必须保持可追溯、可清理，并通过教师侧接口或页面回读。

## M0：来源与数据治理冻结

**状态：已完成**

- 来源仅使用一门连续的中文数学课程，含 14 讲及其真实活动目录。
- 课程主题、讲次顺序和活动类型关系可以映射；生产教师、学生、机构、资源链接和凭证不复制。
- 源课程没有测验活动。验收时保留这一真实缺口，不为凑齐类型创建“伪真实”测验。

**检查点：** 课程来源与映射规则以 [单课程数据集方案](./CLASSIN-SINGLE-COURSE-DATASET-PLAN-2026-09-11.md) 为准；仓库和导入回执不含生产个人信息或密钥。

## M1：课程目录与课堂计划

**状态：已完成**

| 已导入对象 | 数量 | 验收方式 |
| --- | ---: | --- |
| 独立测试课程分类 | 1 | 教师端课程页面能看到“测试映射”课程分类。 |
| 主题单元 | 14 个讲次单元 | 单元顺序与第 1–14 讲数学主题一致。 |
| 课堂活动 | 14 | 每讲一堂，首讲为 2026-09-13 15:30，末讲为 2026-12-20 15:30。 |

**检查点：**

1. 在教师端打开目标班级，确认分类、单元和 14 个课堂均可见。
2. 抽查第 1、8、14 讲：名称、起止时间、录课开关、发布状态和教师归属一致。
3. 确认课堂日期遵循统一的 7 天时间偏移，而非被压缩为虚构的密集排课。

**已知遗留：** 首讲另有一个不含活动的“课程结构”单元。它来自测试环境对接口文档示例的兼容差异；含课堂的首讲单元已修正。测试环境未部署文档中的单元批量删除接口，因此未采用未验证的清理方式。

## M2：教师读接口回读与关系核对

**状态：已完成**

**目的：** 不以“创建成功”代替“教师可读取”。建立课程分类 → 单元 → 活动 → 详情 → 学员范围的稳定读链路，并记录每种接口返回的字段与权限边界。

**完成标准：**

- 课程分类列表能返回目标分类；
- 单元列表能返回 14 个主题单元及其排序；
- 每个抽查课堂的详情能返回时间、录课、发布、评分及目标学员范围；
- 单元活动列表已整体返回 14 个讲次中的 14 个课堂和 1 项已发布作业，且关联到正确单元；
- 不同接口的对象数量和关联关系与 M1 回执一致；
- 读取失败时记录接口、请求条件、错误语义和替代读取面，不把失败解释为“没有数据”。

**建议抽样：** 第 1、8、14 讲各一堂；它们覆盖首讲、课程中段和末讲。

## M3：测试资源准备

**状态：受阻**

**目的：** 为真实活动目录准备测试环境自有、可访问、可删除的资源引用。

**当前阻塞：** 测试环境云盘目录服务在只读探测时发生基础设施故障。它不表示没有文件；在服务恢复前，不能安全选择或绑定目标资源。

**需要准备的对象：** 课程资料、电子讲义、ClassIn 使用说明和录播视频。资源内容可以是经过授权的测试副本或重新制作的等价测试资源；不能直接复用来源机构的文件 ID、云盘链接或访问令牌。

**完成标准：** 每个资源有测试环境内的稳定引用、可由教师预览，并能关联到对应活动；资源名称和活动归属保持来源课程目录关系。

## M4：作业、资料与录播活动导入

**状态：部分完成；资料与录播依赖 M3**

**导入原则：**

- 已发布活动只导入已核对的标题、时间、内容和配置；
- 后续真实草稿可保留为草稿，不能补写来源中没有的正文、题目或资源；
- 源课程的“无测验”结论在目标环境保持不变；
- 任何写入均先以创建回执和详情回读双重确认。

**完成标准：** 教师 API 和页面能在正确单元下读到资料、作业和录播；每项均能打开测试环境内的资源或清晰标记为草稿。

## M5：脱敏学员与真实测试行为

**状态：受阻；依赖测试机构管理员能力**

**目的：** 让 TeachBuddy 可读取“未交、已交待批、已批、已观看、课堂到课”等真实测试行为，而非写入伪造汇总数字。

**前置条件：** 由测试机构管理员预置脱敏测试学员，或提供经批准的学员种子服务。当前创建请求尚未成功；本轮返回参数错误，不能据此判定教师无权限。机构学生目录读取成功但返回 0 人，需核对机构会话和字段契约，或预置测试学员。

**完成标准：**

- 每个测试学员只使用测试身份；
- 学员被加入目标班级并由活动详情接口可见；
- 通过实际登录、提交、批改和观看操作产生状态；
- 汇总数与逐个学员状态可相互核对；
- 课程元数据可源自真实课程，测试行为必须明确标注为测试环境真实发生的行为，不能冒充生产学生历史。

## M6：TeachBuddy 上下文验收

**状态：未开始；依赖 M2、M4、M5**

**验证问题：**

1. AI 能否准确回答教师当前有哪些班级、课程、单元和课堂？
2. AI 能否给出某项作业或录播的时间、内容、目标学员和完成概况，并附上可追溯业务对象？
3. AI 遇到资源、学员状态或权限缺失时，能否明确说明“无法确认”，而不是生成完成率或学习结论？
4. AI 生成的消息草稿、提醒和后续动作能否保持教师审批与正式写回边界？

**完成标准：** 使用固定提问集对教师 API 返回做逐条比对，记录正确、缺失、过期和权限拒绝四类结果；未验证内容在 UI 与评估中保持真值标签。

## M7：交付审计与可重置性

**状态：未开始；依赖 M1–M6**

**完成标准：**

- 形成源—目标映射、写入回执、读取回执和已知缺口清单；
- 回执只保存在受控、Git 忽略目录，仓库只保存脱敏结论；
- 明确哪些对象可以安全删除或重建，哪些需要管理员操作；
- 复跑 M2 和 M6，确认数据仍可被教师接口和 TeachBuddy 正确读取。

## 建议的检查节奏

先检查 M1 的教师端可见结构，再执行 M2 的 API 回读；两者通过后才进入资源和活动导入。这样能避免在读取链路或单元关联错误时继续写入更多对象。M5 可与 M3 并行准备，但在学员和资源到位前，不宣布“完整学情数据集”完成。
