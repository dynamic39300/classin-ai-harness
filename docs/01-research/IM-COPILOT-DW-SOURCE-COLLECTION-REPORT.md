# IM Copilot 真实业务底稿首轮采集记录

## 1. 结论与范围

用户更新令牌后，只读连接已恢复，并已取得一组可追溯的真实业务底稿。原始业务时间、身份标识、状态和文本保留在 Git 忽略的本机私有区，尚未做化名映射、时间平移、模拟事件补充或前端装配。

本轮选择同一机构的一位教师，以下称“候选 A”。目录层覆盖该教师主讲课次关联及班主任归属检索得到的 358 个班级；明细层围绕 2026-09-01 至 09-08 的教学周期，以及另行补查的历史未结束作业展开。**目录完整度与明细完整度分别记录：没有导出 358 个班级的全部历史学生和聊天。**

真实底稿已可用于下一阶段的数据映射设计；群成员、私聊关系、请假与课堂正文等缺口仍然存在，不能据此声明全部场景已经就绪。

依据：[D-130](../00-project/DECISION-LEDGER.md)、[数据准备方案](../04-specs/features/workbuddy-im-collaboration/COPILOT-DW-SCENARIO-DATA-PLAN.md)。

## 2. 候选发现与选择依据

- 发现窗口：北京时间 2026-09-06 00:00 至 2026-09-09 00:00，左闭右开；三个完整自然日均查到到课记录。
- 初筛交叉近期实际授课与近期更新、已有累计提交的作业，取得按覆盖排序的 30 个机构/教师候选；进一步检查前三位候选的作业与群消息覆盖。
- 累计提交仅用于初筛。最终对候选 A 的学生提交时间逐条验证，确认最近三天有 **447 条提交记录、444 名提交学生、11 份有近期提交的作业**。
- 通过教师身份、停留不少于 900 秒、同课次存在学生记录，确认候选 A 最近三天有 **4 节有效授课**。
- 候选 A 的近期作业覆盖在初筛中居前，且能连接到同一教师的课次、活动、学生状态和相关班级消息，因此选为主蓝本。未声称其他 29 位候选都已完成提交事件核验，也未声称这是整个数仓的绝对最优样本。

角色归属通过教师与机构的关系标识、课次主讲标识、作业发布教师和活动教师交叉核对。没有把其他教师的作业合并到候选 A 名下；班级内共同授课者的课次保留其原有归属。

## 4. 完整性核对

- 140 份作业均有对应活动，且教师归属匹配。
- 18,297 个学生作业记录主键无重复；所有批次均完整返回，没有截断，最终查询量低于各自页上限。
- 逐份排除删除标记记录、区分未提交/已提交/已批改并排除草稿后，**140/140 份作业的有效名单人数、提交数、批改数均与主记录一致**。
- 有效状态分布为：未提交 6,761 条、已提交待批改 72 条、已批改 11,449 条。这是多份作业的累计“学生 × 作业”数量，不是当前待提醒学生人数；业务结束状态、截止时间、名单变化与已提醒记录还需共同判断。
- 当前课次关联名单与到课人选存在不一致。原始记录均保留，尚未确认旁听、名单变更及不同源更新时间的影响，**未把集合差额解释成缺勤人数**。
- 日期分区快照与非分区目录是在一次采集过程中分批取得，不是数据库原子事务快照。落盘冻结保证本机版本可重复读取，不保证所有源在同一业务秒上的一致性。

## 5. 明确缺口

| 缺口 | 本轮实际结果 | 对后续的约束 |
| --- | --- | --- |
| 全量班级成员 | 群成员查询未成功完成；课次关联名单和作业名单已取得 | 不把 3,057 条相关学生资料宣称为 358 个班级的全量成员名单 |
| 教师与学生的私聊关系 | 在可查询关系源中未返回该教师的关系行；另一查询引擎未成功完成相同目标查询 | 未读取真实私聊正文；不能据此断言老师没有好友，也不能虚构可达私聊对象 |
| 实时缺勤与请假 | 有到课和课次名单原始记录，缺乏已核对的同一时点名单及请假事实 | 场景化时需要明确补充和标注模拟事件，不能只靠改日期得到生产实时缺勤结论 |
| 课程分类名称 | 活动与单元保留分类标识；本轮没有取得完整的课程分类名称源 | 不把班级外层分类名称或单元名当作班级内课程名称 |
| 课堂内容 | 有课次、活动、到课以及作业正文/批改反馈；未取得课堂转写、课堂音视频正文 | 不宣称已经具有生成完整课堂报告的内容证据 |
| 附件正文 | 已保留源数据提供的引用与内容字段，没有下载媒体或文件附件 | 附件引用存在不代表附件正文已经读取或可解析 |
| 提醒与交付历史 | 本轮未取得产品内已发送提醒、交付回执及撤销记录 | 后续验证去重和交付状态时，需要独立的模拟记录或正式业务接口 |

上述缺口记录为未取得或未核实，不回填伪造的源数据。后续若更换消息更丰富的辅助样本，必须与候选 A 保持身份和业务边界，不拼成一个不存在的真实老师。

## 6. 留存与下一阶段

本机原始结果保存在 Git 忽略的 `.runtime/private/copilot-source-2026-09-09/`。其中 `snapshot-manifest.json` 记录冻结文件、条数、取得时间、来源集合与 SHA-256；`SOURCE-SNAPSHOT.md` 提供本机阅读入口。原始文件不作为应用 Fixture 导入，也不提交到仓库。

本轮使用在线数仓知识库的全局查询指南、业务术语、课堂课节、LMS 活动、基础业务与 IM 聊天指引，并逐项核对查询引擎的实际元数据。知识库与元数据临时文件不留作项目知识缓存。

后续数据加工与开发 Gate 由[数据准备方案](../04-specs/features/workbuddy-im-collaboration/COPILOT-DW-SCENARIO-DATA-PLAN.md)维护；新 M2 的上游产品思考见[上午体验提案 v1.2](../04-specs/features/workbuddy-im-collaboration/COPILOT-CONTEXTUAL-ENTRY-EXPERIENCE-PROPOSAL.md)，下午线框的撤回范围见[重启设计基线](../04-specs/features/workbuddy-im-collaboration/COPILOT-M2-DESIGN-BRIEF.md)。原始快照保持不变，时间平移、补充事件和消息语义改写各自留痕；缺勤口径、课程名称和私聊去向等缺口不能因页面需要而被当作真实事实。
