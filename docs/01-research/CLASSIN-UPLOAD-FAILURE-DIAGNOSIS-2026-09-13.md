# 测试环境作业图片上传与保存失败排查

## 最新结论：新客户端成功，API 正式链路已复现

用户在新安装版本中通过原生图片按钮上传并保存成功，截图显示第 2 讲作业图片正常回显。教师 API 回读取得正式图片对象：云盘 `fileId`、LMS `lmsFileId`、文件名、大小、UUID 和权限均已落入作业 `image` 字段；附件详情为真实云盘文件、转换成功且审核正常。

此前探测不是对新客户端完整请求链的等价复现：云盘请求缺少万象新客户端参数 `appType=1`，LMS 又直接调用 `/lms/app/file/upload`。按成功样本改为 `/cloudspace/api/user/uploadFileMix`（`appType=1`）→ 取返回的 `originId` → `/lms/app/file/uploadByFile` 后，云盘登记、LMS 绑定和附件回读均成功。`userFileId` 与 `originId` 不能混用；前者用于绑定时接口可返回成功，但附件回读为 `isCloudFile=false`。

该链路已用于第 2–14 讲 13 份作业，共生成并验证 26 个正式图片附件。详细结果见 [作业两图两文转换结果](./CLASSIN-HOMEWORK-IMAGE-CONVERSION-2026-09-13.md)。下方失败记录保留为历史诊断证据，不再代表当前可用性；现阶段无需依赖后台日志才能继续作业图片写入。新旧客户端为何表现不同仍缺少可比版本号和客户端网络日志，不能据此断言具体客户端缺陷。

用户反馈：通过 ClassIn 原生图片按钮上传也失败，作业保存不能成功。本轮复现了测试教师的云盘根目录读取失败和 LMS 图片登记失败；已取得服务端返回的请求标识。尚未取得用户点击当次的网络请求或可解码客户端日志，不能把本轮探测回执冒称为用户操作日志，也不能确认客户端保存动作是否实际发出了作业更新请求。

## 判断与后台接续

**已确认**：图片尚未获得有效 LMS 附件 ID；测试账号云盘连根目录读取也失败，而作业详情接口正常返回。因此问题范围超出图片题文字或 HTML 排版，需要检查云盘和附件登记服务。普通 HTTP 200 不能视作上传成功。

**尚未确认**：云盘部署/数据库依赖异常、账号云盘初始化或资源权限、对象路径与附件契约之间，具体是哪一项导致失败；图片失败是否直接阻断了用户的保存请求。9 月 12 日交接文档曾提及旧接口数据库连接错误，但本轮没有找到该原始异常回执，不能用它认定今天的根因。

后台排查顺序：

1. 在测试 14 环境按根目录请求 ID 查询 17:17:57–17:18:07 的网关与 cloudspace 服务日志，定位 `104` 对应的内部异常、下游调用和耗时。
2. 按附件请求 ID 或 trace ID 查询 17:18:45–17:18:48 的 LMS file 服务调用链，确认 `110140007` 的内部原因，是否与 cloudspace 同一依赖有关。
3. 取得用户实际上传时间对应的前端上报事件或经官方工具解码的本机日志，核对 COS 上传域名、重试/fallback、文件登记以及作业 update 是否发出。不得将探测请求与用户操作混为同一事件。
4. 修复后先完成一张图片的原生上传、附件登记、作业保存与客户端回显，再批量恢复两图两文。当前 13 份作业继续保留完整四道文字题。
