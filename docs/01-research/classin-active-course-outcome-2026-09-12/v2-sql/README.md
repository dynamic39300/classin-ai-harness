# 周期研究 v2 查询说明

查询执行日期：2026-09-12。结果属于第一轮观察框统计，限制见[分析报告](../../CLASSIN-PERIOD-ACTIVITY-PARTICIPATION-ANALYSIS-2026-09-12.md)。所有语句只读，不创建临时表，不保存学生级结果。

## 执行环境与顺序

成功查询使用现有数仓工具、StarRocks 引擎和产研视图库。按技能进行权限和知识库自检后执行，不指定 timeout；每条文件为独立语句。先 EXPLAIN 检查当前执行计划，保留日期分区与业务时间双重过滤，禁止删除过滤以规避超时。

1. `01` 生成三档观察机构聚合；机构条件是窗口内已结束课堂，不依赖班级/课程生命周期。近似三分位边界为 1、3。
2. `02` 生成每档 4 所机构的运行时键。种子固定为 `20260912`，MD5 排序并以机构键打破并列。真实机构键不落入聚合附表。
3. `12` 模板将 `02` 返回键填入 `{{sample_institution_ids}}`，探查候选课程。结果不等于已完成每机构至多 3 门的最终课程抽样。
4. `10` 分别抽 10 个作业与测验质量样本，同一 MD5 规则；样本标签依次为 H01–H10 和 E01–E10。只导出活动级元数据，不查询题干、答案、资源内容。
5. `13`、`14` 模板分别填入 `10` 返回的作业业务键和活动键，做样本主表与事件聚合对账。占位符必须替换成当次查询返回、经过数字格式校验的键列表，不手填或猜测。
6. `03`–`07` 分类型计算观察框内的周期活动规模。各类型互斥，活动数可相加；机构、课程组数不能跨类型直接相加。
7. `08` 先按学生—活动聚合事件，再关联活动发布/删除状态，产出正式引用的周期提交量。学生键仅在数据库内参与聚合。
8. `09` 独立复核发布过滤前事件与去重数；`11` 是未过滤发布状态的探索附表，不代替 `08`。
