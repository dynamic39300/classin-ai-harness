# 测试课程作业生成规则

本规则用于当前 ClassIn 测试课程的作业生成、重新生成和格式调整。依据用户 2026-09-13 的明确要求，每次作业固定四道题，其中两道图片题、两道文字题。测验仍按其单独约定生成，不受本规则改变。

## 内容与呈现

1. 每份作业围绕所在单元主题生成四道题，编号连续为 1–4；题目的子问属于该题，不再额外增加独立题。
2. 第 1、2 题各输出一张 PNG 图片，图中含讲次、主题、题号、完整题干和必要条件。使用清晰中文字体与数学符号，手机放大后可读；图片标记为生成测试题。
3. 第 3、4 题在作业正文中直接提供文字题干。正文对前两题只保留题号和看图提示，避免重复显示完整文字题干。
4. 本地保留四道题的准确文字源稿与教师参考答案，用于内容核验和后续重制；题目图片和学生正文中仅放题目，答案按既定公布规则单独管理。
5. 将已有文字题转为图片时保持题意、数字、条件与答案一致。原题相互引用时保留题号及顺序，让同份作业中的条件可追溯。

## 上传与写入

1. 先读取当前作业、正文、单元、分配名单、时间及提交状态，保存修改前快照。已有教师修改需要协作保留。
2. 使用本地排版工具生成题目图片。可运行 `scripts/classin-test-data/render-homework-images.mjs`；参数为题目 JSON、输出目录和可选的讲次列表。完成条件为每份四题、恰好两张图，图片文字与源稿一致且没有横向溢出。
3. 通过测试环境签发的临时凭证，将图片上传到其指定测试存储桶；下载回读比较 SHA-256，确认实际文件存在。
4. 图片必须通过 ClassIn 正式图片上传/附件链路添加。当前测试 14 环境已验证的顺序是：取得 COS 临时权限并上传 → `/cloudspace/api/user/uploadFileMix` 传 `appType=1` → 使用返回的 `originId` 调 `/lms/app/file/uploadByFile` → 回读附件为 `isCloudFile=true`、转换成功、审核正常 → 将 `fileId`、`lmsFileId`、文件名、KB 大小、UUID 和权限组成的对象数组写入作业 `image` 字段。不得把 `userFileId` 当作这里的云盘原文件 ID。
5. 用户已通过客户端截图否定直接把 COS URL 写进正文 `<img>` 的方式；这种方式即使在普通浏览器可读，也不能作为替代方案。附件登记失败、`isCloudFile=false` 或格式未验证时，保持原作业完整可读，保留题图文件并明确记录阻塞。
6. 对现有作业做格式调整时保留原活动 ID、所在单元、分配名单、评分及时间配置，写前再次核对版本。依据用户本次授权生成具体 ProposedAction，逐项记录请求结果与回读证据。
7. 先用一份作业验证正式图片链路及客户端显示，再批量更新。更新后逐份核对：两道图片题、两道文字题、题号正确、附件记录存在、图片可下载且字节一致、正文题目与源稿一致、原名单和业务配置保持不变。

API 回读通过、普通浏览器图片显示和 ClassIn 学生端实际显示分开记录；只有真实执行过的环节才标为通过。生成测试图片不描述为教师实拍照片，尚未发生的学员作答与批改不生成事实记录。
