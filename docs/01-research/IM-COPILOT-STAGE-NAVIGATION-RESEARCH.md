# IM Copilot 四阶段导航与单卡轮播研究

## 研究问题与边界

本轮核验的候选结构是：顶部用“课前 / 课中 / 课后 / 总结”四个圆点和连线承载可点击入口，下方一次只显示一张内容卡，页面可自动轮播，也允许教师手动切换；卡上的 AI 动作一次点击进入当前对话。

研究只使用 W3C/WAI、政府设计系统、产品官方设计系统与产品官方帮助文档。网页于 2026-09-10 核验；未登录外部产品做实机测试，也没有外部产品关于教师场景的转化率、误触率或认知测试数据。WAI-ARIA Authoring Practices Guide（APG）提供模式和示例，但示例页本身明确提醒生产实现仍需针对浏览器与辅助技术组合测试；因此本文不会把“按示例实现”写成已经满足 WCAG。

本次 Write Set 仅为本文，不修改产品决策、Spec 或实现。项目事实仍以 [D-129、D-131、D-135、D-137 的适用部分、D-139、D-141、D-142](../00-project/DECISION-LEDGER.md) 为准：四阶段描述教学业务位置，不是 AI 任务进度；阶段角标统计可处理业务对象；建议动作只发起教师私有 AI 协作，正式发送仍由教师确认。用户本轮提出的新结构尚未升级为锁定决策。

## 结论先行

1. **四阶段应实现成可自由切换的 Tabs，而不是进度 Stepper。** 教师可能在课中查看课后作业，也可能课后回看课前计划；用户没有逐步“完成”四阶段。圆点连线可以作为弱化的时间顺序装饰，但不能表达已完成、当前步骤和未完成步骤。
2. **建议取消定时自动轮播。** 卡片包含需阅读的业务事实和可执行按钮，定时替换会改变阅读目标与点击目标，并把区域变成 WCAG 2.2.2 所说的自动更新信息。四个可见 Tab 已足以承担发现和切换。
3. **角标只表达该阶段去重后的可处理业务对象数。** 被选中的视图、现实中的当前教学阶段、紧急程度是三个不同信号，不能都靠圆点填色或红色角标表达。
4. **卡片动作可以一次点击向当前 AI 对话提交可读请求。** Slackbot 和 Notion Agent 都提供了对象附近的一次点击进入对话案例；Microsoft 和 Intercom 同时提供了“先放进输入框、再由人发送”的另一类做法，说明行业没有唯一答案。ClassIn 采用一键提交时，应把动作边界限制在教师私有 AI 对话，且不得等同于向学生正式发送。

## 1. Stepper、时间线与 Tabs 的适用边界

### 一手事实

- [USWDS Step Indicator](https://designsystem.digital.gov/components/step-indicator/) 把 Step Indicator 定义为多步骤流程的进度提示，推荐与 Back/Next 配合；文档明确说它自身不是导航，也明确排除可任意顺序完成的非线性交互。它的视觉状态是 completed / current / not completed，数字圆点天然带有“第几步”和“完成度”的含义。
- [Carbon Progress Indicator](https://carbondesignsystem.com/components/progress-indicator/usage/) 同样用于线性多步骤任务。默认版本只显示进度；可交互版本允许回到各步骤，前提仍是这些入口属于同一条多步骤任务，并保留完成、当前、未来、错误等步骤状态。
- [GOV.UK Step by step navigation](https://design-system.service.gov.uk/patterns/step-by-step-navigation/) 面向有明确起点、终点和建议完成顺序的端到端旅程。它不适合只是把一组选择放在一起、没有逻辑顺序的内容。
- [英国司法部 MOJ Timeline](https://design-patterns.service.justice.gov.uk/components/timeline/) 只用于按日期展示已经发生的案件、申请或系统事件，并明确排除把 Timeline 用作任务列表、进度提示或导航。该组件当前标记为“To be reviewed”，因此只将其适用边界作为一手官方参考，不将其实现当作成熟度证据。
- [Primer UnderlineNav Guidelines](https://primer.style/product/components/underline-nav/guidelines/) 将 Tabs 用于切换不同视图，并明确 Tabs 支持自由、非顺序导航，不用于 stepped flow；每个视图应尽量允许用户独立完成任务。
- [WAI-ARIA APG Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) 规定 `tablist` / `tab` / `tabpanel`、选中状态及键盘行为。横向 Tab 使用左右方向键移动焦点；若面板已预加载且切换没有可感知延迟，可以让焦点自动激活面板，否则应使用 Space/Enter 激活。

### 对 ClassIn 的判断

| 判断问题 | 当前四阶段事实 | 控件含义 |
| --- | --- | --- |
| 教师是否按四步完成一个任务 | 否；课程会自然经历阶段，教师不会在 UI 中“完成课中” | 不应使用进度 Stepper |
| 是否允许任意顺序查看 | 是；课中可预看课后，课后可回看课前 | 使用 Tabs |
| 前一阶段是否等于已完成 | 否；过去阶段仍可能有未闭环事项 | 不显示完成勾、完成连线 |
| 点击阶段是否改变业务状态 | 否；只改变当前可见面板 | 点击只更新 `aria-selected` 与面板 |
| “当前阶段”是否由教师选择 | 否；它来自课次时间和业务事实 | 用独立“当前”文字标识，不随 Tab 切换 |

因此，本轮方案可以在视觉上借用时间轴顺序，但 DOM 与交互应按 Tabs 实现。例如，教师首次打开时默认选中真实当前阶段；随后选择“课后”只表示正在查看课后内容，“课中·当前”标记仍保留在课中入口上。选中态与当前阶段必须在视觉和辅助技术名称中各自可辨。

如果未来页面变成一个真正的线性教学设计向导，例如“填写目标 → 生成活动 → 检查材料 → 发布”，且每步确有完成、错误、回退与前进状态，届时才适合可点击 Stepper。那是另一类对象，不能与本轮教学阶段导航复用同一状态模型。

Timeline 的边界也不同：它适合按时间展示“草稿已生成、教师已确认、消息已发送”等已经发生且带时间戳的历史事件，节点内部可以有“查看详情”链接；节点本身不应承担切换课前/课中/课后视图的导航职责。

### 圆点连线可保留的条件

圆点与连线只作为时间顺序装饰时，应满足以下条件：

- 语义结构仍是命名为“教学阶段”的 `tablist`，连接线对辅助技术隐藏；
- 不使用步骤编号、完成勾、前段实线/后段灰线等进度语法；
- 选中 Tab 有形状、字重或边框等非纯颜色标识，并有 `aria-selected="true"`；
- 真实当前阶段使用可见“当前”文本，并在可访问名称中保留；
- 左右方向键在四个 Tab 间移动焦点，Space/Enter 激活；鼠标点击和键盘激活结果一致；
- Tab 切换不改变事项数量、业务闭环状态、AI Run 状态，也不自动发起动作。

即使满足这些条件，教师仍可能把圆点连线理解为课程进度。该认知风险没有官方规范可以消除，必须在可用性测试中验证；若多数教师首先说出“步骤”或“完成进度”，应移除连接线，保留普通横向 Tabs。

## 2. 单卡自动轮播的 WCAG 与交互成本

### 一手事实

- [WCAG 2.2 成功准则 2.2.2 的解释](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) 要求：自动开始且与其他内容并行展示的自动更新信息，必须允许用户暂停、停止、隐藏或控制更新频率；自动更新没有“五秒以内可豁免”的规则。该文档把自动前进的演示和消息列为自动更新示例，也说明只在焦点停留时暂停、焦点离开后立即恢复，不构成有效的暂停机制。
- [WAI-ARIA APG Carousel Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/) 要求自动轮播具有停止/开始按钮；键盘焦点进入或鼠标悬停时停止；焦点进入后不能自行恢复，只有用户明确启动才可恢复。停止/开始控件应位于轮播区域 Tab 顺序的第一位，前后切换和停止按钮本身不能把焦点移走。
- APG 还建议自动轮播时动态区域使用 `aria-live="off"`，停止自动轮播、由用户手动切换时使用 `aria-live="polite"`，避免屏幕阅读器被连续内容打断。每张内容需要有“3/4”或可区分名称；隐藏卡不能继续暴露给辅助技术。
- [APG 自动轮播示例](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/examples/carousel-1-prev-next/) 在 `prefers-reduced-motion` 下默认暂停，并直接指出禁用自动轮播能改善可访问性。示例同时提醒其代码不能替代实际辅助技术测试。
- [Media Queries Level 5：`prefers-reduced-motion`](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion) 定义了用户希望减少非必要运动的系统偏好。它处理运动偏好，但不能代替 WCAG 2.2.2 要求的页面内暂停、停止或频率控制。

### 为什么本场景不值得自动轮播

本轮卡片不是装饰性宣传图，而是“教学事实 + 作用对象 + 一个动作”。自动切换会在教师阅读人数、截止时间或动作文案时替换目标，也可能在鼠标准备点击时改变按钮含义。为了让自动轮播合规，页面还要增加停止/开始按钮、当前卡位次、焦点/悬停控制和动态区域语义；这些控件会抵消“简洁清爽”的目标。

更关键的是，自动轮播不能决定哪个阶段真正值得教师处理。真实当前阶段、事项优先级、数据新鲜度和教师刚才主动选择的视图都比固定计时器更有意义。因此推荐：**首次默认显示真实当前阶段，教师用四个 Tab 手动切换；业务数据可以原位刷新，但不得自动切换当前 Tab 或卡片。**

“Tab 获得键盘焦点时自动激活”与“计时器自动轮播”不是同一行为。前者是教师有意移动焦点后的局部导航，且 APG 仅在面板无延迟时推荐；后者在没有直接操作时持续替换内容，属于这里应取消的行为。

### 若原型必须保留自动轮播，最低合同

以下是合规起点，不代表推荐：

| 条件 | 最低行为 |
| --- | --- |
| 开始方式 | 页面提供可见的“暂停自动切换”按钮；系统启用减少动态效果时默认不启动 |
| 键盘与鼠标 | 焦点进入或鼠标悬停即停止；焦点离开后也不自动恢复，只有教师明确按“继续自动切换”才恢复 |
| 手动意图 | 教师点击 Tab、前后按钮、卡片动作或开始输入后，本次会话永久停止自动轮播 |
| 焦点 | 卡片切换不移动键盘焦点；按钮位置和名称保持稳定，不在指针下替换成另一项动作 |
| 通告 | 自动轮播时不连续播报；停止后由教师切换才用礼貌级别通告；每张卡有阶段名和“第 N/4 项” |
| 数据变化 | 新业务事实只更新角标或当前面板，不强制跳到新卡；紧急事实使用独立的非打断提示策略 |
| 内容连续性 | 教师正在阅读或操作的卡不被移除；数据过期时显示“暂无法确认”，不把旧值轮回显示 |

即便实现上述合同，仍需在实际 ClassIn Sidecar 宽度、200% 缩放、键盘和至少一种屏幕阅读器组合下验收。

## 3. 带角标 Tab 应表达什么

### 一手事实

- Primer 将角标 Counter 定义为 Tab 标签旁的可选数量信息。[UnderlineNav Guidelines](https://primer.style/product/components/underline-nav/guidelines/)
- Primer 的 [UnderlineNav Accessibility](https://primer.style/product/components/underline-nav/accessibility/) 说明 Counter 会进入导航项的可访问名称；当前项需要超越颜色的视觉区分和程序化当前状态；空间不足时应使用溢出入口，避免在 320 CSS 像素宽度下依赖水平滚动。
- WAI-ARIA Tabs 只定义“哪个面板被选中”，不会替产品定义角标的业务含义。角标语义必须由产品的数据口径给出。

### ClassIn 推荐口径

角标只计该阶段**按业务对象去重后的可处理事项**。同一份作业同时需要“催交”和“去批改”时，顶层阶段角标仍计作一个业务对象，展开后的卡内再呈现与教师角色相关的动作。以下内容不混入阶段角标：

- 受影响学生人数；
- AI 正在生成、待确认或失败的 Run 数；
- 未读聊天数；
- “全员已到”“全部已提交”“计划已同步”等闭环确认；
- 数据未知、过期或无权限时被推断出来的零。

推荐把三个状态分开表达：

| 状态 | 含义 | 表达方式 |
| --- | --- | --- |
| 选中 | 教师正在看哪个面板 | Tab 选中形状 + `aria-selected` |
| 当前 | 课程现实中处于哪个阶段 | 可见“当前”文字 + 可访问名称 |
| 需处理/紧急 | 该阶段有多少业务对象、是否真有时效风险 | 中性数字角标；只有确有风险时使用红色且配文字 |

可访问名称应解释数字，例如“课后，2 项可处理”，不要只让屏幕阅读器读成“课后 2”。当前阶段可读作“课中，当前阶段，1 项可处理”。数字更新不能切走教师选中的 Tab，也不因点击“生成提醒”而减少；只有业务事实真正变化或事项闭环时才更新。

四个短中文标签在目标 Sidecar 中是否始终放得下，目前没有实测证据。实现前需要覆盖实际最窄窗口、200% 缩放、系统字号放大和两位数角标；若不足，应优先缩短辅助文案或提供明确溢出入口，不能把第四个阶段裁掉，也不能仅靠横向拖动发现。

## 4. AI 建议卡一次点击进入对话的案例

| 官方案例 | 已核验行为 | 可迁移语法 | 不能推断的部分 |
| --- | --- | --- | --- |
| [Slackbot：共享 Prompt](https://slack.com/help/articles/202026038-How-to-work-with-Slackbot) | 共享消息的可见者可点击“Send to Slackbot”，用该 Prompt 开始一段 Slackbot 对话 | 一次点击把可读意图提交到 AI 会话 | 不是教学业务建议，也不能证明适合所有高风险动作 |
| [Notion Agent：从 Inbox 发起](https://www.notion.com/help/manage-your-inbox-with-notion-agent) | 用户在 Inbox 点击 Agent 图标让其整理通知，结果出现在聊天；原 Inbox 继续是真值来源，结果和动作保留在聊天记录 | 业务事实留在原对象，AI 过程与结果进入可追溯对话 | 文档没有公布 Agent 的内部排序、确认或错误恢复实现 |
| [Microsoft Teams Copilot](https://support.microsoft.com/en-us/teams/copilot/how-to-use-microsoft-365-copilot-in-teams-chats-and-channels) | 侧栏提供建议 Prompt 和更多入口；用户选择或输入 Prompt 后再按 Send | 少量建议靠近当前聊天，并保留自由输入 | 建议的选择不是自动提交 |
| [Microsoft 365 Organizational Prompts](https://learn.microsoft.com/en-us/microsoft-365/copilot/organizational-prompts) | 选择 Prompt 会把内容放入 Copilot Chat 输入框，允许修改，且不会自动提交 | 预填可编辑请求适合高歧义或高风险入口 | 该功能仍属 Frontier preview，行为可能变化；不能视为通行标准 |
| [Intercom Copilot](https://www.intercom.com/help/en/articles/8587194-how-to-use-copilot) | 情境 Macro 建议可插入 Composer；Copilot 结果也可加入回复框、修改后发送 | “AI 生成”和“对外发送”分成两个授权点 | 客服回复流程不能证明教学提醒应自动发送 |

这些案例共同支持两点：建议应紧贴当前业务对象；AI 结果应落在可继续追问和回看的对话中。它们没有共同支持“任何建议都应一键自动提交”。ClassIn 的一键行为来自项目 D-129，而不是竞品共识。

### ClassIn 的一键动作合同

当建议对象、课程和动作都明确时，卡上只保留一个主按钮，例如“为 3 人准备提醒”。点击后：

1. 在当前教师私有 AI 对话中立即追加一条可读的教师请求，例如“请为数学一班本讲尚未进入课堂的 3 名学生准备私聊提醒，发送前让我确认”；
2. 同时捕获教师、班级、具体课程、课次/作业和候选对象的最小上下文快照；
3. 把焦点或视口带到新增对话消息与真实生成反馈，不打开必经配置页；
4. AI 的补问、生成、修改、失败恢复、产物审阅和回执留在对话中；
5. 最终学生名单在正式发送前重新核对，教师确认后才产生发送动作。

卡片点击本身不表示业务事项已经完成，不减少阶段角标，也不让页面自动前进到下一阶段。若卡内还包含“查看名单”“查看作业”等其他链接，应让主按钮单独可点击，避免整张卡与内部控件形成嵌套交互；只有整卡唯一动作时才可扩大同一个语义按钮的点击区域。

对象、课程或交付目的地有歧义时不应自动提交猜测。此时可以使用 Microsoft/Intercom 的预填语法：把可编辑请求放入输入区或先补问一个必要问题。选择哪条路径应由上下文完整度决定，而不是所有卡统一采用同一种手势。

## 5. 建议用于下一轮对比的候选

### 推荐候选：静态阶段 Tabs + 单张主建议卡

- 顶部顺序固定为课前、课中、课后、总结；使用 Tabs 语义，连接线若保留只作弱装饰；
- 首次进入选中真实当前阶段，同时用“当前”标识现实阶段；教师手动选择其他阶段后不强制跳回；
- 每个阶段面板一次显示一张当前优先卡，卡内先写事实和更新时间，再写对象范围，最后只放一个主动作；
- 同阶段还有其他事项时，在卡下显示“另有 N 项”或稳定的前后切换按钮，由教师主动展开/切换；
- 无可处理事项时显示有证据的闭环确认；数据未知时显示“暂无法确认”，不能把它当作零事项；
- 不定时轮播；业务事实更新只刷新角标与相关面板，不抢焦点、不改选中 Tab；
- AI 动作一次点击进入当前教师私有对话，后续过程在对话中，正式发送继续走教师确认。

这一候选保留了用户希望的横向阶段感和单卡清爽度，同时减少了圆点进度误解与自动轮播控制。它是研究建议，不替代现有 D-141，也不在本文选择 ClassIn 最终方案。

### 若要对比，保留的实验变量

建议只比较少量独立变量，避免把多个变化混成一次测试：

1. 连接线：普通横向 Tabs vs. 带弱连接线的阶段 Tabs；观察教师是否误读为完成进度。
2. 当前阶段与所选阶段：教师切到非当前阶段后，能否准确说出“现在处于哪个阶段”和“正在看哪个阶段”。
3. 同阶段多事项：卡下“另有 N 项”展开 vs. 手动前后切换；检查是否能发现第二项且不会误认角标为学生人数。
4. 动作提交：上下文完整时一键提交 vs. 先放入输入框；比较误触、可预期性和完成时间。

定时自动轮播不建议作为默认候选；如产品仍希望评估，只能在实现上一节最低合同时作为单独变量，不能与连接线、角标口径和卡片文案同时变化。

## 6. 明确不确定性与验证门槛

| 未知 | 为什么现有资料不能回答 | 进入实现前的验证 |
| --- | --- | --- |
| 教师是否把圆点连线读成流程完成度 | 设计系统只解释通用语法，没有 ClassIn 教师测试 | 给教师展示 5 秒后复述界面含义；重点记录“步骤、完成、未来不可看”等词 |
| 单卡是否会隐藏次要但重要事项 | 官方案例没有本项目业务优先级分布 | 用课前、课中、课后各含 2–3 项的真实化任务测试发现率 |
| 一键提交的误触率 | Slackbot/Notion 证明行为存在，不证明教学场景更优 | 比较一键提交与预填，记录撤回、改写和发送前返回次数 |
| 当前阶段如何判定 | 外部规范不包含课程跨时区、补课、并发课次规则 | 由 ClassIn 业务事实和可重置时钟定义，并覆盖未知/冲突状态 |
| 两位数角标在 Sidecar 是否容纳 | 未测实际最窄宽度、缩放和字体 | 320 CSS px、实际 Sidecar 下限、200% 缩放、系统字号放大 |
| 数据变化应不应播报 | 动态数量频率与教师任务尚未知 | 先默认不逐项 live announce；用屏幕阅读器验证必要提示且不打断输入 |
| 自动轮播是否提升发现 | 没有一手实验数据支持本业务 | 默认关闭；只有提出明确发现率假设时再做受控实验 |

验收至少覆盖：仅键盘完成四阶段切换与主动作、焦点顺序与焦点可见、选中与当前阶段不混淆、角标可访问名称、业务数据更新不抢焦点、减少动态效果偏好、200% 缩放，以及常用屏幕阅读器的 Tab/tabpanel 朗读。
