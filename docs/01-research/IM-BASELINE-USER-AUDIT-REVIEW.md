## 1. 占位可接受，但实现状态与本轮取舍要分开

“PARTIAL，接受当前占位”是一种合理的 Demo 范围决策。它不要求为了表格完整而接通真实数据库、云盘、文件传输、教室服务或生产鉴权。

保留四类消息、沉浸布局、现有资源 Reference 和非核心资料/管理占位，都符合本轮收敛方向。源表的 85 项表示相对历史基线的差异，不应再整体称为下一轮必做任务；实际开发清单应由本次审阅决定形成。

建议以后用两个独立字段记录：

| 字段 | 可选值 | 作用 |
| --- | --- | --- |
| 当前实现状态 | MATCHED / PARTIAL / ADAPTED / MISSING / CONFLICT | 保留可核验的事实。 |
| 本轮决定 | 保持现状 / 补齐 / 待讨论 / 暂缓 | 表达用户的范围取舍；不把“接受占位”误记为完整实现。 |

## 2. 临时教室权限还没有形成唯一结论

源表 `ON-GOV-02` 写“保持盖里角色创建临时教室规则”，结合原条目暂按“管理角色”理解；`ON-GOV-07` 又写“保持 demo 设计现状”。后者当前是在师生附件菜单都显示临时教室创建入口，点击只反馈占位；源表末尾原规则则是“管理角色创建，学生只能进入”。

因此这里是权限表达待澄清，不是已经出现真实越权创建。建议统一为：管理角色可创建，学生可查看和进入；如果希望保留学生入口作为能力介绍，可禁用并说明角色限制。若要让学生也能创建，应作为明确的产品升级决策另记，不能同时标成“与线上规则对齐”。

证据：源表第 224、229、278 行；[当前附件入口](../../src/features/message-workspace/MessageWorkspace.tsx) 的 `attachmentOpen` 分支（2026-09-09 第 1297–1299 行）。用户随后确认本轮仅验收接收卡片，创建保留占位，因此该权限决定可延至创建功能实施前；当前记录为未解决、不阻塞接收侧展示。
