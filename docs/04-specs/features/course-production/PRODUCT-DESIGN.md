## 一、场景概览

| 项目 | 第一版定义 |
| --- | --- |
| 业务场景 | 课程目标 → 课程对象 |
| 教师问题 | 有目标但缺少可直接使用、可审阅和可保存的课程设计结构 |
| 核心交付物 | 可审教课程方案包 |
| 交付对象 | 目标、成功标准、课程范围、单元结构、课时/活动结构、评价安排、资源建议、来源依据、审教意见和版本记录 |
| 最终业务结果 | 教师确认一个可保存为课程、单元和活动草稿的方案包 |
| 第一版真值 | `SIMULATED` |
| 第二版扩展 | 从最终确认方案包派生 PPT 课件 Artifact，并支持页面/章节/活动级课件审教 |

第一版不是“生成一份 PPT”，也不是把课程方案包复制成 ClassIn 新对象。方案包是 WorkBuddy 的组合 `ArtifactDraft`，最终确认后通过业务 Adapter 保存为 ClassIn 课程、单元和活动草稿。

## 二、要帮教师完成什么结果？

### 2.1 一句话结果

教师输入一个教学目标和基本约束，WorkBuddy 形成一份可审教、可修订、可确认并可保存的课程方案包。

### 2.2 第一版成功条件

只有以下条件同时满足，才算第一版业务完成：

1. 目标和成功标准已被教师确认；
2. 课程方案包包含课程、单元、课时/活动、评价和资源建议；
3. 教师完成至少一轮审教，所有阻断性意见已处理；
4. 方案包通过第一版规则校验；
5. 教师明确确认最终版本；
6. 保存动作经过审批并返回模拟执行回执；
7. 评价事件记录目标确认、审教、修改、审批和回执。

“模型返回内容”“草稿生成完成”“教师打开了方案”都不单独代表业务完成。

### 2.3 明确不解决

第一版不解决：

- 具体 PPT 文件生成和页面视觉排版；
- 图片、动画、视频和其他多媒体素材制作；
- ClassIn 正式发布和真实 API 集成；
- 真实学生学习判断、成绩和提交状态变更；
- 多教师协作、负责人审批和意见合并；
- 跨天自动调度和跨机构批量执行。

## 三、谁在什么情况下使用？

### 3.1 角色和范围

| 角色 | 第一版责任 |
| --- | --- |
| 发起教师 | 输入目标、补充约束、审教方案、处理意见、确认保存 |
| 受影响学生 | 仅作为课程方案的潜在教学对象，不在第一版直接参与流程 |
| 机构/课程系统 | 提供模拟课程范围、对象版本和保存回执 |
| WorkBuddy | 组织目标、上下文、方案包、审教版本、待确认动作和评价事件 |

第一版范围固定为：单教师、单机构、单班级课程、单次 WorkBuddy Run。

### 3.2 入口和前置条件

入口：统一教师 WorkBuddy 工作台中的“把课程目标整理成课程方案”任务。

开始前需要：

- 教师身份和机构范围；
- 课程或班级课程范围；
- 年级/学段；
- 预计课时或周期；
- 至少一个可理解的教学目标描述。

信息不足时，WorkBuddy 优先追问；无法得到关键范围时停留在 `needs-input`，不生成看似完整的方案。

## 四、系统将读取和产出哪些东西？

### 4.1 输入

| 输入类型 | 第一版内容 | 所有者 |
| --- | --- | --- |
| 教师输入 | 原始目标、年级、课时、班级特点和补充约束 | 教师 / WorkBuddy Run |
| 业务事实 | 教师身份、机构、班级课程、课程版本和已有结构 | ClassIn 领域（模拟） |
| Domain Knowledge | 课程标准、叙事写作进阶、活动设计原则、机构规范 | Knowledge 系统（模拟） |
| 运行信号 | 缺口、权限拒绝、版本冲突、超时和执行回执 | Runtime / Adapter |

### 4.2 第一版输出

| 输出 | 类型 | 是否正式业务事实 |
| --- | --- | --- |
| 目标草稿 | `GoalIntentDraft` | 否 |
| 上下文快照 | `ContextSnapshot` | 否，是本次使用范围的可追溯引用 |
| 课程方案包 | `ArtifactDraft` | 否，WorkBuddy 组合产物 |
| 审教意见 | `ReviewComment` | 否，是教师控制和版本迭代记录 |
| 待确认动作 | `ProposedAction` | 否，等待审批的写回意图 |
| 审批 | `Approval` | 否，是教师控制事件 |
| 执行回执 | `ExecutionReceipt` | 是业务执行证据，但不等同于正式发布 |
| 评价事件 | `EvaluationEvent` | 是评价记录，不改写 ClassIn 原始事实 |

### 4.3 课程方案包结构

```text
可审教课程方案包
├── 课程目标与成功标准
├── 课程范围与约束
├── 单元结构
├── 课时与活动结构
├── 评价安排
├── 资源建议
├── 来源与依据
├── 审教意见及处理状态
└── 版本、差异与最终确认状态
```

第一版的方案包可以包含课件提纲或活动材料建议，但不生成具体 PPT 文件。第二版的 `PPT 课件 Artifact` 必须保留来源方案包版本引用。

## 五、AI 具体怎样一步步完成任务？

第一版业务步骤如下：

```text
输入目标
→ 目标澄清与缺口检查
→ 上下文与知识依据确认
→ 课程方案包初稿
→ 教师审教
→ 审教意见处理
→ 人工修改或 AI 定向修订
→ 再次审教
→ 规则校验
→ 最终确认
→ 待确认保存动作
→ 模拟写回与回执
→ 结果复查与评价
```

产品层只要求每一步有清晰输入、输出、校验、教师控制和降级方式；不在此文档决定模型或 Agent Runtime 的技术实现。

### 5.1 第一版 Skill 组合

| Skill | 产品作用 | 输出 |
| --- | --- | --- |
| 目标澄清 | 把原始目标整理为可观察目标、成功标准和缺口 | 目标草稿或需要补充 |
| 课程结构生成 | 形成单元、课时和活动结构 | 方案包初稿 |
| 方案包修订 | 根据教师明确意见生成定向修订版本 | 新版本方案包和差异 |
| 方案完整性检查 | 检查目标覆盖、课时约束、活动和评价完整性 | 校验报告和阻断项 |

“保存课程草稿”不是 Skill，而是教师确认后的业务动作；“教师是否有权限保存”不是 Skill，而是业务规则和控制流程。

## 六、教师在哪里参与和做决定？

### 6.1 教师主流程

1. 选择“把课程目标整理成课程方案”；
2. 输入目标、年级、课时和班级约束；
3. 补充 WorkBuddy 指出的必要信息；
4. 查看课程方案包初稿和依据；
5. 按整体方案、单元或活动进行审教；
6. 对每条意见选择人工修改、要求 AI 定向修改、接受或拒绝；
7. 查看修订版本和差异；
8. 再次审教并处理阻断性问题；
9. 确认最终方案包；
10. 查看保存范围、风险和对象版本；
11. 批准保存课程草稿；
12. 查看执行回执和后续复查提示。

### 6.2 教师控制原则

- 目标由教师确认，模型不能替教师决定教学目标；
- 方案包始终可编辑、可比较、可恢复；
- AI 修订只处理教师明确指定的意见或范围；
- 每条意见显示处理状态，不因生成新版本自动标记为已解决；
- 最终确认是显式动作；
- 保存是独立的审批和业务动作；
- 教师可以拒绝方案、退回修订、暂停、重试或继续编辑。

## 七、哪些动作会改变业务，出错怎么办？

### 7.1 版本状态

第一版方案包采用以下版本语义：

```text
初始生成稿
→ 审教修订稿 v2...
→ 最终确认稿
→ 课程/单元/活动草稿写回
```

最终确认稿不等于正式发布稿。第一版只模拟保存课程草稿，正式发布由 ClassIn 领域流程负责。

### 7.2 审教意见状态

```text
open
→ accepted
→ applied
→ verified
```

也可以进入：

```text
open → rejected
open → deferred
```

`verified` 表示教师在新版本中重新确认，不表示模型认为意见已经解决。

### 7.3 阻断性规则

以下问题阻止最终确认：

- 目标不可观察或缺少成功标准；
- 课程范围或课时不完整；
- 单元/活动无法映射到目标；
- 存在教师标记的阻断性审教意见；
- 方案引用未授权资料；
- 方案版本与当前课程版本冲突。

以下问题可以在明确提示后保留：

- 非阻断性表达优化；
- 可选资源未选择；
- 尚未决定的扩展活动；
- 需要第二版 PPT 课件才能解决的页面呈现问题。

### 7.4 恢复路径

| 异常 | 产品处理 |
| --- | --- |
| 信息缺口 | 回到目标补充，不丢失已有输入 |
| 方案生成失败 | 保留目标和上下文，允许重试或缩小范围 |
| 版本冲突 | 展示当前版本变化，不覆盖他人或领域事实 |
| 权限拒绝 | 保留方案包，允许继续编辑或更换范围 |
| 部分写回 | 按课程/单元/活动逐项展示回执，不汇报整体成功 |
| 页面关闭 | 通过 Run 标识恢复当前审教和版本状态 |

## 八、怎么判断真的有帮助？

第一版把指标分成四类：

| 指标类别 | 示例 |
| --- | --- |
| 产物质量 | 目标覆盖率、结构完整性、规则阻断项数、教师质量评分 |
| 教师控制 | 审教轮次、意见解决率、修改距离、采纳/拒绝率、最终确认率 |
| 执行可靠性 | 保存成功率、冲突率、权限拒绝率、部分成功率、恢复成功率 |
| 业务价值 | 从目标到可确认方案的耗时、方案后续使用率、教师重复编辑成本 |

第一版不把 PPT 页面美观度或正式发布率作为核心验收指标，因为具体 PPT 生产属于第二版。

## 九、版本路线

### 第一版：可审教课程方案包

```text
目标 → 方案包 → 审教 → 修订 → 再次审教 → 最终确认 → 课程草稿保存
```

### 第二版：课程方案包到 PPT 课件

```text
最终确认方案包
→ PPT 课件结构
→ 页面内容与课件 Artifact
→ 页面/章节/活动审教
→ 课件修订与版本比较
→ 最终确认课件
```

第二版复用第一版的目标、上下文、来源、教师控制、审教意见、版本和确认机制，不重建一套独立课件工作流。
