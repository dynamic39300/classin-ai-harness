# TeachBuddy IM Copilot 初始面页面承载结构方案对比

## 1. 本轮要决定什么

用户已经确认[初始面内容全集与机会状态模型](./COPILOT-INITIAL-SURFACE-CONTENT-MODEL.md)。本轮只比较这些内容怎样被简洁、清爽、明晰地承载：

- 老师第一次进入时怎样迅速理解 TeachBuddy；
- 当前最值得处理的教学事项怎样被看见；
- 全勤、学生全部提交等闭环确认怎样提供安全感；
- 教师自己的业务待办与 AI 可协作事项怎样不混淆；
- 点击后的 AI 沟通、产物和发送怎样自然留在原对话；
- 自由输入怎样始终保持为主要协作方式。

本轮不恢复下午旧线框，不预设主卡、副卡，也不制作可点击页面。下面的“信息序列”只用于说明层级和出现顺序，不是视觉线框。

## 2. 所有方案共同遵守的约束

| 约束 | 统一要求 |
| --- | --- |
| 教师身份 | 页面简称 TeachBuddy，私有协作区明确“仅你可见” |
| 业务范围 | 每项保留教师、班级、班级内课程及具体课次、作业、测验、题目或周期 |
| 自由输入 | 始终可见，老师可以直接说要求，不必先选择内部能力 |
| 快捷发起 | 对象完整时，一次点击直接提交一条可读的自然语言要求并开始 AI 工作 |
| 信息补充 | 只有真实歧义阻碍继续时，AI 才在同一对话里提问 |
| 正式交付 | 生成不等于发送；发给班级或学生前继续由教师确认 |
| 页面层级 | 不进入二级配置页，不依赖“返回”完成普通任务 |
| 计数 | 业务事项、AI 可处理数、教师业务待办和受影响人数分别计数；对话状态不进入教学动态的阶段计数 |
| 闭环确认 | 有完整、及时数据时明确呈现；不计入待办或红点，不用空白页代替 |
| 数据未知 | 表达“暂时无法确认”，不显示全勤、全部完成或零待办 |
| 视觉语言 | 不出现 Agent 编号、Skill、MCP、模型、工具日志和虚假后台状态 |

## 3. 经典案例及可迁移的界面语法

完整证据、适用条件和限制见[初始面内容承载模式一手研究](../../../01-research/IM-COPILOT-INITIAL-SURFACE-PATTERNS-RESEARCH.md)与[情境引导研究](../../../01-research/IM-COPILOT-CONTEXTUAL-GUIDANCE-RESEARCH.md)。这里仅提炼与页面结构直接相关的设计语法。

| 经典案例 | 官方可核验行为 | 对本项目有价值的语法 | 不直接照搬的部分 |
| --- | --- | --- | --- |
| [Microsoft Copilot / Teams](https://support.microsoft.com/en-us/teams/copilot/how-to-use-microsoft-365-copilot-in-teams-chats-and-channels) | 当前聊天内提供少量建议和更多入口，回答可回到来源消息 | 让少量情境建议靠近输入区，并持续绑定当前聊天 | 外部产品没有证明教学机会排序和同班多课程规则 |
| [Intercom Copilot](https://www.intercom.com/help/en/articles/8587194-how-to-use-copilot) | 根据当前问题给建议，结果可加入回复框后继续编辑 | 建议贴近当前内容，老师输入时不抢焦点，产物先编辑再发送 | 客服知识回答不能替代 ClassIn 的到课、作业和学情事实 |
| [Slack Featured workflows](https://slack.com/help/articles/32393999092883-Manage-the-Workflows-tab-in-channels-and-DMs) | 会话可以突出一个常用 workflow，同时保留普通发消息 | 当前只有一个高置信动作时，给出单一明确入口 | workflow 启动不包含本项目的产物审阅和发送 Gate |
| [Slack Catch up](https://slack.com/help/articles/226410907-View-all-your-unread-messages) | 返回后可以逐项处理积压内容，支持跳过、稍后与撤销 | 多事项积压时提供轻量清理模式 | 不适合作为正在上课时的唯一主界面 |
| [Linear Inbox / Triage](https://linear.app/docs/inbox) | Priority 与 Other 分层，支持筛选、稍后处理和进入对象 | 把需处理事项与普通进展分开，保持稳定排序 | 研发分诊术语和高密度队列会让教师觉得在管理工单 |
| [Notion Home](https://www.notion.com/help/navigate-with-the-sidebar) | Upcoming、Tasks、Recents 等区段按个人工作组织 | 用“现在、接下来、已核对”形成简洁教学简报 | 区段存在不代表 AI 已经完成优先级判断 |
| [Notion Calendar](https://www.notion.com/help/notion-calendar-settings) | 紧凑展示即将发生的事件并提供直接动作 | 时间和教学阶段可以作为跨课程的自然组织轴 | 单纯按时间无法保证异常与教师业务待办优先 |
| [GitHub Copilot agent sessions](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents) | 长时间异步任务有独立状态，可跨页面追踪、继续和查看结果 | 说明异步工作必须可返回和可审阅 | 教师侧的短内容协作留在原对话，不照搬独立任务索引、工程日志、Token、模型或工具细节 |

这些案例共同说明四件事：当前情境只给少量下一步；完整能力按需展开；长时工作必须能回到原现场；完成或无需处理的状态也需要明确反馈。对 TeachBuddy 当前范围，老师点击后的沟通和结果统一留在原对话，不额外引入任务中心。它们没有提供 ClassIn 教师场景的效果数据，以下方案仍属于待比较的设计推导。

## 4. 共同的交互语法

### 4.1 固定信息槽位

无论采用哪种结构，都需要能找到以下六类信息：

1. `仅你可见 · 当前班级/学生`：可见性和当前聊天范围；
2. 当前教学现场：课程、课次或作业及必要时间锚点；
3. 需处理内容：AI 机会与教师业务待办；
4. 闭环确认：已经核对且无需处理；
5. 自由对话：老师与 TeachBuddy 的补问、生成、修改、审阅、发送和结果；
6. 更多能力：长尾能力发现，不承担待办状态。

固定信息槽位是语义要求，不意味着六个常驻区块。没有相应内容的槽位可以不出现。

### 4.2 一键发起

- 点击带动词的操作，例如“准备入课提醒”“生成课堂回顾”，立即把业务对象和意图组成自然语言请求并提交给 TeachBuddy；
- 对话中马上出现老师发起的可读要求，避免按钮按下后不知道发生了什么；
- 信息完整则直接生成，只有一个真实歧义时在同一对话里提问；
- 教师已有未发送文字时，快捷动作独立提交，不覆盖、不夹带原输入；
- “去批改”属于业务导航，与“生成提醒”使用不同动作语言，不伪装成 AI 能力。

### 4.3 展开与查看

- 点击具体动作直接开始工作，不先展开配置；
- 点击数量或区段标题只在原位置展开对应事项，不能跳到二级页面；
- 一次只展开一个较长集合，其他集合保留一行摘要；
- 收起是原位折叠，不需要页面级返回；
- 查看、点击或开始生成都不改变教学事项；只有业务事实、正式提醒记录、冷却窗口或有效期变化时，事项和计数才更新。

### 4.4 颜色与密度

- 红色只用于临近失效、逾期或真实失败，不用于所有可处理事项；
- 闭环确认使用图标与文字共同表达，不能只依赖绿色；
- 每个事项默认一行结果、一行范围或时间、一个主要动作；
- 不使用卡片套卡片，优先用留白、分隔线和稳定对齐组织层级；
- 第一屏不同时铺开完整能力、全部机会、完整对话历史和全部完成记录。

### 4.5 跨聊天对话连续性

- 点击教学事项后，老师的自然语言要求、AI 补问、生成内容、产物和回执都进入当前对话；原事项不改写成运行状态卡；
- 切换聊天后，每段 TeachBuddy 对话仍跟随原聊天保存，不把 A 群的内容注入 B 群；
- 返回原聊天时定位到最新消息或尚未回应处，由对话本身继续，不进入独立二级任务页；
- 若需要在会话列表提示老师返回，只复用普通未读或“待回应”语义，不显示跨聊天任务数量和状态面板；
- 切换聊天或收起 Copilot 不自动停止 Run；只有 Runtime 有真实离页执行证据时，原 AI 消息才能继续显示“生成中”。

### 4.6 两条独立变化链

```text
教学动态：业务事实 → 当前信号 / 闭环确认 → 更新或到期消失
对话协作链路：点击或自由提问 → AI 补问 / 生成 → 修改 / 审阅 → 发送与回执
```

两条链只在“点击时把业务对象带进对话”这一刻相接。仅仅点击、生成或修改内容不会改变教学动态；其中的事项继续出现、更新或退出，只看课程、课堂、作业、正式提醒记录、冷却窗口等业务事实。原事实仍有价值时继续显示，业务条件不再成立时退出。教学动态不会显示“生成中”“待确认”或“已完成”，展开与紧凑也只改变界面密度。

## 5. 方案 A：对话优先 + 情境建议

### 5.1 信息序列

```text
仅你可见 · 当前聊天
一句 TeachBuddy 角色说明（首次或无历史时）
当前事实或闭环确认
1–3 个情境动作
完整对话与产物
自由输入 · 更多教学协作
```

### 5.2 交互方式

老师看到与当前聊天最相关的少量短动作。点击后动作直接变成对话中的自然语言请求，随后所有追问、生成、修改和审阅都在对话里继续。完成确认以一行安静状态放在建议附近。

### 5.3 优点

- 结构最轻，老师很快理解“这是一个可以直接聊的 Copilot”；
- 首次使用和数据不足时仍然自然；
- 与 Microsoft Copilot、Teams 和 Intercom 的会话内建议模式接近；
- 不容易重新长成任务管理器。

### 5.4 风险

- 同时存在多门课程和多项教学事项时，整体状态难以扫描；
- 闭环确认可能被对话滚动淹没；
- 老师跨很多聊天工作时，需要由会话列表的未读或待回应提示帮助找回原对话。

### 5.5 适用情形

当前聊天通常只有零到两个高相关事项，且核心价值是即时生成和修改内容。

## 6. 方案 B：教学简报 + 对话

### 6.1 信息序列

```text
仅你可见 · 当前聊天
现在需要处理
已经核对，无需处理
完整对话与产物
自由输入 · 更多教学协作
```

每个区段只显示最多两到三条紧凑事项，剩余内容在原位展开。

### 6.2 交互方式

老师先扫一眼教学简报，再点击具体动作进入同一对话。简报不会变成独立页面：开始生成后，沟通和产物只在对话里推进；原机会按业务条件、去重和有效时间撤下或继续显示事实，教师待批改仍留在原业务事项中；风险解决后转为闭环确认。

### 6.3 优点

- “需要做”和“已经正常”两类教学信息非常清楚；
- 全勤和任务完成能稳定提供安全感；
- 对同班多课程和同一作业的两侧状态承载能力较好；
- 可以借鉴 Notion Home 的区段结构和 Linear 的优先分层。

### 6.4 风险

- 如果区段和数字过多，会显得像教学后台首页；
- 对话在视觉上可能退居第二位；
- 首次进入时还需要额外说明这些状态都可以直接用自然语言处理。

### 6.5 适用情形

当前班级通常同时存在三到八项教学状态，老师需要先建立整体判断再开始沟通。

## 7. 方案 C：教学阶段议程

### 7.1 信息序列

```text
仅你可见 · 当前聊天
现在：正在上课 / 当前作业窗口
课前
课中
课后
周期总结
完整对话与产物
自由输入
```

系统自动定位当前阶段，其他阶段保持一行摘要。阶段内按具体课程、课次或作业列出事实、闭环确认和动作。

### 7.2 交互方式

老师沿教学时间理解事项。点击动作后直接进入对话；阶段列表只负责定位和扫视。已经过去的阶段保留必要闭环确认，过期机会不继续占据可处理数量。

### 7.3 优点

- 课前、课中、课后、总结与教师的教学心智高度一致；
- 可以清楚解释为什么某条建议现在出现；
- 多课程、多课次和未来安排容易按照时间定位；
- 全勤、已安排、全部提交等状态可以自然出现在对应阶段。

### 7.4 风险

- 单纯按时间可能让阶段区段挤压对话和产物；
- 当前聊天只有一个简单事项时，时间轴显得过重；
- 学情总结、错题跟进等跨阶段工作不总有唯一时间位置。

### 7.5 适用情形

产品更强调一天或一个教学周期的连续安排，且课次和截止时间数据稳定可靠。

## 8. 方案 D：优先收件箱

### 8.1 信息序列

```text
仅你可见 · 当前聊天
需你处理
已核对
按课程 / 事项类型筛选
完整对话与产物
自由输入
```

每项是一行可分诊内容，显示课程、对象、时间、状态和一个动作。支持稍后、忽略本次或关闭同类提示。

### 8.2 交互方式

所有当前异常和教师业务待办进入清晰队列。点击 AI 动作仍直接进入对话；业务导航直接打开 ClassIn 对象。AI 补问、待审阅和失败留在对应对话中；完成状态可以进入“已核对”，但不计未处理数量。

### 8.3 优点

- 多事项和积压状态最容易扫描；
- 适合处理大量业务异常和稍后查看的事项；
- 计数、筛选与稳定排序最清楚；
- 与 Linear Inbox、Triage 和 Slack Catch up 的分诊模式接近。

### 8.4 风险

- 最容易把简单 Copilot 做成任务管理产品；
- 自由对话和内容生成会显得像队列详情；
- “稍后、忽略、筛选”等控制过多时，会重现用户已否定的复杂操作。

### 8.5 适用情形

本阶段不采用。若未来另行设计未绑定具体聊天的跨班工作台，可以重新评估；当前两个 IM 入口都以已经选中的聊天为范围。

## 9. 方案 E：当前教学现场 + 轻量分层（已选基础方向）

### 9.1 信息序列

```text
仅你可见 · 当前聊天
教学动态展开：课前 / 课中 / 课后 / 总结
当前阶段完整显示，当前重点作为阶段内强调行
其他阶段显示一行摘要与“另外 N 项”
教学动态紧凑：教学动态｜课中 1｜课后 2
完整对话与产物
自由输入 · 教学协作
```

这里没有永久主卡，也不把阶段做成四张大卡。页面根据内容量切换：

- 没有可行动事项：在相应阶段显示仍有判断价值的闭环确认，再给少量自然语言示例；
- 只有一项高相关机会：在当前阶段内直接强调，不再复制独立重点卡；
- 有两到四个事项：当前阶段完整显示，其他阶段各保留一行摘要；
- 事项较多：其他阶段显示首项及“另外 N 项”，在原位置展开，不进入新页面；
- 正在上课且机会马上失效时：当前课堂事项优先；
- AI 需要教师补充、审阅或恢复时：由对话末尾和会话列表提示承接，不插入教学动态。

### 9.2 交互方式

具体动作直接开始对话。阶段标题或“另外 N 项”只负责原位展开，不提交任务；具体事项行才承载动作。老师开始沟通并定位到新消息后，整个教学动态可以收为一行。紧凑摘要点击后原位展开；展开和收起不改变事项或 AI 状态。业务事实更新时，紧凑摘要只更新计数和必要提示，不强制展开。AI 的生成、审阅或发送状态继续留在对话中。

### 9.3 优点

- 保留方案 A 的对话感，同时用方案 C 的业务阶段建立清楚秩序；
- 可以明确表达闭环确认，又不让它和紧急事项争抢注意力；
- 不需要二级页面、返回或必经选择；
- AI 过程自然留在对话中，不需要额外任务中心；
- 能适应零事项、一项、多项和返回原对话后的不同密度。

### 9.4 风险

- 自适应规则必须稳定，否则摘要和重点会频繁跳动；
- 当前重点必须直接成为阶段内强调行，不能再长成独立顶部区域；
- 阶段列表的最大高度和较窄窗口行为需要在开发阶段用真实数据验证。

### 9.5 适用情形

当前产品既要维持简单对话体验，又必须承载多课程状态、闭环确认和跨聊天对话连续性。

## 10. 同一教学现场下的五种投影

统一测试场景：当前班级数学课已开始 10 分钟，3 人尚未进入；上一节物理课应到者全部进入；函数作业 32/32 已提交，但仍有 12 份待批；同一 TeachBuddy 对话里另有一份提醒草稿等待老师确认。

| 方案 | 老师首先看到什么 | 闭环确认在哪里 | 提醒草稿怎样继续 |
| --- | --- | --- | --- |
| A 对话优先 | “3 人尚未进入”及“准备提醒” | 建议下方一行“物理课应到者均已进入” | 回到对话末尾直接审阅 |

无论哪种方案，函数作业在全局只算一个需关注的业务事项；“学生全部提交”和“教师仍需批改”同时成立。

## 12. 已选方向：方案 E + 可收起的业务阶段二级列表

用户已经确认以方案 E“当前教学现场 + 轻量分层”作为具体聊天的主方向，并进一步用 Notion 参考图与手绘稿明确：教学事项按业务阶段组织成二级列表。最新修订取消独立的顶部重点区，把当前重点直接放进当前阶段，并允许整个教学动态在进入对话后收成一行。最终组合不是完整时间轴，也不是四张大卡，而是：

- 方案 E 负责轻量密度、展开与紧凑切换及对话中心；
- 方案 C 只贡献 `课前 / 课中 / 课后 / 总结`的业务阶段骨架；
- 方案 B 贡献“需关注、我需处理、已核对”的信息语义；
- 方案 A 贡献首次进入的三个以内情境提示和持续可见的自由输入；
- 方案 D 不进入当前范围，因为从消息聚合入口进入后也一定已经选中一个默认聊天，不存在无聊天的综合 Copilot 首页。

一级阶段帮助老师建立教学心智，二级事项负责表达具体事实和动作。当前阶段获得清楚但克制的强调，最重要事项直接作为该阶段的强调行；阶段内先显示马上失效的事项，再显示临近时间边界、必要准备、课后跟进和闭环确认。已经发起的 AI 协作不参与这套业务排序，它停留在原对话中。

### 12.1 页面信息骨架

```text
仅你可见 · 当前班级群 / 学生私聊
首次角色说明 + 最多 3 条情境提示（仅首次或无历史时）

教学动态 · 展开
课前
  ├─ 一行阶段摘要
  └─ 另外 N 项
课中 · 当前
  ├─ 当前重点强调行 · 一个动作或闭环事实
  └─ 其他具体课程 / 课次 / 到课事实
课后
  ├─ 一行阶段摘要
  └─ 另外 N 项
总结
  ├─ 一行阶段摘要
  └─ 另外 N 项

教学动态 · 紧凑
教学动态｜课中 1｜课后 2

原对话与产物
自由输入 · 教学协作
```

“课前、课中、课后、总结”是一级业务阶段，“具体课程与业务对象”是二级事项。展开与紧凑是同一模块的本地呈现状态。页面不再增加课程选择层、任务详情层或 AI 运行层；同班多课程直接在二级事项中显示课程名称。

### 12.2 展示和展开规则

- 老师第一次进入且尚未开始沟通时，教学动态默认展开；
- 当前阶段默认完整展示有效事项，并用阶段标题旁的 `当前`标识帮助定位，最重要事项作为阶段内强调行；
- 其他阶段有有效事项或闭环事实时显示一行摘要；存在更多事项时显示“另外 N 项”，点击后在原位置展开；
- 老师进入对话并定位到新消息后，教学动态可以收成 `教学动态｜课中 1｜课后 2`一行；点击摘要在原位置展开；
- 展开和收起不改变事项数量、业务状态或 AI 任务状态；
- 紧凑状态下业务事实更新只更新摘要和必要提示，不强制展开打断老师；
- 没有数据、没有有效事项且没有闭环事实的阶段不制造空卡；首次引导中仍可用一句话说明 TeachBuddy 支持该阶段；
- 阶段之间使用留白、短引导线或轻量节点建立树状关系，不使用物流式“步骤 1–4 已完成”进度表达；
- 当前重点就是当前阶段中的一条二级事项强调行，不能复制成独立顶部区域。

### 12.3 业务事实决定出现和退出

- 入课提醒只在具体课次的有效入课窗口出现；课堂结束后直接消失，不要求老师确认“已处理”；
- 课中尚未进入提醒只在课堂仍进行且名单可信时出现；课堂结束后直接消失；
- 作业催交只在截止时间之前且仍有未交学生时出现；到达截止时间后直接消失，不再提示学生交作业；
- 全员已到、全部提交、计划已同步等闭环确认只在当前判断仍有价值且数据完整、及时、范围明确时出现；它们没有确认按钮，也不需要老师回执；
- 业务窗口结束不显示“已过期”卡。若后续阶段存在新的业务事实，例如待批改或可生成课堂回顾，应作为该阶段的新事项出现。

### 12.4 对 Notion 参考图的理解

| 参考 | 理解到的结构价值 | 在 TeachBuddy 中怎样使用 |
| --- | --- | --- |
| 支付宝 AI 首页 | 三条低门槛提示让首次用户马上开口；完整技能另有入口 | 首次进入最多给三条当前教学提示，完整能力收进 `教学协作`，不照搬移动端全屏技能页 |
| 例 1 时间线 | 粗标题、节点和连线能快速建立阶段顺序 | 只借阶段节奏和视觉锚点，不把教学事项表达成物流进度或完成步骤 |
| 例 2 自动流程列表 | 父级主题下缩进排列二级事项，信息密度高但仍清楚 | 借缩进、对齐和就地详情；不展示自动化编号、等待时长或 AI 运行步骤 |
| 例 3 树状清单 | 一个父级下面列多个可扫视子项，层级最接近手绘稿 | 作为一级阶段与二级教学事项的主要结构参考，但不增加勾选和人工维护负担 |
| 例 4 彩色标签 | 小面积颜色可帮助识别不同语义 | 蓝色表示当前阶段或普通信息，琥珀表示有时效的关注，绿色表示有证据的闭环；颜色不表达 AI 生成状态 |

## 13. 已选方案的 UI 信息规则

### 13.1 当前阶段强调行

- 只在当前阶段内强调一个最值得此刻知道或发起的事实，并只带一个直接动作；
- 标题使用教学结果，例如“3 人尚未进入课堂”，不使用能力名称；
- 第二行显示课程、课次和时间，避免老师猜范围；
- 闭环时用事实替代动作，例如“本节应到 30 人均已进入，另有 2 人请假”。

### 13.2 教学动态紧凑摘要

- 形式为一行，例如 `教学动态｜课中 1｜课后 2`；
- 只显示非零且有判断价值的阶段计数，闭环事实不计入数字；
- 业务事实更新时刷新数字并可增加短提示 `有新动态`，不自动展开；
- 点击摘要只在原位置展开，不进入二级页面；
- 展开与收起不影响业务、事项、对话和 AI 状态。

### 13.3 阶段标题与计数

- 一级标题固定使用 `课前 / 课中 / 课后 / 总结`，当前业务阶段附加低强调的 `当前`标识；
- 阶段存在多项可行动内容时，可以显示该阶段的可处理数；只有一项时直接显示事实，不额外显示数字；
- 数字角标只表示该阶段内仍可处理的业务事项。只有确有时效或风险时才使用红色，不把闭环确认计入红点；
- `需关注`、`我需处理`和`已核对`作为具体事项行的语义，不再另建一组并列分类或 Tab；
- 同一个作业可以同时表达学生未交和教师待批，但全局业务事项数仍按作业对象去重，不能把影响人数相加成事项数；
- 数字必须能回到可见的具体事项，不显示没有语义的总数字。

### 13.4 紧凑事项行

- 第一行：事实或结果；
- 第二行：课程、业务对象、时间或影响范围；
- 右侧只保留一个当前主要动作；
- 需要“稍后”或“忽略”时进入低强调更多操作，不与主要动作并排；
- 学生个人状态默认进入 1v1 待审路径，不在班级群公开。

### 13.5 对话与产物状态

- 所有状态都贴着对应的老师消息、AI 回复、产物或回执，不显示在教学动态中；
- `正在生成课堂回顾`只在对应 AI 消息中、且 Runtime 确实运行时显示；
- `还需选择一份作业`由 AI 在对话末尾直接提问，老师原地回答；
- `3 份提醒待确认`作为对话中的产物组逐份核对；
- `对象有变化，请重新确认`更新原产物，不创建第二条教学事项；
- `发送部分失败`只在执行回执中提供失败对象重试；
- `结果可回看`不等于已发送或教学结果已达成。

### 13.6 自由输入与能力入口

- 自由输入始终占据底部主要位置，老师无需打开能力目录才能提问；
- `教学协作`作为输入区旁的紧凑入口，承接完整能力发现，不在初始面铺开四张永久大卡；
- 打开后按课前、课中、课后、总结或教师任务语言分组，不展示 Agent、Skill 或模型；
- 有具体业务对象的能力显示事实与可处理数量；只有一般能力时只显示名称和一句结果说明，不制造红点；
- 选择后对象唯一则直接进入同一对话，对象有真实歧义时由 AI 在对话里补问，不打开配置页。

### 13.7 首次进入

- 用一句话说明 TeachBuddy 能结合当前教学现场准备提醒、回顾、讲解和总结；
- 同时给出“点击当前建议”与“直接说要求”两种起步方式；
- 第一次有效协作后，欢迎说明让位给当前事实、闭环确认和自然对话；
- 老师随时可以从 `教学协作`重新查看能力范围。

## 14. 用户审阅结论与下一步

用户已经确认以下四项结论：

1. 具体聊天采用方案 E，并与按业务阶段组织的二级列表合并；
2. 机会退出和闭环事实均由课程、课堂、作业等业务事实及有效窗口自动决定，不要求教师回执或额外确认；
3. 从班级页面或消息聚合入口进入时，都已经有一个默认聊天被选中，本阶段不设计无聊天状态下的跨班 Copilot 总览。
4. 取消独立顶部重点区；当前重点直接作为当前阶段强调行。教学动态在进入对话后可以收成一行，业务更新不强制自动展开。

本轮锁定的是信息架构方向，不是视觉稿。修订后的页面区域、二级事项字段、教学动态展开与紧凑、阶段显隐与排序、一键进入对话、首次进入、数据未知、对象变化、跨聊天恢复、较窄窗口及关键文案已经进入[初始面详细交互设计](./COPILOT-INITIAL-SURFACE-DETAILED-DESIGN.md)。前端页面、视觉稿和交互实现继续留在后续开发阶段。
