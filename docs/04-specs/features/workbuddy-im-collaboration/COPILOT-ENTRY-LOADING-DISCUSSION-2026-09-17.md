# IM Copilot 进入加载与快捷提问交互讨论稿

最新用户反馈已实施（EL-T11～EL-T12）：删除三问交接的临时提示/高亮，保留普通帮助入口；总结删除活动数量/完整性卡；课中无当前课堂只显示说明，有课堂但考勤不足仍为未知。下方此前批准的 Toast/高亮已被本次撤销，渐变与每小时更新继续有效。

2026-09-17 用户已批准并授权四项增量：输入框方案 A（“问问班级、课程和作业，或让我帮您写消息…”）；推荐进入时读取、成功后一小时刷新、后台暂停；推荐先渐显并调整高度，再收起三问、短暂提示“可以问什么”；顶部数量与操作说明合为一行。实现与验证完成，当前唯一合同为[实施合同](./COPILOT-ENTRY-LOADING-IMPLEMENTATION.md) EL-T8～EL-T10，结果见[验收记录](./COPILOT-ENTRY-LOADING-ACCEPTANCE-2026-09-17.md)。

此前确认的历史默认收起时可展示三问、展开历史/开始新对话后退出、悬停及键盘保护继续有效。下方保留早期讨论过程，其中“仍待确认”和旧实现事实均是历史阶段描述，不覆盖上述批准结论。

## 范围与依据

用户要求先讨论设计，确认后再修改。目标是删除截图中导航下方的常驻环境说明，为顶部推荐加载提供明确动效，并在推荐准备期间呈现三个可先提问的问题。本轮仅记录候选方案，不修改应用、业务 Adapter、运行配置或既有验收结论。

基于[当前阶段导航方案](./COPILOT-STAGE-NAV-ALTERNATIVE-DESIGN.md)、[通用提问详细设计](./COPILOT-GENERAL-QUESTION-GUIDANCE-DETAILED-DESIGN.md)和当前代码核对。旧规则要求“真正无历史且上下文已就绪”才显示首次引导；本次拟解开与推荐加载的等待关系，不重置历史或创建新 Session。用户对有历史时叠加三问保留意见，该条件仍待讨论或视觉评审，不能作为已批准行为实施。

## 最新用户反馈

已确认：三个问题从已审阅的 21 类问题中选取；推荐返回不换题；新一轮问题被成功接收后收起三问；保留“可以问什么”；推荐失败提供重试且保留提问入口和输入；更新不抢焦点、不自动展开、不打断阅读。

用户补充方向：持续失败可采用特殊的顶部简洁状态。具体状态样式见下方候选方案。

仍待确认：有历史信息时是否出现三问。用户担心与历史叠放导致混乱；不将这条保留意见解释为同意实施。建议先评估“无历史展示三问、有历史优先延续对话”的保守方案，后续如预览再发现空白区域的问题，另行讨论。

## 当前实现事实

- [TeachingDynamics](../../../../src/features/workbuddy-im-assistance/TeachingDynamics.tsx) 只有展开内容内的一句加载文字；折叠时标题显示“消息建议暂未就绪”，缺少加载动效。
- [ImSidecarAgentSurface](../../../../src/features/workbuddy-im-assistance/ImSidecarAgentSurface.tsx) 已分别发起教学动态和问题目录请求，但首次引导依赖目录返回且无旧历史。普通输入的可提交判断不直接依赖教学动态加载。
- 红框说明由 `services.deliveryNotice` 在对话区顶部呈现。删除这一行是显示层范围；本次不改变发送 Adapter 的实际能力或既有回执行为。

## 建议方案

### 1. 删除环境说明行

删除“真实业务数据 · 消息发送仅老师端本机模拟 · 学生端不接收”整行及其专用占位间距，让下面内容上移。截图中“实时出勤尚未接入”属于具体业务能力状态，不在这项删除范围。

### 2. 顶部采用局部加载状态

保留现有身份、淡色底和四阶段布局。首次读取时，标题数量位置显示轻量加载标记与“正在整理建议…”。展开时保留四阶段文字和轮廓；数量位置及建议正文使用淡色骨架块和轻微明暗变化。没有结果时不先显示“0 条”“待核”“已核”，不以动画依次点亮阶段来假装业务进展。

状态说明使用“正在整理本班教学建议，您可以先提问”。收起时仍能从标题看出加载状态，不强制展开。读取成功后原位替换为实际数量与内容；空结果显示真实空态；失败停止动画并提供“建议暂时未能加载，重试”。用户开启减少动态效果时改为静态占位加文字。

后台刷新已有结果时保留当前内容，只显示轻量“更新中”；更新失败保留旧内容并说明尚未更新，不把旧结果当成最新事实。首次加载和后台刷新采用不同呈现，避免周期刷新引起整个面板闪烁。长时间未完成时说明“读取时间较长，您可以先提问”，不能无限播放却不给错误恢复。

持续失败的候选样式：首次加载始终没有可用结果，且有限重试仍失败时，停止骨架动效，顶部收敛为身份、状态和重试的一块紧凑区域，例如“AI 消息助手｜教学建议暂不可用 [重试]”，下方小字“您仍可直接提问”。不保留四个空阶段或无限加载占位。推荐恢复只更新信息，不抢焦点或强制展开。若已有有效旧结果，则沿用上方“保留旧内容并标明更新失败”的规则。推荐失效与整个助手连接失效分开表达，后一种仍应显示实际连接状态。

### 3. 推荐下方立即呈现三个通用问法

在满足引导出现条件的空白对话区，导航下方显示轻量问题行；有历史的出现条件仍待确认。初始三题可选用已审阅清单中的 A1、A2、A3：

```text
您可以先问
1  我们班有哪些课程，分别学到哪了？       ↗
2  接下来要上什么课，什么时候上？         ↗
3  我们班有多少学生？                     ↗
```

三个问题从已审阅的 21 类问题清单中选择，复用稳定 questionId 和现有内容源，不另建一套新问题。冷启动优先选已经支持、无需先定位具体作业或学生的班级级问法；已具备可靠对象时才考虑具体对象问题，不能为选题额外等待完整推荐目录。它们是提问模板，不携带预造业务事实。当前班级身份明确后即可发起相应真实查询，无需等待教学建议全部返回。若基础身份或模型连接仍在恢复，可先浏览、点选填入输入框，待就绪后手动发送，不悄悄排队自动提交。

问题行直接复用当前提问交互：空闲且输入为空时一步提问；已有输入、附件、引用或待审草稿时加入输入框并保护原内容；生成中可准备下一问；避免连续点击重复提交。不把点击问题解释为向班级群发送消息。

本次进入期间固定选定的三条，不因推荐返回而突然换题或改变顺序。未来可利用当前班级的有效目录选择更多样的问题，但刷新或旧班缓存不能带入错误对象。原“可以问什么”入口继续负责更完整的问题库。

已经确认的退出行为：第一次新问题成功接收后退出问题行，将空间交给对话；校验失败则保留问题和反馈。引导不插入持久消息历史。

有历史的候选方案（待确认）：已有历史时优先呈现原对话与“可以问什么”，不默认插入三问，也不因为旧历史在 UI 中被折叠就当成新会话。正在恢复显示中的未完成回合或已有活跃生成时，不在回复中间插入引导。如需比较历史场景的其他布局，只做明确标注的视觉评审，不静默改变正式行为。

## 两条独立的加载路径

顶部路径读取并组织推荐；提问路径按当前问题获取真实证据并回答。两者共享授权范围和已有读取服务，但提问不应等待完整推荐或问题目录返回。推荐失败不能单独锁住输入；若具体问题也遇到连接、权限或数据问题，则在该问题的正常流程反馈。开始提问后顶部继续加载，完成时不抢焦点、切阶段、展开面板或改变对话滚动位置。

这项交互优化可以在现有 Agent 架构内完成，不以此前讨论中的 Skill 迁移为前置条件。

## 讨论通过后的验收重点

1. 红框说明和空白占位消失；两个 IM Copilot 入口表现一致。
2. 人为延迟推荐请求时，展开与折叠都能识别加载状态；符合最终引导出现条件时，三个问题可见且不依赖推荐返回，并全部来自已审阅清单。
3. 问题提交走独立取数路径，原输入/附件/引用/草稿不丢失；重复点击不重复执行。
4. 推荐返回、刷新、为空、失败与重试都有准确状态；持续失败退出骨架并采用明确恢复入口；无模拟任务、假数量或假进度。
5. 旧历史、恢复、跨班切换及晚返回请求不导致错误引导或串班；不新建无必要 Session。
6. 推荐更新不打断提问、不夺焦点、不推动正在阅读的消息；输入框与停止按钮始终可达。
7. 骨架与实际布局尺寸接近，窄侧栏无溢出；键盘、状态播报及减少动态效果可用。

“已审阅问题中选择三题、保持稳定、开始交流后收起、保留提问入口、失败恢复与不打断阅读”已经得到用户确认。历史场景仍保留待确认，持续失败的具体顶部样式为候选方案；本轮未授权开始应用修改。设计收敛后按 PRD → Spec → Tickets 落实施工范围，再进入代码和浏览器验证。
