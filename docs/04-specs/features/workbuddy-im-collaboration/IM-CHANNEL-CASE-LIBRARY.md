# WorkBuddy 与班级 Agent 三渠道 Case Library

## 1. 使用边界

本库先回答“任务应该进入哪条渠道”，不把 Case 名单解释为已实现能力。M4.2 锁定 `WB-01 / WB-02 / WB-06 / PA-01 / DA-01`；其余条目均为 `[未来]`，必须经过独立 Spec、Ticket 和验收后才能改变状态。

渠道选择规则：

- 教师私密 WorkBuddy：跨业务对象编排、产生 Artifact 或 ClassIn 副作用、需要教师审批；
- 群内公开班级 Agent：问题和答案适合全班看见，且只在显式结构化 `@Agent` 后响应；
- 教师/学生 Agent 私聊：课程范围内的个别辅导或教师专业协作，不应自动暴露给群成员；教师与学生线程互相隔离。

## 2. 优先级

- `P0`：下一阶段候选，能够复用当前 ConversationRun、Context、Artifact、Approval、Receipt 和 Evaluation 骨架；
- `P1`：渠道价值明确，但需要新增领域模型或治理规则；
- `P2`：需要更强的生产事实、长期结果证据或敏感数据治理，暂不进入实现。

## 6. M4.2 锁定矩阵

M4.2 不进入 `WB-03 / M5`。当前五个 Case 共同覆盖：WB-01/WB-02 的业务事实提取与通知生成、WB-06 的格式中立内容创作与跨 Surface 分发、PA-01 的公开即时提示、DA-01 的隔离分步辅导。

PA-01 与 DA-01 不是同一产品 Case：二者共享 `ClassAgentDefinition` 和 `GuidedTutoringModule`，但公开群必须显式 `@`、群成员可见、回答简短且不使用个体私聊事实；私聊无需 `@`、仅参与者可见、允许连续分步追问。两者都不提供最终答案。

`WB-03` 及其 M5 规格继续保留为 `PARKED` 资产，待 M4.5 完成后由独立恢复决策重新排期。
