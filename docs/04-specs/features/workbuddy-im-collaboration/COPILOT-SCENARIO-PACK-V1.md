# IM Copilot 场景数据包与映射交付记录（v1 归档）

本记录保留多课程新增要求之前的交付证据。它不包含同班多课程建模与验收，当前状态见 [v2 记录](./COPILOT-SCENARIO-PACK.md)。

## 1. 交付结论与边界

已将冻结底稿中的同一教师、两个班级转成可重复生成的匿名数据包，并建立 S1 至 S8 的纯时点投影。原始 56 个组成文件在加工前后逐份验证 SHA-256 不变；没有再次访问 DW，没有修改原始文件、数据库时间或系统时钟。

本记录保存 M1 v1 的历史数据证据。它可以帮助新 M2 理解场景演进，但不作为页面方案或开发数据 Gate；也不代表实际 Runtime、正式消息交付、后台任务持久化或生产实时接口已经完成。此处 S7 提供相同时间下的两班业务状态，任务编辑与恢复由消费方维护，不能用数据投影测试代替完整工作现场的验收。

真实采集范围及查询口径继续由[首轮采集记录](../../../01-research/IM-COPILOT-DW-SOURCE-COLLECTION-REPORT.md)拥有；加工原则沿用[DW 派生数据方案](./COPILOT-DW-SCENARIO-DATA-PLAN.md)。本文记录本版实际选择、变换、Interface、场景参数和验证结果。

## 2. 选样与完整口径

从同一教师的近期明细中，筛选同时具有至少两份作业、课次名单和群消息的班级，按已取得作业数量排序，选择两个连贯教学集合。每班保留已采集的全部作业及其完整有效学生记录，不为演示少人数截取前几条。两班锚点课次均由候选教师主讲，九份作业发布教师一致，九份作业均匹配对应教学活动。

| 匿名对象 | 秋季学习一班 A | 秋季学习二班 B |
| --- | ---: | ---: |
| 课次目录 | 14 | 16 |
| 候选教师主讲课次 | 7 | 8 |
| 已取得源作业 | 7 | 2 |
| 完整有效学生作业记录 | 357 | 252 |
| 作业关联学生去重 | 51 | 127 |
| 原始课次名单记录 | 51 | 126 |
| 原始到课记录 | 45 | 114 |
| 教学活动 | 94 | 154 |
| 单元 | 20 | 20 |
| 群消息 | 2 | 2 |

共保留 **30 条课次、9 份源作业、609 条学生作业记录、178 个作业关联学生、248 条活动、40 个单元、177 条名单、159 条到课记录和 4 条消息的匿名结构/语义改写**。两班的作业关联学生集合在本次源范围内无重叠。

“完整”指所选作业关联集合及已经采集的对应教学明细，不是已核实全班群成员。源 `course.student_num` 两班都为 2000，字段业务语义尚未独立确认；仅保留在内部 `sourceCounts.courseStudentNum`，不将它作为真实班额、应到人数或 UI 群头人数。课次名单与到课记录有差异，也不能通过相减推出真实缺勤。

A 使用其完整 51 人的第一份作业作为首条提醒锚点；B 使用完整 127 人的较早一份作业作为切群后的独立事项。B 的第二份源作业仍完整保留其 125 人名单，不能将两份作业的去重 127 人视为每一份作业都指派了 127 人。

## 3. 稳定身份与业务结构

| 实体 | 仓库内映射 | 原始对应关系 |
| --- | --- | --- |
| 教师 | `copilot-teacher-a`，页面化名王老师 | 机构、教师 UID 与教师关系标识仅留本机私有记录 |
| 其他主讲教师 | 每个不同源标识有独立 `copilot-co-teacher-*` | 不把所有非候选教师合并成同一人 |
| 班级与班级群 | `copilot-class-a/b`、对应 `*-group` | 课程业务对象映射为现有 IM 班级语义，不添加虚构课程层级 |
| 学生 | `copilot-student-001` 等，显示学员001等 | 同一源学生稳定映射；排序可复现，原标识不进入仓库 |
| 模拟私聊 | 对应 `copilot-private-*` | 真实联系人关系未查证，此关联明确为模拟 |
| 课次与作业 | 班级内独立稳定标识 | 目录、指派名单、源末态计数保持对应 |
| 单元与活动 | 班级内稳定标识，保留可核对的对象引用 | 分类名称缺失保持 `null`，不猜测课程分类名称 |
| 源名单/到课参与人 | 学生稳定引用或独立匿名参与人引用 | 不把名单外到课者强行归入作业学生集合 |

原始身份映射及变换记录位于本机 `.runtime/private/copilot-derived-2026-09-09-v1/identity-map-and-transform.json`，目录权限 700、文件权限 600，受现有 `.runtime/` 忽略规则保护。无需添加新的忽略模式。冻结原始区保持不变。

源标题没有足够证据确认阅读、写作、数学或其他具体学科主题；本版保守改写为“阶段学习”“阶段巩固练习”。不从排课名推导具体知识点。源消息只按可检测的宽泛主题改写，不复制姓名、链接、数字、日期或引文；附件正文与定位链接不进入导出。具体教学内容保真度仍受课堂正文和附件缺失限制。

## 5. 时间、事件与真值

全部所选源目录时间使用同一偏移 **1,038,600 秒**，将 A 的原课堂安排平移到场景 2026-09-15 19:00（北京时间）。B 的关联课堂保持四天之后的关系，成为 2026-09-19 19:00；切换聊天不将两班排成同一教师同时开课，也不重置“现在”。

源目录中的课次/作业末态保留在 `source-inventory.json`，绝不把其中的最终提交人数提前放入较早的 Agent 上下文。`pack.json` 的模拟过程另行拥有实际开课、结束、请假、进入、发布、提交、批改和回执时间。固定数据中共 **640 条模拟事件**；原始末态并未被倒推成所谓真实事件日志。

| 处理 | 本版事实与标记 |
| --- | --- |
| 源课堂安排 | `dw-time-shifted`；只说明排课，实际开课必须另有可见事件 |
| 应到集合 | 使用各班完整作业关联集合构造，标记 `simulated-roster-from-homework-associations`，不冒充真实应到 |
| 请假与进入 | 每班一名请假；开课十分钟剩三人未进入，十二分钟一人进入，十五分钟余下两人进入；全部 `simulated-event` |
| A 当前作业 | 指派名单来自真实完整 51 人关联；发布/截止/提交/批改时间独立模拟；与本讲关联为 `simulated-link` |
| B 当前作业 | 采用完整 127 人较早作业；与当前后续课次关系保留未知，不写“本讲作业” |
| A 历史待批 | 为课前次要入口新增一份明确模拟作业，完整模拟 51 人已交、一份待批；不计入九份源作业 |
| 课堂回顾 | 每班两条模拟历史课堂、各一份显式固定模拟材料；只有材料与可用事件均已可见才计数；不宣称获得真实课堂正文 |
| 消息与交付 | 原消息改写日期随统一偏移；另有模拟提醒已发事件。已发不等于已读、提交或完成批改 |
| 失败与权限 | `unknown / denied / retryable` 返回不可用状态及 `null`，不返回假 0；成功恢复通过重新投影当前时点完成 |

模拟回顾材料只支撑入口与资料可用性检查，并带内部 `simulated-material` 来源。M7 仍需独立验证课堂回顾内容、个人证据及生成质量。正常教师 UI 按 D-109 不展示技术真值文案；内部 evidence 和 Agent 数据中的来源字段保留，不能在接入时删除或宣称为真实课堂转写。

## 7. 消费 Interface 与计数

```ts
projectCopilotScenario('S5', {
  classId: 'copilot-class-a',
  // at 可省略以恢复该检查点；切群传入同一个 now。
  // failure: 'unknown' | 'denied' | 'retryable'
  // consumedActionIds 只消耗对应动作，不消耗整个作业。
})
```

返回 `CopilotScenarioView`：

- `classes / classRoom / students`：匿名当前班级及相关人员；`membershipStatus` 始终明确群成员未核实。
- `lesson / homework / publishedHomeworks`：当前课次、当前主作业及本时点全部已发布场景作业。消费副卡时按 `targetHomeworkId` 找真实场景对象，不能直接套用主作业标题或截止。
- `attendance / submission`：供界面和 Agent 共用的当前名单，未交、待批、已批分开；不可用时名单/分母为 `null`。
- `opportunities.main / secondary`：完整动作对象，包括稳定 action ID、按钮文案、自然语言请求、目标名单和交付渠道。教师待批动作为“查看待批改名单”，其 `prompt` 为 `null`，本批不伪造批改页面已接入。
- `visibleEvents / recapMaterials / messages`：只包含当前时点可见的证据；完整包和源 inventory 不进入自动上下文。
- `agentContext`：与界面同一时点、同一业务对象和名单；不含其他班级正文或未来事件。

主卡优先级在本版为“课中未进入 → 临近截止 → 刚发布作业 → 即将开课”。次要入口按仍有动作的业务对象去重计数：回顾按课次，作业按作业。主卡消耗一个催交动作后，同作业的待批改动作仍存在，因此作业角标仍可为1；不将未交人数4和待批人数1相加为角标5。已启动动作通过 `consumedActionIds` 隐藏，原始业务事实不被改写。

投影返回独立副本，消费方编辑输出不污染下一次重置。消费方仍需在插入和发送前使用最新时点复核同一 action ID 的当前对象；此函数不拥有教师审批、运行任务、草稿保存或业务写回。

## 8. 缺口处理与后续归属

| 缺口 | 本版处理 | 后续 |
| --- | --- | --- |
| 全量群成员、私聊可达性未核实 | 群成员未知；私聊采用明确模拟映射 | M4 消费模拟目的地并覆盖不可达；生产关系另行接入 |
| 源名单与到课不一致、缺请假 | 原始匿名快照完整保留；不推断缺勤；独立模拟应到与事件 | M5 动态复核；真实实时口径须依赖ClassIn来源 |
| 源提交/批改末态不等于过程 | 完整末态另存；场景过程全部注明模拟 | M4/M5 只消费时点投影 |
| 作业与本讲关联未证实 | A 明确模拟，B 保持未知 | 不能让自由提问编出未证明的“本讲作业” |
| 源课堂正文、附件、分类名称缺失 | 标记缺失；回顾入口只使用独立模拟材料；分类名null | M7至M9按功能所需补充证据，不据此宣称内容生成通过 |
| 历史消息改写较泛 | 只保留宽泛教学语义与时间，不复制真实身份/链接 | 具体消息个性化在有足够内容证据时再深化 |
| 源表查询不是原子快照 | 保留来源说明 | 不宣称生产一致性或零延迟 |
