# 班级 AI 消息助手：通用提问内容与交互设计清单

## 1. 本轮审阅目标

老师看见顶部推荐后，知道“现在值得做什么”；离开这些推荐，仍应知道“围绕这个班级，我还可以问什么”。本清单先定义内容与回答边界，再供下一步页面结构设计使用。

**已达成共识**：顶部四阶段导航是按业务现场推荐的重要、典型话题；通用引导介绍开放提问范围。二者进入同一段对话、使用同一套授权上下文，内容允许交集。五组是便于老师理解的主题分类，不是五个内部 Agent、固定任务或问题白名单。

**本稿待审阅**：各组问法、回答深度、首屏示例与页面承载方式。本轮只交付设计文档和数据证据；不改页面、模型、接口接入或两项目运行端口。原版物理模拟数据继续保持。

## 2. 先明确“AI知道什么”

业务范围按“当前教师 → 当前班级 → 班内课程 → 单元/教学活动 → 被分配学生与结果”组织。课程和班级不能混用；同班可有多门课程，同一学生在不同课程和活动中的情况独立。

| 主题 | 老师可理解的信息范围 | 回答前必须具备的依据 |
| --- | --- | --- |
| 班级和课程 | 班里有哪些学生、有哪些课程、课程安排、当前进度、后续学习内容 | 在班与成员身份、课程目录、单元和排课；讲数与实际完成状态分别确认 |
| 课堂和学习参与 | 课堂活动、到课、互动、录播观看、学习资料分配和完成情况 | 按课次或活动取得结果；分配名单不是参与记录，课后报告不是实时考勤 |
| 作业和测验 | 作业要求、截止日期、提交与批阅、学生答卷、试题与解析、共性错题 | 作业/测验原文、适用学生、有效提交、批阅口径；正确率需真实作答与统计分母 |
| 某位学生 | 该生在本班课程中的任务、课堂与学习表现、已有进展和可改善之处 | 学生身份与课程关系、明确时间段内的逐项证据；部分记录不能冒充完整画像 |
| 报告和沟通 | 课堂报告、~~教师笔记~~、课程资料、班级阶段总结、~~个别沟通草稿~~ | 报告/资料正文或可引用记录、时间范围和接收对象；生成总结与已有正式报告分清 |

### 本轮实际依据

后续结构核对见[ClassIn教学数据地图与字段字典](../../../01-research/CLASSIN-TEACHING-DATA-MAP-2026-09-15.md)。它新增活动全过程、IM、打卡及学科评测结构和语义差异；下文25条仍是设计候选，不因字段已验证就自动升级为产品已支持的问题。

- [真实测试接口证据](../../../01-research/COPILOT-GENERAL-QUESTIONS-API-EVIDENCE-2026-09-15.md)：重新读取已授权测试账号，取得目标数学课程 54 项活动目录，并抽查五类活动各 2 项详情。包含课程题目、作业文字与图片引用、学生提交文本、课后报告及笔记、录播状态和资料正文。
- [DW 业务样本证据](../../../01-research/COPILOT-GENERAL-QUESTIONS-DW-EVIDENCE-2026-09-15.md)：从另一教师的业务数据核对班级、课程、活动和学习记录关系。与测试 API 是不同样本，分别保留数据窗口和来源。
- 原版固定物理场景：有整体计划、部分课堂/作业、错题与李明个人记录；自由提问仍按关键词挑选有限上下文，并非自动检索全班全部数据。原版的最近消息输入最多 6 条，也不等于已查询全部 IM 历史。

**接口可读不等于原版已可用。** 本稿表内的数据标记说明证据覆盖；没有表示新问题已接入原版，或已通过真实模型对话验收。后续开发需把范围选择、数据读取与同义问法检索接通后再展示相应推荐。

测试接口的课堂和作业内容中有联调构造记录与 AI 生成资料；DW则能提供真实业务使用痕迹。两类数据都能帮助设计问题，但不能据此声称问题的使用频次已被教师调研验证。

DW补查进一步支持四个实际需求：作业原文会说明讲义页码及拍照提交方式；老师需要区分已交与已批；同班不同作业的分配人数并不固定；准备好的活动可能仍是草稿，尚未对学生发布。因此下文保留“怎么交”“交上来的批完了吗”“布置给谁了”“学生看得到吗”等问法，而不只引导笼统的学情分析。课堂学生记录和作业应交记录均按人次统计，不可替代去重在班人数。

## 3. 五组通用问题清单

每组 5 个，共 25 个。它们是供挑选的内容库，**不是在页面同时展开 25 条**。提问示例中的具体课次与学生应由当前班级已知对象替换；尚未明确对象时，AI 在对话中作必要补问。

数据标记：**已有样本**＝本轮读到主要回答依据；**部分依据**＝能回答有限范围，需说明缺失；**需补齐**＝尚不足以作为该场景的主动示例。标记只给设计评审看。

### 审阅填写说明

请在每条问题末尾的“业务数据确认（你标注）”和“补充说明”两列填写。默认“待标注”仅表示尚未审阅；“不确定”表示已审阅但需进一步查证。原有“当前依据”保留实际探查结果，不由业务确认直接覆盖。

| 业务数据确认 | 如何填写补充说明 | 后续处理 |
| --- | --- | --- |
| 完备可获取 | 如已知，注明接口或数据来源、适用范围 | 保留候选，由我核验实际返回与预期回答 |
| 部分可获取 | 写明已有什么、缺什么 | 缩小问题范围或拆分问题，使问法与可取得的数据匹配 |
| 当前没有 | 区分“系统未记录 / 接口尚未开放 / 当前样本没有记录”；原因不清可说明 | 前两类移出首批引导并登记暂缓；样本无记录则按实际班级条件展示，不永久剔除 |
| 不确定 | 写明需要核查的点；不知道接口名称也可以 | 由我继续核查，暂不作为正式推荐 |

“完备可获取”是业务侧确认，不等于已经通过实际回答验证。后续仍需核对数据范围、内容、时效和回答准确性。无需在此填写学生姓名、账号、Token 或带凭据的资源链接。

例如，若只取得课后考勤，可以为 B1 标注“部分可获取”，补充“有课后报告，暂没有实时到课接口”；随后将首批问法收窄为“这节已结束的课，到课情况怎么样？”。这只是填写示例，不代替你的确认。

## 4. 回答深度与通用规则

### 4.1 三种结果，按老师意图提供

| 老师意图 | 默认结果 | 交付动作 |
| --- | --- | --- |
| 查信息：有哪些、什么时候、谁没交 | 直接结论 + 必要列表/时间范围 | 以回答结束；不自动打开消息审阅器 |
| 看内容/做分析：讲了什么、为什么错、怎么改进 | 先说发现，再给依据和具体建议；长内容按需展开 | 可继续追问；需要时由老师要求整理成消息 |
| 写消息：帮我通知、整理一段发给学生 | 清楚的消息草稿，包含必要对象和时间 | 教师审阅、修改、确认发送；真实与模拟交付按现有边界处理 |
注意⚠️：看内容/做分析：讲了什么、为什么错、怎么改进——对以上表格中提到的第二项，看能不能做分析，我们能提炼“讲了什么”。这可以从讲课的视频回放和讲课的逐字稿里面提炼出来。但是“为什么错”和“怎么改进”这部分，我们无法提炼出来。这是给孩子的一些教学指导，这部分我们目前无法支持。



正确率需说明“哪些题、哪些学生、哪次有效作答、按题数还是分值”。未作答不计为答错，未评分不显示0分；统计口径不确定时优先给已知人数与记录，避免虚假精确。

全勤、全部提交等安心反馈仍有价值，但只能在名单、结果和时间范围完整时成立。没有查询结果、接口失败、未生成报告和真实的0分别回答。

### 4.2 默认范围与补问

- “我们班”直接采用当前班级，不要求老师重新选班。——对的，这就是明确的当前大模型的处理上下文。他能够拿到当前班级下边的所有课程、学员的信息，以及教学活动进展的信息和明细
- “这节课/这份作业/他”优先沿用当前对话已明确的对象；顶部当前选中的阶段不是自由提问的范围锁。——如果系统能识别的话，大模型需要反馈出我要处理的是哪节课、哪份作业。如果大模型发现有多节课或多份作业，则需要进行交互式的问答提问，与老师进行确认
- 顶部提醒因结课或截止而退出后，老师仍可查询该课堂或作业的授权历史，例如“昨天截止的作业最后交了多少份”。历史查询不重新生成一个当前待办，也不擅自延长提交期限。——对的，顶部的入口是官方的提示消息和推荐问题。不过，随着业务节点的变化，官方的消息可能会动态增加或消失，但这并不妨碍老师继续提问。
- 初次输入“最近”，建议先使用有数据的近7天范围并在答案中写明日期；请求本周、本单元时按业务周期取数。该默认窗口为本稿建议，尚未实现。——确认
- 多门课确实无法消歧时，只问“您指哪门课？”并可给轻量候选；不串成对象配置表。——确认，对的，需要进一步与老师的交互互动
- 相同名字的学生、课程归属或最终发送目的地有歧义时，先澄清相应对象，不默认跨群发送。——对，有歧义就要澄清，询问老师。
- 只有部分数据时，先回答可确认部分，再说明缺哪一项；系统应先尝试已有授权读取，不把可自动取得的资料反复索要给老师。——对，ai先自己主动查询，不清楚时候主动发起问询，并让老师做选择题决策
- 数据覆盖决定回答边界，不意味着老师不能自由提问。超出当前班级的业务查询说明范围；一般教学解释可以继续回答，并区分教学建议与该班已发生事实。——确认；如果问另一个班级里的问题（不是当前IM班级的），可以明确告知“处理本班信息”避免混淆

## 5. 两条连续对话样例

### 样例一：从交作业情况到教师反馈

1. 老师：“第1讲作业交得怎么样了？”
2. AI：给已交与未交情况；如存在批阅状态冲突就地说明。
3. 老师：“看看学生甲交的内容。”
4. AI：读取该生在这份作业的正式提交；如果过程在图片中，先取得并识别图片；识别失败保留错误，不编造步骤。
5. 老师：“给他写两句反馈。”
6. AI：沿用该生与作业，生成个别反馈草稿；交付到正确对象前按既有机制审阅。

无需老师重新填写课程、作业和学生；也不能把看到一份答卷扩大为全班共性判断。

### 样例二：从资料内容到群消息

1. 老师：“第1讲资料里有哪些学习方法？”
2. AI：根据资料正文提炼绝对值的距离含义、混合运算的符号处理等方法。
3. 老师：“挑一个容易出错的地方举例。”
4. AI：结合原文例题解释，标明这是教学上需要留意的点，而非已观测到全班答错。
5. 老师：“整理成一段发给学生的话。”
6. AI：给短消息草稿；教师确认后进入既有群消息交付流程。
