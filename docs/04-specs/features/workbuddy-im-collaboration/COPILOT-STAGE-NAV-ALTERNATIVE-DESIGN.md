# TeachBuddy 教学阶段导航方案（二）

## 1. 方案目标

把 TeachBuddy 身份、能力说明、`课前 / 课中 / 课后 / 总结`四阶段导航和消息建议合并为一个紧凑的顶部协作面。老师第一眼先理解“这里可以帮我整理要发给学生的消息”，随后直接选择教学环节和具体建议，一次点击把教师可读的要求提交给 AI。

本方案与方案一复用同一个`TeachingDynamicsAdapter`、业务事实、Prompt 动作、Runtime 和消息审阅闭环。方案一继续保留在`codex/copilot-prompt-grid-v1`；本分支只验证合并后的阶段导航承载方式。

## 2. 合并后的页面结构

```text
┌────────────────────────────────────────────────────────┐
│ [头像] TeachBuddy  仅你可见                             │
│ 您好，我会根据当前教学进展，帮您把要发给学生的消息整理好。 │ [收起⌃] [关闭]
├────────────────────────────────────────────────────────┤
│ 选个环节，点一条建议，我马上起草，您确认后发送。          │
│                                                        │
│   (课前)────(课中)────(课后)────(总结)                   │
│   建议1条    建议1条    建议2条    建议2条               │
│                                                        │
│ 高二物理3班 · 动量守恒模型 · 在线课堂                    │
│ 已开课10分钟，3人还未进入课堂              [帮我写提醒]   │
│ 李明、周然、陈晨尚未进入课堂                             │
└────────────────────────────────────────────────────────┘
```

整个区域只使用一组外框、背景和阴影，不再分别设置`TeachBuddy`Header 与`教学动态`卡片，也不再显示`教学动态`这一重复标题。身份、能力说明和教学建议属于同一个产品入口。

四个圆形 Tab 内直接显示`课前 / 课中 / 课后 / 总结`。圆点和连线表达教学阶段位置，不表达 AI 任务步骤。当前业务阶段以绿色轮廓标识，当前选中阶段以绿色实心圆标识。

## 3. 文案与信息规则

展开态固定表达两层含义：

1. 身份与边界：`TeachBuddy · 仅你可见`；
2. 能力与操作：`您好，我会根据当前教学进展，帮您把要发给学生的消息整理好。`以及`选个环节，点一条建议，我马上起草，您确认后发送。`

不使用`一键发送`，因为建议点击后只提交 Prompt 并生成草稿，正式进入群聊或私聊前仍由老师确认。

每个事项依次表达：

1. 班级、课程和业务载体；
2. 当前人数、截止时间或完成事实；
3. 已知学生范围和必要边界；
4. 一个明确动作。

动作使用教师语言，例如`提醒预习`、`帮我写提醒`、`提醒交作业`、`查看错题`、`制作解析`、`生成回顾`和`生成总结`。整行或动作按钮点击一次即把卡片对应的自然语言`teacherRequest`原文提交并显示在当前对话；能力、业务对象、输出格式和必要证据等结构化要求只放入内部上下文，不替换老师可见的 Prompt。信息不足时由 AI 在对话里补问，不进入配置页或对象选择器。

## 4. 切换、收起与滚动

- 首次打开默认选中当前业务阶段；阶段不自动轮播，也不显示播放或暂停控制。
- 老师可点击 Tab 切换阶段；键盘支持左右方向键、Home 和 End。
- 模块进入当前聊天时默认展开。老师可点击右上角`收起`；在对话区域累计向下滚动达到 48px 后也会自动收起。输入框内滚动不触发收起，向上滚动会重置累计值。
- 收起过程用 320ms 的高度、透明度和轻微位移过渡；Reduced Motion 开启时取消动画。
- 收起后身份行继续常驻，并显示当前可用建议摘要，例如`4 项建议`、`当前已核对`或`待核对`。`展开`和箭头组成一个有明确点击范围的控件，与右侧边缘保留间距。
- 点击紧凑行的`展开`只在原位置恢复，不跳页、不出现返回。
- 紧凑状态下业务更新只刷新摘要和必要的`有新动态`提示，不强制展开、不抢走焦点或改变滚动位置。
- Runtime 更新时，只有老师原本位于对话底部或主动提交新要求，页面才跟随最新消息；老师向上查看历史时不得被自动拉回底部。

展开、收起和选中的阶段只是当前聊天的界面呈现状态，不改变事项数量、业务生命周期、AI Run、Artifact、Approval 或消息发送状态。

## 5. 单一连续对话

- Sidecar 是当前 IM 对象对应的一个连续 TeachBuddy 对话，不提供新建 Session、Session 列表、独立历史页或`在 TeachBuddy 中继续`入口。
- 历史就是当前对话时间线；老师向上滚动即可查阅。内部 Runtime Session 因权限恢复等原因轮换时，Sidecar 通过 Binding Trail 按顺序聚合轮换前后的事件，老师仍看到一条连续历史。
- 已保存的 Binding 指向不存在的 Runtime Session 并收到 404 时，Sidecar 透明创建替代 Session 并更新绑定；页面不出现`新建`或 Session 恢复选择。
- AI 的补问、生成、修改、审阅、发送与回执全部留在这条对话中。
- 生成中时，输入框旁显示`停止生成`。老师停止后可继续输入新要求，沿用当前聊天绑定的同一个逻辑对话；停止失败时输入继续锁定，同时保留`停止生成`供老师重试。
- Runtime 可以在恢复故障时更换内部执行实例；Binding Trail 负责保持连续投影，页面不得把内部 Session 概念暴露为教师需要管理的产品对象。

## 6. 业务与 AI 状态边界

Tab 数字只统计当前业务阶段内可发起的建议，不表示 AI 任务数量。事项随课程开始、结束、作业截止和正式回执自然更新。全勤、全部提交等闭环事实只在数据完整且及时的时候出现，并不计入待处理数量。

AI 的运行状态不进入阶段 Tab 或建议卡；生成、停止、失败、待审阅和发送回执继续贴着对话及产物显示。

## 7. 验收重点

- 同一个可访问区域内同时包含 TeachBuddy 身份、仅你可见、能力说明、四阶段 Tab 和当前阶段事项；
- 页面不存在第二个独立`教学动态`标题或嵌套主卡，也不存在新建/历史 Session 入口；
- 四个 Tab 在 Sidecar 默认宽度下完整可见，切换只替换下方内容，不跳页；
- 事项点击一次只提交一次精确 Prompt，并在同一时间线显示卡片自然语言原文；结构化能力/对象/格式要求只进入内部上下文；
- 内部 Runtime Session 轮换前后的事件通过 Binding Trail 聚合成一条可上滑历史；stale 404 Binding 自动替换且不出现新建入口；
- 停止当前生成后，输入框恢复可用，下一条要求继续进入同一逻辑对话；停止失败则输入保持锁定并允许重试停止；
- 向上查看历史不自动收起且不被 Runtime 更新强制滚底；累计向下滚动达到阈值后平滑收起；
- 900×720、1440×900 和最小 384px Sidecar 下无横向溢出、遮挡或不可达操作；
- TypeScript、scoped ESLint、组件测试、Sidecar 集成测试、Chromium 闭环与生产构建通过。
