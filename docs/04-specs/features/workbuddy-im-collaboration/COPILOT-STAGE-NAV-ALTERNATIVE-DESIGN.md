# TeachBuddy 教学阶段导航方案（二）

## 1. 方案目标

把 IM 内的`AI 消息助手`身份、能力说明、`课前 / 课中 / 课后 / 总结`四阶段导航和消息建议合并为一个紧凑的顶部协作面。老师第一眼先理解“这里可以帮我整理要发给学生的消息”，随后直接选择教学环节和具体建议，一次点击把教师可读的要求提交给 AI。独立产品继续使用 TeachBuddy 品牌名。

本方案与方案一复用同一个`TeachingDynamicsAdapter`、业务事实、Prompt 动作、Runtime 和消息审阅闭环。方案一继续保留在`codex/copilot-prompt-grid-v1`；本分支只验证合并后的阶段导航承载方式。

## 2. 合并后的页面结构

```text
┌────────────────────────────────────────────────────────┐
│ [头像] AI 消息助手  4 项建议                     [⌃] │
│ 选环节，点一条建议，AI写消息草稿，您确认后发送       │
│                                                        │
│  (课前)────(课中)────(课后)────(总结)                    │
│   1条        1条        2条        2条                    │
│                                                        │
│ 动量守恒模型 · 在线课堂                                  │
│ 已开课10分钟，3人还未进入课堂              [帮我写提醒]   │
│ 李明、周然、陈晨尚未进入课堂                             │
└────────────────────────────────────────────────────────┘
```

整个区域不再使用悬浮卡片外框。AI 消息助手作为与左侧聊天工作台等高的完整侧栏，由一条全宽固定顶栏、可展开的建议区、连续对话区和底部输入区组成。Sidecar 不再缩高，也不再叠加灰色底板、外边框和阴影；两个工作区只通过既有分栏边界区分。身份、能力说明和教学建议属于同一个产品入口，也不再显示`教学动态`这一重复标题。导航与建议使用统一的浅灰色底，和下方白色消息对话区形成明确分区。

四个圆形 Tab 内直接显示`课前 / 课中 / 课后 / 总结`及简写数量`N条`。圆点和连线表达教学阶段位置，不表达 AI 任务步骤。当前业务阶段以绿色轮廓标识，当前选中阶段以绿色实心圆标识。

建议事项默认使用白色卡面；鼠标悬停和按下分别使用现有中性浅灰 Hover、Selected Token。绿色只承担当前阶段、主要动作和键盘焦点等强语义，避免大面积浅绿 Hover 与灰色导航底争夺层级。

## 3. 文案与信息规则

展开态固定显示`AI 消息助手`身份，名称旁使用业务快照的可操作事项总数，例如`4 项建议`，不再显示`仅你可见`。其下只保留一行能力与操作说明：`选环节，点一条建议，AI写消息草稿，您确认后发送`。老师手动收起导航后，这句说明仍然保留，避免紧凑态失去功能解释。正式消息仍需老师审阅确认后发送，点击建议不会直接发到群聊或私聊。

每个事项依次表达：

1. 课程和业务载体；当前聊天已经明确班级，因此卡片不重复班级名；
2. 当前人数、截止时间或完成事实；
3. 已知学生范围和必要边界；
4. 一个明确动作。

动作使用教师语言，例如`同步计划`、`提醒上课`、`同步任务`、`提醒交作业`、`提醒交测验`、`生成错题卡`、`生成回顾`、`整班总结`和`个人总结`。整行或动作按钮点击一次即把卡片对应的自然语言`teacherRequest`原文提交并显示在当前对话；能力、业务对象、输出格式和必要证据等结构化要求只放入内部上下文，不替换老师可见的 Prompt。信息不足时由 AI 在对话里补问，不进入配置页或对象选择器。

### 3.1 完整提示范围与固定演示快照

物理班演示使用固定时间`2026-08-09 14:40`，把同一班级下不同课程、课次、作业和测验的可用事项投影到四个阶段，供本轮完整视觉评审。每一项都保留独立业务对象引用，不能因为位于同一个班级群就合并进度或完成状态。

| 阶段 | 事实标题 | 补充信息 | 动作 |
| --- | --- | --- | --- |
| 课前 | 3 门课已学 8 讲，还剩 4 讲 | 动量守恒学到碰撞模型；接下来学习电磁感应 | 同步计划 |
| 课前 | 明天 19:00 开课 | 电磁感应在线课堂；准备讲义和预习单 | 提醒上课 |
| 课中 | 已上课 10 分钟，3 人未进入 | 明确尚未进入的学生，语气尊重且不责备 | 提醒上课 |
| 课中 | 已上课 15 分钟，全员到齐 | 30 人已进入，当前无需发送消息 | 无；不计入建议数 |
| 课后 | 本讲安排了 3 份作业、1 次测验 | 已下课；同步任务内容和截止时间 | 同步任务 |
| 课后 | 明天 18:00 截止，6 人未交 | 动量守恒作业 A 组 | 提醒交作业 |
| 课后 | 今晚 21:00 截止，5 人未交 | 动量守恒随堂测验 | 提醒交测验 |
| 课后 | 5 位同学集中答错 7 道题 | 最近两次作业；生成题面与解析双面错题卡 | 生成错题卡 |
| 总结 | 本讲回顾可以发给全班 | 知识点、课堂练习和课后任务 | 生成回顾 |
| 总结 | 可以整理本班阶段学情 | 三门课的进度、共性问题和下一步 | 整班总结 |
| 总结 | 可以整理李明的个人学情 | 课堂表现、作业情况和下一步建议 | 个人总结 |

这些内容是基于课程、课次、作业、测验和学生事实生成的同步消息建议。建议卡不保存“老师已处理”状态；课程开始、课程结束和截止时间等业务事实变化后，相关事项自然出现或消失。满勤等闭环事实只提供确信感，固定显示`无需处理`，不要求老师回执。

## 4. 切换、收起与滚动

- 首次打开默认选中当前业务阶段；阶段不自动轮播，也不显示播放或暂停控制。
- 老师可点击 Tab 切换阶段；键盘支持左右方向键、Home 和 End。
- 模块进入当前聊天时默认展开，只响应老师手动点击右上角箭头；滚动 Copilot 对话不会改变展开状态。
- 收起过程用 320ms 的高度、透明度和轻微位移过渡；Reduced Motion 开启时取消动画。
- 收起后身份行、当前可用建议摘要和引导文案继续常驻，例如`AI 消息助手 · 4 项建议`及`选环节，点一条建议，AI写消息草稿，您确认后发送`。右上角只显示箭头图标，按钮仍保留完整点击范围和无障碍名称。
- AI 消息助手顶栏是 Sidecar 的独立首行，宽度与 Sidecar 一致，不进入对话滚动容器。顶栏使用不透明背景，历史消息不会从上下或两侧露出；展开和收起只通过高度、透明度、轻微位移及背景色变化表达，不再增加边框和悬浮阴影。
- 点击紧凑行的箭头只在原位置恢复，不跳页、不出现返回。
- 紧凑状态下业务更新只刷新摘要和必要的`有新动态`提示，不强制展开、不抢走焦点或改变滚动位置。
- Runtime 更新时，只有老师原本位于对话底部或主动提交新要求，页面才跟随最新消息；老师向上查看历史时不得被自动拉回底部。

展开、收起和选中的阶段只是当前聊天的界面呈现状态，不改变事项数量、业务生命周期、AI Run、Artifact、Approval 或消息发送状态。

## 5. 单一连续对话

- Sidecar 是当前 IM 对象对应的一个连续 TeachBuddy 对话，不提供新建 Session、Session 列表、独立历史页或`在 TeachBuddy 中继续`入口。
- 历史就是当前对话时间线；老师向上滚动即可查阅。内部 Runtime Session 因权限恢复等原因轮换时，Sidecar 通过 Binding Trail 按顺序聚合轮换前后的事件，老师仍看到一条连续历史。
- 已保存的 Binding 指向不存在的 Runtime Session 并收到 404 时，Sidecar 透明创建替代 Session 并更新绑定；页面不出现`新建`或 Session 恢复选择。
- AI 的补问、生成、修改、审阅、发送与回执全部留在这条对话中。
- 生成中时，输入框旁显示`停止生成`。老师停止后可继续输入新要求，沿用当前聊天绑定的同一个逻辑对话；停止失败时输入继续锁定，同时保留`停止生成`供老师重试。
- Runtime 可以在恢复故障时更换内部执行实例；Binding Trail 负责保持连续投影，页面不得把内部 Session 概念暴露为教师需要管理的产品对象。

## 6. 业务与 AI 状态边界

Tab 数字只统计当前业务阶段内可发起的建议，不表示 AI 任务数量。事项随课程开始、结束、作业截止和正式回执自然更新。全勤、全部提交等闭环事实只在数据完整且及时的时候出现，并不计入待处理数量。

AI 的运行状态不进入阶段 Tab 或建议卡；生成、停止、失败、待审阅和发送回执继续贴着对话及产物显示。

## 7. 验收重点

- 同一个可访问区域内同时包含 AI 消息助手身份、`N 项建议`、单行能力说明、四阶段 Tab 和当前阶段事项；
- 页面不存在第二个独立`教学动态`标题或嵌套主卡，也不存在新建/历史 Session 入口；
- 四个 Tab 在 Sidecar 默认宽度下完整可见，切换只替换下方内容，不跳页；
- 事项点击一次只提交一次精确 Prompt，并在同一时间线显示卡片自然语言原文；结构化能力/对象/格式要求只进入内部上下文；
- 内部 Runtime Session 轮换前后的事件通过 Binding Trail 聚合成一条可上滑历史；stale 404 Binding 自动替换且不出现新建入口；
- 停止当前生成后，输入框恢复可用，下一条要求继续进入同一逻辑对话；停止失败则输入保持锁定并允许重试停止；
- 任意方向滚动对话均不改变导航展开状态；手动收起和展开保持平滑过渡；
- 900×720、1440×900 和最小 384px Sidecar 下无横向溢出、遮挡或不可达操作；
- TypeScript、scoped ESLint、组件测试、Sidecar 集成测试、Chromium 闭环与生产构建通过。
