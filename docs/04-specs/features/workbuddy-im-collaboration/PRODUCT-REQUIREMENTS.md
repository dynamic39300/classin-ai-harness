# WorkBuddy IM 人机协作 PRD

## 1. 背景与机会

终局中的 WorkBuddy 是教师的统一主 Agent，但当前 AI 能力和 Skill 资产还不足以支撑一级高流量入口。第一阶段应把能力嵌入教师已经高频工作的具体业务现场，在真实上下文中跑通“提出需求—生成—审阅—执行—回执”，逐步积累用户信任、业务能力与可复用 Skill。

IM 是合适的首个现场：教师原本就在班级群和一对一聊天中组织教学、提醒任务和回答问题；AI 生成内容也天然需要回到这些沟通渠道。关键不是在群里再增加一个万能机器人，而是为教师建立一个不打扰学生的私密协作区，并把公开发送权继续留给教师。

## 2. 产品目标

- 在不暴露 WorkBuddy 给学生的前提下，让教师在当前班级群旁完成一项真实班务任务。
- 验证 WorkBuddy 能否正确利用 ClassIn 班级、作业、成员和提交状态，生成可审阅的结构化结果。
- 验证教师确认后以本人身份写回群聊的信任链路，并让成功、失败和变化都有明确回执。
- 建立可复用的渠道骨架，为后续公开班级 Agent 和学生私聊 Agent 分别验收提供对照基线。
- 在不复制 Agent 配置的前提下，让教师和学生都能在公开班级群 `@` 同一班级 Agent，并进入各自隔离的 Agent 私聊。
- 先验证四类入口和渠道治理骨架，再统一盘点 WorkBuddy、公开群聊与 Agent 私聊需要铺设的业务 Case Library。

## 3. 非目标

- 本期不实现完整教学 Case Library；班级 Agent 只使用一个确定性示例回答验证渠道骨架。
- 不接入真实模型、真实 ClassIn API、生产权限或真实学生数据。
- 不允许 WorkBuddy 自动发送、定时发送、逐个私聊或绕过教师确认。
- 不在本期开放 Agent 上下文范围给机构或教师配置。
- 不把课程详情入口建成另一个“班级 WorkBuddy”身份；未来只作为同一 WorkBuddy 的上下文启动入口。

## 4. 用户与核心任务

### 主要用户

班级任课教师。教师拥有当前班级教学与沟通职责，可以查看作业提交状态并向班级群发送消息。

### 参考任务

> 请找出当前班级群里还没截止的作业中，哪些学员还没有提交；按不同作业分别 `@` 对应学员并提醒。生成后先让我确认，再发到群里。

### 用户价值

- 免去教师逐个打开作业、核对名单、复制姓名和组织话术。
- 在发送前保留教师的判断、编辑和取消权。
- 用一条分组消息降低群内噪音，让学生快速识别自己尚未完成的作业。

## 5. 渠道与身份原则

| 对象 | 教师私密 WorkBuddy | 群内班级 Agent | 教师/学生各自与 Agent 私聊 |
| --- | --- | --- | --- |
| 本期 | 已实现并回归 | 实现骨架 | 实现骨架 |
| 可见者 | 当前教师 | 当前群成员 | 当前用户与 Agent；不同用户私聊彼此隔离 |
| 学生可直接发起 | 否 | 已授权班级内可 `@` | 已授权时可进入自己的 Agent 私聊 |
| AI 结果身份 | 教师确认后显示为教师 | Agent | Agent |
| 教师能否看到学生私聊 | 不适用 | 公开消息可见 | 默认不可见；教师拥有的是独立私聊，不是审阅入口 |
| 上下文范围 | WorkBuddy 按当前任务所需受控读取 | Agent 自身配置 | 与群内同一 Agent 的配置及渠道策略 |

## 6. MVP 用户旅程

1. 教师进入一个班级群，看到低噪但可识别的 `WorkBuddy` 入口。
2. 教师打开右侧私密窗口，看到“仅你可见”、当前班级和体验数据说明。
3. 教师选择参考任务或输入等价要求，主动触发生成。
4. 教师要求进入私密 Run Timeline；Agent 动态展示目标理解和四步执行计划。
5. 系统依次定位班级上下文、查询有效作业、核对学员提交状态并生成分组提醒，每步显示能力、输入和阶段结果。
6. 全部步骤完成后，系统返回按作业分组的未提交名单和一条完整群消息草稿。
7. 教师可以删除某个学生、取消某个作业分组或直接修改话术。
8. 教师点击发送前，看到目标群、最终发送身份和群成员可见范围。
9. 系统在发送前复核提交事实；若有变化，阻止旧名单发送并要求刷新。
10. 发送成功后，Sidecar 显示执行回执，当前群出现一条由教师本人发送的消息。
11. 标准 Shell 中教师可按需关闭 Sidecar；进入沉浸态后 Sidecar 持续显示。两种模式切换均不删除已生成结果和 Run 过程，学生始终看不到。

## 7. 产品需求

### 入口与可见性

- `IM-PRD-001`：标准 Shell 的 WorkBuddy 入口只在教师可交互的班级群或 1v1 私聊 Header 中出现；沉浸态不重复渲染入口，直接持续显示辅助区。
- `IM-PRD-002`：学生端、通知详情、系统/官方公告和只读嵌入态不得出现 WorkBuddy 入口或辅助区。
- `IM-PRD-003`：Sidecar 必须持续表达“仅你可见”和当前班级，不能伪装成群成员或新聊天会话。

### 任务生成

- `IM-PRD-004`：教师主动发起后，WorkBuddy 读取当前班级未截止的已发布作业、目标学生和提交状态。
- `IM-PRD-005`：名单按作业分组；无提交记录或只有草稿记录的学生视为未提交，已提交、被退回、重交或已批改均不进入催交名单。
- `IM-PRD-006`：没有未截止作业或全部已经提交时，给出不同且可理解的空状态，不生成发送动作。
- `IM-PRD-007`：生成中、读取失败和可恢复失败必须显式可见，不能直接跳到伪成功结果。

### 审阅与控制

- `IM-PRD-008`：教师可以移除单个学生、移除作业分组并编辑最终群消息正文。
- `IM-PRD-009`：任何名单或正文变化必须形成新的草稿版本；旧确认不能用于新版本。
- `IM-PRD-010`：发送前明确展示目标群、最终身份和群成员可见范围，并要求教师显式确认。
- `IM-PRD-011`：未经确认不得向群聊写入任何内容。

### 执行与恢复

- `IM-PRD-012`：确认后只发送一条合并消息，作者显示为教师本人，不显示 WorkBuddy 名称、头像或生成过程。
- `IM-PRD-013`：发送前重新核验提交事实；事实变化时停止并要求刷新、重新确认。
- `IM-PRD-014`：成功返回可追溯回执；重复确认不能产生第二条消息。
- `IM-PRD-015`：权限拒绝、事实变化和消息服务失败分别提供符合原因的恢复动作。

### Agent Run 过程感知

- `IM-PRD-016`：教师触发任务后，原始要求必须作为第一条稳定教师消息进入私密 Run Timeline，而不是被加载动画替代。
- `IM-PRD-017`：Agent 必须先形成教师可检查的目标理解和分层执行计划，再进入工具调用；计划至少表达班级定位、有效作业查询、提交状态核对和提醒草稿生成。
- `IM-PRD-018`：每个步骤必须依次经历 `queued → running → completed/failed`，显示使用的 ClassIn 能力或工具、最小输入 Context 和阶段输出摘要。
- `IM-PRD-019`：运行中持续显示当前步骤、总步骤和预计剩余时间；这些信息与 Timeline 投影同一份 Run Progress，不建立第二套互相矛盾的进度状态。
- `IM-PRD-020`：最终提醒 Artifact 只有在前置能力全部完成后出现；失败时冻结已完成事件并提供恢复，不允许动画结束直接伪造结果。

### 沉浸式消息工作区

- `IM-PRD-021`：教师从 ClassIn 一级“消息”入口进入时，同一个 Message Workspace 必须连续扩展为沉浸式工作区；不得跳转为独立 WorkBuddy 产品或丢失消息路由。
- `IM-PRD-022`：沉浸态最多并列会话列表、当前消息与 WorkBuddy 三栏；WorkBuddy 必须复用唯一的完整 Agent Run Surface，不建立摘要版、压缩版或第二套状态。
- `IM-PRD-023`：退出沉浸只恢复标准 ClassIn Sidebar 与 Topbar，仍停留在消息一级导航和原会话；会话、Run、Artifact、审批、输入草稿与滚动状态不得重置。
- `IM-PRD-024`：沉浸态必须提供可识别的显式退出动作；键盘采用 `Esc Esc` 退出，单次 `Esc` 优先交给输入框、菜单、Overlay 与其他局部 Surface。
- `IM-PRD-025`：文件预览和深度确认使用 Overlay / Focus Surface，不增加第四个持久栏。
- `IM-PRD-026`：紧凑宽度优先收起会话列表，再把 WorkBuddy 转为 Overlay；不得通过删减 Agent Run 事件语义解决空间不足。
- `IM-PRD-027`：点击一级“消息”进入沉浸与退出沉浸使用 320ms 的同源 ease-out 布局过渡；Sidebar、Topbar、Stage 与 WorkBuddy Surface 同步变化，内容只使用克制的透明度和微量缩放缓冲换帧。退出引导必须在标准 Shell 完成后出现。Reduced Motion 下取消空间动画但保持相同语义状态与时序；隐藏的 ClassIn 导航必须同时退出指针、键盘和辅助技术可达树。
- `IM-PRD-028`：WorkBuddy 栏底部必须持续提供教师任务输入区；Ready 时发起任务，Run 中发送的补充内容作为私密教师消息进入当前 Run，生成结果不得自动进入公开群聊 Composer。
- `IM-PRD-029`：Run 的 Header、当前 Capability 与执行计划必须持续显示旋转运行标识、`进行中`、当前步骤、已进行秒数与预计剩余秒数；所有时间信息来自同一运行时钟。
- `IM-PRD-030`：Reduced Motion 下停止旋转、脉冲和扫光，但保留运行状态文字、步骤与秒数；完成后以确定性已完成状态替换运行反馈。

### 班级详情的单班级沉浸入口

- `IM-PRD-031`：教师从班级课程详情点击“班级群聊”后，必须进入独立的班级群聊沉浸路由，不再打开 Dialog；原班级上下文必须保持明确。
- `IM-PRD-032`：单班级入口复用消息中心同一个 `MessageWorkspace`、聊天 Composer、WorkBuddy 和完整 Agent Run Surface；因当前班级已经确定，不显示会话列表，最多并列聊天与 WorkBuddy 两栏。
- `IM-PRD-033`：沉浸顶部 UI Bar 必须同时显示“班级群聊”、当前班级名称和显式“返回班级”；退出后回到对应班级详情，并保留从首页进入班级时的来源参数。
- `IM-PRD-034`：进入、退出、紧凑宽度、焦点、Reduced Motion 与 WorkBuddy Overlay 必须遵循消息中心同一 Shell 契约，不为班级详情创建第二套聊天或 Agent 状态。

### 悬浮辅助工作台视觉层级

- `IM-PRD-035`：WorkBuddy 打开时必须明显表达为聊天现场的辅助区，而不是与聊天等权的第三个主栏目；宽屏使用浅灰托盘与四周内缩的白色浮层建立层级。
- `IM-PRD-036`：浮层继续保持 Header、上下文、可滚动 Run Body 与固定 Composer 四区；视觉升级不得压缩、隐藏或复制 Agent Run 事件语义。
- `IM-PRD-037`：Composer 必须成为面板内部带边距的输入 Dock，始终可达且不随 Run 滚动；焦点、禁用、帮助文案和发送命令保持现有契约。
- `IM-PRD-038`：紧凑宽度下浮层转为保留安全边距的 Overlay；打开动效只使用 transform 与 opacity，时长遵循现有短动效 Token，并在 Reduced Motion 下退化为静态显隐。

### 自适应任务输入

- `IM-PRD-039`：WorkBuddy 浮层不显示左侧品牌或状态装饰条；辅助层级只依靠托盘、内缩、边界和阴影表达。
- `IM-PRD-040`：任务输入框必须从单行随内容逐行增长，最高达到 10rem（默认字号约 7 行）；达到上限后 Surface 高度保持稳定，Textarea 内部出现纵向滚动。
- `IM-PRD-041`：单次任务输入最多支持 4,000 字符；达到 3,200 字符后显示当前字符数与上限，短输入不常驻计数器。
- `IM-PRD-042`：动态高度不得改变 Enter 发送、Shift+Enter 换行、中文输入法合成、禁用态和发送后清空行为；清空后输入框恢复单行高度。

### 一主一辅 Surface 与动态栏宽

- `IM-PRD-043`：沉浸消息中心必须把会话列表与当前聊天组织为一个通信主 Surface；两者共享外轮廓、圆角、边界和阴影，内部只使用 1px 分隔，不形成两张独立卡片。
- `IM-PRD-044`：WorkBuddy 保持独立辅助 Surface；宽屏只在通信主 Surface 与 WorkBuddy 之间提供一条可拖拽分隔器，会话列表首期固定 280px。
- `IM-PRD-045`：分隔器必须提供 `role=separator`、可读名称、当前/最小/最大值、被控制区域，以及方向键、Home、End、Enter 和双击复位；视觉线可保持 1px，但 pointer 命中区不得小于 12px。
- `IM-PRD-046`：WorkBuddy 宽度候选为最小 384px、默认 `clamp(384px, 34vw, 520px)`、最大 `min(640px, 45%)`；消息中心通信主 Surface 最小 704px，单班入口最小 576px。恢复偏好时必须按当前窗口重新 clamp。
- `IM-PRD-047`：可用宽度低于 1184px 时，WorkBuddy 转为带安全边距的 Overlay，分隔器不再可见或可聚焦；低于 896px 时消息中心会话列表沿用 72px Compact。
- `IM-PRD-048`：消息中心与单班入口分别保存本机 WorkBuddy 宽度；仅在拖拽结束或键盘调整后写入。布局偏好不得进入 WorkBuddyRun、班级、消息或 Artifact 状态，也不得影响 Run、草稿、审批、Composer、滚动和焦点恢复。

### 待审阅成果面与人工发送 Gate

- `IM-PRD-049`：Agent Run 完成后，群消息草稿必须进入一个独立且连续的“待你审阅”成果面；Run 完成只表示生成结束，不得被表达为教师沟通任务已经完成。
- `IM-PRD-050`：成果面正文默认直接可编辑，并持续显示“可编辑、编辑中、已修改或已保存”的明确状态；教师点击发送时，当前输入框中尚未失焦的最新正文也必须形成当前草稿版本并绑定本次 Approval。
- `IM-PRD-051`：发送目标、教师身份、群成员可见范围、被提醒学生数和作业数必须与正文和发送动作位于同一成果面，不能依赖教师跨区回忆影响范围。
- `IM-PRD-052`：单群、单消息场景使用一个包含明确对象名称的主动作完成确认，不额外叠加通用确认 Modal；只有跨群、目标变化或批量外发等更高风险操作才升级二次确认。
- `IM-PRD-053`：点击确认后进入“复核最新事实并发送”状态，锁定重复操作；事实过期、权限拒绝或可恢复失败必须保留草稿和失败原因，不得把 Run 完成或按钮点击伪装为发送成功。
- `IM-PRD-054`：发送成功后，原成果面原位转为持久执行回执，并提供“在群聊中查看”动作；成功 Toast 只能辅助提示，不能成为唯一执行证据。
- `IM-PRD-055`：待审阅成果面必须在 384px WorkBuddy 最小宽度下保持标题、影响摘要、编辑器与主动作可达且不产生横向溢出；状态变化使用辅助技术可读的通知，不自动夺取编辑焦点。
- `IM-PRD-056`：待审阅成果面固定为四层：单行待办状态、单行发送影响、核心审阅区、单行核验发送；前两层与第四层不得扩展为多行说明区。
- `IM-PRD-057`：第一层只保留待审标签、成果标题和未发送状态；第二层只保留目标群，并以紧凑标签呈现教师身份和群成员可见范围。消息数量、草稿版本及重复帮助文案不进入默认界面。
- `IM-PRD-058`：核心审阅区必须获得成果面最大面积和最高视觉权重，集中承载作业数、唯一学生数、作业分组、学生移除与可编辑正文；正文保持空值校验和编辑状态反馈。
- `IM-PRD-059`：第四层只保留发送前核验提示与唯一主动作。成果面继续使用待处理的琥珀语义，但应提高边界与状态区对比度，并避免使用错误红或完成绿表达待办。
- `IM-PRD-060`：WorkBuddy 浮层是待审阅流程的唯一外层 Surface；Review Artifact 不再重复绘制完整外框、圆角和阴影，四层结构通过色块、留白、排版与对齐表达。
- `IM-PRD-061`：待审状态使用单一暖色状态带；发送影响摘要默认无边，身份与可见范围使用无描边的轻量标签。不得以更多阴影或多种底色替代被删除的线框。
- `IM-PRD-062`：名单核对区使用一个无描边的浅色事实平面，作业之间优先以间距分组，不默认绘制逐行分隔线；正文 Textarea 作为唯一内部编辑控件保留完整边界、Focus Ring 和错误边界。
- `IM-PRD-063`：发送操作区默认无边；只有 WorkBuddy Body 已发生滚动时才允许使用一层轻微顶部阴影表达 Sticky 层级，阴影与分隔线不得同时出现。

### 紧凑执行回执

- `IM-PRD-064`：发送成功后的 ExecutionReceipt 必须继续作为 Sidecar 内的持久证据，但不得复制待审阅成果面的面积和层级。默认只展示成功状态、已发送消息数、发送教师、目标班级、真值标签和定位动作。
- `IM-PRD-065`：回执不得重复展示可由上述字段直接推导的结果说明，也不得使用三行字段表；成功色只形成一个低重量状态平面，操作使用紧凑次级按钮。
- `IM-PRD-066`：回执在 384px 最小栏宽下必须自然折行、无横向溢出，并保持 `role=status`、明确可读名称和“查看群消息”键盘入口；压缩投影不得删除 Receipt 领域事实或以 Toast 取代持久证据。

### 会话 Header 基线与身份单行化

- `IM-PRD-067`：消息中心左侧分类栏与右侧 Conversation Header 必须使用相同高度，二者底部边界在视觉上形成一条连续水平线。
- `IM-PRD-068`：私聊和班级群聊的名称、角色/关系/成员摘要必须位于同一行；名称保持主信息，摘要位于右侧并使用次级文字，不再为摘要单独增加第二行高度。
- `IM-PRD-069`：该规则必须复用于教师私聊、学生私聊、消息中心班级群聊和单班级聊天入口。紧凑宽度下名称与摘要可分别省略，但 Header 操作、可访问标题和系统/公告详情排版不得回归。

### 教师会话管理入口

- `IM-PRD-070`：教师视角下，消息中心中的班级群聊、1v1 私聊，以及从班级详情进入的单班级群聊，必须在会话 Header 右侧持续显示文字明确的“管理”入口；不得以仅图标的省略号替代，也不得因 `fixedClassId`、沉浸模式或入口来源而缺失。
- `IM-PRD-071`：班级群聊管理继续承载群文件、成员与教师可用的全体禁言；1v1 私聊管理承载联系人资料与消息免打扰。学生视角不显示教师“管理”入口，既有学生可用群会话操作保持原权限边界。

### 教师私聊 WorkBuddy

- `IM-PRD-072`：教师消息中心中的所有可交互 1v1 私聊必须在标准 Shell 的 Conversation Header 右侧显示 WorkBuddy 入口，并与“管理”并列；进入沉浸态后由常驻辅助区替代该入口，不得因会话分类切换而卸载 WorkBuddy 状态。
- `IM-PRD-073`：私聊 WorkBuddy 使用当前私聊名称与最近消息作为本地模拟上下文，只生成可编辑的回复建议；“插入回复框”只更新当前教师 Composer，不得直接发送消息，也不得调用班级群发 Action。
- `IM-PRD-074`：班级群聊 WorkBuddy 的班级 ContextSnapshot、Artifact、教师审批和 ExecutionReceipt 链保持不变；学生、只读和嵌入聊天继续不暴露教师 WorkBuddy。

### 沉浸态 WorkBuddy 常驻

- `IM-PRD-075`：教师在消息中心或单班级入口进入沉浸态后，只要当前对象是可交互的班级群聊或 1v1 私聊，WorkBuddy 必须自动打开并持续显示；切换聊天对象只更新当前上下文，不允许出现仅剩会话列表与聊天正文的空旷沉浸态。
- `IM-PRD-076`：沉浸态不显示 Conversation Header 的 WorkBuddy 开关、不显示 WorkBuddy Header 的关闭按钮，也不通过 Splitter Enter 或其他命令折叠辅助区。标准 Shell 只保留 WorkBuddy 入口，点击后直接进入三栏沉浸，不再同时显示独立“进入沉浸模式”按钮，也不得在标准 Shell 内形成第四栏。退出沉浸不得清空 Run、Artifact、私密 Composer 或当前目标状态。
- `IM-PRD-077`：低于并排阈值时 WorkBuddy 继续作为默认可见 Overlay，不恢复关闭命令；学生、只读、嵌入态、系统通知和官方公告继续不显示 WorkBuddy。Overlay 必须保留安全边距、完整输入与退出沉浸路径。
- `IM-PRD-078`：教师消息中心中真实展示过 WorkBuddy 的会话退出沉浸时，必须以整个应用视口为坐标系，在水平与垂直几何中心显示可操作的非阻塞过渡卡，明确说明“已退出沉浸模式，WorkBuddy 已收起”，并说明当前会话与 WorkBuddy 任务状态已保留。卡片宽度约 460–520px，使用中性浅灰 Surface、灰色边界和克制阴影，只在图标与主动作保留品牌绿；默认停留约 6 秒，悬停或键盘焦点进入时暂停倒计时，支持显式关闭，并提供“重新打开 WorkBuddy”主动作及“点击右上角 WorkBuddy”辅助引导。卡片同时提供“不再显示此提示”勾选项：勾选后保留当前卡片，从下一次退出开始在当前页面文档生命周期内停止显示；当前卡片内取消勾选则恢复后续引导。站内路由切换不重置该选择，浏览器整页刷新会清除偏好并恢复引导，以便相同模拟数据重复验收。该偏好是可失败的本机 UI 状态，不进入 Run 或会话。该提示是事实回执：无论 WorkBuddy 进入前是否已打开，提示可见时标准 Shell 都不得继续挂载 Sidecar；退出只收起 Surface，不清空 Target、Run、Artifact 或 Composer。卡片不夺取焦点、不阻断消息操作、不要求确认，并在 Reduced Motion 下取消位移动画。系统通知、官方公告及教师/学生单班群聊的返回班级路径因没有 WorkBuddy Surface，不显示该引导。

### 同一班级 Agent 的公开群聊与隔离私聊骨架

- `IM-PRD-079`：高二物理 3 班公开群聊与教师/学生各自的 Agent 私聊必须引用同一个 `ClassAgentDefinition`、名称、头像、课程范围和 Capability 配置，不得在页面或渠道 Fixture 中复制一份配置。
- `IM-PRD-080`：已授权班级群的 Composer 必须提供低噪、可键盘操作的 `@班级 Agent` 插入入口，同时允许用户直接输入 mention；未授权班级不显示该入口。
- `IM-PRD-081`：教师或学生只有在群消息显式包含当前 Agent mention 时才触发回复；普通群消息正常发送但不得触发 Agent。
- `IM-PRD-082`：群内回复以班级 Agent 自身身份进入同一 MessageThread，所有群成员可见；不得冒充教师、学生或私密 WorkBuddy。
- `IM-PRD-083`：教师与学生的消息列表分别提供同一 Agent 的私聊入口。二者使用独立线程和上下文，不因共享 Agent 身份而共享私聊记录。
- `IM-PRD-084`：Agent 私聊无需 mention 即可触发回复；教师私聊只对当前教师与 Agent 可见，学生私聊只对当前学生与 Agent 可见，教师消息列表、搜索和联系人入口不得发现学生私聊。
- `IM-PRD-085`：公开群聊和私聊都必须显示当前可见范围、Agent 身份、回复中状态与 `SIMULATED` 真值标签；不得把固定模拟回复表述为真实模型或生产服务。
- `IM-PRD-086`：回复 Controller 使用 `idle / replying / replied / recoverable_failure` 显式状态；重复提交、切换线程和卸载不得把回复写入错误线程，失败后保留用户消息并允许重试。
- `IM-PRD-087`：本轮只提供一个围绕当前课程范围的确定性“动量方向判断”示例回答，用于验证相同能力在不同渠道的投影差异；不据此宣称完整辅导、班务或内容生成能力已完成。
- `IM-PRD-088`：教师班级群 WorkBuddy 与教师 1v1 WorkBuddy 的入口、私密边界、审批/插入 Gate 和沉浸态必须完成回归验收，不得因新增公开 Agent 导致身份、触发或可见性串线。

### 多 Agent 发现、公开 Mention 与隔离单聊

- `IM-PRD-089`：一个班级可以授权多个 `ClassAgentDefinition`；教师和学生只能发现当前班级、当前角色与当前渠道真正可用的集合。教师私密 WorkBuddy、其他班级 Agent 和无权对象不得进入候选或结果数量。
- `IM-PRD-090`：公共群聊输入 `@` 与点击可见 `@Agent` 按钮必须进入同一 Agent Discovery 规则；前者显示“班级 Agent / 班级成员”分组，后者只显示 Agent 并自动聚焦搜索输入，不增加二次搜索动作。
- `IM-PRD-091`：Agent 必须支持按显示名、短名、学科/课程和公开 Capability 关键词实时定位；精确名称、名称前缀、课程匹配、能力匹配、最近使用、教师配置顺序依次形成稳定排序，不使用不可解释个性化排序。
- `IM-PRD-092`：选中 Agent 后必须形成结构化 `AgentMentionEntity` 和唯一 Primary Agent Target；Target 在 Composer 中持续显示具体 Agent、群内公开范围和 Context Scope。普通 `@名称` 字符串、复制文本或同名文字不得触发 Agent。
- `IM-PRD-093`：首版每条公开群消息最多一个主 Agent；再次选择时原位替换并提供轻量撤销。正文为空时不得仅发送 Target；删除或替换 Target 不得丢失正文。
- `IM-PRD-094`：发送前必须复核 Authorization Version；撤权、失效或目录变化时保留正文并进入可恢复状态，不写群消息、不创建 Agent Request，也不得显示成功反馈。
- `IM-PRD-095`：教师和学生的新建私聊、搜索与 Agent 会话切换入口必须复用同一 Discovery Module；选中 Agent 后只打开或创建当前 Actor 的隔离线程，不迁移其他线程消息或草稿，进入 Agent 线程后无需重复 mention。
- `IM-PRD-096`：Picker 必须覆盖加载、空集合、无匹配、可恢复失败、重名消歧和 4/10/30 个 Agent；Option 只承担选择，不嵌套管理或私聊操作。教师治理入口与学生 Surface 保持隔离。
- `IM-PRD-097`：键盘、中文输入法和屏幕阅读器必须完成同一链路；`@`、方向键、Enter/Tab、Esc 与焦点恢复行为确定，IME 组合态不得误选择或误发送，动态结果与选择变化使用温和状态播报。
- `IM-PRD-098`：所有候选、回复和私聊继续使用固定、脱敏、可重置的 `SIMULATED` 数据与真值标签；新增多 Agent 能力不得改变教师 WorkBuddy 的私密性、审批 Gate 或身份边界。

### 执行后的评价事件

- `IM-PRD-099`：教师私密 WorkBuddy 产生 ExecutionReceipt 后，必须生成独立 EvaluationEvent，并关联 Run、ContextSnapshot、ArtifactDraft 版本、ProposedAction、Approval 和 Receipt；任一引用不一致时失败关闭，不生成孤立评价。
- `IM-PRD-100`：EvaluationEvent 只记录教师采纳与执行结果。发送成功不得推导为教学有效，权限拒绝、事实过期和可恢复失败也必须记录为“尚未采纳”，且继续保留原始 Receipt。

### Agent 私聊发现、历史与响应体验

- `IM-PRD-101`：教师与学生的私聊目录必须先按当前 Actor、当前班级、私聊渠道和授权版本过滤，再执行搜索。默认显示“全部”，并提供“班级 Agent”和“联系人”范围；未授权 Agent 不进入列表、数量或无结果状态。
- `IM-PRD-102`：同一搜索框必须支持 Agent 名称、短名、课程和公开能力关键词，以及联系人名称、关系和最近消息摘要。全部范围中 Agent 独立分组并优先于联系人，排序必须稳定且可解释。
- `IM-PRD-103`：Agent 在列表、会话 Header、每条 Agent 消息和处理中状态中均使用同一稳定定义，并通过专属头像语义和名称与人类区分；颜色不得成为唯一身份信号。模拟属性由场景级边界统一说明，不在每个条目重复。
- `IM-PRD-104`：点击 Agent 必须恢复当前 Actor 的同一条隔离 Thread。每个历史页同时保留人类与 Agent 消息；教师与学生不得因为引用同一 Agent 而共享 Thread、历史或草稿。
- `IM-PRD-105`：Agent Thread 支持向上加载更早消息。prepend 后保持视觉锚点和线程滚动位置；用户阅读历史时新消息不得强制滚到底部，必须提供可操作的新消息锚点。
- `IM-PRD-106`：私聊回复状态细化为 `idle → replying.understanding → replying.composing → replied` 或 `recoverable_failure`。用户消息立即写入，等待占位显示 Agent 身份与可理解的工作阶段；失败保留用户消息并允许原线程重试。
- `IM-PRD-107`：当前 Mock Adapter 使用固定、可重置的约 1.8 秒响应时序以稳定展示两个处理阶段；真实 Runtime 不得继承人工 sleep，必须由真实事件驱动。界面不得展示隐藏思维链、虚假百分比或虚假精确 ETA。
- `IM-PRD-108`：上述目录、历史、身份和响应行为同时覆盖教师与学生，保持场景级模拟真值边界并满足键盘、状态播报和 Reduced Motion 要求；真实 Directory、生产历史存储和真实流式 Runtime 仍属于后续 Gate。

### WorkBuddy 最终发送话术与内容引用

- `IM-PRD-109`：WorkBuddy 对即将发往群聊或私聊的生成内容统一产出可编辑的最终发送话术；若结果包含讲解、图片或网页等内容，话术内使用可理解的文字链接引用，不把底层格式作为主交付物。
- `IM-PRD-110`：WB-06 的教师审核面必须支持发送前打开文字链接预览，并允许修改最终话术和链接内讲解；任意修改只有应用为新 Artifact version 后才能批准，接收端必须打开同一批准版本。
- `IM-PRD-111`：学生可用课程/单元/作业/题号与卡点指代题目，完整题目由受治理 Context 定位；不能唯一定位时要求补充。IM 条目不重复显示 `[模拟] AI Agent`、`[模拟] Agent` 或 `H5`，但 Domain、Receipt、Evaluation、审计字段及 WorkBuddy 场景级 `[模拟] 数据` 边界不得删除。
- `IM-PRD-112`：所有进入消息时间线的纯文本正文必须逐字保留发送值中的换行、空行与缩进，并在气泡宽度内安全折行；该规则统一覆盖手动消息、WorkBuddy 作业催交、课前通知、单题讲解最终话术和班级 Agent 回复。界面不得折叠结构化空白，也不得自行解析 Markdown 或改写已批准正文。
- `IM-PRD-113`：作业催交群消息、课前通知和单题讲解最终发送话术必须共用可发现的“展开编辑 / 收起编辑”命令。命令只在 WorkBuddy Sidecar 内增加同一个受控 Textarea 的高度，宽度保持不变且不打开 Dialog；展开后聚焦正文并提供字数反馈，收起后把焦点还给入口。内联展开不得复制 Artifact、绕过空正文校验、移动底部 Composer Dock 或改变发送前审批规则。

## 8. 关键页面与交互

### 班级群 Header

- `WorkBuddy` 文本按钮与可见的“管理”入口同层，但不成为永久占位的第三栏。
- 打开状态可感知；关闭后焦点回到触发按钮。

### 私密 Sidecar

- Header：WorkBuddy、仅你可见、当前班级、关闭。
- Ready：参考任务、可编辑指令和“生成提醒草稿”。
- Generating：当前正在读取的业务对象和停止误解的文案，不展示虚假的模型思考。
- Draft / Review Artifact：以四层“待你审阅”成果面承载单行状态、单行影响、重点核对编辑区与单行核验发送；核心审阅区占据最大面积。
- Confirmation：单群单消息不再弹出通用 Modal；发送对象直接写入主动作，确认后进入事实复核与发送状态。
- Receipt / Recovery：成功对象或失败原因，以及定位、刷新或重试动作。

### 响应式规则

- 宽屏使用群聊 + 右侧 Sidecar 共边布局。
- 紧凑窗口使用右侧 Overlay；标准 Shell 的 Overlay 支持关闭与焦点恢复，沉浸态 Overlay 保持常驻，`Esc Esc` 仍可退出整个沉浸工作区。

### 沉浸 Shell

- 一级“消息”进入时隐藏全局 Sidebar 与 Topbar，并在工作区顶部保留 ClassIn / 消息定位与明确的“退出沉浸模式”动作。
- 退出不执行 `history.back`，而是切换同一路由下的 Shell Mode；标准 Shell 恢复后“消息”仍为当前一级导航。
- 标准 Shell 下只提供 WorkBuddy 动作；教师点击后在不离开当前会话的情况下重新进入三栏沉浸工作区。

### 班级详情入口

- “班级群聊”是进入当前班级消息现场的页面级导航，不是临时查看内容的 Dialog。
- 顶部 UI Bar 左侧显示 ClassIn、`班级群聊` 与当前班级名称，右侧显示稳定的“返回班级”；连续两次 `Esc` 与显式返回执行同一退出意图。
- 单班级页面不渲染会话分类和会话列表；群聊 Header、消息流和聊天输入保持与消息中心一致，WorkBuddy 直接以常驻辅助区出现，不重复渲染入口。

## 9. 成功指标与 MVP 判定

当前为体验验证环境，不用伪造业务增长数据。MVP 首轮以可验证行为作为判定：

- 参考数据下，未提交名单准确率为 100%，不包含草稿、未开始或已截止作业。
- 0 次未经教师确认的群消息写入。
- 一次确认只产生一条教师消息；重复确认副作用为 0。
- 事实变化、权限拒绝和可恢复失败均不会伪装成发送成功。
- 教师可在不离开当前群的情况下完成生成、审阅、确认与查看回执。
- 学生端对 WorkBuddy 的入口、草稿和执行过程可见项为 0。

未来生产试点再补充任务完成时长、草稿修改率、发送确认率、撤回率、错误名单率和教师信任反馈。
