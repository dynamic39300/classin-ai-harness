# ClassIn 班级详情 IM 班级范围会话栏设计提案

## 0. 暂缓决定（2026-09-10）

本提案已按用户要求暂停，不进入 `To Spec`、`To Tickets` 或 Implementation。班级详情与课程详情入口继续只打开当前班级群聊及其 TeachBuddy Sidecar；教师私聊继续沿用既有好友/联系人和已有私聊会话入口。

DW Hunter 只读核验得到的产品结论是：

- 班级成员关系与联系人/好友关系是两套独立业务关系，加入班级不会自动成为好友。
- 班级和机构侧存在“是否允许添加好友”一类设置，且可查询快照中同时存在允许与不允许两种配置，因此页面不能把“同班成员”直接等同为“可私聊联系人”。
- 班级群和联系人会话使用不同的会话关系类型，后者还具有当前有效/已解除的关系状态。
- 当前可用数据可以证明上述结构，但不足以单独证明消息服务对“未加好友直接发消息”的完整拦截规则；该规则还可能由在线权限、隐私和风控服务执行。

因此，原 `CR-04`“展示全部有效成员”和 `CR-05`“无 Thread 时直接创建 1v1”不再作为推荐方案。若未来重启，只允许基于真实权限 Interface 展示 `canDirectMessage = true` 的成员；非好友成员是否展示资料或加好友动作，需要另行确认，不能由班级成员身份推断。

以下内容保留为被暂停的历史设计草案，便于后续比较，不代表已批准实施。

## 1. 本轮要回答的问题

教师从班级详情或课程详情进入当前班级的 IM 页面后，如何在不离开班级范围的前提下，快速切换“整班群聊”和“同班成员私聊”，并让右侧 TeachBuddy 始终使用当前会话的正确上下文。

本文件只定义信息架构、版框、状态和交互。当前不修改页面、路由、Domain、Adapter 或测试；用户审阅通过后再进入 `To Spec → To Tickets → Implementation`。

## 2. 对需求的理解

这个入口不再只是一个固定班级群 Thread，而是一个**班级范围沟通工作区**：

- 范围始终锁定当前班级，不出现其他班级、全局好友、系统通知或官方公告。
- 默认打开整班群聊，保留当前班级群公告、重要提醒、消息记录和 Composer。
- 左侧增加“班级范围会话栏”：上方固定整班群聊，下方原计划展示当前班的可沟通成员，并支持成员搜索；该计划现已暂停。
- 只有真实关系与权限 Interface 明确返回可私聊时，才允许切换到该成员已有的 1v1 Thread；不得因同属一个班级而创建私聊 Thread。
- 一级“消息”入口和这里复用同一个私聊 Thread、消息历史、未读状态和草稿，不复制第二套会话。
- 右侧 TeachBuddy 跟随当前 Thread：群聊时使用班级上下文，成员私聊时使用“班级 + 当前成员”的最小上下文；不同 Thread 的 Agent Session、草稿和产物互不串用。

## 3. 结构方案比较（历史草案，已暂停）

| 方案 | 结构 | 优点 | 主要问题 | 建议 |
| --- | --- | --- | --- | --- |
| A. 班级范围会话栏 | 整班固定行 + 成员搜索与列表同时显示 | 一眼看到“聊全班/聊个人”；切换成本最低；最接近一级消息会话列表 | 桌面端增加一列，需要响应式收起 | 历史推荐，现已暂停 |
| B. `班级群聊 / 成员私聊` Tab | 先切 Tab，再搜索或选择成员 | 占用宽度较少 | 把同一班级沟通拆成两层；群聊与个人不能同时被发现 | 备选 |
| C. 底部成员抽屉 | 在聊天底部弹出成员选择器 | 默认页面最简 | 发现性弱；频繁切换需要反复开关；容易遮挡 Composer | 不推荐 |

原草案推荐 A；该推荐已被本文件第 0 节的暂缓决定覆盖。

成员私聊状态遵循以下变化：

- 中央 Header 改为成员头像、显示名、角色和所属班级；群公告、重要提醒、`@所有人` 与群资料入口隐藏。

## 6. 成员搜索规则

- 搜索范围只包含当前班级的有效人类成员；排除当前登录教师、班级 Agent、其他班级成员和全局好友。
- 支持姓名、班级昵称和角色关键词；搜索不扫描聊天正文。
- “班级群聊”固定在搜索框上方，不受搜索条件影响。
- 有既有私聊的成员显示最近摘要、时间和未读数；没有 Thread 的成员显示“开始聊天”。整行均可点击，不增加重复的“发消息”按钮。
- 空结果显示“当前班级没有匹配成员”，并提供“清除搜索”。
- 成员数据部分读取失败时保留整班群聊，并在成员区显示重试；不能把部分列表表达成完整 29 人。

## 7. 切换与路由

建议保持现有页面路径，使用稳定 Thread 引用记录当前选择：

```text
默认整班：/teacher/classes/physics-3/chat
成员私聊：/teacher/classes/physics-3/chat?thread=direct-wang-li
```

- URL 没有 `thread` 时默认打开当前班级群 Thread。
- `thread` 只能解析为当前班级群，或当前教师有权访问且目标仍属于该班的成员私聊；解析失败回到整班群聊并给出可恢复提示。
- 一级消息页和班级入口解析到同一 `MessageThread.id`，因此历史、未读、提交回执和草稿保持一致。
- 顶部“返回班级”始终退出到来源班级/课程详情；会话栏切换不改变这个退出目标。
- 浏览器前进/后退恢复 Thread 选择，不清空各 Thread 本地草稿。

## 8. Interface / Seam 建议

`ClassConversationDirectory` 作为 Deep Module，隐藏班级成员、会话解析、权限与 open-or-create 细节。页面只学习两个命令：列出当前班级会话目标、打开一个目标。

```ts
type ClassConversationTarget =
  | { kind: 'class'; classId: string }
  | { kind: 'member'; classId: string; memberId: string };

interface ClassConversationDirectory {
  list(input: {
    actorId: string;
    classId: string;
    query: string;
  }): Promise<ClassConversationDirectoryView>;

  open(input: {
    actorId: string;
    target: ClassConversationTarget;
  }): Promise<
    | { status: 'ready'; threadId: string }
    | { status: 'forbidden' | 'member-unavailable' | 'failed'; message: string }
  >;
}
```

Module 内部组合现有 Class Domain、Message Thread Store、`MessageLifecyclePort` 和身份/权限 Adapter：

- Class Domain 拥有成员身份、班级昵称、角色和在班状态。
- Message Domain 拥有 Thread、历史、未读、草稿和交付状态。
- `ClassConversationDirectory` 只建立稳定关联，不复制班级成员或消息。
- 当前 Memory Adapter 使用固定、脱敏数据；未来 ClassIn Adapter 负责完整成员目录、真实权限和幂等创建私聊。
- TeachBuddy 继续只消费当前 `WorkBuddyImTarget` 与 `ContextSnapshot`，不读取成员表或自行推断当前对象。

## 9. 数据就绪与异常状态

| 状态 | 页面行为 |
| --- | --- |
| 成员加载中 | 群聊立即可用；成员区显示骨架，不阻塞消息和 TeachBuddy |
| 成员为空 | 保留班级群聊；成员区说明当前没有其他可沟通成员 |
| 部分成员 | 显示已取得成员并标注“成员列表暂不完整”，提供重试 |
| 成员搜索无结果 | 显示空结果与清除搜索 |
| 无既有私聊 | 点击成员后执行幂等 `open`，成功后进入新 Thread |
| 无权私聊 | 留在当前会话，成员行显示不可用原因，不创建空 Thread |
| 成员已离班 | 从当前班级成员列表移除；已打开的 1v1 是否保留由消息权限回执决定 |
| 班级只读/已结课 | 群聊按既有规则保留历史；成员私聊入口按独立权限逐项决定，不由页面统一猜测 |
| TeachBuddy 上下文失败 | 普通 IM 仍可用；右侧显示可恢复失败，不能沿用上一个成员上下文 |

当前 Demo 的 `physics-3` 标注 30 位成员，但 `ClassRecord.members` 只含少量固定成员。进入实现前需要选择：补齐一套固定、脱敏、可重置成员目录，或显式演示“部分成员”状态；不能用 3 条记录冒充完整 30 人。

## 10. 响应式建议

- `≥ 1280px`：三列并存，班级范围会话栏建议 240–260px，当前会话弹性伸缩，TeachBuddy 沿用现有可调宽度。
- `900–1279px`：会话栏收为窄栏或由“班级会话”按钮打开覆盖层；TeachBuddy 沿用当前覆盖/收起策略，同一时刻只允许一个辅助覆盖层。
- `< 900px`：Header 提供“会话”入口，打开全高成员选择面；选中后返回单一聊天正文。Composer 始终可达。
- 会话栏、消息时间线和 TeachBuddy 各自独立滚动，不产生页面级横向滚动。

## 11. 原提案完成边界（已暂停）

以下范围不进入当前实施，仅保留为历史草案：

1. 教师班级详情与课程详情入口默认进入整班群聊。
2. 当前班级整班行、成员搜索、教师/学生分组和成员 1v1 切换。
3. 复用一级消息页同一 Thread、未读、历史和草稿。
4. 群聊/私聊 Header、Composer、群级功能和 TeachBuddy 上下文正确切换。
5. 加载、空、部分、无结果、无权、创建失败和上下文失败状态。
6. 1440、900 和窄视口的可达性、焦点、独立滚动和恢复。

首版不扩展全局通讯录、好友申请、成员管理、批量私聊、多人临时会话、学生分组、班级 Agent 目录或自动发送。
