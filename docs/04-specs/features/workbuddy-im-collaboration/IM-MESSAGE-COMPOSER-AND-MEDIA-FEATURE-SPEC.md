# ClassIn IM 消息输入与媒体 Feature Spec

## Problem Statement

当前普通 IM 已能发送文本、固定表情和具体成员提及，但图片、截图、表情面板、`@所有人` 与视频仍缺少可操作闭环。附件菜单里的照片和拍摄只是占位，截图不能经过选区回填 Composer，消息时间线也不能展示图片缩略图或打开大图。教师和学生因此无法在同一个消息工作区完成常见的图文沟通，审阅者也无法验证线上 ClassIn 已存在的媒体能力是否被完整继承。

本规格只处理普通 IM，不改变 TeachBuddy Agent、IM Sidecar、模型输入或视觉模型。普通 IM 图片是发给会话参与者的消息事实，不进入 Agent Runtime，也不依赖任何图片理解 API Key。

## Solution

在教师端与学生端共享的消息工作区建立一条“选择或截取内容 → 形成会话独立草稿 → 追加文字/提及 → 原子发送 → 缩略阅读 → 大图查看”的纵向闭环，同时把表情选择器、五类集合、收藏/自定义表情与群聊 `@所有人` 纳入同一 Composer 体验。

首个版本使用 `MessageMediaModule` 隐藏浏览器文件、剪贴板、屏幕捕获、预览资源和已发送媒体引用的生命周期。`MessageMediaAdapter` 是外部设备与二进制内容的替换 Seam：首版提供 Browser Adapter 和确定性的 Memory Test Adapter；未来 ClassIn PC Native Adapter 在同一 Interface 下接入原生截图、窗口隐藏、持久上传和正式权限。消息页面只编排媒体草稿 Projection 与命令，不读取浏览器 `File`、Canvas 或设备 API。

视频先通过固定、去标识、可重置的接收消息验证封面、播放动作和时长阅读；视频发送与真实文件传输留到本地文件/云盘模块。

## User Stories

1. 作为教师或学生，我希望从 Composer 打开表情选择器，并在五个集合之间切换，以便快速找到标准 Emoji、教学贴纸和自己常用的表情。
2. 作为消息发送者，我希望选择普通 Emoji 后把它插入当前光标位置，而不是立即发送，以便继续补充文字、图片或提及后统一确认。
3. 作为消息发送者，我希望收藏常用表情，并从本地添加一个自定义表情，以便在“我的”集合中复用；Demo 重置后可以恢复固定初始状态。
4. 作为班级群成员，我希望从 `@` 候选中选择“所有人”，并能同时提及具体成员，以便清楚表达消息受众。
5. 作为私聊用户，我不希望看到无意义的 `@所有人` 候选，以便候选范围符合当前会话对象。
6. 作为教师或学生，我希望从 Composer 启动普通截图，并由浏览器选择要共享的屏幕、窗口或标签页，以便把屏幕内容带回当前消息。
7. 作为截图用户，我希望在捕获画面上拖动和调整选区，看到选区尺寸、坐标和像素颜色提示，并能取消或确认，以便在发送前控制范围。
8. 作为截图用户，我希望确认截图后只把它放入当前会话的待发送区，而不自动发送，以便删除、继续截图或补充文字。
9. 作为消息发送者，我希望直接选择本地图片或使用 Ctrl/Cmd+V 粘贴剪贴板图片，以便在不依赖系统级截图权限时也能完成图文消息。
10. 作为消息发送者，我希望同时加入多张图片，逐张删除，并在旁边继续输入文字、Emoji 和提及，以便一次发送完整说明。
11. 作为消息发送者，我希望图片读取、格式、大小或截图权限失败时保留已经输入的文字与有效图片，并能修改后重试，以免重新编辑消息。
12. 作为消息接收者，我希望图片在时间线中显示清晰缩略图，会话列表使用 `[图片]` 摘要，以便快速判断消息类型。
13. 作为消息接收者，我希望点击缩略图打开大图，使用关闭按钮或 Escape 返回，并回到原缩略图焦点，以便连续阅读且不丢失位置。
14. 作为多图消息接收者，我希望在大图 Viewer 中查看当前序号并切换前后图片，以便不用反复关闭 Viewer。
15. 作为消息参与者，我希望图文消息继续支持回复、Reaction、置顶和按现有规则撤回；撤回后图片不再可打开，以便媒体消息遵守同一消息生命周期。
16. 作为跨语言沟通者，我希望翻译只处理图文消息中的文字，不把图片误称为已被 AI 理解，以便持续区分内容阅读和模型能力。
17. 作为视频消息接收者，我希望从预置卡片看到封面、播放按钮和时长，并能打开固定本地视频播放，以便验证视频消息的阅读结构。
18. 作为教师或学生，我希望这些能力在一级消息页和班级详情的沉浸聊天入口表现一致，同时保持各会话草稿隔离，以免把媒体误发到另一会话。
19. 作为键盘和辅助技术用户，我希望表情面板、截图选择层、大图 Viewer 和视频 Viewer 都有明确名称、可见焦点、Escape 关闭和焦点恢复，以便独立完成操作。
20. 作为 Demo 评审者，我希望固定媒体、用户本地媒体和未来生产媒体在内部证据中保持不同来源，不把 Browser/Memory Adapter 宣称为 ClassIn 生产上传或原生截图。

## Implementation Decisions

- `MessageMediaModule` 是媒体 Deep Module。它通过一个 `MessageMediaAdapter` Interface 隐藏文件选择、剪贴板图片、屏幕捕获、图片解码、草稿预览、已发送二进制引用与资源释放；页面只看到状态 Projection 和意图命令。
- 首版实现 Browser Adapter 与确定性的 Memory Test Adapter，两者共同证明 Interface 可替换。未来 ClassIn PC Native Adapter 只作为替换点记录；首版不再建立更细、但没有第二个真实实现的截图抽象层。
- Message Domain 只拥有稳定 Attachment Reference、Mention Reference、类型、名称、尺寸、时长和来源等消息事实，不持有浏览器 `File`、Base64、Canvas 或 Object URL。二进制内容及其预览解析属于 Adapter。
- 待发送媒体和已发送媒体是两个状态。发送命令先把全部有效草稿提交为 Attachment Reference，再与正文、Mention、Reply 和 Resource Reference 一次写入当前 Thread；任一步失败都不产生半条消息。
- 已发送本地媒体在当前运行期可继续被 Viewer 解析；撤回、Reset 或 Provider 卸载时释放不再可达的临时资源。固定视频和固定图片通过可重置 Fixture 提供稳定引用。
- 普通 IM 只复用共享 Composer 的交互 Interface，不依赖 TeachBuddy Agent Runtime 的图片编码、视觉模型路由、Session 恢复或 BFF 校验。两个业务模块不得共享图片请求状态。
- `@所有人` 与具体成员都写为 Mention Reference，同时保留用户可读正文。当前 Demo 沿用“可写班级群的教师与学生都可选择”的最小策略；精细角色、频控和生产授权留给后续权限 Adapter。
- 五类表情使用固定、去标识、可重置 Catalog。首版建议命名为“最近、Emoji、教学贴纸、常用回应、我的”；这些名称属于当前产品信息架构，不宣称由线上截图证明。
- Unicode Emoji 作为正文插入；教学贴纸和自定义表情作为图片型 Attachment 草稿进入同一媒体链路，避免为贴纸建立第二套发送协议。
- 截图选择层只处理已经由 Adapter 取得的静态画面。它提供选区、暗区、尺寸、坐标和 RGB 提示；标注、涂鸦、OCR、重新编辑和快捷键不进入本阶段。
- 图片 Viewer 和视频 Viewer 使用覆盖当前消息区的临时 Focus Surface，不改变三栏结构，也不与 TeachBuddy Sidecar 竞争常驻宽度。
- 用户生成的本地媒体不写入 URL、日志、长期 Fixture 或 Git。Demo 内部保留来源 metadata；正常产品页面不显示“模拟/仿真”徽标。

## State and Recovery

- 表情面板：`closed → open(category) → selected | closed`；切换集合不改变 Composer 草稿，选择普通 Emoji 后面板关闭并把焦点放回光标。
- 自定义表情：`idle → choosing → validating → ready | recoverable-failure`；失败不清空已有收藏或消息草稿。
- 屏幕捕获：`idle → requesting-permission → captured → selecting → confirmed | cancelled | recoverable-failure`；任何取消和失败都回到同一 Composer。
- 媒体草稿：`empty → validating → ready | partially-ready | recoverable-failure → submitting → sent | recoverable-failure`；批量加入时保留全部已通过项并逐项报告失败。
- 大图 Viewer：`closed → open(index) → navigating → closed`；目标消息撤回或引用失效时关闭并给出不可用状态。
- 视频 Viewer：`closed → loading → ready | recoverable-failure → closed`；加载失败时卡片仍保留封面、时长和重试入口。
- 会话切换：正文、Reply、Resource Reference、Mention 和媒体草稿使用同一 Thread 草稿键；不会跨私聊、班级群或角色复用。

## Testing Decisions

- Domain 单元测试覆盖 Attachment/Mention 稳定引用、图文摘要、`@所有人` 与成员组合、回复安全摘要、撤回后媒体不可达，以及非班级会话拒绝 `@所有人`。
- `MessageMediaAdapter` 契约测试覆盖有效/无效图片、数量与大小边界、部分成功、捕获取消/拒绝、提交原子性、资源解析和释放。测试使用确定性的 Memory Adapter，不触发真实系统截图选择器。
- Integration 测试复用现有 `MessageWorkspaceProvider + MemoryRouter + MessageWorkspace` 高层 Seam，覆盖表情插入、自定义表情、`@所有人`、截图回填、多图图文发送、会话切换、Viewer、视频和错误恢复。
- 浏览器 E2E 至少覆盖一次真实本地图片选择、一次剪贴板图片粘贴、教师班级群完整发送与 Viewer、学生端阅读/发送、一级消息与班级入口一致性。系统级屏幕选择器不作为自动化成功 Gate；选区流程通过注入确定性捕获结果验收。
- 可访问性验证覆盖所有 Overlay 的名称、Tab 顺序、Escape、焦点恢复和严重/关键 Axe 问题；视觉验收覆盖 1440×900、900×720 Sidecar 共存和 390×844 紧凑视口。
- 完成阶段运行类型检查、Lint、相关 Vitest、消息 Playwright 回归和生产构建；只有对应稳定 ID 的验收证据通过后，才更新 104 项覆盖矩阵。

## Out of Scope

- TeachBuddy、IM Sidecar、Agent Runtime、模型图片理解、视觉模型 Key 和 Agent 图片历史。
- 真实 ClassIn IM API、媒体上传服务、云端持久化、断点续传、压缩、杀毒、CDN、送达/已读和跨设备恢复。
- 原生自动隐藏 ClassIn 窗口；当前仅保留 Adapter 能力和不可用表达，待 PC Native Adapter 实现。
- 截图标注、涂鸦、马赛克、OCR、快捷键、自定义排序和再次编辑。
- 图片 Viewer 的缩放、旋转、下载、另存、编辑和外部分享。
- 视频选择/发送、转码、上传、下载、倍速、字幕、画中画和直播；本阶段只验证固定接收卡和基础播放。
- 本地文件、云盘三类来源、群文件管理和真实文件卡；这些进入后续文件模块。
- 表情云同步、跨设备收藏、容量治理、内容审核和线上完整表情集合。
- `@我的` 聚合、桌面通知、`@所有人` 频控与精细角色授权；它们进入公告、提醒或权限模块。
- 生产媒体失败/重试、上传进度和离线幂等。当前 Local Adapter 提交即时完成，只表达读取、权限和校验的可恢复失败。

- `ON-CMP-05` 在线上证据中只有文字部分确认，所以本规格把收藏和自定义表情限定为最小本地管理，不推断云同步或完整治理。
