# 行为合同

`AnalysisProcessProjection` 继续作为 Runtime Event 到可审计过程的唯一 Domain Projection。Sidecar 不建立第二套 Run 状态，只通过 `AnalysisProcess` 的 `compact` 模式压缩呈现；主工作台 `full` 模式保持原合同。

## Compact 分析投影

Compact 摘要的 Interface 为：

- 身份：固定显示 `TeachBuddy`；
- 当前动作：从当前真实步骤的产品文案投影；没有可验证步骤时显示“正在理解你的要求”；
- 耗时：来自 Projection 的真实 `elapsedMs`；
- 结束语义：完成为“已整理好”，失败、停止和等待补充使用对应可恢复文案；
- 展开入口：统一命名“处理过程”；运行和完成默认折叠，失败或需要补充默认展开。

Compact 模式不得在主摘要中显示步骤数量、Tool/Skill 技术名、内部等待事件或“已完成分析”。展开区最多显示当前步骤与最近两个相关步骤，使用固定最大高度和内部滚动。

## 对话回合投影

Sidecar 仍按 `splitAnalysisProcessTurns()` 将持久事件归入教师回合。每轮按以下顺序投影：

1. 教师消息气泡；
2. Compact 分析摘要；
3. Agent 最终回答；
4. 仅在该轮具有消息交付意图时，与最终回答相邻显示审阅或转换动作。

教师和 Agent 的事件标题不再另行显示。错误事件继续保留可见标题和恢复信息。Tool/Skill 事件只进入分析投影，不作为聊天气泡重复出现。

## 草稿与交付

点击审阅动作后，当前轮最后一条 Agent 回答由可编辑消息正文原位替换。`MessageDraftArtifact`、`ProposedAction`、`Approval` 和 `ExecutionReceipt` 的领域合同不变。

`projectImMessageDeliveryIntent()` 将教师可见要求保守投影为三种 Sidecar affordance：

- `none`：查询、分析、事实总结和普通咨询，只显示回答；
- `suggest`：询问如何提醒、回复或沟通，显示低强调转换动作；
- `draft`：顶部教学任务或明确的写消息、通知、提醒、回复要求，显示审阅动作。

该 Projection 是当前 Runtime 尚未返回结构化消息产物类型时的 Deep Module。页面只消费结果，不自行拼接关键词规则；未来 Runtime 提供稳定 Artifact Kind 后可在该 Interface 内替换。

消息生成请求由 `buildMessageDraftRuntimeRequest()` 附加不可见的正文边界合同，教师气泡仍只显示教师原始要求。`extractMessageDraftBody()` 按以下顺序形成编辑器正文：

1. 优先读取 `TEACHBUDDY_MESSAGE_BODY_START/END` 边界内的唯一消息原文；
2. 对未遵循边界合同的旧回答，兼容清除开场说明、独立分隔线、消息标题、要点解释和结尾调整建议；
3. 已经是纯正文的 Artifact 保持原样。

正文提取失败时保留非空原始结果，不能生成空草稿。边界标记和内部生成要求不得出现在教师气泡或最终 IM 消息中。

- 群聊：按钮明确发送目标，发送前重新捕获 Context 并校验；
- 私聊：插入目标输入框，仍由老师在 IM 中发送；
- 发送或插入成功：记录内部 Receipt/采纳事实，关闭审阅区，不渲染成功状态卡；
- 失败：保留修改后的正文和错误，允许重试；
- 取消：关闭编辑区、丢弃本次未发送修改并恢复原回答；不产生 Receipt 或状态卡；
- 已采纳的 Agent Event ID 仅作为当前 Sidecar 的 UI 临时状态，防止当前轮重复出现审阅按钮；它不是新的业务状态。

## Composer

Runtime 运行或发送请求等待期间只禁止提交，不禁止编辑 Composer。图片和文字作为下一轮草稿保留。停止命令与当前 Session 绑定并保持可达；停止成功后继续同一逻辑对话。

# Module 与 Write Set

- `AnalysisProcess` Module：保持共享 Interface，通过 `mode='compact'` 提供 Sidecar 投影密度；
- `ImSidecarAgentSurface` Module：编排对话回合、审阅替换、交付结束和 Composer 命令；
- `WorkspaceComposer` Module：本轮不扩展公开 Interface；调用方分开控制 `disabled` 与 `canSubmit`；
- Domain 的分析、草稿、审批和回执 Interface 不变；新增消息交付意图 Projection，隔离当前文字判定与页面。

Write Set：

- `src/domain/workbuddy/analysis-process.ts` 中仅允许修正面向用户的空等待文案；
- `src/domain/workbuddy/im-message-delivery-intent.ts` 及测试；
- `src/domain/workbuddy/im-message-draft.ts` 的正文生成合同、提取 Projection 及测试；
- `src/features/agent-runtime/AnalysisProcess.tsx` 与样式；
- `src/features/workbuddy-im-assistance/ImSidecarAgentSurface.tsx` 与 Sidecar 局部样式；
- 对应 Domain、Runtime、Sidecar 测试和视觉验收；
- 本 PRD、Spec、Tickets、Implementation Review、D-151 与追踪索引。

# 兼容和失败

- 刷新后仍由稳定 Session ID 恢复历史事件；
- UI 临时采纳标记刷新后不恢复，但已发送消息仍以 IM 事实存在；当前 Demo 不新增持久化采纳索引；
- 连接、权限、上下文校验和发送失败继续使用既有恢复命令；
- 主工作台的 full 分析模式不因 Sidecar 样式调整而改变。

# 自动化合同

- compact 摘要没有步骤数量和“已完成分析”；
- full 摘要仍保留完整状态和步骤计数；
- Sidecar 每轮教师消息、处理过程、最终结果顺序稳定；
- 进入审阅后最后结果不重复；
- 发送成功后审阅区和成功状态卡均消失，消息 Adapter 只执行一次；
- 普通查询没有审阅动作，沟通建议只有转换动作，明确消息要求和顶部任务具有审阅动作；
- 取消审阅不调用消息 Adapter，恢复原回答和审阅入口；
- 审阅正文不包含 Agent 开场、背景说明、分隔线、写法解释和结尾建议；纯正文 Artifact 不被改写；
- 运行期间 Textarea 可编辑、发送不可用、停止可用；
- 展开处理过程具备无障碍名称、受控高度和无横向溢出。

## 2026-09-15 交付修订：IM-CRUX-06/07

本节覆盖旧版的单一“审阅”入口与无成功文字反馈；不改变领域审批合同。

1. 当前可交付回答先按已有正文标记/Artifact优先规则提取，直接显示“消息草稿”及正文。生成合同要求主题分段、并列项使用逐行列表；兼容旧文稿中明确的行内圆点列表，保留文字、数字与公式，不凭句号猜测拆分。
2. 同一份提取正文用于富文本预览、编辑器和发送 Action。IM 当前仍是纯文本消息；列表逐行、空行分段保留，提示词使用纯文字短标题以适配 IM。
3. “修改文案”仅原位编辑；“直接发送”作为教师显式 Approval，通过既有 Context 复核与 MessageDraft Adapter 执行。不得先弹出编辑器。源内容来自不同 Artifact 时，预览必须同步采用真正待发送内容。
4. 发送使用同步互斥锁覆盖上下文读取和 Adapter 执行，防止快速连击；显示“发送中…”。失败保留原草稿，重试复用草稿；成功保留实际发送正文用于阅读，隐藏发送按钮并显示简短“已发送”。不新增完成卡。
5. 编辑后发送以最新版本生成 Approval；取消编辑恢复原预览。当前已有的跨刷新采纳状态恢复限制保持显式，不宣称跨刷新恰好一次交付。
6. 私聊与群转学生私聊继续显示“插入回复框”，不冒称直接发送。普通查询和沟通建议保留原先的回答/转换规则。
7. 老师用“2”“第二项”等简短回复选择上一轮明确列出的编号选项时，交付意图继承被选选项的完整语义。被选项是提醒、通知、回复或发送任务时，下一轮必须按消息草稿生成并展示修改与发送入口；没有对应编号、选项不是消息任务或上下文不可定位时，不凭数字猜测发送意图。

Write Set 限于正文 Domain 及测试、共享 ImSidecarAgentSurface 及局部样式、该模块现有自动化与本组规格记录。业务数据库调研、V2、服务配置与其他入口不修改。

### 消息提及标签（2026-09-15 用户补充）

IM 助手回复内的 `@所有人`、当前学习上下文中可识别的 `@学员姓名`使用浅蓝底/蓝字圆角标签。多个明确提及逐个显示，文本可正常选择和复制；纯文本编辑器及发送正文仍保留原来的 @ 文本。未知姓名、姓名前缀、邮箱、链接和代码不误标；普通富文本调用默认不启用此样式。

本次只增加 Copilot 内的视觉区分，不将文本样式当成真实 IM Mention 对象或额外通知回执。当前学员名称覆盖由已加载的上下文目录决定；后续接入完整班级名单后可扩展识别，不在展示组件中硬编码学生姓名。

### 草稿密度修订（2026-09-15 用户确认后再调）

IM-CRUX-09：保留结构但减少碎片化。生成要求改为同主题短句连贯表达，仅有必要的主题切换才分段；多项课程安排仍逐项列出，列表项之间不空行。覆盖前文普遍要求“小标题+分段”的密度描述。

仅可交付草稿使用紧凑样式：正文保持原字号，行高1.55、段落/列表尾间距4px、相邻列表项2px；“消息草稿”标签与正文间距4px。普通咨询、公式及其他工作台沿用原富文本样式。已有正文只改变视觉间距，不自动改写老师已看到或已修改的内容；合并短句要求对新生成生效。预览、编辑和发送仍共用同一正文。


### 紧凑与结构化的边界（2026-09-15 补充）

IM-CRUX-09 的“同主题合并”仅适用于同一要点内部。课堂回顾中的知识点、练习表现、易错提醒属于不同信息维度，必须分为带简短标签的列表项，不合并成长段；知识点很多时按独立概念逐项列出，避免多层嵌套。课程安排、课后任务继续逐项展示，列表项之间不插空行，沿用现有紧凑样式。

本次 Write Set 仅正文生成要求与本规格/验收记录。历史正文不按句号或关键词自动重写，重新生成后采用此要求；不修改展示组件、发送逻辑或其他线程的研究内容。


### 提及名单补全（2026-09-15）

原有 students 是可选个性化服务证据目录，不等于班级提及名单。LearningContextCatalog 增加可选 mentionLabels，Adapter 按当前会话返回可展示的姓名；共享 Sidecar 合并该字段与非聚合学生目录用于标签。物理模拟场景补齐业务事实里已有的六位学生，不添加虚构个人学情或扩大个性化服务可选对象。私聊只返回对应学生，未支持班级返回空名单，旧 Adapter 缺字段时保持原目录回退。

Write Set：上述合同、模拟目录及 Adapter、Sidecar 取名逻辑、相关自动化与验收记录。不改变正文、发送对象或真实通知行为；未知姓名仍不凭模型文字当作已核验成员。此节更新此前仅依赖可选学生目录的覆盖限制。


### 导航底色试调（2026-09-15 用户确认）

顶部建议区域从浅灰改为淡蓝灰 #F2F7FC（语义 Token --color-assistant-guide-surface），展开与收起统一。内部建议卡片保持白色，绿色阶段选中态与操作按钮、浅灰教师消息气泡保持既有样式，以区分建议入口和消息对话。本节按当前用户确认更新 D-154 的浅灰导航底色，其他交互不变。Write Set 仅颜色 Token、TeachingDynamics 样式、既有浏览器颜色验收与此规格/验收记录。


### 所有消息入口统一提及要求（2026-09-15）

所有四阶段建议、自由输入的明确写消息请求、建议转消息及个性化服务生成均复用 buildMessageDraftRuntimeRequest。此公共生成合同补充：全班群消息以 @所有人 开头，定向群提醒逐一 @ 实际目标学生，不裸写姓名、不遗漏多人中的部分对象；接收对象来自当前请求及证据，而非展示名单。已带@不重复，普通叙述姓名不转为接收对象，私聊不使用@所有人；无法确定对象先补问，遵循教师明确不@的要求。标签与颜色仍由富文本渲染。

本次仅修改公共生成要求、全量演示入口请求长度与提及要求验收、规格记录；不通过字符串猜测替换历史正文或老师编辑内容，不改变发送范围与真实通知语义。对新生成生效，历史裸姓名草稿可要求助手按上述格式重写。


### 顶部整栏折叠入口（2026-09-15 用户确认）

头像、名称、建议数量、引导文案、留白及箭头合并为同一个原生按钮；整栏点击切换展开/收起，Enter与Space等价，保持aria-expanded、焦点回收和原过渡。右侧仅展示箭头，不新增展开/收起文字。可选关闭按钮独立于折叠按钮，点击关闭不触发折叠；阶段和建议操作不受影响。Write Set仅TeachingDynamics及样式、相关测试和记录；更新此前“仅箭头点击”的交互规则，仍不随对话滚动自动收起。


### 页面级历史隐藏（2026-09-15 用户澄清确认）

进入或刷新IM Copilot，保留教学导航和输入框，默认隐藏本次进入前的会话记录、旧产物及其交付按钮。仅页面展示状态变化，不删除服务端历史、不创建新会话、不清除绑定；AI继续原有上下文。首次异步恢复按会话记录可见边界，之后的新回合正常展示，轮询不重新隐藏新消息。历史入口仅在存在历史时显示“↑ 查看历史”，辅以“向上滚动也可查看”；点击或在对话区顶部向上滚轮原位显示历史，导航区滚动不触发。恢复历史时保持阅读位置，不被自动滚底打断；历史查看状态不持久化，刷新再次隐藏。连接错误和正在执行任务的停止入口仍可达。

Write Set：共享Sidecar、页面历史呈现hook、局部样式、对应组件/浏览器验收及此记录。Session恢复、业务上下文、消息写回和V2不修改。更新既有默认立即展示历史的行为。

兼容旧演示链接：resetCopilotOnReload 参数不再清除会话绑定；刷新统一只隐藏页面历史，以符合本次明确保留AI上下文的要求。


### 历史与本次新消息分界（2026-09-15）

查看历史后，若同时存在本次进入前的历史回合与本次新回合，在首个新回合前显示一次“以下为新消息”：红色文字、两侧淡红细线，沿用IM消息分隔的语义Token。边界来自页面首次恢复记录，不按每轮回复插入；轮询、继续对话不移动该边界。没有新消息、没有历史或历史仍隐藏时不显示。刷新后重新记录边界，不改变AI上下文或消息正文。分界前的历史回复不再叠加原灰色尾线。Write Set仅页面历史hook、Sidecar渲染与样式、对应测试和记录。


### IM自我介绍名称（2026-09-15）

按用户标注，IM中的AI回答自我介绍统一为“AI消息助手”，不再自称“AI教学助手 TeachBuddy”。公共IM请求封装加入命名要求，并将内部要求从教师气泡隐藏；旧回答仅对明确的TeachBuddy自我介绍做显示兼容，代码及普通品牌引用保留。发送草稿同步应用相同兼容规则，老师手工编辑仍保持原文；主工作台品牌和Session不改变。Write Set为IM请求封装、名称显示函数、共享Sidecar调用、测试及此记录。
