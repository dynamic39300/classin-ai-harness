# DW 派生数据与场景时间加工方案

## 1. 用户确认的方向

用户认可用有延迟的 DW 数据作为业务底稿，通过模拟时间覆盖课前、课中、课后与再次回访场景，并进一步要求必须先通过数据库读取尽可能完整的真实数据，再做映射与手动改时。随后明确无需指定账号：从最近三天有开课和作业提交的活跃机构/老师中选择数据丰富的集合。不能先沿用少量已有消息投影加工，再把补出来的场景当成已完成的真实底稿采集。

本文细化采集和加工方法。本轮已执行 dw-hunter 升级检查、组件注册检查和连接自检；技能版本为 1.1.2，知识库可读。用户更新令牌后，数据库鉴权与只读查询已恢复，并完成候选发现、选中教师的目录采集和首轮业务明细采集。原始结果已冻结在 Git 忽略的本机私有区，包含 140 份作业、18,297 条学生作业记录等；群成员、私聊关系等缺口仍保留。完整覆盖、核对结果与限制见[首轮采集记录](../../../01-research/IM-COPILOT-DW-SOURCE-COLLECTION-REPORT.md)。M1 已完成独立映射、场景时间加工和 v2 投影，可作为重新设计的业务证据；旧 M2 前端装配已按用户决定撤回，不能再作为数据就绪证明。

产品定位与体验原则由[上午体验提案 v1.2](./COPILOT-CONTEXTUAL-ENTRY-EXPERIENCE-PROPOSAL.md)保存；[M2 重启设计输入基线](./COPILOT-M2-DESIGN-BRIEF.md)只记录线框方案撤回后的范围边界。本文只拥有场景数据准备、时间一致性与开发 Gate，不定义新的产品入口或页面方案。

总体推进由[总里程碑计划](./COPILOT-MILESTONE-PLAN.md)统一维护：原始采集归 IMCP-M0，映射与场景加工归 IMCP-M1，场景在提醒中的实现与验收归 IMCP-M4 至 IMCP-M6。

## 2. “全集”的业务范围

先在当前查询权限范围内比较最近三天的机构/教师候选，再围绕选中的老师整理完整的关联数据。旧的表达与思辨体验班仅作为既有对照，不再默认是本次蓝本。这里的“全集”指选中老师及其所教班级/课程和相关学生的教学业务集合，不是导出整个数仓或与教学场景无关的个人信息。

### 2.1 候选发现与选择

1. **先确认时间覆盖。** 按北京时间最近三个完整自然日筛选；本次目标窗口为 2026-09-06 00:00 至 2026-09-09 00:00（左闭右开）。先核验各源最新完整日期；未入仓日期记为未覆盖，不把没有分区视为没有活动。若需改为最近三个完整可用日期，执行记录明确实际窗口及原因。
2. **先取汇总候选。** 以真实开课/教学参与和作业提交事件为入围条件，不以登录或消息条数代替教学活动。先筛机构，再在机构内比较老师；这一阶段只读取关联标识与数量，不批量读取所有候选的聊天正文。
3. **比较数据完整度。** 看同一老师覆盖的班级/课程、已结束/安排中课次、学生关联、到课记录、作业发布与提交/批改/订正，以及相关群聊/私聊的可用性。完整的业务关联优先于单一消息量最大。
4. **核对归属。** 不把班主任、任课老师、机构管理员和作业批改操作人自动当成同一身份。机构/教师候选须能连接到相同业务对象，避免拼接不同老师的丰富数据成一份虚假画像。
5. **确定蓝本。** 选一个最适合的老师及相关教学集合，记录真实数据截止时间和选择理由。除非首选缺少不可替代的业务维度，再考虑独立的备用样本；不混合不同样本的真实身份。

候选结果以匿名候选编号和覆盖数量报告。已取得 30 个初筛候选，并选定候选 A；逐条核验后确认其最近三天有 4 节有效授课、447 条实际提交记录。没有把累计提交数当作最近三天提交量，也没有宣称所有候选都已完成逐条核验。

### 2.2 选中后的完整关联采集

所需集合包括：

- 班级、教师、学生及可用私聊关系；
- 场景涉及的全部课次、安排与开课/结束事件；
- 对应应到名单、请假、首次进入、离开/重新进入事件；
- 对应作业、发布时间、截止/延期要求、提交、批改和订正事件；
- 与这些课次/作业相关的必要聊天、课堂内容和教师反馈；
- 产品内已有提醒、回顾产物与交付记录，以验证去重和已完成状态。

最近三天用于找到活跃样本，不将完整采集硬截断为三天。选中后读取老师有权关联的班级/课程目录和学生关系，并围绕近期完整教学周期及仍未结束的关联任务补齐明细；实际起止日、班级数、课次数、作业数、成员覆盖和缺失记录在采集清单中列明。业务表中的课程/班级/课次概念按真实关系映射，不自行添加不存在的层级。采集完后才可声明该范围数据完整。缺少历史日志时不得把末态快照宣称为完整过程。

该老师与相关学生的必要群聊/私聊按可验证关系和时间窗口读取；不读取学生与其他无关人员的对话。附件先记录引用、类型与可用性，教学内容确需使用时再处理相关内容。真实业务底稿存入 Git 忽略的本机私有工作区，保持原时间和状态；姓名/标识映射及时间修改在下一阶段独立进行。

## 3. 当前仓库可复用的底稿

2026-09-09 用户在实施中补充：一个班级下有多门课程，同班学生共用班级群，但课程进度、作业与完成情况分别维护。加工时须先核对产品术语与物理数据的实际对应；任务引用明确包含班级、班级课程及具体课次/作业。新增 S9 验证同一学生一门课已交、另一门课未交，并检验同名作业、课程消歧和跨课程回执去重。当前已冻结候选不能证明的多课程关系单独标记为模拟，不把物理字段名称当作语义证据。此项依 D-131 并入 M1/M2 本批。

静态盘点来源：`src/mocks/scenarios/workbuddy-im-learning-evidence.ts` 与 [既有数据研究](../../../01-research/IM-PERSONALIZED-TEACHING-COMMUNICATION-RESEARCH.md)。

| 内容 | 已有状态 | 本次场景所需补充 |
| --- | --- | --- |
| DW 派生班级/联系人 | 一个教学群场景、一名可达私聊学生与聚合跟进对象 | 完整的场景成员名单、对象权限和私聊映射 |
| 教学主题 | 两个课次标签、词汇/表达任务和教师反馈 | 精确的课次时间、开课结束状态及作业业务对象 |
| 到课 | 消息中有迟到、请假、召回沟通 | 完整逐人事件；消息出现不等于确认个人缺勤 |
| 作业/订正 | 有练习要求和单侧沟通，缺学生回执 | 提交、批阅、订正及截止事件；不能把未见回执当未交 |
| 固定物理场景 | 有两节课、作业及六人跟进描述 | 可作 UI 对照，不能混称 DW 查得的业务事实 |

因此已有数据不能通过改日期直接得到完整的实时出勤/作业状态。当前不对它先行改时或补写模拟事件；先完成新一轮数据库采集与完整性检查，再决定有哪些内容必须模拟补充。

## 4. 三层加工与留存

1. **先冻结真实底稿。** 通过数据库只读查询取得选中范围的真实记录，保留原始采集时间、业务时间、关系和版本。完成缺失清单后再开展后续映射。经授权的私有内容沿用仓库忽略目录，进入仓库的内容必须去标识。原数据不原地改写。
2. **场景定义。** 记录所用底稿版本、场景锚点、时间偏移、事件补充和人物映射。新增的请假、进入课堂、提交等记录逐项标记为模拟，避免把一个末态人数误当作可重放事件。
3. **时点投影。** 页面、推荐事项、计数和 Agent 输入消费同一场景时点的可见事实。时点之后的事件不可提前出现。

内部证据至少区分：来自 DW 的原始语义、时间平移、模拟补充。原始 `read-only-business-data` 标签不能单独代表已经改时/补事件后的整个场景；派生场景需要额外变换记录及模拟真值。正常产品 UI 按 D-109 不常驻开发阶段提示。

不修改数据库时间或电脑系统时间。场景时钟独立、可重置；重置恢复同一场景初态，不污染其他真实 Runtime Session 或原始私有底稿。

## 5. 时间与状态的一致性

- 课次安排、真实存在的开课/结束事件、作业发布/截止、提交、消息内容中的日期一起按事件关系处理。不能只把课表改成今天而保留“昨天已提交全部作业”的未来结果。
- 有相对语义的文本，如“明晚截止”“刚下课”，在派生文本中与场景锚点对齐；保留原文底稿及转换记录，不做无差别全局替换。
- 没有事件日志时，固定模拟事件明确拥有时间和来源；不能仅由当前快照反推学生何时进入或提交。
- 到课人数依据应到名单与请假/进入状态计算，不按加入群聊人数推断。迟到后已进入者不继续计为未进入。
- 作业已提交待批改与未提交分别投影；截止延期、请假与已交付提醒共同影响可处理机会。
- 场景中“当前”指场景时钟；真实底稿采集时间只用于内部证据。Agent 不同时接收相互矛盾的原始日期和场景日期。
- 退出再进入不自动把时钟重置为开课 10 分钟；继续同一时点或显式推进。需要重置时从验收控制入口执行，不在教师正常流程加入调时按钮。

## 6. 最小场景矩阵

以下时间、人数和数量已在[场景包 v2](./COPILOT-SCENARIO-PACK.md)中实现为固定场景参数，未宣称为 DW 原始事实。

| 场景 | 主事项 | 次要事项 | 要验证的变化 |
| --- | --- | --- | --- |
| S1 课前 20 分钟 | 全班开课提醒 | 历史两节课堂回顾、1 份待批作业 | 主卡与次要入口同时存在，批改跳转与 AI 生成动作清楚 |
| S2 开课 10 分钟 | 3 人尚未进入 | 课堂回顾 2 | 已请假者不计入；准备 3 份私聊提醒 |
| S3 开课 12 分钟 | 未进入从 3 人变 2 人 | 保留其他可处理事项 | 老师生成/审阅期间对象变化，发出前更新 |
| S4 刚下课 | 已发布作业的全班通知 | 历史回顾与当前课回顾按条件计数 | 已结束且资料可用才成为可生成回顾 |
| S5 临近截止 | 4 人尚未提交 | 同一份作业已有提交待批改 | 作业按业务对象计数，展开明确两种动作 |
| S6 全部提交 | 无催交主动作 | 老师待批改事项仍在 | 不把学生已完成视为老师已处理 |
| S7 任务恢复 | 原会话生成中/待确认 | 新会话展示自己的机会 | 输入、名单、产物保留；机会数与运行任务数分开 |
| S8 数据缺失/权限变化 | 自动读取失败或资料不完整 | 不显示伪 0/虚假人数 | 必要时只追问业务对象或给重试，不要求管理上下文 |
| S9 同班多课程 | 同一群中两门课程各有待处理事项 | 同名作业明确课程；同学生完成状态不同 | 课程甲已交不排除课程乙提醒，课程甲回执不抑制课程乙；歧义只补问具体课程/作业 |

## 7. 后续执行与完成条件

执行时先按 dw-hunter 流程核验在线知识库、权限和查询口径，完成候选发现与选中范围的真实数据采集，再生成派生场景和事件。查询前检查元数据及分区/索引裁剪；优先分阶段聚合和分页，避免把所有域直接连接成重复膨胀的结果。技术接入契约在相应 Feature Spec 中定义，不在本体验修订中临时改动。
