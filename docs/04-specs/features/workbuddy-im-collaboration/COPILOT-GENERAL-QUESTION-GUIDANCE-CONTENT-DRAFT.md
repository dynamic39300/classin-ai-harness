# 班级 AI 消息助手：通用提问内容与交互设计清单

## 1. 已确认的范围

本版根据用户逐条审阅及后续澄清整理。原五组25条中 **18条保留或收窄、6条退出首批、1条待核查**；本轮用户确认新增“对群聊的内容提问”F1–F3，当前为 **六组、21条问题**。原ID保持不变，新三条尚未纳入此前18条数据实测。

当前覆盖：**查询业务事实、整理已有内容、根据已定位题目生成解析、基于报告或群聊写消息**。暂不承诺学生错因诊断、解题卡点判断、学习进步评价、个性化改进指导或教学/考试重点推断。可以提炼实际讲过、资料写过的知识内容；这与判断“主要考什么、为什么错、怎么改进”分开。

顶部四阶段导航推荐重要、典型的业务话题；通用引导说明围绕当前班级还可以问什么。二者使用同一段对话和授权上下文，允许内容交集，六组不是内部 Agent 或问题白名单。

两项澄清已经用户确认：

- **教师笔记**不作为默认数据依赖和主要引导；课堂回顾以课堂内容、回放逐字稿为主，确有可读笔记时可以辅助。
- **个别沟通草稿**不属于原始业务信息；保留“基于学生学情报告生成给家长的话术”这一输出能力。

[用户原始批注快照 v0.2](./COPILOT-GENERAL-QUESTION-GUIDANCE-USER-REVIEW-v0.2.md)逐字保留，含已被本版替代的旧方案，仅供追溯。本文是当前内容范围；v0.4 仅补充逐条取数核查的证据状态，保留已确认的 18 条问题和交互方向，不表示页面接入或模型回答已经实施。

本轮已形成[通用提问引导详细设计](./COPILOT-GENERAL-QUESTION-GUIDANCE-DETAILED-DESIGN.md)及[21条回答样例](./COPILOT-GENERAL-QUESTION-ANSWER-EXAMPLES.md)，供用户审阅。前者定义首次开场、长期入口、点击与草稿保护；后者使用明确标注的虚构设计情境说明回答和追问，不是模型实测记录。v0.5只补充交付索引，不改变18条内容范围。

## 2. 数据依据与业务确认分开

业务范围为“当前教师 → 当前班级 → 班内课程 → 单元/教学活动 → 学生参与与结果”。课程和班级不能混用，学生在不同课程、不同活动中的状态独立。

| 主题 | 可问的信息 | 主要输入 |
| --- | --- | --- |
| 班级和课程 | 成员人数、课程目录、当前进度、后续安排、配套活动 | 班级成员、课程/单元、课次与活动关系 |
| 课堂和学习参与 | 到课、迟到/缺席、录播观看 | 适用名单、带时间的考勤/课后记录、实际观看进度 |
| 作业和测验 | 内容、截止、提交、批阅、哪些题做错 | 已发布活动、有效分配、作答与判分；不从结果推断思维过程 |
| 某位学生 | 学情报告事实、任务完成情况 | 当前班级内的学生报告和逐活动结果 |
| 报告和沟通 | 已有报告、课堂回顾、资料整理、消息草稿 | 可读报告、课堂内容/逐字稿、资料和已确认对话 |
| 对群聊的内容提问 | 最近群聊要点、消息提到的题目解析、针对问题的回复 | 本班授权IM消息及引用关系、对应教学对象和完整题面 |

### 已有探查证据

- [测试接口证据](../../../01-research/COPILOT-GENERAL-QUESTIONS-API-EVIDENCE-2026-09-15.md)：取得目标数学课程 54 项活动目录，五类活动各抽查两项详情，读到部分作业、提交、报告、笔记与资料内容。测试返回包含联调构造记录，不能全部视为自然教学样本。
- [DW 业务样本证据](../../../01-research/COPILOT-GENERAL-QUESTIONS-DW-EVIDENCE-2026-09-15.md)：独立教师样本支持班级、课程、活动、分配、提交与批阅等关系；与测试接口不是同一班级。
- [教学数据地图](../../../01-research/CLASSIN-TEACHING-DATA-MAP-2026-09-15.md)和[教学活动下钻](../../../01-research/CLASSIN-TEACHING-ACTIVITY-BUSINESS-DEEP-DIVE-2026-09-15.md)：说明结构、字段含义和流程证据。结构存在不表示当前接口已开放、内容齐全或全部问题已经通过实际回答验证。
- [18 条问题逐条核查总表](../../../01-research/COPILOT-18-QUESTIONS-VERIFICATION-MATRIX-2026-09-15.md)：已完成本轮只读取数及 Apifox/扫描资料回溯。测试 API 共 209 次业务成功，班内 2/2 课程、54/54 活动详情和名单已读；另有独立真实 DW 样本。报告明确列出可回答范围、统计冲突、缺失正文和未执行查询。
- 原版仍使用固定模拟和有限上下文选择。本轮研究取数没有自动接入产品；模型回答与两个 IM 入口尚待验证。

用户已确认多数数据在业务侧完备可获取；下面保留“此前实际依据”，另列业务确认及后续验证。本轮已由 AI 逐条核查具体 DW 表/字段、业务接口、实际值、内容可读性及覆盖范围；未解决的缺口以核查总表为准，不要求用户重新整理已有技术字段。

提交方式、活动分配和草稿状态仍是可取得的业务事实，但用户判断它们不应成为主要推荐问题。默认关注已发布教学活动；查询碰到草稿时，简要说明“草稿，尚未向学生公开”，不引导老师逐项做可见性检查。

### F. 对群聊的内容提问（本轮新增，方向已确认）

| ID | 老师的问题 | 所需信息 | 预期回答 | 后续可追问 | 证据与接入状态 |
| --- | --- | --- | --- | --- | --- |
| F1 | 总结群里最近两天的聊天要点 | 当前群的时间范围内消息、作者/时间、引用与回复关系、必要附件内容、分页完整性 | 归纳讨论、明确安排及在已读取范围内未见回复的问题，必要时定位原消息 | 只看和作业有关的讨论 | 本轮新增；最新消息读取、时间过滤、完整性和总结效果待验证，不沿用18条已核查结论 |
| F2 | 帮我讲解一下他问的今天作业第二题 | 明确原消息、关联课程/作业及版本、第二题的完整题面/图示/条件，已有标准答案或解析如可用 | 先自然说明定位的题目，再给可核对的步骤和答案；可进一步转写为给学生的回复 | 把步骤写得更容易懂，再整理成回复 | 新增“题目解析生成”范围；消息到题目的定位链与解题正确性待实测，不要求有学生错题判分才可讲题 |
| F3 | 帮我回复一下群里这位同学的问题 | 具体问题、相关前后文和已发生回复、需要核验的业务事实、回复对象与渠道 | 针对原问题生成消息草稿，由老师确认发送 | 再简短一点，直接回答他的问题 | 本轮新增；可复用既有草稿规则，消息引用及新信息刷新仍待验收 |

本轮确认“老师主动发问时读取最新可用消息”，不包含持续后台监听、自动生成待办或自动回复。群聊线索与教学数据联合使用；群里有人说了什么是对话事实，不能直接升格为正式课程安排。F2允许生成解题解析，但不恢复C3/D4的个体错因或卡点诊断，不自动承诺生图。具体规则见详细设计第6.4节，样例见F1–F3。

## 4. 回答与交互规则

### 4.1 四种结果

| 老师意图 | 默认结果 | 交付动作 |
| --- | --- | --- |
| 查信息：有哪些、什么时候、谁没交 | 结论、必要列表、时间范围和口径 | 直接回答，不自动进入消息审阅器 |
| 整理内容：讲了什么、资料写了什么、报告记录了什么 | 基于可读原文提炼事实与内容，必要时指出来源 | 可连续追问或要求整理成消息；不增加诊断、进步评价和个性化指导 |
| 题目解析：这个题怎么做 | 在完整已定位题面基础上生成步骤与答案，区分已有解析与AI新生成内容 | 先给老师解析，明确要求回复学生时再生成可发送正文；不推断学生错误原因 |
| 写消息：通知、提醒、报告改写、群问题回复 | 依据已有事实生成消息正文 | 教师审阅、修改、确认发送；真实/模拟交付仍按既有边界 |

正确率与得分率分开，说明题目、学生、有效作答、时间及分母；未作答不算答错，未评分不记 0 分。全勤、全部提交等反馈仍有价值，但只能在名单、结果及时间完整时成立。未查到、接口失败、未生成报告与真实的 0 分别表达。

### 4.2 默认范围与必要补问（内容规则已确认，待实施）

- 当前班级是默认业务范围，覆盖该班课程、学员与教学活动；这是授权检索范围，不是每次把全部数据塞入模型，也不是当前实现已全量接通。
- “这节课/这份作业/他”优先承接上下文。识别明确时，在回答中自然说明所处理的课次、作业或学生，例如“这份第 1 讲作业……”，不再要求确认已知信息。
- 存在多个合理对象、同名学生或发送目的地歧义时，先主动查询，再给少量可理解的候选，让老师在对话中确认，不使用连续配置表。
- 初次说“最近”，默认近 7 天并在回答中写明日期；“本周”“本单元”等按明确业务范围取数。窗口缺数据时说明缺口，不悄悄换成另一周期。
- 顶部官方推荐随业务节点增减，历史信息仍可询问；不把历史查询恢复为当前待办，也不擅自延长截止时间。
- 跨班业务问题明确说明“当前处理本班信息”，不混入其他班数据。自由输入不受顶部 Tab 锁定。
- 数据不足先回答已确认部分；已有授权信息先由 AI 自行读取，只有确需老师决定或补充时才追问。
- 对暂未支持的错因、进步或改进建议请求，说明当前只能提供相关学情事实或已有内容；不通过“通用建议”绕过此次确认的能力边界。

### 4.3 缺失与异常回答

| 实际情况 | 建议回答 |
| --- | --- |
| 测验无人作答 | “这份测验目前还没有作答记录，暂时不能统计错题。”不附带整理考点/教学重点的承诺 |
| 批阅汇总与明细冲突 | “目前能确认2人已交、1人未交。批阅汇总和学生明细不一致，暂时不能确认是否都批完了。” |
| 只有资料分配 | “这份资料已分配给3位同学，但目前没有取得阅读完成记录，还不能确认是否看完。” |
| 报告存在，未读全文 | “这节课已有分析报告，但目前没有取得正文，暂时不能概括结论。”只有已读到课堂内容/逐字稿或辅助笔记时，才提出整理相应内容 |
| 请求评价进步或诊断卡点 | “目前可以提供已有的学情数据，还不能据此判断进步或具体解题卡点。”可以继续查询任务和结果，不转向改进建议 |
| 文件无法打开/解析 | “这份文件目前无法解析。您可以提供可读取的文档或清晰图片，我再帮您整理其中的内容。”区分未支持、损坏等已知原因，不猜测文件内容 |
| 没有完整周期记录 | 明确已覆盖的课程、活动和日期，只总结这部分；不补造缺失课程的情况 |

示例人数仅为既有测试样本，不能硬编码进实际回答。若只是当前班级暂无记录，不把它解释为系统永久没有这项能力。

## 5. 两条连续对话样例

### 样例一：查询提交，再整理提醒消息

1. 老师：“这份作业交得怎么样了？”
2. AI：承接已明确作业；确有歧义才补问，给已交/未交及可核对的批阅情况。
3. 老师：“只看还没交的。”
4. AI：沿用该作业及有效分配范围，列出未交学生，不要求重新选课或作业。
5. 老师：“整理成一条提醒消息。”
6. AI：依据已有作业内容、期限和对象生成草稿；若已截止且不适合催交，说明业务情况，不生成失效提醒。老师审阅、修改后确认发送。

链路验证对象承接和事实转写，不依赖学生解题过程诊断。

### 样例二：资料内容提炼，再整理群消息

1. 老师：“这份资料里有哪些学习方法？”
2. AI：取得可读正文，提炼原文中已有的方法；读取失败先说明，不编造内容。
3. 老师：“把第二点说得简洁一点。”
4. AI：改写刚才的原文要点，不增加“容易错在哪里”的判断或新的教学指导。
5. 老师：“整理成一段发给学生的话。”
6. AI：沿用内容生成消息正文，由老师审阅确认。

基于学生报告生成家长话术使用相同的事实转写原则；生成草稿与真实家长关系、目的地、送达能力分别验证。

## 6. 页面承载方向

### 6.1 首次进入的轻量开场（方向已确认）

仅在当前班级对话为空、上下文已就绪时出现。顶部保持已有导航，下方对话区以短说明和至多 3 个可点击问题帮助老师起步；恢复加载、读取失败不冒充首次空白。

此前确认的开场文案（本轮建议补充群聊能力，见详细设计3.1）：

> 也可以问我这个班级课程、课堂、作业、学生情况，或帮您出学情报告、写消息草稿

“出学情报告”指调用适用的学情接口、整理真实记录或已有报告，不承诺生成独立的成长评价；正式报告与 AI 整理结果区分。

首批示例方向：

- “接下来要上什么课？”
- “这份作业交得怎么样了？”
- “把这份资料里的方法整理成三点”

展示时替换为当前已知对象，数据不具备时换成可回答示例；与顶部已露出的推荐尽量互补。开场随对话自然上移，不因切 Tab 或收起顶部重复插入。课堂回顾优先使用课堂内容/逐字稿，不依赖教师笔记。

### 6.2 长期可查入口（已确认，实施中）

“可以问什么”按六组展示代表问题，原位查看，不进入二级页面，不计入顶部建议数量，不用待办角标。只有具备明确可用内容后才展示，不直接恢复已删除的“教学协作”占位入口。详细设计推荐入口放在输入框上方外侧，帮助面使用六组连续列表；位置、文案和行为以已确认详细设计为准；实现和验证另见实施合同。

### 6.3 交互细节

| 场景 | 处理方向 |
| --- | --- |
| 输入为空且 AI 空闲 | 点击完整问题一次即发起，显示原文，沿用当前对话 |
| 已有未发送文字/图片 | 保留草稿及附件；详细设计推荐加入现有输入、由老师手动发送，不能覆盖或误带附件发送 |
| AI 正在生成 | 可浏览示例，不并发启动；需要时先停止当前运行 |
| 正在审阅消息 | 保留正在编辑的消息；详细设计推荐下一问只加入普通输入，退出编辑后手动提交 |
| 关闭面板/Esc | 收起帮助、焦点返回，不改变输入、导航或业务状态 |
| 切换班级 | 引导与目标班级一致，历史归原班级，不能把旧问题误送到新班级 |
| 数据不足 | 用可回答内容替代主动示例，不堆放禁用项；必要时如实说明覆盖 |
