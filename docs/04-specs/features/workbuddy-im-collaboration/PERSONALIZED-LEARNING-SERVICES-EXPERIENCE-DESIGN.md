# TeachBuddy IM 四项个性化学情服务体验设计

状态：`SPECIFIED`
日期：2026-09-08
来源：[《6.10版 IM升级：基于学情的个性化师生教学沟通》](https://app.notion.com/p/3d4a5c3b026b8012b602edd0efc07fe0?pvs=204)

## 1. 用户场景

教师正在群聊或学生 1v1 中沟通，不应离开当前消息现场重新搜索业务数据。TeachBuddy 读取当前会话允许的学习事实，帮助教师完成有对象、有依据、有后续动作的沟通。AI 负责整理和生成，ClassIn 拥有课程、课堂、作业、消息和学生事实，教师决定接收对象、内容和发送。

## 2. Sidecar 信息架构

Ready 面首屏保留自由输入，并在其上方提供四张紧凑任务卡：

| 服务 | 教师最少选择 | 产物 | 默认交付 |
| --- | --- | --- | --- |
| 个性化提醒 | 原因、学生、相关任务 | 提醒话术与跟进点 | 多人可走当前群待审；单人可转 1v1 |
| 个性化课堂回顾 | 课次、学生 | 课堂要点、个人关注、下一步 | 学生 1v1 Composer |
| 错题解析与再练 | 学生、错题 | 错因解释、分步讲解、相关练习 | 学生 1v1 Composer |
| 个人学情总结 | 学生、周期 | 进展、困难、建议 | 学生 1v1 Composer |

点击任务卡后，Sidecar 原位进入配置面。顶部保持当前会话身份；中部只显示该任务必要的选择器和一行“将依据哪些事实”；底部唯一主动作是“让 TeachBuddy 生成”。“返回任务”保留已选内容，便于比较任务或修正选择。

## 3. 群聊与 1v1 差异

- 群聊：学生选择器来自当前班且可多选。个人回顾、错题和学情总结的默认交付按钮明确写出“转到李明私聊并插入”，避免把个人证据公开到群。
- 1v1：当前联系人自动锁定，页面不再要求重复选择学生。四项能力都只插入当前 Composer，教师继续手动发送。
- 单学生课程群仍按群聊治理，因为成员可见范围可能包含家长、助教或后续加入者，不能因当前只有一名学生自动视为私聊。

## 4. 生成与审阅

提交后继续使用当前 Thread 绑定的真实 DeepSeek Session。Timeline 显示教师可见的任务描述和真实 Runtime 事件；受控上下文不显示成教师发言。

生成完成后出现统一审阅面：标题、接收对象、依据摘要、可编辑正文、结构化区块和交付渠道。错题能力额外显示“解释”和“再练”两块；课堂回顾和学情总结保持三段式。教师修改后形成新 Artifact 版本。返回修改选择会使旧版本失去可发送资格。

## 5. 状态和恢复

- 目录加载失败：保留当前会话，可重试读取。
- 选择不完整：在对应字段附近提示，不创建 Runtime 命令。
- 生成中：显示真实 Runtime 状态，可停止；不显示思维链、假进度或假 ETA。
- 需要补充：保留已选业务对象，把缺口写回自由输入或选择器。
- 解析失败：保留模型原响应，提供“按结构重新生成”，不伪造 Artifact。
- 上下文过期或权限变化：保留草稿，要求刷新依据；不执行发送或插入。
- 已插入：说明仍需教师在 Composer 中确认并发送。
- 已发送：持久显示 Receipt 和定位动作。

## 6. 数据真值

当前交互同时提供两个可重置场景：高二物理 3 班使用固定、脱敏的 `fixed-demo` 证据；“表达与思辨体验班”使用 DW Hunter 行级只读查询派生、去标识并语义改写后的冻结投影，标记为 `read-only-business-data`。后者保留 T-1 截止时间、来源和未验证关系，但不保存真实标识或消息原文，也不代表在线生产 Adapter 已接通。两个场景都通过同一 Business Context Interface 进入 DeepSeek，页面与 Prompt 不接触 SQL、实例、表或连接信息。
