# 边界

浏览器使用协议模拟响应与原版的模拟消息 Adapter 验证交付行为，不调用线上 ClassIn 消息写回；本轮未重新调用真实模型验证所有文风。生成要求已更新，历史明确圆点列表兼容分行；不会强行拆分任意散文、数字或公式。IM 当前采用纯文本，分段和逐行列表保留；不宣称 IM 已具备完整 Markdown 富文本功能。

采纳标记仍为本机页面临时状态，跨刷新恢复和不确定发送结果的持久幂等属于既有后续范围。本次未修改主线程业务数据研究、V2 项目、服务端配置或运行端口。

## 同日补充：课堂回顾按信息维度分点

根据用户的新截图反馈，调整正文生成要求：知识点、练习表现、易错提醒分别成列表项，单项内保持连贯；多项独立概念按需拆分，避免把紧凑误解为合并不同主题。沿用列表无额外空行和现有紧凑样式。仅修改生成要求和规格记录；8项正文领域测试、类型检查与diff检查通过。本轮未调用真实模型，新规则需重新生成观察，旧稿不自动改写。


## 同日补充：修复部分学员提及漏标

根因是标签使用个性化服务的可选学生目录，漏掉模拟事实里的周然、陈晨、赵可。已通过 LearningContextCatalog.mentionLabels 单独提供当前会话可展示姓名，合并原目录回退；保持个性化服务的可选对象与证据不变，私聊与未支持班级按范围过滤。物理演示已覆盖已有事实中的六位学生，不宣称已获得完整30人名单。

22项Adapter/富文本/Sidecar测试、类型检查、Lint和diff检查通过；两个IM入口浏览器测试均通过，验证所有六位学生加@所有人均显示标签、直接发送与axe检查。已检查1440×900截图，无溢出或遮挡。纯文本正文及发送通知语义不变；刷新后已有消息可按补全名单高亮，无需重新生成。

## 同日补充：统一消息生成的@要求

核查发现普通顶部建议走 submit，个性化服务走 generateLearningArtifact，两者及自由输入的写消息/建议转消息均复用 buildMessageDraftRuntimeRequest；原公共合同缺少强制书写@的要求。已补充按实际收件对象区分@所有人与逐个@姓名的规则，并保留不扩大通知对象、普通叙述不@、私聊不@所有人和遵从老师明确要求的边界。

17项正文/Adapter测试、类型检查、Lint、diff检查通过；十个物理教学推荐事项均检查公共生成要求包含逐人@与全班@规则，原证据范围和长度检查保留。未调用真实模型验证全部输出，生成遵循程度需要继续实测；标签渲染沿用已验证实现，历史裸姓名草稿不会自动改写，需重新生成。
