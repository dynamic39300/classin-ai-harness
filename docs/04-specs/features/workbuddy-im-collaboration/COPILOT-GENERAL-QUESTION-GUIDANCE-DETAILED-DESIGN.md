# 班级 AI 消息助手：通用提问引导详细设计

2026-09-15 用户已确认整体方案（包括F组更名）。现按推荐方案进入[实施合同](./COPILOT-GENERAL-QUESTION-GUIDANCE-IMPLEMENTATION.md)；确认不代表代码或真实API已经接通。

## 1. 这轮要解决什么

老师已经能通过顶部的课前、课中、课后和总结建议发起典型任务。现在需要让老师进一步理解：**还可以直接询问本班课程、课堂、作业和学生情况，也可以让 AI 整理资料、报告和消息，并处理群里最新的讨论、题目提问和回复。**

推荐方案是：**真正首次进入时给一句开场和至多三个具体问题；输入框上方常驻一个轻量的“可以问什么”入口；查信息、继续追问、写消息都在当前对话中完成。**

这份文档承接用户批准的推进计划，完成第1步“提问与回答”和第2步“引导交互”的设计交付。具体位置、操作细节和回答样例现已获用户确认；工程进度单独记录，确认不等于全部生产能力已实现。数据基础足以推进设计；未核清的统计和内容读取问题在接入与问答验收中逐项处理，不重新开始一轮大范围查数。

建议审阅顺序：先看第2–5节的页面和点击行为，再看[21条回答样例](./COPILOT-GENERAL-QUESTION-ANSWER-EXAMPLES.md)，最后在第10节标注意见。

### 范围和事实源

- 内容范围见[当前清单 v0.6](./COPILOT-GENERAL-QUESTION-GUIDANCE-CONTENT-DRAFT.md)：原18条加用户确认的群聊F1–F3，共六组21条。新增基于完整题面的解析生成；个体错因诊断、进步评价和个性化指导仍不纳入。
- 数据事实以[逐条核查总表](../../../01-research/COPILOT-18-QUESTIONS-VERIFICATION-MATRIX-2026-09-15.md)为准。样例中的理想回答不是实测模型结果，也不反向修改数据核查结论。
- 当前项目为原版 ClassIn AI Harness；当前开发范围见实施合同；保留原始批注，不修改V2和服务端口。
- 实施阶段继续按 PRD → Tech Spec → Tickets → Implementation → Acceptance 推进。已按确认建立独立实施合同。

## 2. 页面结构：三个位置、各自一个作用

| 位置 | 内容 | 默认呈现 | 与其他区域的关系 |
| --- | --- | --- | --- |
| 现有顶部导航 | AI 消息助手身份、教学阶段与当前建议 | 沿用现有展开/收起规则 | 回答“当前有什么值得做”；数量只统计业务建议 |
| 对话区首次开场 | 一句能力说明、至多3个具体问题 | 只在真正无历史且上下文已就绪时出现 | 回答“除了顶部建议，我还能怎么问”；开始交流后自然上移 |
| 输入框上方 | `可以问什么`文字入口 | 当前班级内常驻，默认关闭 | 随时查看六组问法；不显示建议数、不加入顶部待办 |

顶部沿用当前已审阅实现：名称为“AI 消息助手”；底色复用 `--color-assistant-guide-surface`（当前淡蓝灰）；整条身份栏可点击收起/展开，右侧只保留箭头；对话滚动不自动折叠。本设计不恢复旧的浅绿Hover、播放按钮、新建Session或任务管理入口。

以下是阅读顺序说明，不是新增线框稿：

1. 顶部已有教学阶段导航。
2. 中间是可滚动的对话。首次无历史时，开场放在这里；已有历史时，沿用当前“查看历史”与新消息边界。
3. 对话下方、输入框上缘外侧，右对齐放置 `可以问什么`。
4. 下面继续使用现有输入框、图片、运行时停止和发送。

不在输入框内部恢复已删除的“教学协作”及“可直接说……”占位提示。新的文字入口只在有完整问题内容可查看时启用，进入的是当前班级的可操作提问帮助。

## 3. 首次开场

### 3.1 文案与问题行

结合新增范围，建议将此前能力说明调整为：

> 也可以问本班课程和学生情况，整理群聊、讲解题目，或帮您写回复
> ——同意，好建议！✅

这条文案已经用户确认；顶部教学阶段的既有说明不改。

其下用小字动作提示：

> 点一个问题试试，也可以直接输入

最多展示三个横向占满可用宽度的问题行，右侧使用现有发送箭头图标表示“提问”。整行可点击，静态就能识别为操作；不用大卡片、彩色分类徽章或另一组阶段导航。

示例（仅为设计情境，名称随当前班级替换）：

| 问题行文案 | 选择依据 |
| --- | --- |
| 接下来要上什么课？ | 当前班级排课目录可用；即使没有未来课，也能如实回答未查到安排 |
| 《第3讲方程练习》交得怎么样了？ | 当前有明确的已发布作业及有效分配/提交信息 |
| 把《方程练习指引》里的方法整理成三点 | 存在可读取的具体资料正文 |

上述是没有明确群聊提问时的默认示例。有可读群聊时，可用“总结群里最近两天的聊天要点”替换其中一条；存在已明确引用的问题时，可用“帮我回复许宁关于作业期限的提问”或“讲解周禾问的作业第2题”替换一条，不增加第四条。已有历史只保留长期入口，不因新群消息重新弹首次开场。

选题覆盖查询、内容处理及群聊协作中的不同用途，与顶部可见建议按**问题意图+业务对象**去重。同一作业的“提醒未交学生”和“看提交情况”不是同一意图，可以共存，但有其他合适话题时优先增加多样性。

可用只有两条就展示两条，不凑三条；没有可用具体对象时，只保留能力说明和长期入口。已有完整目录且返回确实为空，是可如实回答的场景；接口尚未接入、加载失败、无权读取，不冒充“暂无任务”。不随机轮换、不自动轮播、不因时间跳动让老师刚看到的问题改变。

### 3.2 出现、离开和回来

| 场景 | 行为 |
| --- | --- |
| 对话恢复完成，确无教师/AI历史，上下文就绪，尚未发起请求 | 显示开场 |
| 历史恢复中或恢复失败 | 沿用恢复/错误提示，不显示假首次欢迎 |
| 有旧历史但当前页面把历史隐藏 | 不显示首次开场；保留“查看历史”和“可以问什么” |
| 第一次请求被成功接收 | 首次说明作为本次页面内的轻量引导自然留在新消息之前；问题操作行退出，防止反复点发。它不成为模型历史中的一条AI回复 |
| 点击后在发送前校验失败 | 原位保留问题，给对应错误及重试；不生成成功的教师气泡 |
| 请求已接收但生成失败/停止 | 作为正常对话回合恢复，不重新弹欢迎 |
| 切换顶部阶段、手动折叠顶部 | 不重插开场、不重置提问帮助 |
| 再次进入已有历史的同一班级 | 沿用历史呈现规则，不重新当新用户；长期入口仍可用 |

这一条件来自当前实现：页面空白可能只是旧消息隐藏，AI仍有上下文。不得通过“当前DOM没有气泡”判断首次，也不得为了展示引导新建Session或清空历史。

## 4. 长期入口：“可以问什么”

### 4.1 位置与视觉

入口放在输入框上方外侧，右对齐，使用正文次级色文字和可选的小问号图标。默认无底色、无边框、无红点、无数量。Hover使用中性浅灰或文字强调，键盘焦点清晰；不使用绿色大按钮，避免与消息发送争抢注意力。

文字必须常见，不仅依赖图标或Hover。与输入框使用现有间距Token，不覆盖或缩改 `WorkspaceComposer` 内部布局。对话生成时仍可访问，停止和发送位置保持稳定。

### 4.2 原位帮助面

点击后在入口上方打开轻量、非模态帮助面，宽度不超过Copilot正文宽度，底部不覆盖输入框或停止按钮。背景用现有白色Surface，保留一层必要的边界；内部用组标题和行距，不再套卡片。

帮助面在同一窗口尺寸下保持固定高度，最终由现有Token和实际可用高度约束；切换分类只更新内部列表，不能推动输入框上下跳动。问题列表仅在帮助面内部滚动，标题与关闭图标固定。可用高度不足时限制在对话正文区域内，确保至少一条问题、关闭入口和输入区可达；不强制收起顶部换空间，也不引入新页面或全屏遮罩。

面板内只保留标题 `试着问我`。入口名称仍为 `可以问什么`，分类与问题本身已经说明操作方式，因此不再重复展示“选一类”“点一个问题”等说明。

下方采用支付宝“技能清单”的分组发现思路，并针对PC侧栏收窄为单层分类架：六个分类紧凑横排，当前分类高亮，下方只展示该分类的可用问题。不进入二级页面，也不同时铺开六组长列表：

| 分组名称 | 保留的问题 |
| --- | --- |
| 班级和课程 | A1、A2、A3、A4 |
| 课堂和学习参与 | B1、B2、B3 |
| 作业和测验 | C1、C2、C5 |
| 某位学生 | D1、D2、D5 |
| 报告和沟通 | E1、E2、E3、E4、E5 |
| 对群聊的内容提问 | F1、F2、F3 |

分类短标签依次使用“班级课程、课堂参与、作业测验、学生情况、报告沟通、群聊内容”。当前分类已经由高亮入口表达，问题区不再重复完整业务名称；完整名称仅作为无障碍区域标签保留。实际问法见回答样例分册。首期不增加搜索框、收藏、换一批、推荐角标或使用次数。21条是内容库，帮助列表按当前具备的能力和可回答边界投影，不要求21条全部同时有效。

具体呈现规则：

- 有明确业务对象时，把“这份作业/这位同学”替换为已知名称，行上显示的就是将提交的问题文字；补充的不可见上下文只携带业务定位和取数范围。
- 涉及某学生但上下文没有明确学生时，显示自然问法“了解一位同学的学习情况”。点击后AI先查本班名单，再在对话里询问对象；不把问号入口变成必经选人表。
- 目录确实为空，可保留能如实回答的问题；能力未接入或缺关键正文时，不展示承诺该结果的主动示例，不堆置灰条目。某组没有合适内容就不展示该组。
- E5仅在已有可承接的内容时出现；E2需要可读课堂原文，C5需要可解释的逐题判分来源。F1需要群消息可读，F2需要可定位消息和完整题面，F3需要明确原问题；这些新能力尚未实测，不以静态建议冒充接入。将来接口补齐时复用相同呈现方式，不需要重做页面。
- 问法限定在当前班级。班级上下文未加载时可浏览通用介绍，但不呈现旧班问题及旧对象名称，不发起对象查询。

打开时焦点进入当前分类的首个问题；分类按钮通过可见标签与`aria-pressed`表达选择。Tab遍历，Enter/Space激活，Escape关闭并回到入口。点击外部可关闭，不抢走用户刚点击的输入框焦点。关闭不修改草稿、附件、当前阶段、历史显示或运行状态。重新打开同班帮助保留当前分类与阅读位置；切班清除旧帮助选择与位置。

## 5. 点击如何发问：正常路径一步完成

同一套规则覆盖首次问题行和长期帮助中的问题。点击提交的是对AI的问题，**不是给学生发消息**。

| 当前状态 | 点击问题后的行为 | 老师看到的反馈 |
| --- | --- | --- |
| AI空闲，输入与附件为空，无消息编辑 | 一次点击即提交；关闭帮助；只生成一次教师气泡，后续进入正常回答 | 气泡原文与点击问题一致，出现真实运行进展 |
| 有未发送文字或图片 | 不立即提交、不覆盖、不暗带附件发送；在输入末尾另起一段加入该问题，附件保留；焦点回输入框 | 帮助面预先标 `点选后加入输入框`；加入后轻提示 `已加入输入框，可修改后发送` |
| AI正在生成/请求正在提交 | 可浏览；点击把问题加入下一轮输入，不排队、不自动停止、不自动执行 | 帮助面标 `生成中，点选可准备下一次提问`；停止仍由老师主动操作 |
| 老师主动停止 | 等待真实停止结果；保留当前输入 | 停止成功才可手动发送下一问；失败可重试停止，不假装空闲 |
| 正在编辑可发送消息 | 不跳走、不覆盖该消息；点选只加入普通提问输入，待退出编辑后手动发送 | `当前消息还在编辑，问题已放入输入框`；保留原编辑和取消/发送动作 |
| 已有可发送草稿但未进入编辑 | 点选先加入输入框，不立刻替换当前产物；老师手动发送新问题表示转入下一轮 | 原草稿留在对话供查阅，当前可执行交付仍只有一份；不得自动发送或自动恢复旧发送按钮 |
| 正在向IM发送消息 | 只允许浏览帮助，本次问题激活暂不可用；不伪装成加入了已被锁定的输入 | `消息发送中，请稍候`；发送结果明确后恢复 |
| 输入长度不足以加入完整问题 | 不截断、不覆盖原输入，不接收部分问题 | `输入内容较长，请先整理后再加入问题` |
| 问题已加入后连续重复点击 | 同次帮助交互对同一问题只加入一次 | 原输入保留；重新编辑或之后主动重复问不被永久拦截 |

这几种例外只为保护老师已有内容；空闲、空输入的主要路径仍是一击即问。首次开场的动作提示与当前状态同步：已有输入时改为“点一个问题加入输入框”，不继续宣称点即发送。

草稿保护覆盖文字、图片及老师手动编辑的消息。复制已有问题行不能绕过运行互斥，切班后晚返回的数据不能更新新班级。已加入输入的问题随后作为普通草稿由老师决定是否修改、删除或提交。

## 6. AI 怎样承接自由提问

### 6.1 自动补上下文，少问老师

先使用当前班级和对话中的明确对象，再按问题读取所需资料；不把老师带到课程、活动、学生的多步配置流程。后台保留完整证据，不向老师常驻显示表名、API、上下文加载量或数据采集说明。

只在影响答案的真实歧义出现时补问。例如同班有两份近期方程作业，可在对话中问：

> 您想看哪份作业的提交情况？
>
> 《第2讲方程练习》 · 9月14日截止
>
> 《第3讲方程练习》 · 9月16日截止

候选是AI这次补问中的两个轻量操作行。点选相当于回答本轮问题，继续原任务；老师也可以输入“第二份”。不重新提原问题，不打开表单，不重复选择已知班级。候选较多时先请老师补课程名/关键词，不展示几十名学生或活动的长选择器。

“最近”按近7个自然日（含今天）处理，并显示实际起止日期；“本周”按周一至周日，进行中的本周只汇总至查询时点。业务服务提供的有效时区优先；当前演示使用Asia/Shanghai。只取得课程累计报告时明确它的真实周期，不换名为近7天。

### 6.2 四种输出保持区分

| 意图 | 输出 | 后续动作 |
| --- | --- | --- |
| 查事实 | 一句结论 + 必要名单/时间/小表格 | 直接在输入框追问，不默认出现发送按钮 |
| 整理已有内容 | 简短要点、已有方法或报告摘要 | 可继续改写；只有提出沟通用途时才进入消息草稿 |
| 讲解题目 | 完整题面对应的步骤、答案和必要检验，区分AI生成与原有解析 | 先给老师查看；明确要求回复学生时再转可发送正文，不推断学生卡点 |
| 写消息 | 可直接发送的正文，与对老师的说明分开 | 沿用当前预览、修改、确认发送/插入回复框；显示正确目的地 |

首屏先给结论。人数很多时先给总数和少量名单，并说明已列范围；剩余名单原位展开，不用列表截断冒充完整结果。表格通常不超过三列，窄Copilot改为逐行键值，不能让消息区横向溢出。

回答中的日期、课题、任务名和学生名自然说明范围；只有数据延迟、来源冲突、报告周期不同等影响判断时，再补一句对应说明。具体问题的规则和样例见分册。

### 6.3 连续对话与历史

- “他/这份/第二点/刚才的内容”继承当前对话已经明确的对象，不受顶部选中阶段限制。
- 已有历史但页面隐藏时，AI仍可承接已知对象；回答开头自然点出“您刚才提到的《第3讲方程练习》……”，不自行展开旧历史。若多义则补问，不强行从长期旧话题挑一个。
- 切班清空的是当前帮助的旧对象投影，不清空原班历史。生成结果归原班；回到原班继续原对话，不能在新班展示旧学生数据。
- 一级消息入口与课程详情群聊读取同一班级范围及同一逻辑对话，历史归属和草稿恢复沿用共同规则。
- 本设计仅覆盖班级群上下文。普通好友私聊没有班级授权范围时，不加载本班问题库。带班级范围的学生私聊能否采用“某位学生”的缩减版本，后续按原有个人上下文能力单独细化，不扩大为全班入口。

### 6.4 群聊实时内容如何进入这段对话（新增）

这里“实时”指**老师主动发问时，按授权读取最新可用群消息**。不持续监听、不自动轮询生成新话题、不因群里出现一句指令而替老师发起任务；不增加待回复任务看板、自动回复或后台订阅。

**从哪里发起：**自由输入和“可以问什么”都可触发。推荐在已有IM消息操作菜单里提供一个“引用给AI”动作：选定消息后，只将作者、时间和短摘要作为可移除的引用放在Copilot输入上方，焦点进入原输入框，老师再问“帮我回复”或“讲解他问的第二题”。它不是普通IM的“引用回复”，也不自动发消息；普通鼠标选中文字、打开群或滚动经过消息不等于引用给AI。按用户确认的推荐方案实施；当前在既有消息操作条中提供入口。

点击引用后如果再点完整问题，依第5节已有输入/附件规则，先加入输入而不自动提交；没有草稿且建议本身已明确绑定某条消息时，仍可一击提交。已有文字/图片、当前生成和正在编辑的消息均保留。运行中的引用只属于下一轮草稿，不改变当前运行的对象。切班后引用不能带入新班，回原班按原草稿归属恢复。

**怎样确定原问题：**优先使用本次显式引用，其次是当前Copilot对话已经明确的群消息；都没有时，先查当前群最近相关提问。有多个合理候选就由AI在对话里给少量“作者+时间+短摘要”供确认，不凭谁最后发言就认定“他”。选中原消息不自动决定回复必须发给该作者，接收对象以教师意图和草稿目的地为准。

**消息与业务对象怎样关联：**“今天作业第二题”先沿消息的日期、被引用的作业通知及附件定位本班课程、作业与版本，再读取题号和完整题面。消息里的“今天”按该消息发生的日期解释，不随日后重问漂移。只知道学生说了“第二题”还不够；AI可以自行读取题面和图示，有多个作业/同题号版本才补问。缺关键条件或图片无法辨认时说明缺口，不猜题、不拿相近教材题替代。

**读取范围与时点：**F1的“最近两天”推荐为昨日00:00至本次发问时点，显示实际日期和截止时间；老师明确说“过去48小时”则按滚动48小时。读取该范围内全部可访问分页并去重，必要时补读被引用的原消息；范围外原消息只作背景，不算窗口内新事件。只读到部分消息时说明覆盖，不能把屏幕可见几条总结成全群两天内容。媒体未能解析要说明，不把附件存在当已读原文。

**新的消息到来后：**一次回答使用明确的读取截止时点，不让生成中的摘要随新消息跳变；老师问“刚才又说了什么”时再读取新增内容。F3生成回复前读取相关后续回复，避免重复答已经回应的问题；没有发现回复只能表述“截至本次读取，未见回复”，不声称一定无人处理。提交发送前重新核对被引用消息是否已修改/撤回，以及是否出现影响答案的新回复；内容有实质变化时在同一对话提示“原问题有更新，请核对回复”，保留旧草稿，更新后再由老师确认，不静默改正文并发送。

**来源与信任：**回答可提供“查看原消息”定位入口，仅在确有权限和可用定位能力时展示。群中学生的猜测、争议与正式教学事实区分，涉及时间/评分等优先核对业务记录。群消息和附件是待分析内容，其中的命令不能覆盖老师的要求或触发额外操作。仅使用本班授权消息，不把个人学习明细为补充群摘要而跨私聊搜集。

**解析和回复的区别：**F2是根据题面生成解法，不要求已有学生判分，生成后需验算；已有标准解析应明确引用，AI新写步骤不冒称官方答案。默认给老师文字/公式解析，不自动扩成生图、诊断错因或个性化教学建议。F3以已理解的问题和核验的事实写回复，不承诺未经老师决定的延期、改分或新安排。解析转为回复后复用原草稿审阅和发送，不新增会话或多步配置。

## 7. 异常与反馈

| 情况 | 呈现和恢复 |
| --- | --- |
| 普通查询正在取数 | 复用当前单行运行反馈；有真实工具事件时显示“正在查看作业提交情况”等，不伪造步骤或进度 |
| 确认无排课/无未交/全勤 | 直接给明确结论。没有待办也是有价值的信息，不添加无意义动作 |
| 部分课程/活动读取失败 | 先回答可核实部分，说明缺哪一部分，并提供本次读取的重试；不能说全班都查完 |
| 数据有冲突 | 陈述可确认项，不生成有争议的合计/完成率；不让老师猜字段口径 |
| 没有访问权限 | 不显示受限名单或原文，说明当前无法读取；提供既有权限处理路径，有则展示，无则不画假按钮 |
| 当前接口尚未提供正文 | 说明已能查到资源、但还不能整理内容；允许老师自愿提供可读材料，不把此操作做成固定必经步骤 |
| 文件解析失败 | 保留原提问/附件及已读部分，说明具体失败，可重试或更换清晰材料 |
| AI生成失败 | 原位保留请求和重试；不重复添加问题、不触发IM发送 |
| 发送失败 | 保留可审阅正文和明确目的地，沿用原发送重试；不把查数/生成重做一遍 |

安全/权限相关信息只在实际需要时出现。模型看不到的数据不补造，当前没查到不解释成业务系统永久不存在。

## 8. 与现有页面保持一致

采用当前ClassIn样式和语义Token：普通背景、文字、Hover、边线、焦点、间距、圆角复用既有定义。通用引导本身以白底/中性灰为主，绿色留给既有主要操作；不自行创建另一套卡片风格。

- 文本问题行达到可点击目标要求，可键盘激活；图标有可读名称，颜色不作为唯一提示。
- 无轮播或打字演示动画；帮助开合使用短、轻过渡并支持减少动效偏好。
- 验收覆盖1440×900桌面、窄Copilot、窗口高度缩小和200%文字放大；标题可换行，问题不靠省略号隐藏关键课程/对象。
- 只由对话/帮助自己的容器滚动，页面Body不因展开帮助开始滚动；输入、停止、关闭可达。
- 最新[对话行为规格](./COPILOT-CONVERSATION-RUN-UX-FEATURE-SPEC.md)已补充淡蓝灰底色、整栏点击折叠、默认隐藏旧历史及新消息边界。本设计按这些当前行为兼容，不按过时截图重置。

| 群聊闭环 | F1消息总结、F2消息到题目、F3针对问题回复 | 核验最新消息分页/权限、题面定位与解法、引用原消息及发送前更新；不持续监听 |
| 覆盖扩展 | 其余问题沿相同对话路径接入 | 21条均有正常、空记录或能力缺口的真实处理；高要求正向场景另补数据验证 |
| 最终验收 | 两个IM入口、数据对照、模型回答、视觉与键盘 | 给出逐条通过/部分通过及原因，不以接口成功率代替回答准确率 |

本设计的最低验收清单（新增F组按独立数据链路验证）：

1. 无历史显示开场；恢复中、历史被隐藏时不假冒首次。
2. 空输入点击问题只发一次，展示的问法与教师气泡一致。
3. 已有文字、图片、消息编辑均不被覆盖或误发送；运行中点问题不并发、不自动排队。
4. 只有老师主动操作改变顶部展开/收起；打开帮助不改变建议数量或业务状态。
5. 自由问法和示例问法触发相同能力；切顶部Tab不锁定检索范围。
6. 同名/多对象通过对话补问，已知对象自动承接；切班不泄漏原班信息。
7. 普通查询不带群发送动作；家长草稿不误发班级群；任何IM发送仍由老师确认。
8. 数据真空、查询失败、未作答、未评分、逾期和统计冲突均正确区分。
9. 消息正文、目的地、修改和最终交付与现有合同一致；发送失败可恢复。
10. 六组共21个保留ID可追溯，不静默恢复已退出问题；UI只呈现可支撑的问法。

11. F1消息窗口、分页和截止时点清楚；不把争议写成定论、不把未见回复说成未处理。
12. F2先定位作业版本和完整第2题，再生成并检验解析；无判分不妨碍讲题，缺题面不能猜题。
13. F3引用、已有后续回复、原消息撤回/修改与草稿目的地正确处理；生成与最终发送均受教师控制。
