# 问题与目标

当前 IM Sidecar 把一次 TeachBuddy 协作拆成教师消息卡、分析步骤卡、Agent 回复卡、草稿审阅入口和草稿编辑卡。窄侧栏内连续的边框、标题、状态和按钮让老师像在操作任务后台，生成的消息反而失去视觉主位。

本轮把一次协作收敛为连续的对话回合：**老师提出要求，TeachBuddy 用一条业务进展说明正在做什么并直接呈现可使用的结果；只有这一轮明确产出消息草稿时，才让老师在结果旁完成审阅和发送。** 可审计过程继续存在，但只作为老师主动展开的辅助证据。

# 用户结果

1. 老师能连续读懂自己说了什么、TeachBuddy 正在做什么、生成了什么以及接下来可以做什么。
2. 运行过程使用教学业务语言，不要求老师理解步骤数量、MCP、模型响应或内部 Session。
3. 最终回复和可发送消息是视觉主角；页面不再出现卡片套卡片。
4. 顶部教学任务和老师明确提出的消息写作要求可直接进入审阅；查询、分析和普通咨询不会被误判成群消息。
5. 老师可取消消息编辑并回到原回答；采纳或修改后发送时，本轮自然结束，不再显示“业务已完成”状态卡。
6. 老师在生成期间仍可输入下一条要求，并可在输入区停止当前生成；已有输入不丢失。

# 主流程

```text
教师消息气泡
  ↓
TeachBuddy · 正在核对本次课堂到课情况 · 6s
处理过程（按需展开）
  ↓
最终回复
  ├─ 普通查询 / 分析 → 留在对话
  ├─ 沟通建议 → 可选“整理成群消息”
  └─ 明确消息草稿 → 查看正文 → 直接发送 / 修改文案后发送 → 消息进入 IM
```

# 页面结构

一次对话最多出现两个有背景的内容容器：

- 教师消息气泡；
- 需要编辑和发送的消息正文。

TeachBuddy 身份、实时进展、处理依据、普通解释和结果操作使用自然排版、留白与细分隔线，不再分别包装成悬浮卡片。顶部教学动态仍是独立的任务发起入口，不属于本轮对话内容。

# 内容与状态

## 运行中

状态行显示 `TeachBuddy · 当前业务动作 · 实际耗时`，例如：

- 正在理解你的要求；
- 正在核对本次课堂到课情况；
- 正在整理缺勤学生提醒；
- 正在生成可以发送的话术。

没有真实 Runtime Event 时只能显示“正在理解你的要求”，不能伪造数据读取或能力调用。

## 处理过程

折叠入口命名为“处理过程”。展开后显示来源于 Runtime Event 的产品级摘要和经治理证据，不显示原始思维链、Prompt、数据库、SQL、密钥或内部协议。Sidecar 中固定最大高度并局部滚动；运行和完成时默认折叠，失败或需要补充时默认展开。

## 等待老师操作

回答生成后直接呈现结果。只有以下情况提供“修改文案”“直接发送”两个动作（私聊使用“插入回复框”）：

- 老师点击顶部教学动态中的可行动任务；
- 老师在自由对话中明确要求写、拟、生成、改写或发送消息、通知、提醒或回复。

查询、分析、总结事实和普通咨询只显示回答。老师在询问“怎么提醒”“如何回复”等沟通建议时，可以得到一个低强调的“整理成群消息”或“整理成回复”动作；点击后由 TeachBuddy 另起一轮生成真正的消息草稿，不直接把建议正文放入编辑器。

进入编辑态后，结果原位替换为可编辑消息正文，不再新增一张重复草稿卡。编辑器只接收可直接发送的消息原文；“好的，王老师”“以下是……”、生成背景、分隔线、标题、要点说明和结尾调整建议均留在对话回答中，不进入草稿。编辑区同时提供“取消”：点击后丢弃本次未发送修改、恢复原回答和审阅入口，不发送、不新增取消状态卡。

无需额外显示“等待老师操作”状态徽标；正文和操作本身已经表达当前状态。

## 发送后

群消息成功进入当前会话，或私聊回复插入对应输入框后，本轮即结束。Sidecar 不保留“业务已完成”“已采纳”或成功回执卡；实际 IM 消息或输入框内容承担结果反馈。失败时保留编辑内容和可恢复错误。

# 交互要求

- 教师消息右对齐，不重复显示“您”标题；
- 审阅和发送只出现在具有消息交付意图的回合；
- 编辑态提供“取消”，并原位恢复该轮回答；
- 每轮只显示一次 TeachBuddy 身份；
- 处理过程整行可点击，具有 `aria-expanded`、键盘焦点和状态播报；
- 展开过程不把 Composer 推出可视区域；
- 运行期间 Composer 可编辑，发送命令不可用，停止命令持续可达；
- 用户上滚阅读历史时，Runtime 更新不抢滚动位置；
- Reduced Motion 下移除旋转以外的非必要过渡，并提供静态状态差异。

# 范围

本轮只调整 ClassIn IM 右侧 TeachBuddy Sidecar。主 TeachBuddy 工作台继续遵循 D-123 的完整可审计分析形态；不修改 Runtime 协议、消息写回 Gate、上下文权限、教学动态内容、真实 Adapter 或学生端。

# 验收标准

1. 一次普通生成不再同时出现分析卡、Agent 回复卡和独立草稿卡。
2. Sidecar 完成态不显示步骤数量或“已完成分析”。
3. 教师消息没有“您”标题，Agent 回复没有重复的 TeachBuddy 卡片标题。
4. 处理过程可展开，最大高度受控，来源仍为真实 Runtime Event。
5. 生成期间可继续输入并停止；停止后草稿仍在。
6. 审阅态原位替换当前最终回复；发送后不保留成功状态卡。
7. 失败、停止、需要补充和发送失败均保留可理解的恢复路径。
8. TypeScript、Lint、相关 Vitest、IM Playwright 和 1440×900 视觉检查通过。
9. 普通课程查询不出现消息审阅入口；沟通建议只出现轻量转换动作；明确写消息和顶部任务仍可进入审阅。
10. 取消编辑后不发送消息、恢复原回答，重新审阅时从原始生成结果开始。
11. 审阅编辑器只包含消息正文，不包含 Agent 对老师的开场、背景解释、写法说明或结尾建议。

## 2026-09-15：结构化正文与明确发送动作（用户已确认）

- IM-CRUX-06：并列安排逐项换行，主题分段，短提醒保持简短；模型说明不进入待发送正文。预览、编辑和发送共用正文。
- IM-CRUX-07：草稿下显示“发送至：班级名”；次按钮“修改文案”，主按钮“直接发送”。点击主按钮即代表对眼前正文的发送确认，不再进入编辑器或弹二次确认；发送前的权限、目标、上下文复核不省略。
- 编辑态保留“取消”“确认发送”；空正文不可发送。发送中显示“发送中…”，禁止重复点击；失败保留正文并显示“重试发送”；成功用一行“已发送”反馈，不新增成功卡片。
- 本次修改优先于本文件旧版“实际IM消息独自承担反馈”的表述；私聊仍只插入，不增加自动私信能力。一级消息和班级详情共用同一组件。

- IM-CRUX-08（2026-09-15 用户补充）：Copilot 中的 @所有人、@单个/多个已知学员以一致的浅蓝底标签区分。保持原文及发送行为，不增加操作或说明文案。

- IM-CRUX-09（2026-09-15 密度修订）：草稿减少不必要的标题、短句拆行和段间空白；课程日程保留列表。当前草稿即时缩小视觉间距，新生成内容按同主题连贯表达；不通过改写历史正文压缩空间。
