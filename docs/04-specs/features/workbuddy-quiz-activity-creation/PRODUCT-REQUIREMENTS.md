# WorkBuddy 对话生成测验并创建教学活动草稿 PRD

## 1. 背景与目的

一级 WorkBuddy 已有“生成单个课件”和“生成课程方案包并写入 ClassIn”的可运行闭环，但教师仍需离开对话、进入复杂表单逐题录入，才能把一次即时测评沉淀为课程教学活动。新增场景要证明同一个统一主 Agent 可以把“生成内容”继续推进到“形成 ClassIn 草稿对象”，同时把正式发布权稳定留在 ClassIn 课程详情。

本场景不是再生成一个普通文件，也不是让 Agent 代替教师发布。它是第三个独立 Task Type：`生成测验并创建教学活动草稿`。

## 2. 用户与 Job

主要用户是当前班级课程的教师。典型 Job：

> 我刚完成一个单元，希望快速生成一份可用于诊断掌握情况的测验；我愿意在 WorkBuddy 中确认题目结构和活动参数，但正式使用前仍要回到班级课程详情逐题复查、修改并亲自发布。

## 3. 成功定义

1. 教师通过自然语言提出测验目标，WorkBuddy 结合已确认的班级、课程、单元和课程资料生成结构化试卷草稿。
2. 教师能审阅试卷题目、答案、解析、难度与分值，并能确认活动标题、时间、答题限时、评分方案和归属位置。
3. 写回前明确展示差异、目标和“仅创建草稿，不会发布”；未经教师批准不写入 ClassIn。
4. 成功回执只声明“测验活动草稿已创建”，提供前往班级课程详情的入口。
5. 班级课程详情能看到同一个草稿对象；教师可二次编辑，并通过独立的“发布”命令使其对学生可见。

## 4. 核心旅程

```text
教师描述测验目标
  → WorkBuddy 建议并确认班级 / 课程 / 当前单元 Context
  → 交互面确认试卷结构并开始生成
  → WorkBuddy 连续展示整理方案、分析目标、组织题型、生成答案解析与校验
  → 自动形成 QuizPaperArtifact 并进入独立试卷审阅检查点
  → 右侧自动打开完整试卷，教师审阅题目、选项、答案与解析
  → 教师确认当前试卷版本
  → 交互卡确认测验活动参数
  → ProposedAction：在当前单元创建“测验”草稿
  → 明确提示“仅草稿，不发布”
  → 教师 Approval
  → ClassIn Adapter 校验权限、目标版本与幂等键
  → ExecutionReceipt：草稿已创建
  → 前往班级课程详情
  → 二次编辑
  → 教师在 ClassIn 页面显式发布
```

## 5. 试卷内容需求

首个固定 Demo 采用“高二物理 3 班 / 动量与碰撞 / 第一单元 受力与动量”的单元诊断测验，生成 5 题、总分 100 分：单选题、多选题、判断题、填空题、问答题各 1 题。每题包含稳定 ID、题型、题干、分值、难度、正确答案和解析；选择题包含选项。综合题能力保留在领域枚举中，但首个 Demo 不生成。

教师在 WorkBuddy 中可以整体预览试卷及教师版答案。本期不建设完整富文本逐题编辑器；详细二次编辑在 ClassIn 课程详情承接。

## 6. 活动参数与交互卡

参考 `reference/Classin-新建测验/` 中的 17 张截图，字段分为两组：

### 6.1 WorkBuddy 必须确认

- 活动标题、说明；
- 开始时间、截止时间；
- 答题限时：不限时、10/40/60/90/120 分钟或自定义；
- 评分方案：分数制、百分比、优良评分、ABCD、不评分；
- 班级、课程、当前单元；
- 试题数量与总分摘要。

### 6.2 题目结构中承载

- 题型：单选、多选、判断、填空、问答、综合；
- 题干、选项、答案、解析、难度；
- 填空题多答案、顺序/大小写容错作为后续详细编辑能力。

### 6.3 首期不进入 WorkBuddy 表面

- 从题库选题、保存到“我的题库”；
- 新建班级、新建课程、新建单元主题；
- 自定义评分方案管理；
- 批量导入、下载试卷和完整富文本编辑器；
- “更多设置”中尚未由截图确认的字段。

这些字段不能由实现猜测；后续只有获得确定业务定义后才进入独立需求。

## 7. 产品规则

- `QuizPaperArtifact` 是 WorkBuddy 产物；`QuizActivityDraft` 与正式发布状态由 ClassIn 拥有。
- WorkBuddy 只允许在已确认 Context 的当前班级、课程和单元创建草稿，不提供任意目标选择器。
- 参数卡优先使用 Context 和合理默认值预填，只追问缺失或影响结果的字段，不复制整张 ClassIn 表单。
- “批准创建草稿”和“发布测验”是两次不同命令、两个不同权限检查和两份不同回执；WorkBuddy 不得调用发布命令。
- 草稿对教师可见、对学生隐藏。正式发布后学生才能看到。
- 重复确认使用同一幂等键只创建一个草稿；相同幂等键但载荷不同必须失败关闭。
- 生成、审批、执行和评价均保留 Run、ContextSnapshot、Artifact、Action、Approval、Receipt 引用。
- UI 只说明当前是 `[模拟]` 体验，不暗示真实模型或生产 ClassIn API 已接入。
- 系统拥有的生成步骤自动连续推进；只有试卷结构、试卷内容审阅、活动参数和最终写回是教师确认点。刷新发生在生成中时恢复同一 Run 阶段并继续，不增加“开始生成”或“继续设置”活动按钮。
- 试卷结构不是静态摘要：WorkBuddy 以问答确认面询问题型和总分，教师修改后再生成；当前 Demo 的题量由所选题型决定，生成产物必须与确认值一致。
- Run 底部持续提供统一聊天输入框，教师可补充要求并在时间线看到 WorkBuddy 的可见回应。
- 产出完成前不展示空白试卷 Inspector；生成完成后自动展开右侧试卷并停在审阅检查点，同时保留时间线“查看生成的测验试卷”入口。教师确认试卷后才显示活动参数。

## 8. 显式状态与恢复

覆盖 `needs_context`、`needs_parameters`、`plan_ready`、`generating`、`awaiting_paper_review`、`awaiting_activity_parameters`、`awaiting_approval`、`creating_draft`、`draft_created`、`permission_denied`、`version_conflict`、`recoverable_failure`、`timeout`。

- 权限拒绝：不创建活动，返回选择有权限目标/联系管理员的终止路径；
- 版本冲突：重新读取当前单元并重新确认；
- 超时/可恢复失败：明确未产生可确认副作用后，才允许同幂等命令重试；
- Receipt 证据不匹配：进入人工复查，不生成 Evaluation，不盲目重试；
- 已创建草稿：不在 WorkBuddy 内继续发布，只允许前往详情或结束任务。

## 9. 需求 ID

- `WQ-PRD-001`：新增独立 `quiz-activity-creation` Task Type，不并入单课件或课程方案包。
- `WQ-PRD-002`：Context 必须唯一确认班级、课程和单元。
- `WQ-PRD-003`：通过结构卡生成可审阅的 QuizPaperArtifact。
- `WQ-PRD-004`：首个 Demo 生成 5 题、100 分、答案与解析完整的固定测验。
- `WQ-PRD-005`：通过活动参数卡确认标题、说明、时间、限时、评分和归属。
- `WQ-PRD-006`：写回前显示精确目标、差异、影响与“仅创建草稿”。
- `WQ-PRD-007`：只有 ProposedAction + Approval + 领域校验通过后才创建草稿。
- `WQ-PRD-008`：成功 Receipt 返回稳定草稿 ID、版本和课程详情 URL。
- `WQ-PRD-009`：课程详情显示同一草稿，支持编辑并通过独立命令发布。
- `WQ-PRD-010`：学生不可见草稿，发布后才可见。
- `WQ-PRD-011`：权限、冲突、超时、可恢复失败和证据不匹配均有显式恢复。
- `WQ-PRD-012`：评价事件只记录草稿采纳/写回，不推断教学效果或正式发布。
- `WQ-PRD-013`：生成 Run 使用连续动态时间线，逐步投影系统工作；中间系统步骤自动推进，必要教师检查点不得被越过。
- `WQ-PRD-014`：题型与总分通过对话式确认面填写，并真实决定 QuizPaperArtifact 的题量、分值与校验摘要。
- `WQ-PRD-015`：任务窗口持续提供标准 Composer，并将补充要求和回应投影回当前时间线。
- `WQ-PRD-016`：试卷生成前不展示预览；Artifact 到达后由显式入口按需展开/收起右侧 Inspector。
- `WQ-PRD-017`：Run Header 与辅助区复用标准工作台契约：标题、状态、上下文/产出计数和文字收起命令位置稳定；上下文与产出在单一辅助区切换，版本仅作为 Artifact 元数据。
- `WQ-PRD-018`：试卷生成后先进入独立审阅检查点，自动打开试卷产出；未确认当前 Artifact 前不得展示或提交活动参数。
- `WQ-PRD-019`：试卷确认形成绑定 Artifact ID/version、教师和时间的显式审阅证据；ProposedAction 只允许引用已确认版本。

## 10. 范围外

真实模型、真实 ClassIn API、真实题库、真实富文本/公式编辑器、自动发布、定时自动发布、考试监考、防作弊、自动批阅、学生作答页、成绩分析、生产持久化与跨设备同步均不在本期。

## 11. 验收标准

- 从一级 WorkBuddy 可发起并完成上述完整旅程；
- 未审批前班级课程中不存在新活动；一次审批只产生一个草稿；
- WorkBuddy 与课程详情展示相同草稿 ID、标题、题数、总分与目标单元；
- 草稿标签、二次编辑入口和独立发布动作清晰；
- 学生视角在发布前不可见，发布后可见；
- 关键 Domain、Adapter、Integration、E2E、a11y 与 1440×900 视觉检查通过。
