### 2026-09-17 具名学生自然问法回归

用户复核旧审阅回答时发现，“请总结测试学生B本周的学习情况”没有带入成员级课堂考勤。根因是旧路由只识别包含“同学/学生”的 D1 问法，具名学生加“本周学习情况”落入普通活动详情，只得到班级应到/实到汇总，无法判断具体到课人。

当前路由以授权班级名册中的精确姓名识别 D1，仍要求姓名唯一归属；真实 Context 复测已返回测试学生B本周三节课堂的成员级结果，其中第2讲为到课、在课1364秒，另外两节为缺席且请假状态未知。班级范围的“我们班本周学习情况”继续进入 E4，不因本次规则扩大而误路由。

### 2026-09-17 草稿发送复核与群聊结构化呈现回归

用户在课程进度与逐题统计草稿上复现“生成草稿后业务事实已经变化”，但业务对象实际未变化。根因有两层：发送前复核丢失原始老师问题，导致重新取数时切换到默认路由；逐题统计和周学情聚合版本把读取时间计入摘要，导致相同业务事实的连续读取产生不同版本。

当前发送复核沿用生成草稿时的原始问题、对象引用和引用消息；聚合版本只包含业务状态、对象和统计结果，读取时间继续保留为证据元数据但不再触发假过期。真实接口连续读取已验证逐题统计版本稳定，业务事实发生变化时仍由状态和结果摘要产生新版本。

群聊消息使用共享 `RichTextContent` 渲染，支持标题、表格、有序/无序列表、加粗、斜体、引用和链接。样式只有在草稿正文包含对应 Markdown 结构且消息成功进入群聊后出现；不把普通列表自动伪造成表格或标题。浏览器回归已验证成功发送后不存在原始 `**` 或 `| --- |` 标记，宽表保持在消息气泡内横向可达。

### 2026-09-17 表格选择与阅读层级回归

用户进一步要求录播进度、课程进度等结构化事实在适合时使用表格。Runtime 现按数据形态选择表达：至少两个同类对象共享字段，或单个对象包含至少四项简短属性时使用 GFM 表格；逐人进度另表呈现。单个事实、步骤、叙述和长文本继续使用段落或列表，不为排版补造字段，也不重复陈述表内事实。

共享 `RichTextContent` 统一强调表头与第一列行标签，因此 AI 审阅区和发送后的聊天气泡保持相同结构与视觉层级。浏览器测试同时核验语义表格、首行和首列字重、Markdown 控制符消失、气泡无横向溢出及严重级可访问性违规为零。
