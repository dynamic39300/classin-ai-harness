# 1. 背景与决策请求

用户已完成独立 API 审阅台两阶段验收，认为整体约 85% 符合预期，并确认继续沿“老师提问 → 模型选择只读工具 → 真实业务接口取数 → 结构化 Context → 模型回答 → 教师审阅”的框架实施。85%表示整体方向和问答效果评价，不是接口覆盖率、逐字段准确率或生产就绪度。

本 PRD 提议把审阅台验证过的取数与回答合同接入当前 ClassIn Copilot Demo。接入后，教师仍在原消息页面使用 `AI 消息助手`；页面结构、交互和稳定文案不变，班级、课程、学生、时间、任务、课堂内容等业务槽位由真实测试 API 填充。

用户已确认本轮需求文档没有问题，并补充要求四阶段无任务空态以及约10条推荐Prompt做到不重不漏。进入实现的批准基线包括本 PRD、[Feature Spec](./FEATURE-SPEC.md)、[21题验收矩阵](./ACCEPTANCE-MATRIX.md)、[四阶段与10条推荐覆盖矩阵](./TEACHING-DYNAMICS-COVERAGE.md)和[里程碑计划](./MILESTONE-PLAN.md)。

# 2. 产品目标

1. 在现有 Copilot Demo 内回答六组21类教师问题，不要求教师理解工具、接口或模型路由。
2. 每次回答使用与问题直接相关的真实 ClassIn 测试业务数据；真实 API 不可用时明确说明缺口，不静默回退到模拟业务事实。
3. 保留教师对回答匹配、相关性和质量的核心评价方式；工程侧负责工具选择、字段映射、对象归属和证据充分性。
4. 保留现有生成、修改、审阅和确认发送流程。普通 IM 正式发送未通过前，发送仍明确为老师端模拟回执。
5. 按里程碑逐批接入，每批可独立验证和回退，不等待21题全部完成才获得价值。

# 3. 用户体验范围

## 3.1 保持不变

- 消息页左侧会话列表、中间消息区、右侧 Copilot 布局；
- `AI 消息助手` 名称、头像和固定引导文案；
- `课前 / 课中 / 课后 / 总结` 四阶段建议；
- 六组21类通用问题的入口、连续对话、停止/恢复、历史和重试；
- 消息引用、草稿修改、教师确认和回执状态机；
- 图片产物、下载、重试和消息顺序；
- 当前设计 Token、密度、滚动和响应式行为。

## 3.2 新增行为

- 授权测试班以独立真实 Thread 进入消息工作区，与固定演示班的历史、Context、草稿和运行隔离；
- 教师输入问题后，DeepSeek 从允许的只读业务工具中选择所需工具；
- 运行前绑定明确班级、课程、课堂、作业或学生对象；存在多个合理对象时先追问，不自行猜测；
- 回答使用真实业务 Context，并在需要时提供简洁来源说明、数据时间和限制；
- 页面保留失败、部分成功、需补对象、权限拒绝和可重试状态；
- 开放式提问复用同一工具目录和对象约束，不获得任意 URL、shell 或写工具。

## 3.3 本轮明确不做

- 生产账号、多租户SSO和生产发布；
- 未经教师批准的自动发送、自动改期、自动批改或业务写回；
- 把普通 IM 捕获快照冒充稳定生产消息 Reader；
- 把课后考勤报告冒充课中实时在线名单；
- 把 ASR、AI授课分析或群聊自述提升为正式学生事实；
- 个体错因诊断、进步评价、学习态度判断和自动教学决策；
- 为真实接入另建一套页面或把接口字段直接暴露给教师。

# 4. 数据真实性等级

每份 Context 证据必须具备一个内部等级，页面按需用业务语言表达：

| 等级 | 定义 | 可用于回答 |
| --- | --- | --- |
| `FORMAL_FACT` | ClassIn正式业务记录，如活动、提交、批阅、课后报告 | 可直接陈述，但受对象和时间范围约束 |
| `CAPTURED_FACT` | 已登录客户端在明确时间窗取得的真实消息或事件 | 可总结实际取得部分，不声称完整历史 |
| `TEACHER_NOTE` | 当前教师本人笔记 | 可作为教师记录，不当作授课时间轴或学生表现 |
| `MACHINE_TRANSCRIPT` | 回放文件对应ASR | 可归纳讲解内容，需保留误识别和文件主题冲突边界 |
| `AI_DERIVED` | AI授课分析、摘要、评分或推断 | 只能作为辅助线索；与正式事实冲突时降级或排除 |
| `SIMULATED_DELIVERY` | 当前老师端模拟消息发送/回执 | 只表示Demo交付，不声称学生收到、已读或真实送达 |

# 5. 分批产品范围

## 批次一：审阅台已验收的10题

`A1、A2、A3、A4、B1、C1、C2、E1、E2、F1`。前九题使用实时只读 API；F1 首期使用已验证真实捕获链并标明实际时间窗，稳定 Reader 未完成前不宣称完整历史。

## 批次二：已有底层数据的扩展题

`B2、B3、C5、E3、E5`。需要跨课堂/活动聚合、录播逐人进度、逐题统计、资料正文和连续对话草稿复用。

## 批次三：个人学情与班级周报

`D1、D2、D5、E4`。优先接学情报告/学情 Agent 的正式 Interface；在正式合同未提供前，只允许使用已验证活动事实做有覆盖率说明的受限聚合。

## 批次四：群聊引用与回复

`F2、F3`。依赖稳定普通 IM Reader、消息引用/撤回/修改核验和作业题目定位；真实发送不作为只读接入的完成条件，教师确认后仍可生成可复制或模拟发送的草稿。

# 6. 成功定义

计划整体成功需要同时满足：

1. 21题在验收矩阵中均有明确状态：`PASS`、`CONDITIONAL_PASS`或`BLOCKED_EXTERNAL`，不得以模拟事实伪装通过；
2. 已预验证10题在 Demo 内全部完成真实对象选择、工具路由、取数、Context、DeepSeek回答和页面恢复；
3. 每道进入 `PASS` 的题，当前验收样本中的关键事实与原始接口逐项一致，不能出现对象串线、时间错位、人数/状态误算或无证据结论；
4. 用户对该题最新回答的“匹配、相关、质量”均至少为“基本满意”，且没有阻断性事实错误；
5. 模型只执行目录内工具，身份、对象、URL和分页不能由模型覆盖；
6. 真实接口失败时保留原错误和重试，不显示虚构成功；
7. 固定模拟班与真实测试班的 Thread、Runtime Session、Context、草稿、历史和回执隔离；
8. 原 Copilot 模拟基线、两个入口、消息引用、历史、草稿交付和恢复回归通过；
9. 1440×900、1100×720和390×844关键流程可达，无横向溢出、遮挡或不可操作控件；
10. 不向浏览器、模型输入、日志或仓库暴露 Token、报告票据、签名URL、回放FileId或未授权学生数据。
11. 四阶段始终完整可见；无事项、已核对无动作和数据未知三种状态不混淆；顶部建议数只统计可执行动作。
12. P01–P10十条推荐均有唯一稳定Key、真实触发事实、工具/API、对象、Prompt、空/0/未知处理和验收用例；最终达到`10/10 PASS`且没有重复动作。

# 7. 发布与回退

真实测试接入使用独立配置与测试 Thread。每个里程碑先在测试入口开放，通过验收后再作为该 Thread 默认 Context Adapter；固定演示班继续使用既有 Mock Adapter。任一批次失败可以关闭对应 Capability Manifest 或回退该问题为明确的受限回答，不回滚已通过的其他问题。
