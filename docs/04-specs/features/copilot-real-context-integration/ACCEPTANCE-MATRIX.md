# 最终状态说明

- `PASS`：当前真实测试样本已完成对象、路由、Context、DeepSeek、页面和回归闭环。
- `CONDITIONAL_PASS`：可用范围已闭环，页面必须保留数据覆盖或接口能力限制。
- `BLOCKED_EXTERNAL`：测试环境没有所需外部合同，不以模拟结果顶替。

每题完成必须经过：对象绑定 → 模型计划 → 实际工具/API → 结构化Context → DeepSeek回答 → 用户问答评价 → 回归与恢复。

# 横向验收

| 环节 | 通过标准 |
| --- | --- |
| 对象 | Thread、班级、课程、活动、学生和引用消息归属全部由服务端核验；错对象请求拒绝 |
| 路由 | 实际工具属于目录、种类匹配对象、无重复或越权参数；缺对象先澄清 |
| API | 成功/空/0/失败/部分结果区分；分页、重复、数量和版本检查通过 |
| Context | 关键字段与原响应逐项一致；派生规则可复算；证据等级、时间、覆盖和限制存在 |
| 回答 | 关键事实准确率100%（以当前验收样本人工对账）；无Context外事实；三项用户评价至少“基本满意” |
| UI | 现有页面模板不变；加载、错误、重试、历史、引用、草稿和恢复可操作 |
| 隔离 | Mock/真实、教师/学生、班级/课程、Session/草稿/评价无串线 |
| 安全 | 凭据、票据、签名URL、FileId和越权学生数据不进入浏览器、模型或日志 |
| 回归 | 类型、Lint、必要单元/集成、Playwright、axe和三视口视觉检查通过 |
