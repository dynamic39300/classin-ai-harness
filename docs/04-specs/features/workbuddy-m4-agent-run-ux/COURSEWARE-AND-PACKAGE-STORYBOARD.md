# WorkBuddy M4.1 单课件与课程方案包动态 Storyboard

## 1. 使用说明

本 Storyboard 是下一阶段视觉原型、E2E 和用户 Review 的共同事实源。每一帧描述同一 Run URL 中发生的可观察变化，不使用页面跳转代表业务阶段。

固定示例业务上下文：

- 教师：王老师；
- 班级：高一（3）班；
- 课程：高中数学·必修一；
- 单元/主题：函数的性质；
- 资料：课程教学计划、学生学习计划、函数图像素材；
- 普通课件任务默认不带入学生姓名或个体证据。

## 2. NineClaw 证据映射

本 Storyboard 的帧编号是 ClassIn 目标旅程的产品帧，不替代 NineClaw 源视频的逐帧清单。实现前必须把每个视频时间点中的可见元素、原始文案、状态变化和动效映射到以下目标帧；目标帧允许组合多个源帧，但不得无记录省略源帧事实。组合后的唯一叙事是“生成智能课件”：V04/V06 的教学动画和课后练习只提供交互证据，其任务文案不得进入目标 Timeline。

| 本 Storyboard 阶段 | 主要证据 |
| --- | --- |
| Goal、缺参、确认、TaskCreate、Skill/工具过程、完成总结 | V05 新建任务—生成智能教案 |
| 阶段结果、右侧产物、交互式预览 | V04 新建任务—生成教学动画 |
| 聚焦阅读层、工具位置和退出结构 | V06 新建任务—生成课后练习；内嵌编辑按 D-044 不复刻 |

ClassIn 特有的 Core Context、业务审批、Receipt、权限与版本恢复来自已审阅 PRD 和 M4 领域实现，不声称来自 NineClaw 录屏。这些内容作为 `ADDED_DOMAIN_GOVERNANCE` 插入；V04/V06 向智能课件语义的统一标为 `TASK_SEMANTIC_NORMALIZATION`，NineClaw 专有品牌或 ClassIn 对象的等位替换标为 `CLASSIN_ADAPTATION`，敏感信息脱敏标为 `SECURITY_REDACTION`。

## 3. Storyboard A：生成单个课件

### A00｜进入新任务

| 项目 | 规格 |
| --- | --- |
| 中央区 | 空 Timeline；Composer 获得输入焦点 |
| 右侧 | 默认展开 `上下文`，显示“我的教学 / 我的空间”树 |
| Header | `上下文 0`、`产出 0` |
| 教师动作 | 输入或先选择 Context |

### A01｜选择班级与课程

教师依次展开并勾选：

```text
高一（3）班
└─ 高中数学·必修一
   └─ 第二单元：函数
      └─ 函数的性质
```

Composer 实时出现：

```text
[高一（3）班] [高中数学·必修一] [函数的性质]
```

选择课程不会自动勾选全部文档和学生。

### A02｜选择资料

教师继续选择“课程教学计划”和“函数图像素材”。Composer 显示第四个 Chip 和 `+1`；右侧 Header 变为 `上下文 5`。

### A03｜输入并发送 Goal

教师输入：

> 为高一（3）班生成一份函数单调性课件，包含概念讲解、图像示例、课堂探究和随堂练习。

发送后：

- 立即创建 Run 与历史条目；
- Timeline 固化教师消息；
- Composer 进入运行中模式；
- 原页面不跳转，只更新稳定 Run URL；
- Agent 状态显示“正在整理任务要求”。

### A04｜Agent 目标理解

600–1200ms 后，状态原位完成并展示：

> 我理解您要为高一（3）班设计一份“函数单调性”课件，使用高中数学·必修一和您选择的课程资料。课件将包含概念、图像示例、课堂探究与随堂练习。开始前还需要确认课时和希望的课件风格。

Timeline 紧接补参卡。

### A05｜结构化补参

补参卡字段：

| 字段 | 类型 | 默认/规则 |
| --- | --- | --- |
| 课时 | 单选 | 1 课时 / 2 课时 / 其他；必填 |
| 每课时时长 | 数字 | 45 分钟；必填 |
| 课件风格 | 单选 | 简洁讲授 / 探究互动 / 例题强化；必填 |
| 教材版本 | 单选/其他 | 根据课程建议；必填 |
| 额外要求 | 长文本 | 可选 |

教师选择“1 课时、45 分钟、探究互动”并提交。

### A06｜补参结果冻结

补参卡折叠为：

```text
✓ 您已确认
1 课时 · 45 分钟 · 探究互动 · 人教 A 版
```

Agent 继续回复，不开启新页面。

### A07｜Context 确认

Timeline 显示 Context 摘要卡：

```text
高一（3）班 · 高中数学·必修一 · 函数的性质
课程教学计划 · 函数图像素材
未带入学生姓名和个体学习证据
```

右侧仍保持树选择。教师点击“确认并生成计划”；系统冻结 Snapshot，并在 Timeline 记录已确认状态。

### A08｜Agent 提交 Plan

Plan 卡：

1. 对齐课程目标与教材范围；
2. 设计课件结构和课堂节奏；
3. 生成概念与图像示例；
4. 生成探究活动和随堂练习；
5. 组装课件并完成质量检查。

显示预期产物“一份可编辑课件”，以及会使用的能力摘要。教师可确认、修改计划、调整 Context 或取消。

### A09｜确认并开始执行

教师点击“确认并开始”。Plan 卡原位转换为进度容器，第一步进入运行中；Composer 显示“补充要求”和“停止”。

### A10｜步骤 1：目标与范围对齐

Timeline 追加步骤组：

```text
● 正在对齐教学目标与教材范围
  调用：课程目标结构化
```

完成后显示：

```text
✓ 已形成 3 条教学目标和 4 项成功标准
```

展开调用卡可看到实际使用的 Context Projection，但默认不显示内部命令。

### A11｜步骤 2：课件结构

显示 Skill 调用从 `running` 到 `completed`：

```text
✓ 已完成 12 页课件结构
  导入 → 概念辨析 → 图像探究 → 例题 → 随堂练习 → 总结
```

阶段结果作为摘要卡进入 Timeline。

### A12｜步骤 3/4：内容与活动

两个相关调用聚合在同一个 Process Group：

- 图像示例与例题生成；
- 探究活动与随堂练习生成。

每个调用经历可见执行态；失败时只失败对应步骤，可重试或补充要求。

### A13｜步骤 5：组装与校验

显示：

```text
● 正在组装课件
● 正在检查目标覆盖、术语和课堂时长
```

完成后产生 Artifact，不用动画结束直接宣告业务保存成功。

### A14｜Artifact 到达

同时发生：

- Timeline 追加“函数单调性课件 v1”卡；
- Header `产出 1` 出现未读状态；
- 若教师未编辑 Context，右侧自动切换到产出；
- 右侧显示课件预览；
- Plan 进度显示 5/5 生成完成、等待教师复查。

### A15｜全局只读预览

教师点击“全局预览”，进入不替换 Timeline 状态的聚焦阅读层：

- 左侧显示 18 页课件目录；
- 主区显示当前页完整内容；
- 支持上一页、下一页、目录跳转与键盘翻页；
- Esc 退出并把焦点返回“全局预览”按钮。

### A16｜专业编辑器边界

教师点击“使用专业编辑器打开”。当前体验环境不伪造第三方工具连接，只提示尚未接入；未来真实 Adapter 应把教师带到专业文档编辑器。Work Buddy 预览器不显示内容选区、AI 修改输入、保存草稿或 v1/v2 编辑比较。

### A17｜确认课件可用

教师在右侧点击“确认课件可用”。Timeline 记录教师复查决定，但不显示已经写入 ClassIn。

### A18｜ProposedAction

教师点击“保存到 ClassIn”。Timeline 产生 Action 卡：

- 保存到高一（3）班 / 高中数学·必修一 / 函数单元；
- 新增课件资源；
- 来源课件 v1；
- 权限允许、可逆、有效期；
- 修改目标、确认执行或取消。

### A19｜Approval 窗口

点击确认执行后弹出窗口，显示目标对象、影响、版本和风险。教师批准；窗口关闭，焦点回到 Action 卡。

### A20｜执行与 Receipt

Action 卡先显示“已确认，正在执行”。只有执行完成后，Timeline 才追加 Receipt：

```text
✓ 已保存到高中数学·必修一
课件：函数单调性
版本：v1
[打开课程资源]
```

Run Header 进入“已完成”；Composer 允许追问或创建关联课程方案包。

## 4. Storyboard B：直接生成课程方案包

### B00｜创建独立任务

教师回到新任务，选择“生成课程方案包”，输入：

> 为函数单调性设计一套完整课程方案，包含课件、作业、测验和录播讲解脚本。

Context 默认展开，教师选择与 A 相同的班级、课程、单元和资料。提交后创建独立 Run。

### B01｜Agent 理解与补参

Agent 说明四类交付物，并追问：

- 课程课时；
- 作业题量与难度；
- 测验时长；
- 录播脚本时长；
- 是否使用同一教学目标。

补参在同一 Timeline 卡内完成。

### B02｜Context Snapshot

教师确认独立 Snapshot。即使来源对象与单课件相同，也不能沿用另一 Run 的隐式 Snapshot。

### B03｜Artifact Graph Plan

Plan 卡显示：

```text
课程目标与结构
  └─ 课件
      ├─ 作业
      ├─ 测验
      └─ 录播脚本
```

教师可取消某项产物、调整优先级或确认全部生成。

### B04｜并行过程表达

确认后 Timeline 先执行共享目标和课件结构；课件结构完成后，作业、测验和录播脚本以一个并行 Process Group 展示：

```text
课程方案包  2/4
✓ 课件
● 作业
● 测验
— 录播脚本（等待课件讲解结构）
```

Timeline 不为每个低层日志生成大量消息；右侧产出目录同步对象状态。

### B05｜逐项 Artifact 到达

每个产物完成时：

- 对应步骤进入完成；
- Timeline 追加/更新方案包阶段结果；
- 右侧目录数量和状态更新；
- 教师可以提前查看已完成项，不必等待全部结束。

### B06｜方案包复查

四项完成后，Timeline 显示完成总结；右侧产出显示目录和当前选中项。教师可以：

- 逐项打开；
- 提出单项修改；
- 排除某项写回；
- 确认全部或部分可用。

单项修改只产生该 Artifact 新版本，不推翻其他已确认项。

### B07｜批量 ProposedAction

教师选择“保存到 ClassIn”，Timeline 产生批量 Action 卡，默认展开四项候选：

- 课件保存到课程资源；
- 作业创建为草稿；
- 测验创建为草稿；
- 录播脚本保存到课程资源。

教师可取消单项；确认窗口必须保留实际选择。

### B08｜对象级执行与 Receipt

批准后先显示执行中，再显示对象级 Receipt。主成功路径四项均成功；Run 完成。

### B09｜部分成功分支

可控体验场景允许测验创建失败、录播脚本等待依赖：

```text
✓ 课件已保存
✓ 作业草稿已创建
× 测验创建失败：题型规则不兼容
— 录播脚本未执行：依赖仍未满足
```

教师在原 Timeline 中修改测验规则并重试失败项；已成功对象不重复执行。最终 Receipt 追加恢复结果并保留首次部分成功证据。

## 5. Storyboard C：由课件派生方案包

这是 B 的入口变体，不是第三套交互：

1. 在 A20 完成后的 Run 中点击“基于此课件生成课程方案包”；
2. 创建新 Run，并在第一条系统摘要中显示来源课件；
3. 右侧默认打开 Context，课件作为锁定 `sourceArtifactRef`；
4. 班级、课程、时间和产物清单必须重新确认；
5. 后续从 B01 继续；
6. 原课件 Run 保留指向派生 Run 的入口，新 Run 可返回来源 Artifact。

## 6. Storyboard D：运行中改变目标

在 A11 后，教师输入“改为两课时，并增加小组探究活动”：

1. Teacher message 进入 Timeline；
2. Agent 说明这会影响课件结构和后续步骤；
3. 产生 Replanning 影响卡；
4. 教师确认；
5. 新 Snapshot/Plan 进入当前 Run；
6. 旧 Plan 和已产生的阶段结果标记 superseded；
7. 执行从受影响步骤继续；
8. 不创建第二个历史任务，不丢失旧证据。

## 7. Storyboard 验收锚点

- A00–A20 在同一 Run URL 完成；
- A05、A08、A10、A14、A18、A20 分别形成可截图的关键帧；
- B03、B04、B06、B08、B09 分别形成方案包关键帧；
- Context 选中与 Composer Chip 在 A01/A02 同步可见；
- Artifact 到达时 Timeline 与右侧产出同步，但不覆盖 Context 草稿；
- Approval 后仍需等待 Receipt；
- Reduced Motion 下所有状态顺序保持，不能因取消动画直接跳过 running；
- 所有失败和修改路径都在原 Run 内完成。
- A00–A20 始终引用同一个智能课件目标、ContextSnapshot 和 Artifact 版本链；目标 Timeline 不出现“生成教学动画”“生成课后练习”或对应旧文件名、旧完成总结。
