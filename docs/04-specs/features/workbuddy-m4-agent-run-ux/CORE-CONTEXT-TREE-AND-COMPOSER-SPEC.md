# WorkBuddy M4.1 Core Context 树与 Composer 绑定规格

## 1. 目标

Core Context 不再主要呈现“来源、实时事实、快照分离”等解释性文案，而是让教师直接看见和选择与任务有关的 ClassIn 业务对象。来源、版本、权限、敏感度和快照语义保留在详情与治理层，不占据默认阅读路径。

## 2. 默认行为

- 新建任务进入时右侧 `上下文` 默认展开；
- 自动带入当前教师和机构，作为锁定 Scope，不占用可移除 Chip；
- 不自动选择最近班级、课程、学生或资料；
- 可根据 Goal 推荐节点，但推荐与选中必须视觉区分；
- Context 选中项立即同步到 Composer；
- 发送 Goal 时校验必需项，确认后冻结 ContextSnapshot。

## 3. 信息架构

### 3.1 主树

```text
我的教学
├─ 高一（3）班
│  ├─ 班级信息
│  ├─ 学习者范围
│  │  ├─ 全班 32 人
│  │  ├─ 已有分组
│  │  └─ 指定学生
│  └─ 高中数学·必修一
│     ├─ 课程计划与资料
│     │  ├─ 教学计划.docx
│     │  ├─ 学生学习计划.pdf
│     │  └─ 课程标准与机构规则
│     ├─ 第一单元：集合
│     │  ├─ 单元目标
│     │  ├─ 教学活动
│     │  └─ 资源
│     └─ 第二单元：函数
│        ├─ 单元目标
│        ├─ 活动 1：函数概念导入
│        │  ├─ 教案
│        │  ├─ 课件
│        │  └─ 视频素材
│        └─ 活动 2：单调性探究
│           ├─ 随堂练习
│           └─ 图像素材
└─ 高一（4）班

我的空间
├─ 最近使用
├─ 教材与参考资料
├─ 个人文档
├─ 收藏资源
└─ WorkBuddy 产出
```

### 3.2 Domain Knowledge

Domain Knowledge 不与普通文件混成同一棵无来源树。与当前课程/单元匹配的规则和知识放在对应课程的“课程标准与机构规则”节点；完整详情显示来源、版本和适用范围。

### 3.3 学习者范围

普通课件任务默认只允许选择范围摘要：全班、分组或人数，不自动把学生姓名和个体证据放进 Context Projection。展开指定学生时必须显示使用原因和敏感提示；没有任务必要性或权限时禁用选择。

## 4. Tree Node 字段

| 字段 | 默认行显示 | 详情显示 |
| --- | --- | --- |
| 名称 | 是 | 是 |
| 类型图标 | 是 | 是 |
| 子项数量 | 有子项时 | 是 |
| 选择状态 | checkbox | 是 |
| 推荐状态 | `建议`，不等于选中 | 推荐原因 |
| 来源 | 默认隐藏 | ClassIn / 教师 / 机构 / AI 推断 |
| 版本/更新时间 | 默认隐藏 | 是 |
| 权限 | 异常时显示 | 是 |
| 敏感度 | 敏感时显示 | 是 |
| 不可用原因 | 行内显示 | 是 |

默认行不显示“可读取”“实时事实与任务快照分开”“最小投影”等教学性说明。

## 5. 选择语义

### 5.1 选择父节点

- 勾选班级：只选择班级基础对象，不自动选择学生、课程和全部资源；
- 勾选课程：只选择课程基础对象，不自动选中所有单元和文档；
- 勾选单元：选择单元目标与结构，不自动选中所有活动物料；
- 勾选活动：选择活动定义，不自动带入所有附件；
- 勾选文件/资源：明确带入该资源引用。

这样避免“选一个课程就把整棵树发送给 Agent”。

### 5.2 父子状态

| 状态 | 表达 |
| --- | --- |
| 未选 | 空 checkbox |
| 已选本对象 | checkbox 选中，子项不受影响 |
| 部分子项已选 | indeterminate |
| 推荐未选 | 轮廓强调 + `建议` |
| 不可选 | disabled + 原因 |
| 已由入口锁定 | lock，不可移除 |

父节点的 checkbox 控制本对象，不做默认级联；单独提供“选择当前节点下全部可用资源”批量动作，并在执行前显示数量。

### 5.3 依赖补齐

选择单元或活动时，系统可以自动添加必需的祖先对象引用，例如班级和课程，但必须：

- 在选择后即时说明“已同时带入所属课程”；
- 祖先引用标记为依赖；
- 移除祖先时列出将被移除的下级项；
- 不自动添加兄弟节点或全部资源。

## 6. Composer Context Chips

### 6.1 显示规则

Composer 上方显示最多四个高价值 Chip，其他项合并为 `+N`：

```text
[高一（3）班] [高中数学·必修一] [函数的性质] [教学计划.docx] [+2]
```

优先级：班级 > 课程 > 单元/主题 > 教师明确选择的关键资料 > 学习者范围 > 其他资源。

### 6.2 Chip 行为

- 点击：打开右侧 Context 并定位节点；
- 删除：取消该对象；若存在下级依赖，先显示影响确认；
- `+N`：打开已选项摘要；
- 锁定 Chip：不可删除，显示来源入口；
- stale/permission_changed：Chip 显示状态，不静默移除；
- 手机/窄屏：只显示两项和 `+N`，不挤压发送按钮。

### 6.3 Prompt 绑定

Context 不作为一段不可编辑文本直接拼进 Prompt。Composer 提交的是：

```text
Goal text
+ selected Context references
+ attachment references
+ Task Type
```

页面可以显示“已带入 4 项上下文”，但不生成教师看不见的大段隐藏 Prompt。Agent 目标理解消息需要复述实际使用的高价值 Context。

## 7. 搜索与定位

- 树顶部支持搜索班级、课程、单元、活动和资源名称；
- 搜索结果保留层级路径；
- 选择搜索结果后，树展开到真实位置；
- 不把无权访问对象的名称暴露在结果中；
- 最近使用只是一种视图，不复制新的 Context Item；
- 从 Composer Chip 定位时清除搜索筛选并聚焦目标节点。

## 8. Context Proposal 与 Snapshot

### 8.1 Proposal

发送前所有勾选都属于 Context Proposal。它可以编辑、替换和移除；右侧 Footer 显示是否满足任务必需项。

### 8.2 确认

教师确认后冻结 Snapshot，Timeline 产生 `context_snapshot` 事件。Snapshot 摘要包含：

- 班级、课程、单元/主题；
- 学习者范围；
- 资料与资源数量；
- Domain Knowledge 数量；
- 生成时间和来源版本；
- 被最小化排除的敏感项数量。

### 8.3 运行中修改

次要资源变化：

- 形成待应用修改；
- 只影响尚未开始的步骤；
- 应用后产生 Context 变更事件。

主班级、课程、单元或产物范围变化：

- 产生影响分析；
- 列出将清除的下级对象；
- 列出受影响 Plan、步骤、Artifact 和未执行 Action；
- 教师确认后生成新 Snapshot 和 Plan；
- 旧证据标记 superseded。

## 9. Panel 结构

```text
Header
  上下文 · 已选 4
  搜索 / 收起

Selected summary
  高价值已选项 + 清除可选项

Tree
  我的教学
  我的空间

Footer
  状态：还需选择课程 / 可以开始
  [确认并生成计划]
```

Header 和 Footer 固定，Tree 是唯一滚动区。默认宽度遵循统一右侧活动区规格。

## 10. 状态与错误

| 状态 | 树表达 | Composer 表达 |
| --- | --- | --- |
| empty | 只有教师/机构；提示选择范围 | `核心上下文 0` |
| proposing | 推荐节点出现 skeleton/进度 | 已选 Chip 保留 |
| needs_attention | 问题节点展开并标记 | 显示缺少课程等提示 |
| ready_to_confirm | 已选项稳定 | 可发送/确认 |
| snapshotting | 选择临时只读 | 防重复提交 |
| ready | 显示 Snapshot 状态 | Chip 显示已确认 |
| stale | 节点显示有更新 | Chip 显示待刷新 |
| permission_changed | 正文隐藏，显示原因 | Chip 显示权限变化 |
| unavailable | 节点不可用，可替换/移除 | 阻断或降级提示 |

## 11. 验收标准

- 新任务打开时 Context 默认展开；
- 班级、课程、课程计划、单元、活动、资源和 Space 文件可逐层展开；
- 选择父节点不会自动选中整棵子树；
- 选择下级对象时依赖祖先明确可见；
- 勾选、Chip 和 Timeline Context 摘要三处使用同一选择事实；
- 普通课件任务默认不发送学生姓名和个体证据；
- 发送 Goal 后冻结 Snapshot，而不是每个 Tool 重新读取整个实时树；
- 运行中主范围变化必须通过影响分析和 Replanning；
- 关闭/切换到产出后，未应用 Context 草稿和树滚动位置保持；
- 页面默认路径不出现零碎的治理解释，但详情中仍可追溯来源、版本、权限和敏感度。
