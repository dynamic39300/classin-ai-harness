# Work Buddy 能力页面 NineClaw 高保真重设计规格

## 1. 改造目标

上一版用统一的“标题 + 工具栏 + 轻量列表 + 右侧详情”表达六个目的地，功能可操作，但错误压平了 NineClaw 已验证的多种页面范式。本轮保留 ClassIn Shell、Work Buddy 二级导航、路由、领域状态和模拟 Adapter，只重做页面级信息架构、视觉层级与交互容器。

## 3. 共通视觉规则

- ClassIn Shell 不复制 NineClaw 品牌栏；内容区复刻 NineClaw 的布局比例、卡片密度、层级和交互形态。
- 六个 Agent 工具页面统一使用 ClassIn `var(--color-canvas)` 纯色工作区背景；UI 定稿前不使用页面级氛围渐变。卡片使用白色 Surface、12–16px 圆角、轻边界和短阴影。
- 市场卡不再展示工程式长元数据行；首层只显示图标、标题、简述、来源/协议和主状态。权限、版本和治理信息进入详情。
- Skill/Tool 采用 2 列；Content 在 1440 宽度下采用 4 列封面卡；文件采用任务分组下的轻量精简列，时间信息保持清晰但不主导；定时任务采用证据中的全宽单列大卡。
- 详情不再固定占用右侧窄列。Skill/Tool 使用 720–920px 居中弹窗，Content/File 使用接近全宽的大预览层。
- 选中、Hover、禁用、阻断、连接失败、加载和空结果必须同时有形状或文案表达，不能只靠颜色。
- Skill 与 Tool 目录卡共享同一 `catalogCard` 视觉契约：`12px` 圆角、轻边界、短阴影、`28px` 图标热区、约 `126px` 高度和“标题状态 / 单行说明 / 类型场景”三段式密度。业务字段不同，但容器、间距和反馈规则不分叉。

## 5. ClassIn 等位适配

- ClassIn Shell 继续使用 ClassIn 语义绿；定时任务保留 NineClaw 的调度结构和蓝色操作语义，但页面底色与其他 Agent 工具页面统一使用 ClassIn Canvas 纯色背景，字号与控件密度服从 ClassIn PC 现有规范。营销会员、积分、价格和用户匿名信息不进入 Work Buddy。
- “安装”仍是能力配置，不代表真实 Skill/MCP 已接入。定时任务主路径不显示 `[模拟]`、Demo、版本或评审标签，模拟边界由项目级说明和 Adapter 事实源承担，不污染任务页面。
- Tool 详情不增加“立即运行”；内容改编和文件引用只进入新任务草稿；定时任务立即运行仍进入标准 Run 与审批链。
- 100% 高保真指对素材可见的结构、元素、状态和节奏覆盖；素材未证明的后台能力保持 `UNKNOWN`，不伪造生产完成度。

### 5.1 定时任务可见文案与字段锁定

- 页面只显示标题“定时任务”、页签“任务 / 历史”和截图证明的操作，不显示搜索、Eyebrow、说明副标题、状态胶囊或“下次运行 / 最近结果”等自行演绎字段；
- 空态主操作为“新建任务”，说明为“创建定时任务，让 AI 按计划自动执行”；
- 创建/编辑字段顺序锁定为：标题、提示词、计划、工作目录、到期时间（可选）、IM 通知（可选）；
- 标题 Placeholder 为“输入任务标题”，提示词 Placeholder 为“输入要执行的提示词...”，日期 Placeholder 为“年 /月 /日”，默认时间为“09:00”，默认工作目录引导为 `ClassIn Space / 我的云盘`，默认通知为“无”；
- IM 通知选项锁定为：飞书、企业微信、钉钉、QQ、微信；除飞书外均显示“未配置”；
- 已创建卡片示例锁定为“开课前 10 分钟提醒老师上课”，提示词为“请在我的每一堂课开课前 10 分钟，用短信和 ClassIn APP 消息的方式提醒我”，计划为“每天 · 09:00”；
- 定时任务默认视图直接展示上述一条已启用任务，便于验证任务卡、启停和操作菜单；删除任务后仍保留空态作为恢复状态；
- 创建/编辑弹窗采用约 `720 × 660px` 的紧凑桌面尺寸，并以当前工作区为最大边界；常规桌面应完整显示底部操作，更小窗口才使用弹窗内部滚动；
- 卡片操作锁定为“立即运行 / 编辑 / 删除”；立即运行后历史表显示“标题 / 执行时间 / 状态”，运行状态为“运行中”。

- 工具广场使用双列目录卡，卡片首层只显示图标、工具名、适配后的说明、协议、连接摘要与“安装”；ClassIn 官方能力的首层连接摘要统一显示“ClassIn 托管连接”，不暴露旧品牌服务路径；不增加权限标签、场景标签或其他自行演绎的能力说明；

- “自定义”支持表单 / JSON 两种模式；表单支持 stdio、SSE、HTTP 流式传输，以及命令或 URL、参数、环境变量或 HTTP 请求头；JSON 模式使用兼容格式提示；
- 当前材料没有证明工具权限声明、真实连通性、凭证保存与远端执行结果，因此这些能力保持 `UNKNOWN`，不在页面首层自造说明。

### 5.3 Skill / Tool 卡片状态统一

- Skill 卡片首层使用与 Tool 卡片一致的容器、图标尺寸、标题基线、说明行高和动作区尺寸；Skill 底部用“能力来源 / 适用场景”替代 Tool 的“协议 / 连接摘要”，不为了视觉一致抹掉领域语义；
- 可安装 Skill 的动作使用带图标的“安装”，已启用、已安装和更新可用继续表达状态，不把所有状态伪装成同一个主按钮；
- 精细指针 Hover 时卡片上移 `1px`，边界增强并提升为 Workbench 阴影；Focus Within 使用标准焦点色，Active 轻微压下。Hover 不承载唯一动作，无 Hover 设备保持完整信息和操作；
- 动效使用 `--dur-short` 与 `--ease-out`，`prefers-reduced-motion` 下关闭过渡，不改变最终 Hover / Focus 视觉状态。

### 5.4 Skill 添加与任务选择闭环

- “添加技能”按钮位于搜索框右侧，点击打开与按钮右边缘对齐的紧凑菜单，菜单依次为“查找技能 / 上传技能 / 创建技能”；Hover、Focus 和选中态共享标准控件反馈。
- “查找技能”导航到新任务，预填“帮我找一个技能，这个技能是为了：”并选择 `find-skills`；“创建技能”预填“帮我创建一个新技能，这个技能是为了：”并选择“技能创建器”。两条路径都只建立草稿，不自动开始 Run。
- “上传技能”打开居中弹窗：上半部为拖拽区和本地选择，下半部为 GitHub/ZIP URL 输入，底部为文件规范。无效扩展名和无效 URL 在当前控件附近给出可恢复错误。
- 模拟导入成功后关闭弹窗、切换到“我的 Skills”、显示新 Skill 卡片和状态反馈；不读取真实远端仓库，不声明 Skill 已在真实运行时可用。
- 新任务输入区提供可选 Skill 按钮。弹层包含搜索框、已安装官方 Skill 列表和技能市场入口；选中结果以可移除标签呈现。普通任务不要求选择 Skill，仍遵守统一主 Agent 入口决策。

### 5.5 定时任务多卡片扫描层级

- 保留 NineClaw 全宽单列任务卡结构，但把原先接近画布的半透明白块提升为独立实体 Surface：白色底纹、清晰细边界、12–16px 圆角和冷灰蓝轻阴影。
- 卡片左侧使用 3px 状态轨道和任务图标作为视觉锚点。启用为 ClassIn 蓝，停用为中性灰；状态仍显示“已启用 / 已停用”文案，不只依赖颜色。
- 标题、提示词和开关位于信息主区；计划与更多操作位于浅色底纹的信息条，形成稳定的两段式扫描节奏。
- 卡片间距固定为 12–16px。Hover 或 Focus Within 仅轻微增强边界与阴影，不移动大段内容，不隐藏开关或菜单入口；Reduced Motion 下移除过渡。
- 该调整不改变任务字段、排序和行为，也不增加未经一手证据证明的优先级、运行结果或下次执行字段。

## 6. 验收门槛

- 六个路由在 1440×900 与 1000×768 均无横向溢出或不可达操作。
- Skill、Tool、Content 三页首屏不再呈现为同一种文本列表。
- Skill/Tool 详情、Tool 自定义、Schedule 创建、Content/File 预览均使用与证据一致的大容器。
- Settings 的模型页具备左设置导航、Provider 列表、配置详情三层结构。
- 行为测试、axe、视觉快照、类型检查与 Lint 全部通过。
