# ClassIn 真实测试环境接口整体判断与接入基线

> 2026-09-16 后续安排更新：用户要求先建设独立测试页面，逐题审阅真实响应、实际模型上下文与回答，并记录备注、形成共识后再接入现有 Demo。具体建议见[独立审阅台方案](./COPILOT-API-CONTEXT-REVIEW-LAB-PROPOSAL-2026-09-16.md)。下文“可接/完整”属于接口盘点判断，尚不是逐题充分性或模型回答准确性的验收结果；此前“约 90%”仅为工程估计，需用逐题测试的实际通过数量替换。

> 第一阶段审阅台已实现，见[实测验收](./review-lab/ACCEPTANCE-2026-09-16.md)。新增证据缩小了部分“完备”表述：当前 IM 捕获虽然有 21 条消息结构，但正文在旧采集时已全部脱敏，不能验收聊天摘要；本次 AI 课堂报告的内容主题与目标数学课不匹配，接口返回成功不代表内容可直接作为业务上下文。以下盘点不自动授予这两项数据充分性或模型回答验收通过。

## 1. 整体结论

结合人工审阅意见、Apifox 契约、V2 现有实现，以及 2026-09-16 对教师端 `7777`、两个学生端 `7779/7780`、在线课堂、普通 IM、作业、测验、课堂报告和考勤链路的监听，当前可以形成以下统一判断：

1. **当前 IM Copilot 所需的只读业务数据，在业务覆盖层面已经基本完备。** 班级、课程、成员、单元、五类教学活动、排课时间、作业、测验、录播、资料、提交/批阅结果、课后出勤、课堂报告、回放、教师笔记和普通 IM 历史都已找到真实来源。21 个通用问题均已有真实数据路径或明确的业务能力来源，不再存在需要继续无边界搜索的“大类接口空白”。
2. **人工审阅中所说的“数据完备”大部分成立，但不能直接等同于“接口已经接入完成”。** 部分能力的数据已经存在，剩余工作是按时间范围、课程或学生做聚合；这属于项目 Module/Skill 的职责。另一些能力虽然业务侧确认存在接口，当前仍缺已登录正向样本、稳定身份合同或 V2 Adapter，必须继续保留接入 Gate。
3. **可以启动下一阶段真实只读接入。** 不需要等待普通 IM 发送、作业/测验写入、ASR 或学情专用 Agent 全部完成，再开始替换当前模拟业务事实。首轮可先接入已经 `DOC/CALL/V2` 的主链，并把成员级实时考勤和真实 IM 历史作为同一阶段中的条件性 Gate。
4. **真实写入闭环仍不完整。** 测验 `submitPaper` 已取得真实请求与跨端结果回读；教师批改结果事件也已观察到。但普通 IM 发送、教师批改发起请求、PC 作业提交、ACK、幂等、超时恢复和最终收件/回读尚未形成完整合同，不能因只读数据完备而一并宣称可用。
5. **页面约束已经形成共识。** 原消息页结构、稳定文案、交互和视觉保持不变；班级、课程、人数、课堂、日期、任务、内容和结果等业务槽位使用真实值；页面不展示 Endpoint、连接状态或“真实 API”等工程标签；`N 项建议` 使用当前真实可操作事项数量。

因此，当前真实测试环境的准确表述应为：

> **真实只读业务事实已经具备首轮工程接入条件；聚合类问题主要是产品 Module/Skill 工作；少数专用数据源仍需完成授权实调；普通 IM 发送和业务写回继续独立验收。**

这份判断不等同于生产就绪，也不改变 D-157 下当前默认模拟组合根。后续仍按 PRD → Feature Spec → Tickets → Implementation 推进。

## 2. “完备”的统一口径

人工审阅、接口研究和工程实现使用了不同层面的“完备”。本项目从现在起按四个维度分别判断，避免把其中一个维度通过写成整体完成：

| 维度 | 判断问题 | 完成含义 |
| --- | --- | --- |
| 业务数据覆盖 | 业务问题需要的原始事实是否存在真实来源 | 能找到正式接口、客户端协议、数据库或已确认的业务服务；字段足以表达目标事实 |
| 测试环境实调 | 当前授权测试账号是否实际读取或写入成功 | 有真实请求/响应或请求与跨端回读，且能核对学校、课程、课节、活动、学生等对象归属 |
| V2 工程接入 | 当前仓库是否已有服务端白名单、领域合同和投影 | 浏览器不持有 Secret；失败、权限、刷新和用途隔离已经实现并验证 |
| 业务闭环 | 用户动作是否有 ACK、回读、幂等和失败恢复 | 写入或发送能确认最终结果，不因超时重复执行，也不以本地模拟回执冒充真实送达 |

本文中的“数据完备”默认指第一维。只有后面三个维度也通过，才能说“当前产品已接通”或“写接口可用”。

| 人工审阅判断 | 统合结论 | 原因与共识边界 |

当前需要继续讨论的不是“这些业务是否有价值”，而是四个具体事实：

1. 成员级实时考勤成功响应及字段单位；
2. ASR 正文的准确 Endpoint、生成时机和权限范围；
3. 专用班级/个人学情报告或学情 Agent 的稳定调用合同；
4. 普通 IM 发送的受支持身份、ACK、回读与失败恢复。

## 6. 21 个通用问题的最终判断

状态统一为：

- **直接可接**：现有 V2 真实 Read Port 和 Runtime 已足以回答；
- **数据完整，需聚合/Adapter**：不缺外部原始事实，需完成项目内 Module、Skill 或真实 Reader；
- **条件性接入**：业务路径存在，但仍有一项授权实调或完整性 Gate；
- **写闭环待完成**：可以生成结果或草稿，不能宣称已经真实发送/写回。

| E5 整理为消息 | 直接可接 | 继续使用现有 Runtime 与审阅流程 |
| F1 两天聊天总结 | 条件性接入 | 实现真实 IM Reader、时间窗分页和完整性标记 |
| F2 讲解群消息中的作业题 | 数据完整，需绑定 Module | 绑定消息引用、课程活动、题目和解析 |
| F3 回复群内同学 | 写闭环待完成 | 真实数据生成草稿；发送继续独立 Gate |

## 7. 建议的开发批次

### 第一批：真实只读主链

1. 保持原 IM Copilot Surface 和稳定文案；
2. 接入真实班级、课程、成员、单元和五类活动；
3. 接入作业、测验、录播、资料、提交/批阅结果与资源；
4. 接入课后报告、回放、教师笔记和规范化后的 AI 授课分析；
5. 接入真实 IM 历史 Reader，但以分页、时间窗和对象归属 Gate 控制开放；
6. 实时考勤先接已验证的课节发现与聚合在线人数，成员名单在 `getClassMember` 正向验收后开放；
7. 真实 API 失败时显示现有不足/重试状态，不回填固定物理模拟事实。

### 第二批：聚合 Module 与 Skill

1. 每门课程各自的进度摘要；
2. 多课堂迟到/缺席聚合；
3. 跨作业/测验高频错题统计；
4. 单学生学习情况和未完成任务；
5. 班级周总结与个人学情总结；
6. 课堂回顾证据拼装，以及 ASR/学情 Agent 可用后的增强。

这些项目原则上不再等待新的大类业务接口；实现时只补字段语义、权限和边界样本。

### 第三批：真实交付与业务写入

1. 普通 IM 文本/图片/文件发送、ACK、回读、学生可见和重启恢复；
2. 教师作业/测验批改写回；
3. 学生提交、订正和重交的正式产品合同；
4. 所有写动作的 ProposedAction、审批、幂等和 ExecutionReceipt。

第三批不能因第一、二批数据完备而自动开放。

## 8. 首轮 PRD 的验收边界

下一份 PRD 可以直接采用以下结论：

- Surface Contract 100% 冻结；
- 班级名称与课程名称分别绑定真实字段，页面主对象不再混用；
- 时间来自服务器与真实活动，不使用演示时间；
- `N 项建议` 只统计当前真实可操作事项；
- 当前选中班级下的课程逐门展示进度，不计算跨课程混合总进度；
- 聚合结论必须可追溯到活动、学生、题目和读取时间；
- 正式业务事实、教师笔记、AI 生成分析和模型建议分层；
- 个人结果只进入教师私有上下文，班群草稿默认使用汇总；
- 真实 Thread 不以 Mock 补业务事实；固定 Mock 只用于独立回归和一键回退；
- 普通 IM 历史与发送使用两个独立 Capability Gate；
- 当前未通过的写入能力继续显示模拟或不可用回执，不暗示学生已收到或业务已修改。

## 9. 当前可作出的项目判断

| 判断问题 | 结论 |
| --- | --- |
| 是否还需要继续大范围寻找课程、活动、作业、测验、资源和报告接口？ | **不需要。** 主体接口覆盖已经足够，后续以补字段合同和 Adapter 为主 |
| 是否可以开始把 IM Copilot 的模拟业务事实替换成真实测试数据？ | **可以。** 按第一批范围进入新的 PRD、Spec 和 Tickets |
| 是否可以回答人工审阅中多数“数据是否完备”的问题？ | **可以。** 原始数据覆盖基本完备，聚合类能力由项目实现 |
| 是否可以现在显示课中未进入学生名单？ | **暂不可以。** 成员级实时考勤正向样本仍待验证 |
| 是否可以使用真实普通 IM 历史？ | **测试环境读取可用，V2 条件性接入。** 需补分页、重连和归属合同 |
| 是否可以宣称普通 IM 真实发送可用？ | **不可以。** 发送侧 ACK、回读和学生可见未完成 |
| 是否可以宣称作业/测验写入整体可用？ | **不可以。** `submitPaper` 已有真实证据，但其他写入和恢复合同不完整 |
| 是否达到生产就绪？ | **没有。** 当前结论只覆盖授权真实测试环境与下一阶段工程输入 |
