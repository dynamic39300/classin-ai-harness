# 目标

第一阶段四题证明了“模型判断需要什么信息 → 只读工具取得真实业务数据 → 结构化 Context → DeepSeek 回答 → 教师只评价问答质量”的核心链路可行。用户确认核心大方向约 80% 正确，继续沿该轨道推进；这表示方向通过，不等于每个答案或接口达到 80% 准确率。

第二阶段在独立审阅台扩展六个高价值问题：A1 课程进度、A3 班级人数、A4 本讲配套活动、B1 到课情况、C1 作业要求、E1 报告/回放/板书。同时增加开放式提问入口，用真实模型在完整可用工具目录中决定取数计划。主 Demo、真实发送及业务写入不在本阶段。

# 产品要求

1. 固定问题和开放式提问走同一计划、执行、证据、回答、审阅链；开放入口不能绕过对象归属和只读白名单。
2. 开放问题可选择一个课堂或作业对象，也可不选；缺少会改变答案的对象时由模型提出澄清，不猜对象。
3. A1 按课程分别说明进度，不将多个课程混成总百分比。A3 区分学生、旁听、教师。A4 只列所选课堂同单元的真实配套活动和资料。
4. B1 对已结束课堂使用正式课后考勤；正在上课时，成员实时接口尚未取得已登录成功样本，不显示未进入、迟到或早退名单。页面明确这是能力边界。
5. C1 使用真实作业说明和截止时间，不读取学生提交正文。E1 分别报告正式报告、回放文件、板书/高光和教师笔记是否存在；资源存在不等于已理解媒体内容。
6. 用户仍只评价匹配、相关、好用；技术证据折叠。新答案不继承旧评分，第一阶段历史完整保留。

# 成功条件

- 10个固定问题和1个开放入口均可在页面运行；
- 第二批每题至少完成一次真实计划与只读取数，失败或条件性能力如实显示；
- 开放入口能展示模型计划与实际调用差异，缺对象时不会越权猜测；
- 形成第二批逐题审阅记录，作为真实 Demo 接入前的共识输入。
