# 目标

用户批准独立审阅台方案，先实现 A2 下一课、C2 作业提交与批阅、E2 课堂回顾、F1 两天群聊。重点验证真实数据是否正确、模型上下文是否够用、回答是否合格；第一阶段增加真实模型选工具与计划/执行对照。

工具选择由真实模型根据问题和工具目录完成。Function Calling 是第一阶段实现方式，页面明确为本地工具；没有 MCP 服务器握手就不标记 MCP 已接入。开放式跨问题入口列下一阶段，四题输入允许改写。

# 2026-09-16 审阅职责调整（用户补充，覆盖旧四维审阅）

人工主评问题与回答的匹配、相关性、质量，可只写一句意见，不要求懂工具全集、字段或定位技术片段。技术侧负责接口覆盖、工具路由、字段语义、对象归属和证据充分性；用户满意不能推导这些检查全部通过。

提供“还可以补充哪些信息”：从已有盘点中筛选与本题可能相关、该运行尚未调用的接口，用业务语言说明预计返回的信息、关键字段含义、可能改善什么以及适用限制。用户可选建议补充/暂不需要/需要讨论并备注；本次仅保存建议，不自动增加调用或改变原回答。已调用失败不能写成未调用；未接入、仅文档证据、捕获回放分别标明。建议来源为工程盘点，不能冒充模型计划或真实返回。

# 验收

1. 独立目录、进程、端口启动；既有 Demo 无需运行，默认 Copilot 不变化。
2. 四题可改写问题并选择授权业务对象；模型返回实际工具调用提议，展示目的、参数、预期字段与底层接口。
3. 执行后逐项显示成功、失败、阻塞和差异；系统归属核验请求单列，不能冒充模型选择。
4. 真实 API 响应保留字段结构，敏感票据遮蔽；模型输入、来源、统计/状态规则与缺口可检查。
5. 真实模型生成回答，关键引用可以查看证据；无真实调用不填手写答案。缺失/部分/权限失败显式展示。
6. 保存快照，支持重放与重复生成；备注按运行版本保存、刷新恢复、导出，Agent 不自动代用户通过。
7. F1 可先回放已捕获真实 IM 帧，明确非实时、分页未完备；实时 Reader 未具备稳定身份合同时标为阻塞。
8. 读请求受原测试范围约束；工具只读，不发送 IM、不提交/批阅业务对象。

## LAB-06 补充建议语义修正

用户发现课名和时间已答，却被再次推荐调用另一接口读取相同信息。候选必须有相对于已取得数据的业务增量；未调用接口不等于缺信息。已取得但可补入回答的信息单列。实际接口与原始返回入口靠近答案，候选的接口路径直接可见。保存现有用户反馈及未保存的问答评价草稿，不因候选版本升级而丢失。

## LAB-07 真实聊天优先

用户明确：优先用实际取得的聊天正文测试总结，多少条都可用；最近5天为查询目标，完整覆盖不作为开始测试的前提。实际条数、时间范围与完整性如实标注。重新通过已登录测试教师的授权班群读取正文，受控保存并给现有 DeepSeek 分析，不用旧脱敏标记冒充正文。

## LAB-08 人工审阅后的修正

按[四题审阅结论](./USER-REVIEW-CONSENSUS-2026-09-16.md)推进 A2/C2相关拓展、E2教学内容聚焦、F1凝练及LMS交叉核对。用户已授权根据页面反馈继续工作。保留原答案及反馈，新版本不继承验收。

### LAB-08 补充：真实 AI 转写

用户提供课堂回放→AI转写入口并授权监听。实测已取得第一讲及第二讲原文，课堂内容回顾应优先将选中课节的转写作为讲解材料，按回放文件分开保留。ASR可能有识别错误，同课节多文件也可能主题冲突；不能把文件归属等同内容正确，更不能混入别的课节。保留原始文本及时间戳供用户核对。
