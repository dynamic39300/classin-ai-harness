# 第一阶段合同

状态：APPROVED_FOR_IMPLEMENTATION，依据用户批准与补充要求。

## 隔离与 Write Set

独立程序位于 `tools/copilot-api-review-lab/`，自带 package.json，Node 24 内置运行时与原生浏览器界面，不导入现有 Demo 源码。服务仅监听 127.0.0.1:4186；独立进程读取本机已有测试凭据和模型配置，可通过环境变量指定证据根目录。私有记录写 `.runtime/private/copilot-api-review-lab/`，目录 0700、文件 0600。其余 Write Set 为本目录文档、原方案状态及项目当前状态的入口；不改既有产品路由和默认 Adapter。

验证工具配置另允许 `eslint.config.js` 为独立工具声明 Node/Browser globals，保留既有规则。用户补充指定与 Demo 相同的 DeepSeek，第一阶段模型固定默认 `deepseek-v4-flash`，复用本机公司网关与服务端凭据。

## Module 与 Interface

- ReviewRun Module：createPlan、execute、generate、review、export，负责显式运行状态和版本持久化。
- Model Adapter：以现有公司网关的已配置模型生成 function tool_calls；生成回答使用独立请求。保存实际请求体、内容输出和模型标识；凭据与内部推理不进入审阅记录。
- BusinessRead Module：提供已登记的只读工具目录，封装身份签名、固定测试范围、归属验证及响应留痕。Live 与 Snapshot Adapter 在相同工具执行 Seam 替换。
- Evidence Module：保留 JSON 字段、标记来源与缺口，统计有规则依据；提供源路径引用与字段观察表。

## 工具计划与执行

模型可从可见目录选择课程活动、活动详情、作业名单、正式课堂报告、教师笔记、AI 分析和 IM 历史；预期参数绑定 UI 选中的授权对象。目录同时说明工具映射的业务 API、当前接入方式、实时可用性和证据限制。

计划记录原始 tool_calls、模型给出的简短业务用途和预期字段。只将白名单工具、合法参数转换为可执行计划；未知工具、对象不适配、缺少参数或超过调用预算逐项拒绝。没有选工具时保留模型澄清内容，不能补造计划。

执行器可增加明确标记的身份/归属核验及必要依赖请求，逐条关联模型工具调用 ID。不得以问题 ID 硬编码接口计划或补齐模型漏选工具。业务 API 固定路由；模型不能传任意 URL、凭据或身份。

运行状态：planning → planned/plan_failed → executing → executed/partial/failed → generating → answered/answer_failed。请求互斥；失败保留中间证据。计划生成后改写问题或改选对象须新建运行。重放指定已保存的运行，固定其采集时间与业务对象；无对应工具快照时明确缺失，不暗中实时补取。

## 证据及上下文

HTTP 状态与业务外壳成功分开。每次 API 请求记录来源、业务参数、起止时间、真实响应（票据/签名链接遮蔽）、状态和错误。JSON 观察字段表不冒充完整供应商 schema，未知单位/枚举保持待核。

模型输入包含：问题、明确业务对象/时间、工具执行结果与证据引用、已核实派生结果、缺口、业务规则。系统与用户消息原样可审阅；正文视为待分析数据，不能覆盖系统规则。资源链接存在不表示已经读取媒体内容。AI 报告不替代正式出勤。

A2 按执行时钟或快照时钟筛选已发布、未取消未来课堂。C2 按分配名单核对数量，状态参考既有已验证 Read Port：stStatus 0 未交、1 已提交待批、2 已批，isDraft 1 为草稿；未知值独列，不消费语义未明的 correctTotal。E2 正式事实、教师笔记和 AI 分析分层。F1 过滤授权群、去重、按消息时间限制窗口，缺页明确部分，不把 20 条称为两天全集。

A2 的时间戳由程序额外投影为 Asia/Shanghai 日期文本，保留原始秒值；实时和快照复测都经过同一规范化函数，记录版本。回答日期偏差、由图片计数推测互动及无依据弱化正式出勤 0 时提供待核对提示；这些检查不自动代用户判定通过。F1 同时记录可读与已脱敏正文数量。

## 审阅与复测

主页面按“老师的问题 → 实际回答 → 回答评价和可选补充信息”排列。一键测试依序执行原有 plan/execute/generate，失败或澄清停止后续；独立步骤保留在默认折叠的技术证据内。引用点击可以展开证据。回答质量未验收时不能用接口成功替代。

新反馈采用 answer-quality-v2：answerId、snapshotHash 绑定当前回答；match（答到点上）、relevance（相关）、quality（好用）均为可选评价（待评价/满意/基本满意/不满意/无法判断），note 自由备注，不再要求 anchor。新回答清空评价草稿，不继承通过；保存过期回答反馈时服务端拒绝。旧四维反馈只作为历史保留，不翻译成新质量结论。

Review Suggestions 以确定版本的工程盘点目录生成：按四题业务场景列候选，结合逐条 trace（含依赖、失败和回放）排除已尝试接口，并排除已返回相同工具证据的候选。候选说明信息内容、关键字段含义、用途、未调用的可观察原因、接入条件及依据。不是全量完备性证明，不修改模型实际计划、证据或输入。计划尚未执行时不展示“遗漏”建议；没有候选时明确说明。

反馈保存 suggestions 中候选 ID 对应的建议补充/暂不需要/需要讨论，可留每项意见；服务端校验候选 ID 和版本，并存下当时的候选说明与决定。导出展示人类可读反馈与候选依据，JSON 保留完整结构。建议不触发额外 API，不算自动审批。

Write Set 补充：独立工具的 review Module、页面、服务反馈契约、测试、README、本目录 PRD/Spec/Tickets/验收及项目状态入口。既有 Demo、模型选择策略、业务取数工具保持原合同。

## LAB-06 按已获信息去重与证据入口

Write Set：review.mjs、app.js/style.css、范围测试与本文档链。A2 按当前已解析下一课的 name/startTime/endTime/status.studentTotal 判断可用字段；0 人是有效值，null/缺失不是。既有课表已含课名时间，不再推荐详情和24小时课节列表重复查；学生人数已在 Context 时列为“已取得，可补充到回答”，带真实字段路径和来源请求。只有下一课已定位且人数确实缺失，才推荐课堂详情 studentTotal，明确尚需下一课对象绑定。

候选采用新目录版本，原反馈保留说明副本。客户端更新候选时保留问答评价与文字；不兼容的旧候选意见另存本机草稿归档，不能套用到不同含义的新候选。保存时采用当前版本及仍存在的候选 ID。

答案旁直接展示本次接口路径、请求数及查看返回按钮。定位到对应 trace 的真实响应，字段表和完整上下文仍可查看；实际调用（含系统校验/依赖）、捕获和快照回放分别标记。候选路径直接显示，说明增量及与本次接口的关系；已有数据无需新增接口。这里只改变审阅呈现，不改写历史真实答案或私自补调。

## LAB-07 私有真实 IM 样本

Write Set：独立工具采集脚本、BusinessRead/Evidence、F1 目录/文字、测试与文档链。使用本机已登录教师客户端的已授权班群页面，短时监听实际 WS 收件并触发该页加载历史；验证 auth.uid 与固定测试教师一致，仅保存目标群的历史/收件消息和读取请求元信息，凭据永不落盘。正文保留在受限目录，仅用于授权审阅及当前 DeepSeek；通用捕获器及旧脱敏证据不覆盖。不是独立服务端实时 Reader。

F1 新运行默认请求最近5天，并以实际采集结束时钟筛选目标群、去重和排除撤回消息。有可读正文即可生成部分摘要，不要求完整分页。输入与页面区分目标窗口、实际最早/最晚消息、读取数量、可读正文数量；未全取则明确部分。旧快照复测保持其原48小时或其他已记录窗口和时钟，不能静默扩大旧证据。

用户进一步要求消息正文完全保留，不做脱敏；原始正文（含链接、表情和换行）在私有样本、API证据、模型实际输入和审阅 UI 逐条一致。鉴权帧不保存。为避免模型将 UTC 当本地时间，另附北京时间字段，原始正文和原始时间均不改写。

## LAB-08 合同与 Write Set

范围：独立工具 lib/answer-policy.mjs、catalog/business/evidence/runs、页面模式入口及测试、文档链。主 Demo 和原反馈不改。

A2 用活动列表的下一课人数及相邻后续课堂，计算起点到起点的间隔小时/天；区分当前时钟倒计时，不混淆课间休息。C2 同班 getCourseMember 只取姓名映射，按 studentUid=memberUid 且 identity=1 关联；无姓名则保留明确未匹配状态。提交状态0/草稿不判准时；1/2且refTime为有效Unix秒，才与 endTime 比较。等于截止为按时，早于截止标截止前，晚于截止标迟交；无合法时间则未知。保留原名单，新增派生列表及规则/来源。

回答策略按四题固定业务目的约束详略，但不能伪造模型计划。E2主要提炼教师笔记与AI中有依据的知识、方法、练习线索，标明AI分析来源，禁止把生成对白叫ASR；缺题干不编例题。默认不展示出勤、评分、图片计数等。F1通常3条主题要点，单条尽量短，核对结果最多2条。原始聊天、模型请求仍完整保存。

LAB-08 ASR Write Set 补充：lib/transcript.mjs、现有 BusinessRead/工具目录/计划及回答策略/候选说明、契约测试和验收文档。新增 read_class_transcript 本地只读工具：先验证活动归属，再 getLessonRecordInfo 核验 lessonId，由其 fileList 提供 FileId，逐文件以 bizType=1、subtitle=1、isRetry=false 调用 /course-ai-assistant/app/file/richVideoSummary。不硬编码选择某个文件，不触发重新生成。此次响应已直接含 content.children[].desc 和 metadata.times，采用这个正文；cosUrl 仅用于实测交叉验证，不作为运行时任意下载入口。
