# WorkBuddy 线框原型设计规范

## 设计读法

这是一个教师专业工作台的结构原型，不是营销页、最终 UI 视觉稿或 ClassIn 品牌换肤。目标是让产品、教研和工程共同看见任务、上下文、产物、控制点和结果。

## 三个设计旋钮

- `DESIGN_VARIANCE: 3`：规整的工作台网格，重点让关系可扫描；
- `MOTION_INTENSITY: 2`：只使用状态反馈和轻微过渡，不用装饰性动画；
- `VISUAL_DENSITY: 4`：教师首屏只承载一个任务、一个下一步和必要的方案信息。

## 视觉基线

- 主题：浅色中性 Canvas；
- 主色：黑、白、灰；最多一个低饱和语义强调色，仅用于当前步骤、可执行操作或真实状态；
- 不使用 ClassIn 品牌绿作为默认设计依赖，不复刻品牌字体、Logo 或设计 Token；
- 页面区块用布局、留白和细边界组织，不在卡片内套卡片；
- 圆角只保留三档：0、6、10；原型优先方正，避免消费产品的圆润卡片感；
- 字号遵循页面标题、区块标题、正文、元信息四级，不使用装饰性大标题或小写大写眉题；
- 所有文案使用直接功能语言，模拟和未来能力显示在状态标签中。

## 工作台信息架构

默认首屏采用任务引导式结构：选择一件教学工作，用自然语言补充目标，浏览方案草稿，确认后再保存。能力域入口仍属于终局信息架构，但不在首屏抢占注意力。

默认主流程表达四个步骤：

1. 选择任务；
2. 说清目标；
3. 查看课程方案；
4. 确认保存。

Run、Artifact、ContextSnapshot、Harness 和 Adapter 属于产品内部结构，不在教师默认首屏直接出现。需要评审内部实现时，通过评审模式查看过程视图和异常状态。

## 交互原则

- 教师先看到“我可以帮你完成什么”和唯一主要动作，再看到目标复述和方案结果；
- 默认每个页面只回答三个问题：我现在要做什么、WorkBuddy 正在做什么、下一步按哪个按钮；
- 每个 AI 产物都可编辑、可查看来源、可比较版本；
- 业务写回先进入待确认动作，显示范围、风险、可逆性和对象版本；
- 加载、缺口、冲突、部分成功、权限拒绝、可恢复失败和完成待复查必须是可操作状态；
- 教师不需要知道 Agent、Skill、MCP、A2A 或模型名称；
- 任何不能明确标注事实所有者的 UI 状态先回到 Spec，不进入原型。

## 原型真值标记

统一使用：`[真实]`、`[模拟]`、`[集成模拟]`、`[未来]`。当前第一版默认所有业务对象和执行回执为 `[模拟]`，知识包为固定版本 `[模拟]`，未来 ClassIn Adapter 为 `[未来]`。

## 可访问性与验收

- 桌面基线为 `1440x900`；同时检查窄屏不产生横向溢出；
- 所有可操作元素有可见焦点、键盘顺序和文本名称；
- 文本与背景达到 WCAG AA 对比度；
- 不用颜色作为唯一状态信号；
- 视觉验收先看任务是否可完成、状态是否可理解，再看装饰偏好；
- 变体切换、任务推进和错误恢复必须不依赖 Hover。
