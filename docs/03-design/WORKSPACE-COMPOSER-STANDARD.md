# Workspace Composer 统一规范

> 状态：当前实现规范
> 适用范围：教师端与学生端的公开聊天输入、WorkBuddy 私密输入、新任务目标输入、运行中补充输入和历史任务追问。
> 不适用范围：审批正文编辑、表单字段、作业作答和其他文档编辑器。

## 1. 设计目标

不同页面可以拥有不同业务命令，但不得自行重新拼装输入框、工具栏、状态提示和发送按钮。所有适用入口统一通过 `WorkspaceComposer` Module 表达，以小而稳定的 Interface 隐藏尺寸、自动增高、键盘提交、字符计数、禁用态和焦点态规则。

这一收敛只统一交互骨架，不合并业务语义：

- 公开聊天仍向当前会话发送消息；
- WorkBuddy 与 Agent Run 输入仍保持私密，不进入群聊；
- 新任务输入创建新的 `WorkBuddyRun`；
- 运行中补充输入只向当前 Run 追加教师要求；
- 审批和正式执行继续使用各自的显式确认动作。

## 2. 结构

Composer 由两行组成：

1. 输入区：无第二层重边框的 `textarea`；
2. 底部栏：左侧工具、居中的状态提示、右侧次级命令与发送按钮。

发送按钮固定在右下区域，使用统一的 32 × 32 px 图标按钮。按钮必须有可访问名称，不在图标下方或旁边重复显示“发送”文字。工具、状态和发送动作必须处于同一基线，不允许绝对定位后产生上下错位。

## 3. 尺寸与排版

- `conversation` 模式从单行高度开始，随内容自动增高，最多显示 10rem；超过后仅 textarea 内滚动；
- `task` 模式保留较大的任务描述面积，但使用相同的边界、底部栏和发送按钮；
- textarea 禁止手动拖拽；
- Composer 自身使用完整边框、圆角和 `focus-within`，textarea 不再绘制第二个焦点框；
- 页面只负责 Composer 的布局位置和外边距，不得覆盖其内部 padding、按钮尺寸或行高；
- 窄宽度下状态提示可省略号截断，发送按钮始终可见、不可被工具区挤出。

## 4. 输入行为

- `Enter` 提交；
- `Shift + Enter` 换行；
- 中文输入法组合态不得误提交；
- 空白内容不得提交；
- 提交后由业务调用方清空或保留草稿，Module 不擅自改变业务数据；
- 需要上限的入口使用 `maxLength`，到达阈值后显示计数；
- 禁用输入不等于禁用底部的恢复类次级命令，例如“继续执行”。

## 5. 状态与可访问性

- textarea、发送按钮和工具按钮必须各自具备明确的可访问名称；
- 禁用态同时通过 `disabled` 与视觉弱化表达，不能只靠颜色；
- 焦点落在 Composer 任一可交互元素时，统一在外层显示焦点环；
- 字符计数使用 `output` 并与 textarea 建立 `aria-describedby`；
- 动态结果由页面现有的 `role="status"` 或 `aria-live` 区域播报，Composer 不逐键播报；
- Reduced Motion 下不增加额外位移动画。

## 6. 页面变体

| 场景 | 模式 | 左侧工具 | 状态提示 | 次级命令 |
| --- | --- | --- | --- | --- |
| 新建任务 | `task` | 附件、Skill、Core Context | 可省略 | 无 |
| Agent Run | `conversation` | 无 | 当前步骤或补充说明 | 停止/继续 |
| 历史任务 | `conversation` | 无 | 当前命令语义 | 无 |
| WorkBuddy 私密窗口 | `conversation` | 无 | 私密性、当前 Run 状态 | 无 |
| 公开聊天 | `conversation` | 表情、附件 | 可省略 | 无 |

## 7. 验收基线

- 所有适用入口均可定位到 `[data-workspace-composer]`；
- 输入区能随多行内容增高，并在上限后内部滚动；
- 工具栏和发送按钮垂直对齐，公开聊天不再使用固定 5rem 的边到边输入区；
- 所有入口的发送按钮尺寸、圆角、禁用态与焦点态一致；
- `Enter`、`Shift + Enter` 和输入法组合态行为一致；
- 公开聊天、私密 WorkBuddy 与 Agent Run 的发送目标没有被共享视觉 Module 改变；
- 1024 × 640、1280 × 800 与 1440 × 900 下无水平溢出、遮挡和不可达按钮。
