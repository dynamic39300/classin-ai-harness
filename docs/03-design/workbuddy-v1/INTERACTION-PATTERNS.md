# WorkBuddy V1 交互模式基线

## 1. 稳定 Shell，任务化工作区

- ClassIn Shell 持续表达教师、机构和一级位置；
- 新建任务、运行中任务、产物编辑和能力管理使用适合自身任务的工作区；
- 不为了统一而把所有页面固定为三栏；
- 从沉浸编辑返回时恢复任务、滚动、展开项和产物版本现场。

## 2. ClassIn 一级主导航与 AI Agent 二级导航面板

- ClassIn PC 一级主导航提供 AI Agent 入口；进入后打开一列对标 NineClaw 的 AI Agent 二级导航面板；
- 二级面板扁平承载新建任务、近期任务、Skills、Tools、内容、定时任务、文件和设置；Section 标题只用于分组，不创建第三级菜单；
- 任务历史直接位于二级面板，不在 Work Surface 中再增加第三根历史栏；
- `1440×900` 下默认可见 6 条近期任务，更多任务在该 Section 内部滚动查看；
- 历史任务以连续列表呈现，不套独立浮动卡片；
- 默认在条目右侧显示相对时间；
- Hover、Focus 或选中时显示 `…`，点击打开小浮层；
- 浮层提供重命名、置顶、删除；
- Hover 不是唯一入口，键盘 Focus 和选中态同样可达；
- 删除属于可恢复界面动作时提供 Undo；涉及真实 ClassIn 对象时使用明确确认和影响说明。

## 3. 渐进披露的执行过程

| 层级 | 默认内容 | 展开内容 |
|---|---|---|
| 教师摘要 | 阶段目标、正在做什么、当前结果、下一步 | 关键依据和阶段输入输出 |
| 能力追踪 | Skill/Tool 名称、作用、状态、耗时 | 参数摘要、依赖、返回结果 |
| 技术详情 | 默认折叠 | 原始参数、日志、命令、路径、错误诊断 |

失败、等待补充、等待确认和恢复动作必须在摘要层可操作，不能只藏在技术详情中。

## 4. 列表、详情与工作现场恢复

- 打开任务或产物详情时保留来源列表和选中项；
- Context、筛选、排序、搜索和滚动位置在返回时恢复；
- 对象归属面包屑与返回来源分别建模；
- 复杂编辑进入扩展或全屏后，返回原任务而不是默认首页；
- 任务状态变化后，来源列表即时显示新状态，但不重排到令用户失去位置。

## 5. Core Context 的阶段 1 表达边界

本阶段只锁定交互层级，不定义字段全集：

1. 输入区附近的紧凑 Context 摘要；
2. 可打开的 Context 详情；
3. 执行过程中对已使用 Context 的可追溯引用；
4. 单次 Run 的 Context Snapshot。

Context 来源、业务对象、自动选择、权限和失效规则必须在阶段 2 中基于 ClassIn PC 资料专项定义。

右侧活动辅助区同一时间只承载 `Artifact / Core Context / 执行详情` 之一，通过显式入口或 Tab 切换；任务状态可以建议打开相应面板，但不能在未经教师操作时反复抢占焦点。

## 6. Artifact 工作模式

- Artifact 由任务生成，但拥有独立类型、状态和版本；
- 支持预览、编辑、AI 修改、比较、确认和保存；
- 单课件任务只需要一个主要 Artifact 也能完成闭环；
- 课程方案包任务使用多个关联 Artifact，允许单项重做和独立审阅；
- 产物面板可按需打开或扩展，不强制一直占据右侧；
- 多产物局部失败不能把整个任务简单标为成功或失败。

## 7. 反馈与控制

| 类型 | 交互 |
|---|---|
| 低风险、可逆 UI 操作 | 即时执行 + Toast + Undo |
| 内容生成与 AI 修改 | 显示生成中、可取消、结果对比和版本 |
| 需要补充信息 | 就地结构化补参，保留已有目标和 Context |
| ClassIn 业务写回 | 建议动作 → 影响范围 → 教师确认 → 执行回执 |
| 部分成功 | 显示逐项结果、已完成对象、失败原因和继续/重试 |
| 权限拒绝 | 说明缺少的权限、未执行动作和可恢复路径 |

## 8. 键盘与可访问性

- 所有点击能力支持可见 Focus；
- Hover 和右键菜单不能承载唯一关键动作；
- 弹层关闭后焦点回到触发元素；
- 状态不能只靠颜色表达；
- 动态过程使用可理解的文本状态，不用持续动画代替信息；
- `1440×900` 下关键操作可达，无隐藏在不可见滚动区的唯一主行动。
