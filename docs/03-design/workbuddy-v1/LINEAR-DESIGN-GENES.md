# Linear PC 设计基因与 WorkBuddy 转译

## 1. 研究依据

本文是面向设计实施的提炼，不重复完整研究。事实、官方来源和证据边界见：

- `../../01-research/source-notes/product_research_linear_pc_design_genes_20260820_v1.md`；
- `golden-samples/linear/` 中从 Linear macOS 实机材料选出的代表样本；
- `source-materials/classin-product-dna-20260810.md` 中已经完成用户复核的 ClassIn 迁移边界。

Linear 值得迁移的不是灰白配色、圆角或“少边框”，而是一套让复杂度按意图出现、保持工作现场并降低视觉噪声的桌面工作台语法。

## 2. 十二条设计基因

### G1：Shell 退居背景，当前任务成为视觉主角

全局导航持续表达身份和位置，但面积、对比度和操作权重低于当前 Run。WorkBuddy 继承 ClassIn Shell，不复制 Linear 的 Workspace/Team 结构。

### G2：统一关系和动作语法，不统一所有页面列数

新建任务、运行过程、产物审阅、Skill/MCP 管理可以采用不同工作区。统一的是标题、状态、选择、详情、返回和操作反馈语法。

### G3：容器深度跟随认知深度

```text
扫描列表 → 临时预览 → 同屏详情 → 扩展编辑 → 沉浸全屏
```

任务历史、Artifact 和 Core Context 均按内容深度选择容器，不让所有操作都跳新页面，也不把复杂编辑困在窄抽屉中。

### G4：保留工作现场

返回后恢复来源、筛选、搜索、滚动、选中项、草稿、未完成输入和当前 Artifact 版本。对象归属与返回来源分别建模。

### G5：一个动作模型，多种输入方式

显式按钮、菜单、键盘和命令面板共享同一动作语义。主流程必须可见、可点击；快捷方式只提供加速，不承担唯一入口。

### G6：全局找对象与局部缩小集合分离

- 全局业务对象搜索：班级、课程、课节、学生、作业、资源；
- 当前任务历史过滤；
- Agent 输入中的显式 Context 引用；
- 产物或过程正文内查找。

四类行为不共用一个含糊的搜索状态。

### G7：完整能力通过渐进披露存在

默认层只显示教师理解状态和决定下一步所需的信息；Skill、工具调用和输入输出进入展开层；原始参数、命令、路径、JSON 和诊断进入高级层。简洁不能依靠删功能。

### G8：高密度依赖字段纪律

任务行、历史行和过程事件采用稳定字段顺序与重复节奏。颜色、图标和文字各自承担明确语义，避免每一行都出现完整工具条。

### G9：颜色表达真实状态，表面表达空间层级

大面积保持中性，品牌色用于 ClassIn 识别、焦点和关键行动；状态色用于成功、风险、错误和信息。AI 不获得独立高饱和渐变皮肤。

### G10：一个 WorkBuddy，多种入口和容器

完整工作台承载复杂任务；课程、班级、作业和资源对象内可以发起轻量 WorkBuddy 入口并自动带入 Context；放大后继续同一任务，而不是创建断裂的新会话。

### G11：Agent 使用现有业务对象与权限

Core Context 引用 ClassIn 真实业务对象并继承当前教师权限。Domain Knowledge 作为机构、学科、年级和个人规则层独立治理，不混成聊天记忆。

### G12：AI 变化必须可审阅、可归属、可恢复

过程显示当前进度；产物显示 AI 修改归属和版本差异；业务动作进入教师确认；执行结果提供回执；错误和低风险操作提供恢复路径。

## 3. WorkBuddy 三层表达

| 层级 | 教师看到什么 | 设计目的 |
|---|---|---|
| 默认业务层 | 目标、Core Context 摘要、当前阶段、关键结果、待决策事项、Artifact 状态 | 3 秒内理解当前状态和下一步 |
| 能力追踪层 | Skill、Tool、使用原因、输入范围、输出摘要、耗时与状态 | 保留 NineClaw 完整过程与可追溯性 |
| 高级技术层 | 原始参数、命令、路径、JSON、底层日志和诊断 | 支持高级用户、评审和问题定位 |

三层均属于产品设计范围。默认折叠不等于功能删除。

## 4. Agent 容器转译

| Linear 观察 | WorkBuddy 使用 | ClassIn 边界 |
|---|---|---|
| Agent 有完整页、快捷入口和对象内协作 | WorkBuddy 一级工作台 + 业务对象内发起入口 | 教师只面对一个统一 WorkBuddy 身份 |
| Peek/Panel/Full-screen 逐级深入 | Context、Artifact、执行详情按深度升级容器 | 复杂课件编辑不得长期困在窄面板 |
| Agent 以现有对象作为上下文 | 课程、班级、课节、学生、资源等进入 Core Context | 来源、权限、更新时间与快照必须可见 |
| 对话可沉淀 Skill 和自动任务 | 保留 NineClaw Skill、MCP、定时任务与任务回流 | 普通教师默认不需要先选底层能力 |
| AI 修改显示归属与恢复 | Artifact 版本、差异、教师审批和执行回执 | 正式写回不能只依赖 Undo |

## 5. 明确不复制

- 不复制 Linear 的品牌、色值、研发术语和对象层级；
- 不把所有 WorkBuddy 页面固定成三栏；
- 不把 Hover、右键或命令面板作为关键动作唯一入口；
- 不把系统通知、教师会话和 Agent 任务混成一种 Inbox 状态；
- 不从截图反推字体、间距、圆角、阴影和动效 Token；
- 不把低风险即时 Undo 直接用于课程、作业、成绩或发布状态写回；
- 不把 Skill 菜单存在等同于 Agent 闭环完整。

## 6. Phase 2 直接输入

Linear 基因将在阶段 2 约束以下设计：

1. WorkBuddy 一级入口与业务对象内入口的连续性；
2. 任务历史、当前 Run 和 Artifact 的容器层级；
3. Core Context 从摘要、面板到对象原页的逐级深入；
4. Agent 过程的三层披露；
5. 单课件和课程方案包的多 Artifact 审阅；
6. 返回现场、版本、差异、审批、回执和恢复状态。

任何具体页面仍必须回到 NineClaw 功能证据和 ClassIn 业务对象事实验证，不能只凭“像 Linear”作为设计理由。
