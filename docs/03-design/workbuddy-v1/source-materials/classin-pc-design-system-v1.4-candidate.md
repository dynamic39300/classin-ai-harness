# ClassIn PC Design System

**版本**：v1.4 Candidate
**日期**：2026-08-11
**状态**：中性白色 Canvas 与全页面中性表面已锁定；页面内容审计仍为 `OPEN-VALIDATE`

## 1. 体验方向

ClassIn PC 是专业、克制、现代的教学工作台：

- 保留移动端业务命名、品牌绿和状态语义。
- 使用桌面侧栏、工具栏、多栏工作区和可伸缩详情面板。
- 大屏增加并列上下文，不无限增加单行信息或把空白全部填满。
- 老师强调扫描与连续处理；学生强调下一行动与结果反馈。
- 视觉一致但页面叙事不同，不建立角色主题色。

## 2. 视觉层级

1. `Canvas`：纯白应用背景与大工作区。
2. `Shell/Surface`：纯白侧栏、顶栏、列表、内容和 Inline Panel。
3. `Muted Surface`：工具条、搜索、分段控件和辅助区域的浅中性灰底。
4. `Selection`：中性灰选中面、文字权重和必要的品牌绿细标记，不使用品牌绿填充作为通用选中态。
5. `Action/Status`：主操作、警告、错误、成功和未读。
6. `Overlay/Modal`：菜单、浮层与阻塞确认。
7. `Immersive Canvas`：为未来明确接入的沉浸工具保留；当前黑板页面不启用该层级。

页面 Section 不是浮动卡片。优先使用对齐、标题、间距和背景差；细边框只用于必要边界。

| `action.strong` | `#0B6E4F` | 必须使用白字的强主操作 |

| `ink.onObject` | 纯白 | 中性深灰对象上的文字与图标 |

### 3.2 应用规则

- 主 CTA 优先使用 `brand.core + brand.onCore`。
- 深色次级强操作使用 `ink.900 + white`。
- 需要白字的绿色按钮使用 `action.strong`，不使用 `brand.core + white`。
- 应用侧栏使用纯白表面、Ink 主文字、中性灰选中面和品牌绿焦点标记。
- 当前黑板使用普通工作面与中性 Placeholder；保留的 `canvas.immersive` Token 不代表页面已经接入真实画布。
- 品牌绿不用于大面积页面背景。
- 普通页面 Canvas、Shell 和主要 Surface 不带绿色色相；绿色只表达品牌、操作焦点或真实业务状态。
- 绿色“可点击”与绿色“成功”必须通过形态、文案和独立语义 Token 区分。
- 所有中性背景、选中面、Hover 面、边线、蒙层和 Overlay 阴影必须使用等通道 RGB 值（`R = G = B`），避免 OKLCH 到 sRGB 的截图舍入产生绿色偏差。
- `surface-muted` 当前锁定为 `rgb(244 244 244)`；其他中性层级沿用同一等通道原则，不以品牌绿或状态色替代。
- `brand-soft`、Success/Warning/Danger/Info Soft 仅允许出现在明确的品牌强调或状态反馈组件中，不得作为页面 Canvas、通用控件或通用选中态。
- Divider 只在归属、扫描或操作边界确有需要时使用；同一 Surface 内优先用间距与对齐区分。

### 3.3 状态色

- Success：完成、连接成功、提交成功。
- Warning：临近截止、风险、需要关注。
- Danger：逾期、错误、破坏性动作。
- Info：课堂变化、系统说明和中性通知。
- Data：课程类型和图表序列，不能复用警告/错误色造成误读。

状态 Tag 使用浅底 + 深字。所有最终色值在实现后运行对比度检查定版。

## 4. 圆角与边界

| Token | 值 | 对象 |
|---|---:|---|
| `radius.none` | 0 | 相接面板、表格边界、全宽分区、Canvas |
| `radius.control` | 4px | Button、Input、Tag、列表选中底 |
| `radius.object` | 6px | 独立任务项、文件缩略项、小状态面板 |
| `radius.overlay` | 8px | Menu、Popover、Tooltip、Dialog、Overlay |

- 头像、状态点、单值 Badge 和 Toggle 可使用全圆角。
- 拼接组件共享边使用 0px，仅保留外轮廓圆角。
- Inline Panel 使用 Divider，不使用悬浮卡片阴影。
- 阴影只用于 Overlay、Dialog、Menu 和拖拽对象。

## 5. 间距与密度

### 5.1 基础网格

4px 基础网格：

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`

同组紧、跨组松；页面区块不依赖套卡片制造间隔。

### 5.2 候选密度

| 对象 | Compact | Comfortable |
|---|---:|---:|
| 图标按钮命中区 | 32px | 36px |
| 普通按钮/输入 | 32px | 36px |
| 导航/菜单行 | 36px | 40px |
| 单行数据/任务 | 36-40px | 44-48px |
| 双行列表 | 48px | 52-56px |
| Toolbar | 44-48px | 52-56px |
| 页面内边距 | 20-24px | 24-32px |

首版默认中等密度：

- 老师任务、消息、空间、数据表使用 Compact 候选。
- 学生首页、成长、表单和阅读详情使用 Comfortable 候选。
- 字号不随密度缩小；通过行高、间距和次级字段显隐调整。
- 最终值只通过 `1440x900` 设计基线截图验证；其他尺寸不新增适配或交付门禁。

## 6. 排版

| Token | 候选值 | 用途 |
|---|---|---|
| `pageTitle` | 20/28 semibold | 页面标题 |
| `sectionTitle` | 16/24 semibold | 区块/面板标题 |
| `itemTitle` | 14/20 semibold | 列表主标题 |
| `body` | 14/20 regular | 正文和字段 |
| `meta` | 12/18 regular/medium | 时间、班级、Tag |
| `dataFocus` | 24/32 或 32/40 | 少量关键数字 |

字体规范（`LOCKED`）：

- UI 拉丁字符与数字统一使用本地自托管的 `Inter Variable`；中文按 `PingFang SC`、`Microsoft YaHei` 顺序回退，不引入另一套展示字体。
- `font-display` 与 `font-body` 使用同一字体栈，标题通过字号和字重建立层级，不使用装饰性标题字体。
- 正文使用 400、导航与元数据强调使用 500、标题和强标签使用 600；已有特殊标识可保留更高字重，但不得成为页面常规层级。
- 时间、日期、计数、指标、百分比、Badge 和表格数值统一启用 `tabular-nums lining-nums`，确保同行数字稳定对齐；技术代码才使用等宽字体。
- 字距统一为 0；字号不随 viewport 连续缩放。

### 7.1 候选尺寸

| 区域 | `1440x900` 基线 |
|---|---:|
| 展开侧栏 | 216-224px |
| 顶部工具栏 | 44-56px |
| 主工作区 | 剩余宽度，优先保住主任务 |
| 详情/集合面板 | 344-360px |
| 展开编辑面板 | 480-640px |

### 7.2 交付视口

- 当前唯一设计、实现与视觉验收视口为 `1440x900`。
- 不为 `1280x720`、`1024x640` 或其他尺寸新增 Compact、Overlay、重排或字段裁剪逻辑。
- 历史多视口截图只保留为证据，不作为本轮实现依据。
- 禁止用 `transform: scale()` 缩放整个应用。

### 7.3 浅色壳层

- Sidebar 与 Topbar 属于同一浅色主题，不用深色半屏制造品牌锚点。
- Sidebar 只保留与工作区之间的结构边界；品牌、角色、导航组和账户区域不逐层画分隔线。
- 当前导航使用中性灰底、Ink 文字和绿色细标记；Hover 使用更弱的浅灰底。
- 角色上下文使用图标 + 角色名，不显示“当前工作区”等重复微标签。
- Account Menu 作为 Overlay 保留边界与阴影。

## 8. 页面焦点与比例

- 每个工作区只有一个明确主焦点和一个主操作层级。
- 黄金比例可用于首页开放构图和视觉检查，不用于强制计算侧栏、表格、课程表或详情面板。
- 阅读正文限制最大宽度；课程表、数据表、文件网格和黑板可使用完整工作区。
- 超宽屏增加外侧留白、详情上下文或可调分栏，不增加无限行宽。
- 视觉平衡依靠稳定对齐、重复节奏和任务权重，不追求机械对称。

## 9. 集合面板、对象详情与编辑

- Inline Panel 用于保持集合或上下文，例如任务集合筛选结果和班级辅助信息。
- 对象详情默认沿用所属 Feature 的已锁定模式；当集合面板必须持续保留全量上下文时，可以使用独立命名 Dialog 展示单一对象详情。
- 课程表使用固定右侧辅助栏，其中月历与“当日安排”分别作为独立白色圆角浮层模块；右栏只展示所选日期的完整课程组，点击课堂或学习活动打开独立 Dialog，禁止在模块内展开详情导致列表被挤走。
- 独立 Dialog 使用纯白 Surface、8px 圆角、单层 Overlay 阴影和稳定标题栏；不再在 Dialog 内叠加抽屉或第二个 Modal。
- 中等编辑可使用 480-640px 面板；复杂画布型任务进入完整工作区。
- 关闭面板或 Dialog 后焦点回到原触发项，并保留筛选、日期、选择和滚动位置。

### 9.1 连续属性列表

- 老师端高频属性列表优先使用 Linear 式连续行：数据行之间不使用 Divider、外边距或卡片边界，依靠固定列对齐、列内留白和稳定行高区分对象。
- Compact 双行属性列表统一使用 `collection-row-height`（56px），表头使用 `collection-header-height`（36px）；行内容变化不得改变列表节奏。
- 默认数据行保持透明；Hover 使用 `surface-hover`，键盘 Focus 使用 `surface-selected` 与 `focus` 内描边，反馈统一使用 `radius.control` 且不得引发布局位移。
- 工具栏与属性表头之间可以保留一条 `line.subtle` 结构边界；表头与数据行、数据行与数据行之间不重复画线。
- 行导航与最右侧操作按钮必须是独立焦点目标，操作按钮不得误触发行导航；Hover 不能成为编辑操作的唯一入口。
- 同构集合页的排序入口统一使用 Lucide `ArrowUpDown` 15px 图标和 32px icon-only 控件；原生排序 Select 覆盖完整命中区，选项文案不常驻占用工具栏空间。

## 10. 交互状态

每个控件至少定义：

`rest / hover / focus-visible / pressed / selected / disabled / loading`

- Hover 只补充反馈和次级操作，不承载唯一功能。
- Focus 使用 2px 可见焦点环，与 Selected 区分。
- Selected 使用持久底色、文字/图标权重和必要侧边标记。
- Loading 保持控件尺寸，不让工具栏跳动。
- Disabled 保持可读，并通过 Tooltip/辅助文案解释原因。

## 11. 图标、按钮与工具栏

- 使用 Lucide 图标；有现成图标时不手绘 SVG。
- 教学对象图标从共享语义注册表读取，不允许页面维护局部 `ACTIVITY_ICONS`、`TASK_ICONS` 或同类映射。
- 对象类型使用稳定轮廓表达，状态使用颜色表达。图标自身默认继承中性 `currentColor`，只有当前、进行中、临近截止、逾期、成功或错误等真实状态可以改变颜色。
- 工作区入口与业务对象分层：入口回答“去哪里”，对象图标回答“这是什么”。例如课程表入口使用 `CalendarDays`，课程表中的课堂使用 `Presentation`。
- Lucide 教学对象图标统一使用 `1.75px` 绝对线宽；紧凑元信息为 14px，普通列表为 16px，强调列表或控件为 18px，空态/Placeholder 为 24-40px。
- 图标与相邻类型文字共同出现时设为装饰性；图标单独承担操作时，按钮必须提供可读 `aria-label` 和 Tooltip。
- 熟悉工具优先使用图标按钮并提供 Tooltip；清晰命令使用图标 + 文字。
- 不给每个图标套独立圆形容器。
- 工具栏同一时刻只保留一个高权重主操作。
- 教学活动列表快捷操作统一使用 `32px` 高、`76px` 固定宽的文字按钮，文案最多四个汉字。主操作为白底、品牌色文字与中性控件边界，辅助操作为白底、中性文字与浅边界；人数和进度进入状态或元信息，不拼接进按钮。
- 首页、待办、课程表当日安排和班级课程目录必须复用同一教学快捷操作组件。首页、待办和班级目录展示主操作及有价值的辅助操作；课程表当日安排只展示一个主操作，更多动作进入详情 Dialog。
- 黑板与投屏位于老师侧栏的“即时工具”，不参与业务导航选中模型。
- 不在 Web 内容中伪造 macOS/Windows 系统窗口按钮。

### 11.2 结果反馈与能力边界

- 非阻塞且无需用户选择的短结果使用 Toast，并通过 `role="status"` 对辅助技术可见。
- 需要说明真实能力边界、权限限制或明确下一步的 Placeholder 使用命名 Dialog；关闭后焦点返回触发控件。
- 表单校验错误就地显示并聚焦首个错误字段，不用 Toast 或 Dialog 替代表单错误。
- Toast 只反馈本次操作结果，不拥有业务状态。提交、发布、批阅等操作完成后，页面必须继续显示可恢复、可复查的持久状态。
- 作业提交的标准组合是轻量 Toast + 当前工作区内持久的“已提交，等待批阅”状态；持久业务状态不是第二个反馈浮层。
- 同一操作不同时叠加 Toast、状态条和 Dialog；按信息复杂度选择一个主要反馈载体。

## 12. 动效

- Hover/状态反馈：约 80-120ms。
- 常规淡入/选中：约 120-180ms。
- 面板展开：约 220-260ms。
- 动效只解释空间关系、状态变化和结果，不做装饰性漂移、缩放或弹跳。
- `prefers-reduced-motion` 下改为淡入淡出或即时切换。

## 13. 无障碍

- WCAG 2.2 AA。
- 正文至少 4.5:1。
- 指针目标至少 24x24 CSS px。
- 全功能键盘可达；Tab 顺序与视觉顺序一致。
- Dialog 正确锁定焦点；关闭后恢复触发点。
- Tooltip 同时支持 Hover 与 Focus。
- 颜色不是状态的唯一编码；选中态至少有颜色 + 形态/边界双重表达。

## 14. 角色表达

两个视角共用 Token 和 Shell：

- 老师：更高列表密度、批量操作、跨班级扫描和数据比较。
- 学生：更强行动聚焦、单任务流程、反馈和成长叙事。

角色差异不得依赖更换主题色。

## 15. 验收门禁

- MacBook `1440x900` 截图作为当前设计验收基线；其他视口截图仅作历史证据。
- 无文本截断、重叠和布局跳动。
- 键盘遍历与焦点恢复。
- 自动对比度与 axe 检查。
- 黑板 Placeholder 文案、图标、工作面适配与无伪操作检查。
- Compact/Comfortable 对比后再锁定最终密度 Token。

## 16. 界面语言

- 微文案必须承担状态、风险、权限、结果或下一步信息。
- 删除重复相邻标题/角色信息的 eyebrow、装饰性英文标签和泛化引导句。
- 保留 Placeholder、隐私、错误恢复、表单约束和会改变操作结果的说明。
- 元数据可使用一个中点分隔两项；三项以上优先换行、分列或改用自然语言。
- 页面可见文案不使用长破折号作为装饰性分隔。

## 17. 全页面色彩覆盖矩阵

以下规则适用于老师视角与学生视角的所有路由、工作区、集合页、详情页、表单、Dialog 和 Overlay。

| 页面表面 | 实现 Token | 统一要求 | 合法例外 |
|---|---|---|---|
| 应用底座、Sidebar | `color-app-frame`、`color-shell` | 等通道中性灰，形成一体化底座 | 角色选择页不使用 App Shell |
| 主工作面、Topbar、主内容区 | `color-surface`、`color-canvas` | 纯白，等通道 RGB | 无角色主题差异；黑板 Placeholder 同样适用 |
| 搜索、输入、筛选、表头、辅助栏 | `color-surface-muted`、`color-surface-raised` | 等通道浅灰，不带品牌绿 | 明确状态反馈不得复用这些 Token |
| Hover、Selected、Divider、控件边界 | `color-surface-hover`、`color-surface-selected`、`color-line-*` | 等通道灰，通过文字权重、边界和标记表达状态 | 品牌焦点环仍使用 `color-focus` |
| 蒙层、Dialog 阴影、Popover 阴影 | `color-overlay`、`shadow-overlay` | 等通道黑灰，仅改变明度和透明度 | 无绿色着色阴影 |
| 成功、警告、错误、信息反馈 | `*-soft` + 对应深色文字 | 只在真实状态组件中使用 | 不得扩散到页面背景或通用选中态 |
| 品牌识别与主要操作 | `color-brand`、`color-action-strong` | 仅用于 Logo、焦点、操作和品牌强调 | 不作为大面积 Canvas 或通用 Surface |

实现检查项：业务 CSS 只引用语义 Token；新增页面不得直接写背景色、边框色、阴影色；视觉验收在 `1440x900` 同时检查老师与学生路由，并抽查控件计算样式是否满足 `R = G = B`。

## 18. Linear 式全局工作台壳层

老师首页样板已通过用户视觉确认，“中性灰应用底座 + 单一白色主工作面”推广至老师与学生两棵角色页面树：

- 应用底座和左侧导航统一使用 `color-app-frame`，保持等通道中性灰。
- 右侧 `stage` 是页面唯一的大型圆角工作面，包含 Topbar 与正文滚动区。
- 主工作面使用 `radius-workbench` 与 `shadow-workbench`；不响应 Hover，不做位移动效。
- 页面内部区块不继承主工作面的圆角与阴影，继续通过分栏、细线、对齐和留白建立层级。
- 所有 `/teacher/*` 与 `/student/*` 路由统一生效；`/select-role` 保持 App Shell 外例外。
- 黑板导航与页面区域纳入同一壳层，当前主体只展示 Icon 与能力边界说明，不展示画布、工具轨或保存等伪操作。
- 非模态详情 Overlay 必须定位在白色主工作面内；Modal Dialog 继续覆盖完整视口。
- 当前验收参数为 `1440x900`、12px 外边距、16px 主工作面圆角；灰底与阴影只能使用等通道中性色。

## 19. Anchor Arrival Pattern

跨模块摘要进入详情时，目的地必须把用户带到可见且可解释的目标区域：先解析来源携带的对象上下文，选择所属班级/课程/单元或筛选项，再展开目标节点，完成滚动与键盘聚焦，最后以持久的绿色边标和中性选中面保留到达反馈。参数未匹配时显示中性不可定位状态，不使用临时 ID 映射。返回来源页时恢复触发项焦点和关键滚动位置；该模式仅在真实存在目标锚点的页面使用，不为普通列表增加装饰性高亮。

行业依据详见 `docs/01-research/PC-DESKTOP-UX-STANDARDS.md`。
