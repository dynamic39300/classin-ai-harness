## 2. ClassIn 的产品核心

ClassIn PC 不是“内容管理工具 + 消息模块”，而是围绕教学关系组织的桌面工作台。用户在同一账户和组织中，持续处理四类不同事实：

| 主轴 | 事实所有者 | 用户问题 | 主要页面 |
|---|---|---|---|
| 时间 | 课程表 | 什么时候发生了什么？ | 课程表、首页今日关注 |
| 行动 | 任务中心/待办 | 现在需要做什么？ | 任务中心、待办、作业详情 |
| 沟通 | 消息 | 谁需要和谁沟通？发生了什么通知？ | 私聊、班级消息、系统通知、官方公告 |
| 解释 | 教学洞察/学生成长 | 结果如何，下一步是什么？ | 教学洞察、成长、报告/结果 |
| 内容 | 班级、课程、空间 | 教学对象和资源是什么？ | 班级、公开课、空间、资源详情 |
| 沉浸操作 | 黑板/投屏 | 需要即时展开什么工具？ | 黑板、投屏全屏工作区 |

## 3. 角色与页面树

### 3.1 老师视角

```text
老师视角
├── 首页
├── 课程表
├── 任务中心
├── 教学洞察
├── 空间
├── 消息（全局）
├── 黑板（即时工具）
└── 投屏（即时工具）
```

老师的核心工作是：确认今日教学节奏，处理跨班级任务，理解班级/学生表现，准备和管理内容，并在需要时即时发起教学工具。

### 3.2 学生视角

```text
学生视角
├── 首页
├── 课程表
├── 待办
├── 成长
└── 消息（全局）
```

学生的核心工作是：知道今天要上什么课，完成当前待办，理解自己的成长和反馈，并与老师/班级沟通。

### 3.3 不可混淆的边界

- 角色通过内容、权限和行动表达差异，不建立两套视觉主题。
- 学生不显示空间、教学洞察、黑板创建和投屏发起入口。
- 角色切换进入目标视角首页，不做跨角色页面映射。
- 角色切换期间，草稿、提交、上传、上课和投屏等中断状态必须受到保护。

## 4. 业务事实所有权

### ADOPT

- 课程表只负责时间事实，不替代任务、消息或对象详情。
- 任务中心/待办只负责执行事实，不把消息已读当作任务完成。
- 消息负责告知和沟通；私聊与班级群是会话，系统通知与官方公告是只读或深链入口。
- 班级/公开课/课程/单元/课堂/活动拥有自己的对象关系和返回路径。
- 教学洞察负责教师对班级、课堂和学生表现的判断。
- 学生成长负责学生对长期进展、结果和学习记录的理解。

### 关键状态边界

```text
消息已读 != 任务完成
通知已处理 != 作业已提交
课堂已查看 != 课堂已完成
手动归档 != 业务完成
临时黑板结束 != 已关联教学对象
```

这些不是视觉建议，而是领域状态约束。

## 5. 首页产品语法

两个角色首页都采用“今日关注”，但内容优先级不同：

| 角色 | 首要内容 | 次级内容 | 明确不做 |
|---|---|---|---|
| 老师 | 当前/下一课堂、今日时间线、高优任务、班级关注 | 我的班级、我的公开课 | 独立待批改模块；由任务中心承接 |
| 学生 | 今日课程、未来 3 天课程、紧急待办、学习状态、班级消息 | 我的班级、我的公开课 | 独立主任务、最近反馈模块 |

`今日关注` 是摘要和转场，不维护一套与课程表、任务、消息、成长重复的业务状态。

### PC 转译

- 手机单列和卡片横滑转译为桌面纵向时间线、并列摘要和可关闭详情面板。
- 首页核心内容先呈现“现在最重要的行动”，完整集合通过明确的“查看全部”进入所有者页面。
- 创建班级和创建公开课位于对应列表区域，不进入全局新建菜单。
- 首页深链携带来源、对象 ID 和锚点，详情返回首页而不是集合页。

## 6. 页面原型分类

Linear 的“列表 + 详情”被纳入 ClassIn 的桌面表达工具箱，但按页面任务选择，不作为统一模板。

| 页面类型 | 适合结构 | ClassIn 示例 | 不应套用 |
|---|---|---|---|
| 高频对象工作区 | 列表 + Inline Panel/详情 | 任务、待办、消息、班级、公开课、资源 | 课程表、黑板 |
| 时间工作区 | 周视图 + 当日列表 + 详情 | 课程表 | 普通对象列表 |
| 叙事分析工作区 | 结论 -> 证据 -> 行动 | 教学洞察、学生成长 | 纯指标卡片墙 |
| 领域详情工作区 | 对象主信息 + 相关内容 + 角色动作 | 班级、作业、公开课 | 只显示一段孤立通知正文 |
| 画布工作区 | 全屏、持续状态、即时工具 | 黑板、投屏、复杂作答 | 右侧窄抽屉 |

### 列表型实体的试用边界

班级列表、公开课列表等可以试用 Linear 式列表 + 详情：

- 列表用于扫描名称、状态、下一事件和最小摘要。
- 详情用于展示对象上下文和角色动作。
- 试用必须通过具体用户任务验证，不预先锁定所有列表都使用相同三栏。
- 不能因列表 + 详情而删除移动端已有字段、状态、权限和深链。

## 7. 教学洞察与学生成长

### 7.1 教学洞察

移动端锁定顺序：

```text
班级筛选 -> 班级数据/诊断 -> 最近 3 次课堂 -> 学生表现
```

确定性内容：

- 课程进度 `18/24`
- 出勤率 `92%`
- 作业完成 `78%`
- 平均准确率 `71%`
- 最近课堂包含日期、课节、出勤、平均分和报告入口。
- 学生表包含考勤、互动、提问、答题和作业质量，并区分 `需关注 / 可奖励 / 稳定`。
- 诊断必须同时给出优势、改进点和可执行建议。

PC 结构：

- 顶部保留班级上下文和筛选。
- 中部以一个班级判断主轴组织摘要与诊断，不做互相竞争的指标卡片墙。
- 最近课堂作为证据列表，可展开报告详情。
- 学生表现作为下一层证据，支持关注/奖励等已存在动作。
- 不增加学生私聊或消息触达入口；移动端没有该能力。

### 7.2 学生成长

移动端锁定顺序：

```text
班级筛选 -> 学情诊断 -> 六项成长概览 -> 课程进度 -> 奖励墙 -> 学习记录
```

确定性内容：

- 上课 `12 天`、作业完成 `89%`、连续学习 `7 天`、累计 `18 小时`、准确率 `76%`、奖励 `24 枚`。
- 课程进度覆盖至少两个班级。
- 学习记录包含出勤、分数、奖励、报告状态和作业结果/课堂报告/回放/笔记入口。
- 全部班级按班聚类，最近活跃班默认展开，其余折叠；单班筛选后显示扁平记录。
- 准确率下降使用中性、可行动文案，不使用惩罚性红色箭头或无来源归因。

PC 结构：

- 以成长解释和阅读舒适度为主，不照搬老师洞察的密集数据表。
- 六项指标是摘要，不是页面的唯一内容；课程进度、奖励和记录负责提供证据。
- 记录展开使用详情面板或纵向证据区，不制造多层卡片。
- 反馈指向下一步学习行动，保持非惩罚、非预测和不制造 AI 置信度。

## 8. 消息产品语法

ClassIn v1 固定四分类：

| 分类 | 语义 | 展示形态 | 允许动作 |
|---|---|---|---|
| 1v1  消息 | 账号双方全局唯一会话 | 时间轴 | 发送、基础会话操作 |
| 班级群聊 | 具体班级群聊 | 锁定班级的时间轴 | 发送、已定义群操作 |
| 系统通知 | 业务结果、课堂、截止和管理提醒 | 只读通知 + 业务深链 | 查看、进入业务对象 |
| 官方公告 | 与角色相关的官方信息 | 只读文章 | 查看、返回 |

Linear 的 Inbox 适合系统通知/官方公告的扫描和深链语法，不适合直接覆盖私聊和班级群。

## 9. PC 视觉与交互转译

### ADOPT

- 深色品牌锚点 + 浅色工作区。
- 低噪 Shell、明确选中、Hover 补充反馈和 Focus-visible 等桌面语法。
- 默认中等密度，老师高频工作区优先 Compact，学生阅读和成长优先 Comfortable。
- 默认主构图以 MacBook Pro 14 英寸 Golden Screen 为目标。
- 通过列表、面板、对齐、留白和状态底色建立层级，不把页面 Section 套成卡片。

### ADAPT

- Linear 的列表 + 详情转译为 ClassIn 已锁定的 `Inline Panel -> 扩展面板 -> 全屏工作区`。
- Linear 的消息到 Issue 深链转译为消息到任务、课堂、班级、作业、报告或资源的对象 Link resolver。
- Linear 的低风险即时反馈要结合 ClassIn 的提交、批改、上课、投屏和数据影响边界；关键状态需要中断保护或确认。
- Linear 的复杂 Filter 只迁移“按意图披露”原则，不迁移研发工具字段规模。
- 教师与学生共用 Token，但通过字段、密度和动作权限表达角色差异。

### REJECT

- Linear 的研发术语、Workspace/Team/Project 组织模型和具体视觉皮肤。
- 用 Icon 和颜色单独表达 ClassIn 消息类别。
- 把所有页面固定成三栏，尤其是课程表、教学洞察、成长、黑板和投屏。
- 用白色、浅灰和少边框机械模拟“清爽”，却减少业务字段或状态反馈。
- 把移动端页面横向放大，或把大屏空间全部填满。

### UNKNOWN

- 真实生产后台的权限差异、推送保留、IM 协议、设备发现和投屏错误码。
- 移动端与当前 PC 仍未关闭的 `PI/DI/ND/EC` 对齐项，继续由 Feature Matrix 和具体 Spec 管理。
- 教学洞察和学生成长未来生产数据的刷新频率、异常阈值和服务端解释规则。

## 10. Golden Flows

### 老师视角

```text
登录/角色选择
-> 今日关注
-> 当前课堂或高优任务
-> 班级/作业/洞察对象详情
-> 角色动作
-> 返回原上下文继续处理
```

### 学生视角

```text
登录/角色选择
-> 今日关注
-> 今日课程或紧急待办
-> 作业/课堂/成长记录
-> 唯一主行动或结果阅读
-> 返回待办/成长继续学习
```

### 共同约束

- 深链使用对象 ID、来源和锚点，不只跳集合页或显示 Toast。
- 返回路径由来源决定：首页回首页，列表回列表，班级群回班级详情。
- 业务 Placeholder 必须有入口、边界、反馈和返回路径。

## 11. 用户复核与第二轮校准

| 编号 | 用户确认 | Round 2 结论 |
|---|---|---|
| 1 | 认可“教学工作台”作为 ClassIn PC 的统一产品隐喻 | `LOCKED`：后续 PC 信息架构以教学工作台为总语境，不按内容管理后台组织。 |
| 2 | 列表 + 详情可在班级、公开课、任务、消息等高频实体中试点，但不保证是最终设计 | `RECOMMENDATION`：按具体任务制作原型并验证，不将其升级为所有列表的统一模板，也不在未验证前删除字段。 |
| 3 | 教学洞察与学生成长保留移动端叙事，但 PC 体验和视觉仍需后续迭代 | `LOCKED` 业务叙事、`OPEN-VALIDATE` PC 表达：保留叙事顺序，后续通过桌面布局、视觉层级和原型验收优化呈现。 |
| 4 | 消息四分类严格区分会话与只读通知，并通过 Link resolver 连接业务对象 | `LOCKED`：私聊/班级消息保留会话语义；系统通知/官方公告采用通知分拣语法；已读不等于任务完成。 |
| 5 | 认可 MacBook Pro 14 英寸作为设计主视口；实际设计评审以单一 Golden Screen 为主 | `LOCKED` 设计目标：以单一 Golden Screen 组织页面，不制作三套独立构图。工程质量门禁仍按项目 `AGENTS.md`、`DECISION-LEDGER.md` G-03 和测试规范执行三档回归，二者不是同一件事。 |

### Round 2 执行约束

- 先锁定业务叙事，再在 PC 端重排信息层级；不得为了视觉简洁删减移动端已确认的能力、字段、状态或权限。
- 教学洞察优先验证“结论 -> 证据 -> 行动”的阅读主线；学生成长优先验证“诊断 -> 指标 -> 进度 -> 记录”的阅读节奏。二者可以采用不同页面结构。
- 列表 + 详情只作为可验证的工作区选项。班级、公开课、任务和消息分别验证扫描、定位、处理、返回是否更顺畅，再决定最终形态。
- Golden Screen 用于统一构图、视觉评审和设计沟通；三档视口用于工程质量检查，不要求为每个视口重新设计一套页面。
- 未知的后台权限、数据刷新、IM、投屏和洞察计算规则继续标为 `UNKNOWN` 或 `PLACEHOLDER`，不由本案例补写。
