# ClassIn 教师 WorkBuddy V1 设计基线

## 1. 目标体验

ClassIn 教师 WorkBuddy 是一个专业、克制、连续的 Agent 教学工作台。老师不需要先理解模型、Skill、MCP 或内部 Agent 拓扑，而是从当前教学目标和业务现场开始工作；系统负责补齐 Context、组织执行、交付产物并在教师控制下写回 ClassIn。

设计不是把 NineClaw 换成 ClassIn 配色，也不是把 Linear 的外观套到聊天页面上，而是同时满足：

- NineClaw 的紧凑功能与任务闭环；
- ClassIn 的教师身份、业务对象、权限和上下文连续性；
- Linear 式的低噪层级、渐进披露、即时反馈和工作现场恢复。

## 2. 三源融合原则

| 来源 | 负责决定 | 不负责决定 |
|---|---|---|
| NineClaw | Agent 任务、执行过程、能力调用与产物闭环 | ClassIn 业务事实、权限和最终视觉 |
| ClassIn PC | 角色、对象、入口、Context 来源、桌面交互和品牌语义 | Agent 内部能力编排 |
| Linear | 页面秩序、信息密度、详情关系、渐进披露与视觉气质 | 教学领域模型和产品功能范围 |

发生冲突时，当前项目锁定决策与已审阅目标规格优先。

## 3. 十条设计原则

### P1：从教师目标开始，不从工具目录开始

首屏优先让教师表达“要完成什么”。Skill、MCP、模型和工具集合是可检查的能力层，不是默认决策负担。

### P2：完整保留能力，分层表达复杂度

第一版设计为 NineClaw 已知功能提供完整去向。简洁通过信息层级和渐进披露实现，不通过预先删除功能实现。

### P3：Core Context 是工作现场，不是附件列表

业务上下文与 Domain Knowledge 共同约束任务，但必须区分来源、所有者和更新方式。页面在任务入口、详情、过程引用和任务快照四层表达 Context。

### P4：一个 Run，一条主阅读轴

当前任务的目标、澄清、计划、执行、产物和下一步构成唯一主线。导航、历史、Context、属性和高级日志不得与主线争夺首屏焦点。

### P5：Task → Artifact 是结果闭环

Agent 的价值不是“回复了一段话”，而是交付可查看、可编辑、可比较、可确认的 Artifact。单课件与课程方案包是两个独立任务类型，共享这条骨架。

### P6：过程可见，但按教师理解分层

默认层说明“正在做什么、为什么、得到什么”；展开层显示 Skill、工具、阶段输入输出；高级层显示必要的参数、技术日志和错误诊断。

### P7：稳定方向，任务化工作区

ClassIn Shell 持续表达身份与全局位置，WorkBuddy 工作区根据新建、执行、产物编辑、Skill/MCP 管理等任务改变结构，不机械维持同一列数。

### P8：桌面宽幅用于保持关系

宽屏优先让目标、Context、执行和产物之间的关系可见。辅助区域应可收起、扩展或转场，不能把页面堆成持续四栏。

### P9：教师控制靠状态与回执实现

草稿、建议动作、教师确认、执行结果和失败恢复是显式状态。低风险界面动作可即时恢复；ClassIn 业务写回必须具备审批、校验和回执。

### P10：克制来自纪律，不来自空白

排版、对齐、重复节奏、稳定对象语义和状态反馈共同形成简洁。不能用大面积空白、减少必要字段或删除关键状态来模拟高级感。

## 4. WorkBuddy 容器候选

### 锁定结构：共享 ClassIn Shell + 专属 Agent Work Surface

```text
ClassIn PC
├── 一级主导航：角色、业务模块、消息、即时工具、账户
├── AI Agent 二级导航面板（NineClaw 式扁平导航）
│   ├── 新建任务 / 近期任务（默认可见 6 条）
│   └── Skills / Tools / 内容 / 定时 / 文件 / 设置
└── WorkBuddy 专属 Work Surface
    ├── 当前 Agent Run 主轴
    └── 按需产物、Context 或执行详情区域
```

设计意图：

- WorkBuddy 继承 ClassIn 身份、组织和业务入口，不成为完全割裂的独立应用；
- Agent Run 获得接近专属应用的连续工作空间；
- AI Agent 作为 ClassIn 一级入口打开专属二级导航面板；面板内所有目的地和任务条目保持扁平，Section 标题不形成第三级；
- 任务历史直接位于该二级面板，不在工作区内额外生成第三根历史侧栏；
- 右侧区域由当前意图决定是 Artifact、Core Context 或执行详情，默认不同时常驻三者；
- 复杂课件编辑和多产物审阅可进入扩展面板或沉浸式全屏，并保留返回现场。

此结构已在 2026-08-20 Phase 1 Review 中确认并锁定。

## 5. 信息层级

### L0：全局方向

教师身份、机构、ClassIn 一级导航、全局消息和账户。

### L1：任务现场

任务标题、目标、当前状态、下一步、任务历史和来源入口。

### L2：Agent 执行主线

信息补齐、计划、阶段进度、过程摘要、教师交互和异常恢复。

### L3：结果与辅助上下文

Artifact、Core Context、执行详情、版本和关联 ClassIn 对象。

### L4：高级能力与技术证据

Skill、MCP、工具参数、原始输入输出、命令、日志和诊断信息。

默认只展开 L0-L3 中完成当前任务所需的内容。L4 始终可追溯，但不抢占教师主流程。

## 6. 视觉方向

关键词：`专业 / 克制 / 安静 / 精确 / 连续 / 可恢复`。

- 使用中性浅色 App Frame 与白色主工作面；
- 品牌色只承担 ClassIn 识别、焦点和关键行动，不铺满中性区域；
- 页面结构依靠对齐、留白、排版和轻边界，不制造卡片墙；
- 当前任务和可执行下一步拥有最高视觉权重；
- 教师高频列表和过程使用 Compact 密度，长内容和 Artifact 使用 Comfortable 阅读密度；
- 动效只表达进入、展开、状态变化、完成和恢复，不做装饰性演出；
- 目标视口为 `1440×900`。

目标设计规格已经通过 D-018 锁定。D-003 仅继续约束当前旧原型仍处于视觉低保真交付阶段；后续新原型何时切换到目标视觉高保真，仍需单独更新实施阶段状态。

## 7. Agent 特有设计语言

### 任务不是聊天记录

自然语言是输入与协作方式，任务结构必须同时表达目标、状态、计划、过程、产物和下一步。

### 过程不是调试控制台

工具调用应有教师摘要、能力名称、作用、输入范围、输出结果和状态；原始技术细节进入更深层。

### 产物不是消息附件

Artifact 拥有类型、标题、状态、版本、来源、编辑、AI 修改、保存和关联对象语义。多个 Artifact 可以形成方案包，但单个课件也必须独立成立。

### Context 不是永久记忆

Context 必须表达来源、使用范围、更新时间和任务快照。教师可以看到、调整或移除影响本次任务的关键 Context。

## 8. Phase 1 完成条件

- 每条设计原则能追溯到当前决策、ClassIn PC 或 Linear/NineClaw 证据；
- 来源规则有明确采纳状态；
- WorkBuddy 容器和功能区域关系有可评审候选；
- Golden Samples 覆盖 Shell、列表、详情、返回现场和 ClassIn 业务工作台；
- 未把 Core Context 的候选字段或 Token 值伪装成已锁定事实；
- 用户完成 Phase 1 Review 后，才进入页面与 Core Context 详细规格。
